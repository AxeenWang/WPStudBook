# CE 匯入五月對帳 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 接上五月繁殖圈名單的對帳：快照帶上次五月匯入、定年、這一局的母馬與還沒進過繁殖圈的自家牝駒；以能力番号＋出生年配對（缺能力番号的以唯一馬名輔助），每一列分成繼續在圈、撤銷離圈、已登記賣出、回歸、新進自家產駒、新進其他或錯誤，沒被見到的在圈母馬判為缺席或未配對，列出用途把關清單；使用者可以更正缺席原因、替未配對的母馬指定一列或確認缺席、處理已登記賣出、改掛用途；套用時逐項交給寫入操作（缺席的離圈、撤銷離圈、補齊身分、回歸、轉入、新建市場母馬、轉場、繁殖牝馬馬番号、修改用途），要確認警告的項目整筆回復並回傳 `item-unconfirmed`（需求規格 8.4、8.5、11.2、11.5，技術設計 4.3、4.4「流程」「五月對帳」）。

**Architecture:** CE 匯入拆成九塊，本計畫是第四塊（4-1 解析 → 4-2 流程 → 4-3 一月 → 4-4 五月對帳 → 4-5 五月資料補齊 → 4-6 七月 → 4-7 四月 → 4-8 累加匯入 → 4-9 選用匯入）。母馬的用途、在圈狀態與用途的指定移到 `core/mares.ts`（`storage` 照舊從 `records.ts`、`mare-assignment.ts` 引用）；`core/imports.ts` 加上五月的快照型別、九種計畫項目與 MAY-02 的筆數。`storage/imports.ts` 的 `loadImportSnapshot` 在五月另讀 `may`，`applyImport` 依項目的種類分派寫入操作，要確認的項目回傳 `item-unconfirmed`。新的寫入操作：`departMare`（`herd-writes.ts`）、`fillHorseIdentity`（`horse-writes.ts`）、`importHorseNumber`（`horse-numbers.ts`）、`importMare`（`mare-writes.ts`）；`transferFilly` 替已售出的產駒記來源其他。`ce-import/may.ts` 是純函式：`previewMay` 配對、分類並套用使用者的決定，`mayContent` 產生計畫的內容。`ce-import` 與 `storage` 互不引用，只透過核心的型別交接；畫面只負責串接（之後的畫面計畫）。

**Tech Stack:** TypeScript（strict）、Dexie、Vitest（`node` 環境）、`fake-indexeddb`。不新增套件。

**Spec:** `docs/specs/需求規格.md`（6.2、6.4、8.4、8.5、8.9、11.1、11.2、11.5、第 15 章）、`docs/specs/技術設計.md`（4.2、4.3、4.4「流程」「五月對帳」、第 10 節）。

## Global Constraints

- 成品：`app/dist/WPStudBook.html` 單一檔案，Windows 最新版 Edge 與 Chrome 以 `file://` 離線使用；執行時不依賴 CDN、網路、本機伺服器或擴充功能。（AGENTS.md）
- 瀏覽器能力一律用內建 API，不加套件（AGENTS.md、技術設計第 2 章）；Vitest 維持 `environment: 'node'`，不加 jsdom。
- TypeScript strict，維持 TypeScript 6.x。`src/` 的 `lib` 是 ES2022：不要用 `findLast`、`toSorted`、`Object.groupBy` 這類 ES2023 以後的方法。`verbatimModuleSyntax` 已開啟：只當型別用的匯入要寫 `type`。
- 模組邊界（AGENTS.md，ESLint 已設定）：`src/ce-import/` 與 `src/storage/` 在專案模組中只能引用 `src/core/`，兩者互不引用；`src/core/` 不得引用其他模組與 DOM 全域物件。
- 型別檢查的範圍：`src/` 底下的檔案（含測試，以及測試引用的 `tests/support/` 檔案）由 `tsconfig.app.json` 檢查，沒有 Node 的型別；`tests/acceptance/`、`tests/local/` 與只被它們引用的 `tests/support/import-flow.ts` 由 `tsconfig.node.json` 檢查。
- 錯誤處理（技術設計第 5 章、4.3「寫入操作」、4.4「五月對帳」）：規則以回傳值表達（阻止、錯誤、待核對、待確認）；畫面不會送出的狀況（不合法的決定、未配對沒處理完就產生內容）丟出 `RangeError`；找不到資料列或資料列互相矛盾丟出錯誤；預期外的失敗讓 Dexie 交易回復。
- 本計畫不新增套件。需求規格 8.4、11.5、第 15 章與技術設計 4.3、4.4、第 10 節已和本計畫的設計一起更新（`main` 的 23fbdab 與本計畫的 commit），實作時不再改文件；本計畫的程式與需求規格或技術設計衝突時，以文件為準並回報。
- 單元測試放在原始檔旁的 `*.test.ts`。驗收測試在 `app/tests/acceptance/`，每個情境代號前綴一個檔案，測試名稱以情境代號開頭。
- 計畫裡的測試就是規格：不得修改或刪除測試與斷言。照抄實作後測試仍然失敗，停下來回報 BLOCKED，不要改測試遷就程式。
- 註解、錯誤訊息用繁體中文；系統名、馬名、欄名等遊戲用語保留日文。日文與特殊用字照抄，不要換成相近的字：「番号」不是「番號」，「状態」的「状」不是「狀」，「繋牧」的「繋」不是「繫」；測試裡的日文馬名（例如 `ミスタイプ`、`ミスタイポ`、`ノーザンダンサー`、`エーニジュウゴ`）逐字照抄，長音「ー」不是破折號，`(外)`、`[地]` 的括號是半形。

## Review Focus

規格隱含、容易出錯的輸入，以及釘住它們的測試（都已在下列任務的測試裡）：

- 手動新增時馬名打錯，名單那一列配不到她 → 未配對；沒處理完不能產生內容，否則同一匹馬會變成兩筆（Task 5 的未配對與 `mayContent`、Task 6 的指定、Task 7 的 MAY-14）。
- 兩列以馬名輔助配到同一匹，或衝突的列指到在圈的母馬 → 那幾列是錯誤，母馬算見到、不判缺席（Task 5）。
- 同一次匯入裡姊姊缺席、妹妹第一次出現 → 缺席先離圈，妹妹判定時姊姊已不在圈，是暫定保留（Task 5 的項目順序、Task 7 的 MAY-09 第二個測試）。
- 資料更正時，被更正那次判定缺席的母馬又出現 → 撤銷離圈，不建立回歸事件；一般套用時照回歸（Task 1 的 `departedThisYear`、Task 5、Task 7 的 MAY-15）。
- 用途把關改掛到替代配對而 8.3 撞系 → 套用時整筆回復並回傳 `item-unconfirmed`，確認後才寫（Task 4、Task 7 的 MAY-11）。

## 規則依據（原文）

下列引文逐字取自 `docs/specs/需求規格.md` 與 `docs/specs/技術設計.md`。實作與審查都以原文為準；本計畫自己的判斷放在下一節。

**需求規格 5.3、6.2、6.4**

> - **匯入分權**：各時點匯入只更新自己負責的資料（11.2）。
> - 能力番号與出生年都相同：同一匹馬，包含回歸的舊馬，沿用原內部識別。
> - 兩者都相同但馬名或父母明顯不符：衝突，由使用者處理。
> - 既有紀錄沒有能力番号（例如手動新增）：唯一馬名相符，且出生年相同或未填時，才輔助配對並補入；既有紀錄已有不同能力番号時為衝突，不得覆寫。
> - 幼駒、競走馬、繁殖牝馬、種牡馬各有馬番号。取得新階段馬番号時保存馬番号、階段、遊戲年與來源，舊值留在歷程；同一階段重複出現相同馬番号時不重複記錄。只有馬番号相同、能力番号不同的資料不得合併。
> - 繁殖牝馬與種牡馬馬名經匯入確認後唯讀；匯入時同一身分馬名不同，列為衝突並略過。手動輸入、尚未經匯入確認的馬名可以更正，保存更正歷程（例：11.6 的名稱不符）。
> - 手動新增時填的父母名與自身父系比照手動馬名：只輔助身分配對，與匯入值不同不算衝突，匯入時改用匯入值。經匯入確認前，手動新增的馬名、能力番号、出生年、父母名與自身父系都可以更正並保存歷程（2026-09-26 決定）。
> - `(外)`、`[地]` 前綴後面一定接著馬名。只有前綴、沒有馬名時屬於資料異常（5.2）：手動輸入時提示並不建立；匯入時警告並略過該筆，不寫入。

**需求規格 8.4、8.5、8.6、8.9**

> - **修改用途**：市場母馬的用途可隨時在卡片上修改（改掛到另一條配對，或改為待指定用途），五月繁殖圈名單的預覽是最後把關（11.5）。已有八系指定配種紀錄者，舊紀錄保留規則快照，新用途從下一次配種生效。自家母駒的系與代數由出生紀錄決定，不能修改。
> - 自家母駒（非自由配種所生）引退轉為繁殖牝馬時，除了五月匯入（11.5），也可以從產駒手動轉入：系統依出生紀錄帶入系與代數，並依 8.9 判定接替狀態，規則與五月匯入相同。來源為所屬競走馬引退轉入；牧場處置已售出的產駒（售出後再買回）來源為其他（2026-10-08 決定）。
> - 玩家只能賣出母馬，不能讓她引退：卡片只提供「賣出」（顯示影響並保存事件），不提供退役操作。賣出可以事先在管理器登記，也可以不登記，由五月匯入依缺席判定。引退只因定年，由五月匯入判定（11.5），可人工更正。
> - **撤銷離圈**：誤登記的賣出或定年引退可以撤銷，回到生產中，不建立回歸事件；自家母駒回到離圈前的接替狀態，但圈內已有另一匹正式保留的姊妹時改為候選（8.9）（2026-09-26 決定）。
> - **買回**：已售出的母馬再進入繁殖圈（五月繁殖圈名單或候選 TXT 以能力番号＋出生年配對到，或手動新增時確認）→ 恢復生產中並建立回歸事件，沿用原識別與血緣。自家母駒沿用出生紀錄的系與代數，姊妹狀態依 8.9 重新判定；市場母馬沿用原用途，從任務新增或匯入時改用該配對的用途，預覽顯示原用途與新用途。
> 據點依繋養牧場番号顯示（第 3 章），`33` 不得分成兩個。據點變更保存原據點、新據點、年、時點與來源；手動變更時時點可以留空（2026-09-26 決定）。繁殖牝馬資料不使用馬主番号。
> - 狀態：暫定保留、候選、正式保留、已被取代、已售出。自家母駒轉入時，姊妹不在圈內 → 暫定保留；已有姊妹在圈 → 候選。

**需求規格 11.2、11.5**

> | 五月繁殖圈名單 | 繁殖圈對帳（含買回）、新進母馬用途的最後把關、據點、活力快照、仔出、繁殖年數與頭數、補齊父母與父系、繁殖牝馬馬番号 | 建立正式受胎結果、把父系寫成替代系、改變自家母駒的系與代數 |
> - 不是全世界總表，只含據點 `32`～`35` 的自家母馬，也就是經過買賣、新增、轉入與定年引退後，目前實際在繁殖圈的母馬；數量不設上限（規劃約 100 匹）。出現其他或缺少繋養牧場番号 → 整份停止；不得以活力、國籍或生產國推斷範圍。
> - 以能力番号＋出生年配對既有母馬（在圈或已離圈）、手動或候選母馬及還沒進過繁殖圈的自家牝駒，保存繁殖牝馬馬番号；沒有能力番号的紀錄依 6.2 以唯一馬名輔助配對，補入能力番号與出生年。同一筆紀錄被兩列以上配到時，那幾列都是衝突（2026-10-08 決定）。
> - 預覽顯示遊戲年、總數、據點分布，以及繼續在圈、新進、回歸、定年引退、售出、轉場、未配對、衝突的筆數。
> - **新進（自家產駒）**：八系指定配種所生 → 自動加入父馬所屬系、出生紀錄代數的母馬群，狀態依 8.9，不需使用者指定；自由配種所生 → 生產中並標示不可成為後繼，不入八系母馬群。
> - **新進（其他）**：生產中，不猜測系、代數或自身父系；預覽中未指定用途者為「待指定用途」。馬名、能力番号、出生年、父母、牝系與父系欄的值照名單保存，經匯入確認，但不據此推定所屬母馬群（2026-10-08 決定）。
> - **用途把關**：預覽列出今年新進與回歸的市場母馬，包括上次五月匯入後以手動或候選 TXT 登記的，以及名單上第一次出現的，並顯示目前用途。套用前可改掛到另一條配對或改為待指定用途（8.4）。這是修正登記錯誤的最後把關；購入母馬通常到隔年五月才第一次配種，所以此時修改不影響已執行的配種。「上次五月匯入」指這一局年份早於這份名單的五月繁殖圈名單中，年份最晚、同年時最後套用的一筆；之後才登記（新增或買回）的都算，沒有上次時都算。改掛時需要確認的警告（8.3 親系統、7.3 例外補入）在套用時逐筆確認（2026-10-08 決定）。
> - **回歸**：已離圈的母馬再出現（例如買回）→ 恢復生產中並建立回歸事件，沿用原識別、血緣、自身父系、母馬群與代數；姊妹狀態依 8.9 重新判定。五月前已由候選 TXT 或手動新增登記買回者，沿用已登記的結果。
> - **缺席**：上年在圈（含上次五月匯入後才登記的）、今年缺席者，已在管理器登記賣出的照紀錄，不重複建立事件；未登記者依上次五月馬齡判斷：達定年預設「定年引退」，否則「售出」（被取代的姊妹也記為售出）。上次五月馬齡取名單年份減 1 那年的馬齡：定年是在年末引退，中間跳過一年沒匯入也判斷得對；出生年不明時預設「售出」（2026-10-08 決定）。預覽列出名單可逐匹更正，但不要求逐匹填寫，不產生缺漏警告。
> - **已登記賣出卻仍在名單**：上次五月匯入後在管理器登記賣出、名單上仍有的母馬列入待核對，由使用者撤銷賣出紀錄或視為買回；不處理時維持售出，該筆不套用。更早登記、上次五月已照紀錄處理的，再出現時是回歸（2026-10-08 決定）。
> - **未配對**：在圈但沒有能力番号或出生年的母馬（例如手動新增），名單沒有一列配到她時列為未配對，須逐匹處理才能套用：從名單上沒配到既有紀錄的列指定一列（照配到處理，那一列不另外新增），或確認缺席（售出或定年引退）。不處理就套用，名單上她那一列會另外新增一匹（2026-10-08 決定）。
> - **轉場**：據點變更保存事件。
> - `状態` 有值也不建立正式受胎結果。無法判斷的身分列入衝突，不覆寫。
> - **資料更正**：以資料更正重新匯入同年的五月名單時照本節對帳；被更正的那次匯入判定缺席、更正檔又出現的母馬改為撤銷離圈（8.5，不建立回歸事件），其他照常。錯誤較多時可回溯檢查點（12.4）後重新匯入（2026-10-08 決定）。

**需求規格第 15 章（本計畫驗收的情境）**

> - **ID-04**：已售出或定年引退的母馬以相同能力番号與出生年出現在五月繁殖圈名單 → 沿用原識別並建立回歸事件。
> - **ID-07**：手動新增、未填能力番号的母馬，五月以唯一馬名配對 → 補入能力番号、出生年與馬番号；既有能力番号不同 → 衝突。

**技術設計 4.2、4.3**

> - **同一匹馬**（`identity.ts`）：只傳目前遊戲局的馬匹，馬番号不參與判斷。能力番号由匯入層與手動輸入統一寫法後保存與比對，`0x0000` 是有效值。馬名與父母名稱用基本馬名；還不是正式馬名的名稱（四月的「母馬名の0歳」、未命名的產駒）不傳。手動輸入、尚未經匯入確認的馬名要標 `manualName`：只用來輔助配對，與匯入名稱不同時不算衝突，由匯入名稱取代（需求規格 6.4、9.4、BRD-09）；經匯入確認的馬名不同時仍是衝突（ID-08）。兩邊都有值而且不同才算「明顯不符」，比較時忽略前後空白。以馬名輔助配對時，候選是馬名相符、出生年相同或未填的紀錄；候選兩筆以上，或能力番号與出生年配到兩筆以上，都列為衝突（需求規格 11.5「無法判斷的身分列入衝突」）；輔助配對到的紀錄父母明顯不符也是衝突；以馬名配到的紀錄已有不同的能力番号時也是衝突，不得覆寫。同一匯入檔內重複的能力番号由 `duplicateAbilityNumbers` 列出，只看能力番号、不看出生年，有任何一個時整份停止套用。一月總表以父馬、母馬、出生年配對舊產駒（11.3）屬於匯入層（4.4「一月」）。
> - **母馬的年齡與列入任務**（`mares.ts`）：定年與高齡提醒年齡由儲存層從設定帶入，預設 25、18 歲。高齡提醒只在未達定年時顯示，因為已達定年的母馬不能賣出（需求規格 4.6）。五月缺席的預設原因只看上次五月的馬齡，被取代的姊妹也照同一條規則；馬齡不明時預設售出。列入任務時馬齡不明當作未達定年。出售母親提醒只看暫定保留或正式保留的女兒。馬齡不是 0 以上的整數時丟 `RangeError`。
> - **既有馬匹**（`KnownHorse`）：父母名優先用保存的匯入名稱，沒有才用連結馬匹經匯入確認的基本馬名；那匹馬的馬名還是手動輸入、尚未經匯入確認時不傳，免得手動名打錯時子女被誤判為衝突（使用者 2026-09-24 決定）。手動輸入的父母名（父母名與父系的來源為手動）同樣不當作匯入名稱，改用連結馬匹經匯入確認的馬名，沒有時不傳（需求規格 6.4，使用者 2026-09-26 決定）；追蹤名與「母馬名の0歳」不是正式馬名，不傳。
> | `mares` | 進過自家繁殖圈的母馬 | 用途（自家、替代第 q 系 N 代、第 1 系起點用、待指定用途、自由配種所生）、在圈狀態（生產中、售出、定年引退）、接替狀態（離圈時保留離圈前的值，4.2）、是否使該代成立、來源（8.1）、據點、例外補入原因（7.3） |
> - **一個操作一個交易**：每個操作在一個 rw 交易內完成：先讀遊戲局確認存在，再從資料列重新組出核心的輸入並重做檢查，最後寫入資料列與事件，並把遊戲局的更新時間設為現在、應用版本設為目前版本（見「備份與還原」）。設定、代表色這類不寫事件的操作也更新，備份提醒（需求規格 12.2）以此判斷有沒有未備份的變更。操作可以包進呼叫端的外層交易（Dexie 的巢狀交易），CE 匯入以此在單一交易內套用多個操作（4.4）。
> - **母馬的用途**（需求規格 7.3、8.3、8.4）：新增市場母馬、修改用途與從任務買回時，畫面傳任務看板上的一條配對（產出的系與代數）或待指定用途，不直接傳替代的系與代數。交易內組出八系快照，以 `listBoard` 從任務（含暫停中的）與可開啟分支的配對中找產出相同的那一條，找不到時阻止；一個產出只有一條配對，已宣告補公系時就是補公系配對。由配對推出：母馬群是起點時為第 1 系起點用，否則為替代配對母馬群的系與代數；種牡馬是零代而且不是建系起點（建立新系、補公系）時為例外補入，警告並確認、原因必填，其他情況不保存原因。替代母馬以 `checkSubstituteMare` 檢查親系統（8.3），同一代的其他替代母馬包含已離圈的、不含她自己；撞到時警告並確認，自身父系未知時只在完成的結果帶提示。
> - **新增市場母馬**（需求規格 8.4、MARE-05、MARE-29、MARE-31）：馬匹照手動建立的馬，性別為牝；在圈，不使該代成立；據點選填，事件一併記下初次據點。來源由配對推出：補公系配對，或配對的母馬群已宣告補母系（未撤銷）時為市場補系；否則建系起點、推進原系與建立新系為市場創系，循環為市場補血；待指定用途由使用者選市場混血或其他；都可附備註。已售出的母馬中，基本馬名相同、能力番号與出生年也不矛盾（兩邊都有值而且不同才算矛盾）時，警告可能是買回並列出那些母馬：使用者確認不是買回就照常建立；是買回時畫面改用買回操作，不建立新馬。
> - **修改用途**（需求規格 8.4、MARE-28）：只限在圈的市場母馬（替代、起點用、待指定用途）；自家母駒與自由配種所生的系與代數由出生紀錄決定，不提供。與目前相同時阻止。來源記的是購入時的目的（8.1），不隨用途改變。已有的配種紀錄保留自己的規則快照，新用途從下一次配種生效，不另外處理。
> - **賣出**（需求規格 8.5、MARE-08）：只限在圈的母馬；已達定年時阻止（4.6「無法再生產的母馬不能賣出」），出生年不明時可以賣出。這條只適用於手動賣出；五月缺席由「五月缺席的離圈」處理，缺席時的馬齡可能已達定年。
> - **更正離圈原因**（需求規格 8.5、11.5、MARE-32）：已離圈的母馬可以改為售出、定年引退，或撤銷回到生產中；與目前相同時阻止。撤銷不建立回歸事件；自家母駒回到保留的接替狀態（4.2），原本是正式保留而圈內已有另一匹正式保留的姊妹時改為候選。
> - **買回與回歸**（需求規格 8.5、8.9、ID-04、MARE-30、CAND-07）：只限已離圈的母馬。自家母駒沿用出生紀錄的系與代數，接替狀態以 `entrySisterStatus` 重新判定，成為暫定保留時 `establishedGeneration` 設為 true（不改回）；自由配種所生只恢復生產中。市場母馬沒有傳用途時沿用原用途，不重做 8.3 檢查；從任務買回時傳配對，照「母馬的用途」處理，事件記原用途與新用途。自家母駒與自由配種所生不接受用途。可以一併填據點。
> - **轉場**（需求規格 8.6、MARE-19）：只限在圈的母馬，與目前相同時阻止；事件記原據點（原本不知道時留空）與新據點，年份、時點與來源在事件的共用欄位。
> - **自家母駒轉入**（需求規格 8.4、8.9、9.6、11.5、LINE-17、MARE-07）：只限這一局還沒進過繁殖圈（`mares` 沒有這一列）的自家牝駒，其他的丟出錯誤；已在 `mares` 的用「買回與回歸」。以 `buildSuccessorCandidate` 組出核對輸入：八系指定配種所生以 `verifySuccessor` 核對（目標是出生紀錄的系與代數），不符時阻止；通過時用途為自家，母馬群依出生紀錄，接替狀態以 `entrySisterStatus` 判定，暫定保留時 `establishedGeneration` 設為 true。自由配種所生或比照自由配種（核對輸入為 free）：生產中，用途為自由配種所生，不分群、沒有接替狀態。需求規格 8.4 的手動轉入只提非自由配種所生，但五月匯入（11.5）用同一個操作，所以儲存層兩種都接受；畫面是否對自由配種所生提供手動轉入由畫面計畫決定。來源為所屬競走馬引退轉入，牧場處置已售出的產駒（售出後再買回）為其他（需求規格 8.4，使用者 2026-10-08 決定），可附備註；據點選填。不設年齡門檻，不改牧場處置。事件記用途與母馬群、接替狀態與據點（使用者 2026-09-28 確認）。
> - **五月缺席的離圈**（需求規格 8.5、11.5、MARE-09、MAY-12）：`departMare`，五月繁殖圈名單的計畫項目（4.4「五月對帳」），由 `applyImport` 在匯入的交易內呼叫。只限在圈的母馬，其他的丟出錯誤；原因是售出或定年引退，由預覽依馬齡預設、使用者可以更正。在圈狀態改為那個原因，自家母駒的接替狀態保留離圈前的值（4.2）。不檢查定年：缺席時的馬齡可能已達定年，「無法再生產的母馬不能賣出」只限制手動賣出。事件 `mare-departed`，不會阻止。
> - **補齊身分**（需求規格 6.2、ID-07、MAY-14）：`fillHorseIdentity`，五月以馬名輔助或使用者指定配到、缺能力番号或出生年的馬（4.4「五月對帳」），由 `applyImport` 呼叫。項目帶名單的能力番号與出生年，只補空白：馬匹已有不同的值時丟出錯誤（配對時已排除）；兩者都已有相同的值時阻止（什麼都不用改）；這一局另一匹馬已有相同的能力番号與出生年時阻止並附那一匹（`same-horse`，6.2）。事件 `horse-identity-filled` 記補上的值。不改馬名、父母與父系（4-5 五月資料補齊）。
> - **五月新進的市場母馬**（需求規格 8.4、11.5、MAY-03、MAY-11）：`importMare`，五月名單上沒配到任何紀錄的列，由 `applyImport` 呼叫。項目帶名單的完整馬名（第 1 欄）、基本馬名（第 59 欄）、能力番号、出生年、父母名、父系、牝系、據點、繁殖牝馬馬番号與用途。馬匹：性別為牝，馬名來源與父母名、父系的來源都是經匯入確認；父母名去掉前綴存基本馬名，空白或只有前綴的父母名、空白的父系與牝系不存。阻止：完整馬名只有前綴或基本馬名空白（6.4）；這一局已有相同能力番号與出生年的馬（`same-horse`）；用途的阻止同「母馬的用途」。用途、例外補入與來源照「新增市場母馬」，待指定用途的來源為其他；8.3 親系統與例外補入的警告要確認。不做「可能是買回」的警告：已售出的母馬由匯入的配對找到，配不到才新建。母馬在圈、不使該代成立；以 `recordHorseNumber` 記繁殖牝馬階段的馬番号。事件 `mare-added` 記初次據點。
> - **繁殖牝馬馬番号**（需求規格 6.4、MAY-06）：`importHorseNumber`，五月配到的母馬（新建的由 `importMare` 一併記），由 `applyImport` 呼叫。以 `recordHorseNumber` 記繁殖牝馬階段；同一階段已記過相同的馬番号時阻止（什麼都不用改；預覽只為還沒記過的產生項目）。不寫事件，`horseNumbers` 本身就是歷程。

**技術設計 4.4「流程」**

> | 4-4 五月對帳 | 五月繁殖圈名單的配對與對帳：繼續在圈、新進、回歸、缺席、已登記賣出、未配對、轉場、用途把關、補能力番号與出生年、繁殖牝馬馬番号；計畫項目的逐項確認（見下方「五月對帳」） | MAY-02、03、06、09～16，ID-04、07，MARE-09、10、19 |
> - **快照**（`ImportSnapshot`，核心）：通用的部分是遊戲局識別、目前遊戲年、更新時間、這一局的匯入紀錄，以及檢查點的摘要（識別、年、時點、建立時間）。`storage` 的 `loadImportSnapshot(db, gameId, { type, year })` 在一個唯讀交易內讀出，類型與年份是使用者確認的；各類型要用的資料依類型只讀需要的部分，由 4-3 起各塊加入（一月見「一月」）（使用者 2026-10-07 決定）。
> **計畫**（`ImportPlan`，核心；`ce-import` 的 `buildImportPlan(判斷結果, 使用者的選擇, 內容)` 產生，內容是各類型的預覽產生的摘要與項目）：遊戲局識別、快照當下的更新時間 `expectedUpdatedAt`、檔名、雜湊、類型、年、時點、套用方式、`corrects`、推進到的年份 `advanceYear`（不推進時沒有）、確認過的警告、摘要與項目 `items`。每一項對應一個寫入操作，型別 `ImportPlanItem` 是各類型項目的聯合型別（4-2 時沒有項目，4-3 加入一月的 `foal-name`，見「一月」；4-4 加入五月對帳的九種，見「五月對帳」）。選了判斷沒有提供的做法，或需要推進而沒有確認時丟出 `RangeError`（畫面不會送出）。回溯不是計畫的一種：回溯後資料變了，要重新組快照、重新預覽，再產生新的計畫。
> - 逐項套用 `items`：依項目的種類呼叫對應的寫入操作（巢狀交易），事件來源是 `{ kind: 'import', importType, importId }`，時點取計畫的時點，寫入時間是套用時間。某一項回傳阻止時丟出內部的例外，整筆回復，推進年份與前面的項目都不留；`applyImport` 在交易外接住，回傳 `item-blocked`，附第幾項（`index`，從 0 起算）、那一項，與寫入操作的阻止原因（`ImportItemBlock`，各類型寫入操作的阻止原因的聯合型別）。被阻止時不建立檢查點、不備份（CE 匯入子計畫 4-3，使用者 2026-10-07 決定）。某一項回傳待確認時同樣丟出內部的例外、整筆回復，回傳 `item-unconfirmed`，附第幾項、那一項與寫入操作的警告；畫面請使用者確認後，把那一項標為已確認（項目的 `confirmed` 為 true，套用時傳給寫入操作的 `confirmed`），重新產生計畫再套用。只有可能要確認的項目帶 `confirmed`（五月對帳的 `mare-return`、`mare-create`、`mare-usage`），其他項目回傳待確認時丟出錯誤（預期外的失敗）。一次只回報第一個要確認的項目：要確認的只有用途把關改掛時的 8.3 與 7.3 警告，很少同時出現兩筆（CE 匯入子計畫 4-4，使用者 2026-10-08 決定）。
> 4. 回傳匯入紀錄、檢查點的結果與備份的結果，或阻止（`changed-since-preview`、`item-blocked`、`item-unconfirmed`）。遊戲局不存在時丟出錯誤。
> - **畫面的串接順序**：`readImportFile` → 使用者確認類型與年份 → `parseImportFile` → `hashImportFile` → `loadImportSnapshot` → `judgeImport` → 預覽與選擇（一月是 `previewJanuary`，使用者指定列後重新預覽，再以 `januaryContent` 產生內容；五月是 `previewMay`，使用者每做一個決定就重新預覽，再以 `mayContent` 產生內容）→ `buildImportPlan` → `applyImport`（回傳 `item-unconfirmed` 時請使用者確認，標記那一項後重新產生計畫再套用）。

**技術設計 4.4「五月對帳」（全文）**

> #### 五月對帳
>
> 由 CE 匯入子計畫 4-4 負責，對應需求規格 8.4、8.5、8.9、11.2、11.5、MAY-02、03、06、09～16、ID-04、ID-07、MARE-09、10、19（使用者 2026-10-08 決定）。5 月活力快照、仔出、繁殖年數與頭數、父母與父系的補齊、既有母馬的馬名與系統名稱的提示由 4-5 五月資料補齊負責。
>
> - **快照**：類型是五月繁殖圈名單時，`loadImportSnapshot` 在同一個唯讀交易內另讀 `may`（型別 `MaySnapshot` 放在核心）：
>   - `year`：名單的年份（使用者確認的年份）；缺席判斷的馬齡以它減 1。
>   - `lastMay`：上次五月匯入，也就是這一局五月繁殖圈名單的匯入紀錄中，年份早於這份名單、年份最晚、同年時套用時間最晚的一筆（識別、年與套用時間）；沒有時留空。「上次五月之後」的事件是寫入時間晚於它的套用時間的事件，沒有上次時是全部事件；以 `[gameId+year]` 讀年份不早於它的事件，再依寫入時間篩選：目前遊戲年不能改到最後紀錄年之前（4.3「寫入操作」），所以之後寫入的事件年份一定不早於它。
>   - `retirementAge`：`settings` 的定年。
>   - `mares`：這一局 `mares` 的每一列（在圈或已離圈），帶馬匹的識別、能力番号、出生年、完整馬名、基本馬名、馬名來源、父母名的兩種值（同「一月」的 `ImportParentNames`）、用途與母馬群、在圈狀態、據點、已記的繁殖牝馬馬番号，以及三個由「上次五月之後」的事件推出的旗標（接替狀態由寫入操作在交易內判定，快照不帶）：
>     - `entered`：有她的 `mare-added` 或 `mare-returned`（用途把關的「上次五月匯入後登記的」）。
>     - `soldByUser`：在圈狀態是售出，而且她最後一筆離圈事件（`mare-departed`，或改成售出、定年引退的 `mare-departure-corrected`）的來源是手動（MAY-13 的「已登記賣出」）。
>     - `departedThisYear`：她最後一筆離圈事件的來源是年份與這份名單相同的五月匯入（資料更正的特例）。
>   - `fillies`：還沒進過繁殖圈（`mares` 沒有這一列）的自家牝駒（有出生紀錄、性別為牝），出生年不晚於年份減 2，以 `[gameId+birthYear]` 的範圍讀出：識別、能力番号、出生年、馬名、馬名來源、父母名的兩種值、是不是自由配種所生（出生紀錄沒有系與代數）、牧場處置是不是已售出。
>   - 母馬與牝駒連結的父母找不到時丟出錯誤（同「一月」）。其他類型不讀這些資料。
> - **配對**（`ce-import` 的 `previewMay`，純函式）：
>   1. 母馬與牝駒轉成核心的 `KnownHorse`：馬名用基本馬名，手動輸入的馬名標 `manualName`，父母名用經匯入確認的名稱（4.2「同一匹馬」）。每一列以 `matchHorse` 配對，列的馬名取第 59 欄，父母名以 `splitHorseName` 去掉前綴（需求規格 6.2）。
>   2. 同一筆紀錄被兩列以上配到（只會發生在以馬名輔助時）→ 那幾列都是衝突。
>   3. 配到或衝突的列指到的母馬與牝駒算「名單上見到了」，不判缺席。
> - **列的分類**：
>   - 繼續在圈：配到在圈的母馬。據點與名單不同時另計轉場；原本沒有據點時補上，不算轉場。
>   - 已登記賣出（MAY-13）：配到 `soldByUser` 的母馬，列為待核對。
>   - 回歸（ID-04）：配到其他已離圈的母馬。資料更正時，配到 `departedThisYear` 的母馬改為撤銷離圈（需求規格 11.5「資料更正」）。
>   - 新進（自家產駒）：配到牝駒。
>   - 新進（其他）：沒配到任何紀錄。
>   - 衝突：`matchHorse` 判為衝突，或上面第 2 步；錯誤，不套用。
>   - 第 1 欄只有前綴、沒有馬名，或第 59 欄空白的列是錯誤，不論分類（6.4）；配到的母馬仍算見到。第 1 欄去掉前綴後與第 59 欄不同時，新進（其他）的列警告、照樣建立，基本馬名取第 59 欄（同「一月」）；既有母馬的馬名由 4-5 處理。
> - **缺席**：沒被見到的在圈母馬：
>   - 有能力番号與出生年 → 缺席。預設原因以 `defaultAbsenceReason` 判斷，馬齡是名單年份減 1 那年的馬齡；出生年晚於那一年時當作馬齡不明（預設售出）。使用者可以逐匹更正。
>   - 缺能力番号或出生年 → 未配對。
>   - 已離圈的不動；`soldByUser` 的另外列出，照紀錄處理（MAY-12）。
> - **使用者的決定**：`previewMay(entries, snapshot, mode, decisions)` 的 `decisions`，畫面每改一次就重新預覽：
>   - `absences`：母馬 → 售出或定年引退。改缺席的預設原因，或確認未配對的母馬缺席。
>   - `picks`：未配對的母馬 → 行號。那一列要是新進（其他）、還沒被別匹指定，她已有的能力番号或出生年要與那一列相同。指定後照配到處理（配對方式為指定），父母經匯入確認的名稱與那一列明顯不符時為錯誤（4.2「同一匹馬」）。
>   - `soldPresent`：已登記賣出的母馬 → 撤銷離圈或視為買回。不處理時那一列待核對、不套用，她維持售出。
>   - `usages`：用途把關清單上的母馬（既有的以母馬識別，新進其他以行號）→ 用途（`MareAssignment`）、例外補入原因與是否已確認。與目前相同的用途畫面不送出：繼續在圈的母馬改成相同用途時，修改用途的寫入操作會阻止（`unchanged`），整筆回復。
>   - 不合法時丟出 `RangeError`（畫面不會送出）：指定的不是未配對的母馬、同一匹又確認缺席，或那一列不是新進（其他）、已被指定、能力番号或出生年矛盾；`absences` 的母馬不是缺席或未配對；`soldPresent` 的母馬不是已登記賣出；`usages` 的對象不在用途把關清單。未配對的母馬沒有全部處理（指定或確認缺席）時，`mayContent` 丟出 `RangeError`（需求規格 11.5「未配對」，使用者 2026-10-08 決定）。
> - **用途把關**（需求規格 11.5、MAY-11）：清單是市場母馬（替代、起點用、待指定用途）中，新進（其他）的列（預設待指定用途）、這次回歸或視為買回的（預設原用途；撤銷離圈的不算）、繼續在圈而且 `entered` 的。改了用途時：新進的照新用途建立，回歸的把用途交給 `returnMare`，繼續在圈的另加一項交給 `changeMareUsage`。用途是否在任務看板上、8.3 親系統與 7.3 例外補入由寫入操作在交易內檢查（4.3「母馬的用途」）；預覽拿不到任務看板與系統對照表，不預檢，要確認的警告在套用時逐筆確認（「流程」的 `item-unconfirmed`）。
> - **預覽的結果**：遊戲年、列數、據點分布（32～35 各幾列）；每一列的分類、配到的母馬與配對方式（能力番号、馬名或指定）、要做的變更（補上的能力番号與出生年、據點的原值與新值、新的繁殖牝馬馬番号）、警告與錯誤；缺席的母馬（預設原因、選的原因、判斷用的馬齡）；已登記賣出、這次缺席的母馬；未配對的母馬（可以指定的列與目前的處理）；用途把關清單（目前用途與選的用途）。筆數：
>   - MAY-02：繼續在圈、新進（自家產駒加其他）、回歸（含視為買回）、定年引退、售出、轉場、未配對、衝突；定年引退與售出只算這次判定的缺席。
>   - IMP-05 以列計，每一列只算進其中一種：可套用（有項目的列）、略過（繼續在圈但什麼都不用改的列）、待核對（已登記賣出、還沒處理的列）、錯誤；四種加起來等於列數。警告是可套用的列中有警告的列數。4-4 還不存年度資料，大部分繼續在圈的列在 4-4 都算略過。
> - **內容與項目**：`mayContent(preview)` 產生「流程」的內容。摘要的 `total`、`applied`、`skipped`、`pending`、`warnings`、`errors` 同「一月」，另加選填的 `herd`：MAY-02 的筆數與據點分布。項目依下列順序，同一類依行號（缺席依母馬在快照的順序，確認缺席的未配對接在缺席之後）：
>   1. `mare-depart`（`departMare`）：缺席與確認缺席的未配對，帶原因。
>   2. `mare-revoke`（`correctDeparture` 回到生產中）：已登記賣出選撤銷，與資料更正的特例。
>   3. `horse-identity`（`fillHorseIdentity`）：以馬名輔助或指定配到、缺能力番号或出生年的。
>   4. `mare-return`（`returnMare`，帶據點、用途、例外補入原因與 `confirmed`）、`filly-transfer`（`transferFilly`，帶據點）、`mare-create`（`importMare`，帶 `confirmed`）。
>   5. `mare-move`（`moveMare`）：繼續在圈、據點不同或原本沒有。
>   6. `horse-number`（`importHorseNumber`）：配到的母馬還沒記過這個繁殖牝馬馬番号。
>   7. `mare-usage`（`changeMareUsage`，帶 `confirmed`）：用途把關改了繼續在圈的母馬。
>
>   離圈先做，回歸與轉入以 8.9 判定姊妹狀態時才看得到這次的缺席；撤銷在轉入之前，因為她一直在圈。
> - **測試**：
>   - 單元測試：配對的三種方式（能力番号、馬名、指定）與兩列配到同一匹；每一種分類；缺席的預設（年份減 1 的馬齡、馬齡不明、出生年晚於那一年）與更正；三個旗標（「上次五月之後」以寫入時間切開、年份更早的五月才算上次）；資料更正的特例；未配對的指定、三種 `RangeError` 與沒處理完時不能產生內容；用途把關的範圍與三種套用方式；項目的順序；筆數的加總；據點分布。快照只在五月讀這些資料。新寫入操作的每一種阻止與事件，`transferFilly` 的來源；`applyImport` 的 `item-unconfirmed`（整筆回復、第幾項、確認後套用成功）與 `confirmed` 有傳到寫入操作。
>   - 測試資料預設兩年、兩局（同「一月」）。
>   - 驗收測試照畫面的順序串接：MAY-02、03、06、09～16，ID-04、ID-07（走五月流程），MARE-09、10、19，IMP-10 的五月部分。
>   - `tests/local` 以 1968 年五月實檔對空局預覽：10 列全部是新進（其他）。

## 本計畫的詮釋

需求規格與技術設計沒有逐字寫出、由本計畫決定的地方。技術設計 4.4「五月對帳」已經和使用者確認；下面是本計畫在程式層級的決定，審查時請逐條對照上一節的原文。

1. **快照**（Task 1）：
   - `MareUsage`、`HerdStatus`、`MareAssignment` 移到 `core/mares.ts`，因為核心的快照與計畫項目要用；`storage/records.ts` 與 `storage/mare-assignment.ts` 從核心引用再轉出，儲存層其他檔案的引用不變。
   - 「上次五月匯入」：五月繁殖圈名單的匯入紀錄中年份早於這份名單的，取年份最晚、同年時套用時間最晚的一筆。事件：有上次時以 `[gameId+year]` 從上次的年份讀到 `Dexie.maxKey`，只留寫入時間晚於套用時間的；沒有上次時以 `gameId` 讀全部。讀出後依寫入時間排序（`sort` 是穩定排序，同一時間維持讀出的順序）。
   - 三個旗標：`entered` 是有 `mare-added` 或 `mare-returned`；離圈事件是 `mare-departed`，或 `to` 不是 `in-herd` 的 `mare-departure-corrected`，取排序後的最後一筆；`soldByUser` 要在圈狀態是售出而且那一筆的來源是手動；`departedThisYear` 要不在圈而且那一筆的來源是年份與名單相同的五月匯入（以來源的 `importId` 對到匯入紀錄）。
   - 母馬以 `gameId` 讀出（依識別排列），馬匹與父母以 `bulkGet` 讀出；牝駒以 `[gameId+birthYear]` 從 `Dexie.minKey` 讀到年份減 2，只留有出生紀錄、牝、還不在 `mares` 的（依出生年、識別排列）；繁殖牝馬馬番号以 `[gameId+horseId]` 的 `anyOf` 讀出，只取 `broodmare` 階段。`year` 是快照範圍的年份，`retirementAge` 取 `settings`。
   - 一月的父母讀取與名稱組裝抽成 `loadParents`、`importNames`，與五月共用，一月的結果不變。其他類型的快照沒有 `may`；原本以五月的範圍測通用欄位的測試改用候選 TXT，因為五月現在多帶 `may`。
2. **寫入操作**（Task 2）：
   - `departMare(db, gameId, horseId, reason, options)`：只讀寫 `mares`，沒有阻止原因（`WriteResult<MareRow, never>`）；不在圈內時的錯誤訊息是「不在繁殖圈內的母馬不能判定缺席」。
   - `fillHorseIdentity(db, gameId, horseId, { abilityNumber, birthYear }, options)`：寫法在交易外檢查（`RangeError`）；交易內找不到馬匹、已有不同的值時丟出錯誤；`same-horse` 與 `unchanged` 一起列出；事件只記補上的欄位。
   - `importHorseNumber(db, gameId, horseId, stage, number, options)`：馬匹要在這一局；沒有記（已有同一階段的相同馬番号）時回傳 `unchanged`，什麼都不寫，遊戲局的更新時間也不變。
   - `transferFilly` 的來源：牧場處置是已售出時記其他，其他照舊；備註照記。
3. **新建市場母馬**（Task 3）：`importMare(db, gameId, item, options)` 的阻止依序列出 `horse-name`、`same-horse`、用途的阻止；`same-horse` 以項目的能力番号與出生年查，不排除任何馬。父母名先去掉前後空白再以 `splitHorseName` 取基本馬名，空白或只有前綴時不存；三者任一有值時父母名的來源是匯入；牝系去掉前後空白後不是空的才存原文。結果沿用新增市場母馬的 `AddedMare`。
4. **套用**（Task 4）：九種項目的型別放在 `core/imports.ts`，`ImportPlanItem = FoalNameItem | MayItem`。`applyItem` 依 `kind` 分派：回歸傳 `{ location, assignment, exceptionReason }`，修改用途傳 `{ assignment, exceptionReason }`；項目的 `confirmed` 為 true 時才把 `confirmed` 傳給寫入操作。可以確認的項目是 `CONFIRMABLE`（`mare-return`、`mare-create`、`mare-usage`），其他項目回傳待確認時照舊丟出錯誤。一次只回報第一個要確認的項目。
5. **預覽**（Task 5）：
   - 列的馬名用第 59 欄原文（`matchHorse` 比較時忽略前後空白），父母名先去掉前後空白再去掉前綴。兩列以上配到同一筆時，那幾列都改成 `ambiguous` 的衝突。
   - 「見到」的母馬：配到的、衝突指到的，以及錯誤的列（只有前綴或第 59 欄空白）配到的。
   - 缺席依快照的母馬順序；預設原因以 `defaultAbsenceReason` 判斷，傳入的設定只換定年（高齡提醒年齡用不到）。未配對的候選是新進（其他）的列（沒配到任何紀錄、馬名沒問題）中能力番号與出生年不矛盾的。`registeredSales` 是 `soldByUser`、沒被見到的母馬。
   - 列與錯誤都依檔案的順序。變更的 `identity` 只列原本空白的欄位，項目照樣帶名單的兩個值；據點和母馬目前的不同時列出原值（不知道時沒有）與新值，牝駒與新進其他一定列出；馬番号還沒記過才列出。
   - 分類依「牝駒 → 在圈 → 資料更正而且 `departedThisYear` → `soldByUser` → 回歸」判斷。項目在列內依撤銷、補齊身分、回歸或轉入、轉場、馬番号的順序；繼續在圈與撤銷離圈的據點不同時才另加轉場（回歸與轉入把據點交給寫入操作）。
   - `mayContent` 先放缺席的離圈，再把各列的項目依 `ITEM_ORDER` 排序（穩定排序，同一類維持行號的順序）。快照沒有五月的資料時丟出一般的錯誤；牧場不是 32～35 時丟出 `RangeError`。
6. **使用者的決定**（Task 6）：
   - `absences` 的母馬不在缺席與未配對裡時丟出 `RangeError`（「這匹母馬不是缺席或未配對：…」）。
   - 指定依 `picks` 的順序處理：不是未配對的母馬、同一匹又確認缺席、那一列不是新進其他（含配到別匹、錯誤、檔案沒有、已被前面的指定拿走）、能力番号或出生年矛盾，各有一種 `RangeError` 訊息（見 Task 6 的測試）。指定的列父母經匯入確認的名稱明顯不符時，那一列是錯誤（`sire`、`dam`），母馬仍算處理過。
   - 已登記賣出的決定只看分類是 `sold-present` 的列；撤銷照撤銷離圈、視為買回照回歸（`actingKind`），還沒選時那一列沒有項目、算待核對。
   - 用途的決定在組列時就帶進項目（新進其他的 `mare-create`、回歸的 `mare-return`、繼續在圈另加 `mare-usage`），組好用途把關清單之後才檢查對象在不在清單上，不在時丟出 `RangeError`（「不在用途把關清單上：…」）。決定的欄位原樣展開到項目上。
   - MAY-02 的定年引退與售出包含確認缺席的未配對；`unmatched` 是還沒處理的匹數。`mayContent` 的離圈先放缺席、再放確認缺席的未配對。

 * 在 loadImportSnapshot 的交易內呼叫
 */
async function loadMay(
  db: WPStudBookDatabase,
  gameId: string,
  year: number,
  imports: readonly ImportRecord[],
): Promise<MaySnapshot> {
  const lastMay = lastMayImport(imports, year)
  const { retirementAge } = await loadSettings(db, gameId)
  const mareRows = await db.mares.where('gameId').equals(gameId).toArray()
  const mareIds = new Set(mareRows.map((mare) => mare.horseId))
  const horses = new Map<string, HorseRow>()
  for (const horse of await db.horses.bulkGet([...mareIds])) {
    if (horse) horses.set(horse.id, horse)
  }
  const fillyRows = await db.horses
    .where('[gameId+birthYear]')
    .between([gameId, Dexie.minKey], [gameId, year - 2], true, true)
    .filter(
      (horse) => horse.birth !== undefined && horse.sex === 'female' && !mareIds.has(horse.id),
    )
    .toArray()
  const parents = await loadParents(db, [...horses.values(), ...fillyRows])
  const numbers = await db.horseNumbers
    .where('[gameId+horseId]')
    .anyOf([...mareIds].map((id) => [gameId, id]))
    .filter((row) => row.stage === 'broodmare')
    .toArray()
  const flags = mareFlags(await eventsSince(db, gameId, lastMay), imports, year)
  const mares = mareRows.map((mare): ImportMare => {
    const horse = horses.get(mare.horseId)
    if (!horse) throw new Error(`找不到馬匹：${mare.horseId}`)
    return {
      ...importHorse(horse, parents),
      usage: mare.usage,
      ...(mare.groupLine === undefined ? {} : { groupLine: mare.groupLine }),
      ...(mare.groupGeneration === undefined ? {} : { groupGeneration: mare.groupGeneration }),
      herd: mare.herd,
      ...(mare.location === undefined ? {} : { location: mare.location }),
      broodmareNumbers: numbers
        .filter((row) => row.horseId === mare.horseId)
        .map((row) => row.number),

    }
  })

    ...importHorse(horse, parents),
    free: horse.birth?.placement === undefined,
    sold: horse.disposition === 'sold',
  }))
  return { year, ...(lastMay === undefined ? {} : { lastMay }), retirementAge, mares, fillies }
}

/** 上次五月匯入：年份早於 year 的五月繁殖圈名單中，年份最晚、同年時套用時間最晚的一筆；沒有時為 undefined */
function lastMayImport(imports: readonly ImportRecord[], year: number): LastMayImport | undefined {
  let last: ImportRecord | undefined
  for (const record of imports) {
    if (record.type !== 'may-herd' || record.year >= year) continue
    const later =
      last === undefined ||
      record.year > last.year ||
      (record.year === last.year && record.appliedAt > last.appliedAt)
    if (later) last = record
  }
  return last === undefined
    ? undefined
    : { id: last.id, year: last.year, appliedAt: last.appliedAt }
}

/**
 * 上次五月之後的事件，依寫入時間排序：寫入時間晚於上次五月匯入的套用時間；沒有上次時是這一局的全部事件。
 * 目前遊戲年不能改到最後紀錄年之前，之後寫入的事件年份一定不早於上次五月的年份，所以先以 [gameId+year] 縮小範圍
 */
async function eventsSince(
  db: WPStudBookDatabase,
  gameId: string,
  lastMay: LastMayImport | undefined,
): Promise<EventRow[]> {
  const events =
    lastMay === undefined
      ? await db.events.where('gameId').equals(gameId).toArray()
      : await db.events
          .where('[gameId+year]')
          .between([gameId, lastMay.year], [gameId, Dexie.maxKey], true, true)
          .filter((event) => event.recordedAt > lastMay.appliedAt)
          .toArray()
  return events.sort((a, b) =>
    a.recordedAt < b.recordedAt ? -1 : a.recordedAt > b.recordedAt ? 1 : 0,
  )
}

/**
 * 由上次五月之後的事件（依寫入時間排序）推出母馬的三個旗標（技術設計 4.4「五月對帳」）：
 * entered 是有新增或回歸的事件；離圈事件是 mare-departed，或改成售出、定年引退的 mare-departure-corrected，
 * 取最後一筆：在圈狀態是售出而且它是手動的為 soldByUser，它來自年份為 year 的五月匯入為 departedThisYear
 */
function mareFlags(
  events: readonly EventRow[],
  imports: readonly ImportRecord[],
  year: number,
): (mare: MareRow) => Pick<ImportMare, 'entered' | 'soldByUser' | 'departedThisYear'> {
  const entered = new Set<string>()
  const departures = new Map<string, EventSource>()
  for (const event of events) {
    switch (event.kind) {
      case 'mare-added':
      case 'mare-returned':
        entered.add(event.horseId)
        break
      case 'mare-departed':
        departures.set(event.horseId, event.source)
        break
      case 'mare-departure-corrected':
        if (event.to !== 'in-herd') departures.set(event.horseId, event.source)
        break
    }
  }
  const records = new Map(imports.map((record) => [record.id, record]))
  return (mare) => {
    const source = departures.get(mare.horseId)
    const record = source?.kind === 'import' ? records.get(source.importId) : undefined
    return {
      entered: entered.has(mare.horseId),
      soldByUser: mare.herd === 'sold' && source?.kind === 'manual',
      departedThisYear:
        mare.herd !== 'in-herd' && record?.type === 'may-herd' && record.year === year,
    }
  }
}

/** 這些馬連結的父母；找不到的不放進來，由 parentNames 丟出錯誤。在 loadImportSnapshot 的交易內呼叫 */
async function loadParents(
  db: WPStudBookDatabase,
  horses: readonly HorseRow[],
): Promise<Map<string, HorseRow>> {
  const ids = new Set<string>()
  for (const horse of horses) {
    if (horse.sireId !== undefined) ids.add(horse.sireId)
    if (horse.damId !== undefined) ids.add(horse.damId)
  }
  const parents = new Map<string, HorseRow>()
  for (const parent of await db.horses.bulkGet([...ids])) {
    if (parent) parents.set(parent.id, parent)
  }
  return parents
}

/** 補齊身分的輸入：名單的能力番号（已統一寫法）與出生年 */
export interface HorseIdentity {
  abilityNumber: string
  birthYear: number
}

/**
 * 補齊身分的阻止原因：
 * - same-horse：這一局另一匹馬已有相同的能力番号與出生年（需求規格 6.2），horseId 是那一匹
 * - unchanged：能力番号與出生年都已有相同的值，什麼都不用改
 */
export type IdentityBlock = { kind: 'same-horse'; horseId: string } | UnchangedBlock

/**
 * 補齊身分（需求規格 6.2、ID-07、MAY-14；技術設計 4.3「補齊身分」）：五月以馬名輔助或使用者指定配到、
 * 缺能力番号或出生年的馬，由 applyImport 在匯入的交易內呼叫。只補空白，不改既有值與其他欄位
 * （馬名、父母與父系由 4-5 五月資料補齊處理）。事件 horse-identity-filled 只記補上的值。
 * 馬匹找不到、屬於其他局，或已有不同的能力番号或出生年時丟出錯誤（配對時已排除）；
 * 能力番号沒有統一寫法或出生年不是整數時丟出 RangeError
 */
export async function fillHorseIdentity(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  identity: HorseIdentity,
  options: WriteOptions = {},
): Promise<WriteResult<HorseRow, IdentityBlock>> {
  const { abilityNumber, birthYear } = identity
  if (normalizeAbilityNumber(abilityNumber) !== abilityNumber) {
    throw new RangeError(`能力番号沒有統一寫法：${abilityNumber}`)
  }
  if (!Number.isInteger(birthYear)) throw new RangeError(`出生年不是整數：${birthYear}`)
  return runWrite(db, gameId, [db.horses], options, async (context) => {
    const current = await db.horses.get(horseId)
    if (!current || current.gameId !== gameId) throw new Error(`找不到馬匹：${horseId}`)
    if (current.abilityNumber !== undefined && current.abilityNumber !== abilityNumber) {
      throw new Error(`能力番号與名單不同：${horseId}`)
    }
    if (current.birthYear !== undefined && current.birthYear !== birthYear) {
      throw new Error(`出生年與名單不同：${horseId}`)
    }
    const filled = {
      ...(current.abilityNumber === undefined ? { abilityNumber } : {}),
      ...(current.birthYear === undefined ? { birthYear } : {}),
    }
    const blocks: IdentityBlock[] = []
    const same = await findSameHorse(context, abilityNumber, birthYear, horseId)
    if (same) blocks.push({ kind: 'same-horse', horseId: same.id })
    if (Object.keys(filled).length === 0) blocks.push({ kind: 'unchanged' })
    if (blocks.length > 0) return { status: 'blocked', blocks }
    const horse: HorseRow = { ...current, ...filled }
    await db.horses.put(horse)
    await context.addEvent({ kind: 'horse-identity-filled', horseId, ...filled })
    return context.done(horse)
  })
}

/**
 * 五月新進的市場母馬（需求規格 8.4、11.5、MAY-03、MAY-11；技術設計 4.3「五月新進的市場母馬」）：

 * 空白（或只有前綴）的父母名、空白的父系與牝系不存。用途、例外補入與來源照新增市場母馬（resolveAssignment），
 * 待指定用途的來源為其他；8.3 親系統與例外補入的警告要確認。不做「可能是買回」的警告：已售出的母馬由匯入的
 * 配對找到，配不到才新建。母馬在圈、不使該代成立，記據點；以 recordHorseNumber 記繁殖牝馬階段的馬番号。
 * 事件 mare-added 記初次據點。據點不是 32～35 時丟出錯誤
 */
export async function importMare(
  db: WPStudBookDatabase,
  gameId: string,
  item: MareCreateItem,
  options: WriteOptions = {},
): Promise<WriteResult<AddedMare, ImportMareBlock>> {
  assertBase(item.location)
  return runWrite(db, gameId, [...ruleTables(db), db.horseNumbers], options, async (context) => {
    const rows = await readRuleRows(db, gameId, context.game)
    const blocks: ImportMareBlock[] = []
    if (splitHorseName(item.fullName) === null || item.baseName.trim() === '') {
      blocks.push({ kind: 'horse-name' })
    }
    const same = await findSameHorse(context, item.abilityNumber, item.birthYear)
    if (same) blocks.push({ kind: 'same-horse', horseId: same.id })
    const resolved = resolveAssignment(
      rows,
      item.assignment,
      { sireSystem: item.sireSystem },
      item.exceptionReason,
    )
    if (!resolved.ok) blocks.push(...resolved.blocks)
    if (!resolved.ok || blocks.length > 0) return { status: 'blocked', blocks }
    const { placement, sourceKind, exceptionReason, warnings, parentSystemUnknown } = resolved.value
    const stop = gate([], warnings, context.confirmed)
    if (stop) return stop

    const horse = importedMare(gameId, item)
    const mare: MareRow = {
      horseId: horse.id,
      gameId,
      ...placement,
      herd: 'in-herd',
      establishedGeneration: false,
      source: { kind: sourceKind ?? 'other' },
      location: item.location,
      ...(exceptionReason === undefined ? {} : { exceptionReason }),
    }
    await db.horses.add(horse)
    await db.mares.add(mare)
    await recordHorseNumber(context, horse.id, 'broodmare', item.horseNumber)
    await context.addEvent({
      kind: 'mare-added',
      horseId: horse.id,
      placement,
      mareSource: mare.source,
      ...(exceptionReason === undefined ? {} : { exceptionReason }),
      location: item.location,
      ...confirmation(warnings),
    })
    return context.done({ horse, mare, parentSystemUnknown }, warnings)
  })
}

/**
 * 五月繁殖圈名單的配對與預覽（需求規格 11.5，技術設計 4.4「五月對帳」）。快照要有五月的資料，否則丟出錯誤。
 * 母馬與還沒進過繁殖圈的自家牝駒以 matchHorse 配對（能力番号＋出生年，配不到時以唯一馬名輔助）；同一筆紀錄
 * 被兩列以上配到時那幾列都是衝突。沒被任何列見到的在圈母馬：有能力番号與出生年的缺席，預設原因看名單年份減 1
 * 那年的馬齡；缺能力番号或出生年的是未配對。牧場不是 32～35 時丟出 RangeError（解析已擋下）
 */
export function previewMay(
  entries: readonly BroodmareEntry[],
  snapshot: ImportSnapshot,
  mode: ImportMode,
): MayPreview {
  const { may } = snapshot
  if (may === undefined) throw new Error('快照沒有五月繁殖圈名單的資料')
  const mares = new Map(may.mares.map((mare) => [mare.id, mare]))
  const horses = new Map<string, ImportHorse>(
    [...may.mares, ...may.fillies].map((horse) => [horse.id, horse]),
  )
  const results = matchRows(entries, [...horses.values()].map(knownHorse))
  const seen = new Set(results.flatMap(({ found }) => foundIds(found)))
  // 新進（其他）的列：沒配到任何紀錄、馬名沒有問題
  const newEntries = results
    .filter(({ entry, found }) => found.kind === 'new' && !horseNameError(entry))
    .map(({ entry }) => entry)

  // 沒被見到的在圈母馬：有能力番号與出生年的缺席，缺的是未配對
  const settings = { ...DEFAULT_MARE_AGE_SETTINGS, retirementAge: may.retirementAge }
  const absences: MayAbsence[] = []
  const unmatched: MayUnmatched[] = []
  for (const mare of may.mares) {
    if (mare.herd !== 'in-herd' || seen.has(mare.id)) continue
    if (mare.abilityNumber === undefined || mare.birthYear === undefined) {
      const candidates = newEntries
        .filter((entry) => consistent(mare, entry))
        .map((entry) => entry.line)
      unmatched.push({ horseId: mare.id, candidates })
    } else {
      const age = lastMayAge(mare.birthYear, may.year)
      const defaultReason = defaultAbsenceReason(age, settings)
      absences.push({
        horseId: mare.id,
        ...(age === undefined ? {} : { age }),
        defaultReason,
        reason: defaultReason,
      })
    }
  }
  const registeredSales = may.mares
    .filter((mare) => mare.soldByUser && !seen.has(mare.id))
    .map((mare) => mare.id)

  // 列：錯誤的不套用，其他依配到的對象分類
  const rows: MayRow[] = []
  const errors: MayError[] = []
  for (const { entry, found } of results) {
    const reasons = errorReasons(entry, found)
    if (found.kind === 'conflict' || reasons.length > 0) {
      errors.push({ line: entry.line, horseIds: foundIds(found), reasons })
    } else if (found.kind === 'new') {
      rows.push(newRow(entry))
    } else {
      const horse = horses.get(found.id)
      if (horse === undefined) throw new Error(`找不到馬匹：${found.id}`)
      rows.push(matchedRow(entry, found.match, horse, mares.get(found.id), mode))
    }
  }

  const applicable = rows.filter((row) => row.items.length > 0)
  const pending = rows.filter((row) => actingKind(row.kind) === undefined)
  return {
    year: may.year,
    total: entries.length,
    rows,
    errors,
    absences,
    registeredSales,
    unmatched,
    usages: usageEntries(rows, mares),
    herd: herdSummary(entries, rows, errors, absences, unmatched),
    counts: {
      applicable: applicable.length,
      skipped: rows.length - applicable.length - pending.length,
      pending: pending.length,
      errors: errors.length,
      warnings: applicable.filter((row) => row.warnings.length > 0).length,
    },
  }
}

/**
 * 五月的內容（技術設計 4.4「五月對帳」）：還有未配對的母馬沒處理時丟出 RangeError（需求規格 11.5「未配對」）。
 * 項目依離圈、撤銷離圈、補齊身分、回歸／轉入／新建、轉場、馬番号、修改用途的順序，同一類依行號；
 * 缺席依快照的順序。摘要的 total 是列數，另填待核對、警告與錯誤的筆數，以及 MAY-02 的筆數與據點分布
 */
export function mayContent(preview: MayPreview): ImportContent {
  if (preview.unmatched.length > 0) {
    const ids = preview.unmatched.map((item) => item.horseId).join('、')
    throw new RangeError(`未配對的母馬還沒處理：${ids}`)
  }
  const { applicable, skipped, pending, warnings, errors } = preview.counts
  const departures = preview.absences.map((absence): MayItem => ({
    kind: 'mare-depart',
    horseId: absence.horseId,
    reason: absence.reason,
  }))
  // sort 是穩定排序：同一類維持列的順序，也就是行號的順序
  const rowItems = preview.rows
    .flatMap((row) => row.items)
    .sort((a, b) => ITEM_ORDER[a.kind] - ITEM_ORDER[b.kind])
  return {
    summary: {
      total: preview.total,
      applied: applicable,
      skipped,
      pending,
      warnings,
      errors,
      herd: preview.herd,
    },
    items: [...departures, ...rowItems],
  }
}

/** 項目的套用順序：離圈先做，回歸與轉入判定姊妹狀態（8.9）時才看得到這次的缺席；撤銷在轉入之前 */
const ITEM_ORDER: Record<MayItem['kind'], number> = {
  'mare-depart': 0,
  'mare-revoke': 1,
  'horse-identity': 2,
  'mare-return': 3,
  'filly-transfer': 3,
  'mare-create': 3,
  'mare-move': 4,
  'horse-number': 5,
  'mare-usage': 6,
}

/** 一列的配對結果：配到一筆紀錄、沒配到任何紀錄，或衝突 */
type Found =
  | { kind: 'matched'; id: string; match: MayMatch }
  | { kind: 'new' }
  | { kind: 'conflict'; ids: string[]; reasons: IdentityConflictReason[] }

/** 每一列以 matchHorse 配對；同一筆紀錄被兩列以上配到時，那幾列都改為衝突（無法唯一判斷） */
function matchRows(
  entries: readonly BroodmareEntry[],
  known: readonly KnownHorse[],
): { entry: BroodmareEntry; found: Found }[] {
  const results = entries.map((entry) => ({
    entry,
    found: foundOf(
      matchHorse(
        {
          abilityNumber: entry.abilityNumber,
          birthYear: entry.birthYear,
          name: entry.baseName,
          sireName: parentName(entry.sireName),
          damName: parentName(entry.damName),
        },
        known,
      ),
    ),
  }))
  const claims = new Map<string, number>()
  for (const { found } of results) {
    if (found.kind === 'matched') claims.set(found.id, (claims.get(found.id) ?? 0) + 1)
  }
  return results.map(({ entry, found }) =>
    found.kind === 'matched' && (claims.get(found.id) ?? 0) > 1
      ? { entry, found: { kind: 'conflict', ids: [found.id], reasons: ['ambiguous'] } }
      : { entry, found },
  )
}

/** matchHorse 的結果換成列的配對結果 */
function foundOf(match: HorseMatch): Found {
  switch (match.kind) {
    case 'same':
      return { kind: 'matched', id: match.id, match: 'ability-number' }
    case 'assisted':
      return { kind: 'matched', id: match.id, match: 'name' }
    case 'new':
      return { kind: 'new' }
    case 'conflict':
      return { kind: 'conflict', ids: match.ids, reasons: match.reasons }
  }
}

/** 列指到的紀錄：配到的那一筆或衝突的那幾筆；這些母馬算見到，不判缺席 */
function foundIds(found: Found): string[] {
  if (found.kind === 'matched') return [found.id]
  return found.kind === 'conflict' ? found.ids : []
}

/** 比對用的既有馬匹：馬名用基本馬名，父母名用經匯入確認的名稱（技術設計 4.2「同一匹馬」） */
function knownHorse(horse: ImportHorse): KnownHorse {
  return {
    id: horse.id,
    abilityNumber: horse.abilityNumber,
    birthYear: horse.birthYear,
    name: horse.baseName,
    manualName: horse.nameSource === 'manual',
    sireName: horse.sire.confirmed,
    damName: horse.dam.confirmed,
  }
}

/** 檔案的父母名去掉前綴的基本馬名；空白或只有前綴時為 undefined */
function parentName(text: string): string | undefined {
  return splitHorseName(text.trim())?.baseName
}

/** 這一列的據點；解析已擋下 32～35 以外的值，不符時丟出 RangeError */
function baseOf(entry: BroodmareEntry): Base {
  if (!isBase(entry.farm))
    throw new RangeError(`第 ${entry.line} 行的牧場不是 32～35：${entry.farm}`)
  return entry.farm
}

/** 第 1 欄只有前綴、沒有馬名，或第 59 欄空白（需求規格 6.4） */
function horseNameError(entry: BroodmareEntry): boolean {
  return splitHorseName(entry.fullName) === null || entry.baseName.trim() === ''
}

/** 列的錯誤：matchHorse 判出的衝突，與只有前綴或第 59 欄空白 */
function errorReasons(entry: BroodmareEntry, found: Found): MayErrorReason[] {
  const reasons: MayErrorReason[] = found.kind === 'conflict' ? [...found.reasons] : []
  if (horseNameError(entry)) reasons.push('horse-name')
  return reasons
}

/** 這一列和這匹馬已有的能力番号、出生年不矛盾 */
function consistent(horse: ImportHorse, entry: BroodmareEntry): boolean {
  return (
    (horse.abilityNumber === undefined || horse.abilityNumber === entry.abilityNumber) &&
    (horse.birthYear === undefined || horse.birthYear === entry.birthYear)
  )
}

/** 缺席判斷用的馬齡：名單年份減 1 那年的馬齡；出生年晚於那一年時當作馬齡不明 */
function lastMayAge(birthYear: number, year: number): number | undefined {
  return birthYear <= year - 1 ? ageInYear(birthYear, year - 1) : undefined
}

/** 新進（其他）的一列：建立市場母馬，預設待指定用途；第 1 欄與第 59 欄不同時警告 */
function newRow(entry: BroodmareEntry): MayRow {
  const location = baseOf(entry)
  const split = splitHorseName(entry.fullName)?.baseName
  const warnings: MayWarning[] =
    split !== undefined && split !== entry.baseName
      ? [{ kind: 'base-name', split, baseName: entry.baseName }]
      : []
  return {
    line: entry.line,
    kind: 'new-other',
    changes: { location: { to: location }, horseNumber: entry.horseNumber },
    warnings,
    items: [createItem(entry, location)],
  }
}

/** 新進（其他）建立市場母馬的項目：這一列的值，待指定用途 */
function createItem(entry: BroodmareEntry, location: Base): MareCreateItem {
  return {
    kind: 'mare-create',
    fullName: entry.fullName,
    baseName: entry.baseName,
    abilityNumber: entry.abilityNumber,
    birthYear: entry.birthYear,
    sireName: entry.sireName,
    damName: entry.damName,
    ...(entry.sireSystem === null ? {} : { sireSystem: entry.sireSystem }),
    femaleLine: entry.femaleLine,
    location,
    horseNumber: entry.horseNumber,
    assignment: { kind: 'unassigned' },
  }
}

/** 配到母馬或牝駒的一列：分類、變更與項目 */
function matchedRow(
  entry: BroodmareEntry,
  match: MayMatch,
  horse: ImportHorse,
  mare: ImportMare | undefined,
  mode: ImportMode,
): MayRow {
  const kind = rowKind(mare, mode)
  const location = baseOf(entry)
  const filled = {
    ...(horse.abilityNumber === undefined ? { abilityNumber: entry.abilityNumber } : {}),
    ...(horse.birthYear === undefined ? { birthYear: entry.birthYear } : {}),
  }
  const from = mare?.location
  const moved = from !== location
  const recorded = mare?.broodmareNumbers.includes(entry.horseNumber) ?? false
  const changes: MayChanges = {
    ...(Object.keys(filled).length > 0 ? { identity: filled } : {}),
    ...(moved ? { location: { ...(from === undefined ? {} : { from }), to: location } } : {}),
    ...(recorded ? {} : { horseNumber: entry.horseNumber }),
  }
  const acting = actingKind(kind)
  return {
    line: entry.line,
    kind,
    horseId: horse.id,
    match,
    changes,
    warnings: [],
    items: acting === undefined ? [] : rowItems(acting, horse.id, entry, changes, location),
  }
}

/** 配到的對象決定分類：牝駒是新進；在圈的繼續在圈；已離圈的依撤銷、已登記賣出、回歸的順序判斷 */
function rowKind(mare: ImportMare | undefined, mode: ImportMode): MayRowKind {
  if (mare === undefined) return 'new-own'
  if (mare.herd === 'in-herd') return 'continuing'
  if (mode === 'correction' && mare.departedThisYear) return 'revoked'
  return mare.soldByUser ? 'sold-present' : 'returned'
}

/** 列實際照哪一種處理：已登記賣出待核對，不套用（undefined）；其他照分類 */
function actingKind(kind: MayRowKind): MayRowKind | undefined {
  return kind === 'sold-present' ? undefined : kind
}

/** 配到的一列的項目（技術設計 4.4「五月對帳」）：撤銷離圈、補齊身分、回歸或轉入、轉場與馬番号 */
function rowItems(
  kind: MayRowKind,
  horseId: string,
  entry: BroodmareEntry,
  changes: MayChanges,
  location: Base,
): MayItem[] {
  const items: MayItem[] = []
  if (kind === 'revoked') items.push({ kind: 'mare-revoke', horseId })
  if (changes.identity) {
    const { abilityNumber, birthYear } = entry
    items.push({ kind: 'horse-identity', horseId, abilityNumber, birthYear })
  }
  if (kind === 'returned') items.push({ kind: 'mare-return', horseId, location })
  if (kind === 'new-own') items.push({ kind: 'filly-transfer', horseId, location })
  if ((kind === 'continuing' || kind === 'revoked') && changes.location) {
    items.push({ kind: 'mare-move', horseId, location })
  }
  if (changes.horseNumber !== undefined) {
    items.push({ kind: 'horse-number', horseId, stage: 'broodmare', number: changes.horseNumber })
  }
  return items
}

/** 市場母馬：替代、起點用、待指定用途 */
function isMarket(usage: MareUsage): boolean {
  return usage === 'substitute' || usage === 'start' || usage === 'unassigned'
}

/**
 * 用途把關清單（需求規格 11.5、MAY-11）：新進（其他）的列、這次回歸的市場母馬，
 * 以及上次五月之後新增或回歸（entered）而繼續在圈的市場母馬；依行號
 */
function usageEntries(
  rows: readonly MayRow[],
  mares: ReadonlyMap<string, ImportMare>,
): MayUsageEntry[] {
  return rows.flatMap((row): MayUsageEntry[] => {
    if (row.kind === 'new-other') return [{ key: row.line, current: { usage: 'unassigned' } }]
    const mare = row.horseId === undefined ? undefined : mares.get(row.horseId)
    if (mare === undefined || !isMarket(mare.usage)) return []
    const acting = actingKind(row.kind)
    const listed = acting === 'returned' || (acting === 'continuing' && mare.entered)
    if (!listed) return []
    const current = {
      usage: mare.usage,
      ...(mare.groupLine === undefined ? {} : { groupLine: mare.groupLine }),
      ...(mare.groupGeneration === undefined ? {} : { groupGeneration: mare.groupGeneration }),
    }
    return [{ key: mare.id, current }]
  })
}

/** MAY-02 的筆數與據點分布 */
function herdSummary(
  entries: readonly BroodmareEntry[],
  rows: readonly MayRow[],
  errors: readonly MayError[],
  absences: readonly MayAbsence[],
  unmatched: readonly MayUnmatched[],
): HerdSummary {
  const bases: Record<Base, number> = { 32: 0, 33: 0, 34: 0, 35: 0 }
  for (const entry of entries) bases[baseOf(entry)] += 1
  const count = (kinds: readonly MayRowKind[]) =>
    rows.filter((row) => {
      const acting = actingKind(row.kind)
      return acting !== undefined && kinds.includes(acting)
    })
  const staying = count(['continuing', 'revoked'])
  return {
    continuing: staying.length,
    newArrivals: count(['new-own', 'new-other']).length,
    returned: count(['returned']).length,
    retired: absences.filter((absence) => absence.reason === 'retired').length,
    sold: absences.filter((absence) => absence.reason === 'sold').length,
    moved: staying.filter((row) => row.changes.location?.from !== undefined).length,
    unmatched: unmatched.length,
    conflicts: errors.length,
    bases,
  }
}

    target.resolution = { line }

/**
 * 五月繁殖圈名單一列要換掉的值：馬齡、能力番号與馬番号必填；基本馬名省略時取完整馬名去掉前綴，
 * 父馬、父系、母馬與牧場省略時照 SAMPLES
 */
export interface MayRowValues {
  fullName: string
  baseName?: string
  /** `年`：馬齡 */
  age: number
  sire?: string
  /** `父系`：帶結尾「系」的原文 */
  sireSystem?: string
  dam?: string
  /** `牧場`：繋養牧場番号 */
  farm?: string
  abilityNumber: string
  horseNumber: string
}

/** 五月繁殖圈名單的一列：照 SAMPLES 的虛構值，換掉第 1、3、43～45、48、57～59 欄（附錄 A.3） */
export function mayRow(values: MayRowValues): ExportValues {
  return {
    ...SAMPLES.broodmare,
    1: values.fullName,
    3: String(values.age),
    ...(values.sire === undefined ? {} : { 43: values.sire }),
    ...(values.sireSystem === undefined ? {} : { 44: values.sireSystem }),
    ...(values.dam === undefined ? {} : { 45: values.dam }),
    ...(values.farm === undefined ? {} : { 48: values.farm }),
    57: values.abilityNumber,
    58: values.horseNumber,
    59: values.baseName ?? splitHorseName(values.fullName)?.baseName ?? '',
  }
}

/**
 * 五月的預覽選項：年份預設 1990；mode 省略時取判斷提供的第一個不是回溯的做法；decisions 是使用者的決定
 */
export interface MayOptions {
  year?: number
  mode?: ImportMode
  decisions?: MayDecisions
}

/** 五月的預覽：判斷結果、選的套用方式與預覽 */
export interface MayFlow {
  judgment: ReadyImport
  mode: ImportMode
  preview: MayPreview
}

/**
 * 照畫面的串接預覽五月繁殖圈名單（技術設計 4.4「流程」「五月對帳」）：組出 CP932 的檔案、讀檔、解析、算雜湊、
 * 組快照、判斷，再以 previewMay 預覽。讀不出來、解析失敗或判斷是重複時讓測試失敗
 */
export async function previewMayFile(
  db: WPStudBookDatabase,
  rows: readonly ExportValues[],
  options: MayOptions = {},
): Promise<MayFlow> {
  const year = options.year ?? 1990
  const fileName = `${year}年 5月1週_繁殖牝馬.txt`
  const bytes = cp932(exportText('broodmare', rows))
  const read = readImportFile(bytes, fileName)
  if (read.status !== 'ok') throw new Error(read.reason)
  const parsed = parseImportFile(read.text, 'may-herd', year)
  if (parsed.status !== 'ok' || parsed.format !== 'broodmare') throw new Error('解析失敗')
  const file: ImportFile = {
    fileName,
    sha256: await hashImportFile(bytes),
    type: 'may-herd',
    year,
    fileTiming: { month: 5, week: 1 },
  }
  const snapshot = await loadImportSnapshot(db, GAME, file)
  const judgment = judgeImport(file, snapshot)
  if (judgment.kind !== 'ready') throw new Error(judgment.kind)
  const mode =
    options.mode ?? judgment.options.find((option): option is ImportMode => option !== 'rollback')
  if (mode === undefined) throw new Error('只能回溯')
  const preview = previewMay(parsed.entries, snapshot, mode, options.decisions)
  return { judgment, mode, preview }
}

/** 接著以 mayContent 產生計畫（確認推進年份）並套用；套用被阻止時讓測試失敗 */
export async function applyMayFile(
  db: WPStudBookDatabase,
  rows: readonly ExportValues[],
  options: MayOptions = {},
): Promise<{ preview: MayPreview; applied: AppliedImport }> {
  const { judgment, mode, preview } = await previewMayFile(db, rows, options)
  const plan = buildImportPlan(judgment, { mode, advanceConfirmed: true }, mayContent(preview))
  const result = await applyImport(db, plan)
  if (result.status !== 'done') throw new Error(JSON.stringify(result))
  return { preview, applied: result.value }
}
