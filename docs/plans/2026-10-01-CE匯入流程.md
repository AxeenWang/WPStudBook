# CE 匯入流程 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 接上 CE 匯入的流程：匯入紀錄表、匯入的分類與目前進度、匯入比對快照、判斷重複／資料更正／直接補匯／回溯／推進年份並產生套用計畫，以及在一個交易內套用、提交後建立檢查點與自動備份（需求規格 11.1、12.1、12.2、12.4，技術設計 4.4「流程」）。計畫的項目在本計畫還是空的，以空的計畫驗收。

**Architecture:** CE 匯入拆成八塊，本計畫是第二塊（4-1 解析 → 4-2 流程 → 4-3 一月 → 4-4 五月 → 4-5 七月 → 4-6 四月 → 4-7 累加匯入 → 4-8 選用匯入）。共用的型別與規則放在 `core/imports.ts`：年度匯入的固定時點、時間點的先後、匯入紀錄、目前進度、快照與套用計畫。`ce-import/flow.ts` 是純函式：`hashImportFile` 算檔案的雜湊，`judgeImport` 以快照判斷可選的做法，`buildImportPlan` 依使用者的選擇產生計畫。`storage/imports.ts` 的 `loadImportSnapshot` 在一個唯讀交易內組出快照，`applyImport` 依計畫在一個 rw 交易內套用，提交後年度匯入建立檢查點並自動備份。`ce-import` 與 `storage` 互不引用，只透過核心的型別交接；畫面只負責串接（之後的畫面計畫）。

**Tech Stack:** TypeScript（strict）、Dexie、Vitest（`node` 環境）、`fake-indexeddb`；瀏覽器內建的 `crypto.subtle`。不新增套件。

## Global Constraints

- 成品：`app/dist/WPStudBook.html` 單一檔案，Windows 最新版 Edge 與 Chrome 以 `file://` 離線使用；執行時不依賴 CDN、網路、本機伺服器或擴充功能。（AGENTS.md）
- 瀏覽器能力一律用內建 API，不加套件（AGENTS.md、技術設計第 2 章）；Vitest 維持 `environment: 'node'`，不加 jsdom。
- TypeScript strict，維持 TypeScript 6.x。`src/` 的 `lib` 是 ES2022：不要用 `findLast`、`toSorted`、`Object.groupBy` 這類 ES2023 以後的方法（`Object.hasOwn` 是 ES2022，可以用）。`verbatimModuleSyntax` 已開啟：只當型別用的匯入要寫 `type`。位元組一律寫 `Uint8Array<ArrayBuffer>`，照計畫的程式。
- 模組邊界（AGENTS.md，ESLint 已設定）：`src/ce-import/` 與 `src/storage/` 在專案模組中只能引用 `src/core/`，兩者互不引用；`src/core/` 不得引用其他模組與 DOM 全域物件。
- 型別檢查的範圍：`src/` 底下的檔案（含測試，以及測試引用的 `tests/support/` 檔案）由 `tsconfig.app.json` 檢查，沒有 Node 的型別，所以 `tests/support/imports.ts` 只能是純 TS；`tests/acceptance/` 由 `tsconfig.node.json` 檢查。
- 錯誤處理（技術設計第 5 章、4.4「流程」）：判斷與套用的結果以回傳值表達；畫面不會送出的狀況（年份不是整數、選了沒有提供的做法、需要推進而沒有確認）丟出 `RangeError`；遊戲局不存在丟出錯誤；預期外的失敗讓 Dexie 交易回復。
- 本計畫不新增套件。需求規格 11.1、12.1、第 15 章 IMP-11 與技術設計 4.2、4.3、4.4、第 10 節已和本計畫的設計一起更新（`main` 的 2d1b2f2 與本計畫的 commit），實作時不再改文件；本計畫的程式與需求規格或技術設計衝突時，以文件為準並回報。

下列引文逐字取自 `docs/specs/需求規格.md` 與 `docs/specs/技術設計.md`。實作與審查都以原文為準；本計畫自己的判斷放在下一節。

**需求規格 11.1（共通規則）**

> - **分類**：
> - **年度匯入**：一月二歲馬總表、四月誕生幼駒名單、五月繁殖圈名單、七月受胎名單。每年在固定時點各匯入一次，列入年度工作清單（13.2）。
> - **累加匯入**：候選 TXT、目標種牡馬 TXT。全年可多次匯入，逐筆新增或補齊。
> - **選用匯入**：十月全世界繁殖牝馬總表、種牡馬總表。只追蹤自家產駒的去向，不列入年度工作清單，沒有匯入也不視為未完成。
> - **時點**：年度匯入的時點依類型固定（一月 1 月 1 週、四月 4 月 1 週、五月 5 月 1 週、七月 7 月 1 週，4.1），檔名的時點只用來預選類型，與類型的時點不同時提示、不阻止；累加匯入與選用匯入以檔名的時點為準，解析不了時沒有時點（2026-10-01 決定）。
> - **流程**：解析 → 驗證 → 身分配對 → 差異預覽 → 確認 → 單一交易套用 → 結果摘要。預覽分列可套用、略過、待核對、警告、錯誤；有阻擋錯誤時資料不變。
> - **重複與更正**：
> - 年度匯入與選用匯入：同局、同年、同時點、同類型、同內容雜湊 → 提示重複，不重複建立歷程。同年、同時點、同類型但內容不同 → 確認「資料更正」，保存原值、新值、兩份來源檔與時間，並重新驗證受影響的預定出生、繁殖圈、受胎與八系狀態。
> - 累加匯入：同一份檔案（同雜湊）再次匯入 → 提示重複。內容不同的檔案各自套用，不視為資料更正；檔內已登記的馬逐筆略過或補齊，已售出的母馬依 8.5 買回。
> - 雜湊以檔案的原始位元組計算。年度匯入與選用匯入只和同年、同時點、同類型最新的一筆比：先匯入 A、更正成 B，再匯入 A 是把 B 更正回 A，不是重複（2026-10-01 決定）。
> - **年份與進度**：
> - 目前進度是最近一次套用的年度匯入的年與時點（例：已套用 1970 年五月繁殖圈名單 → 目前進度為 1970 年 5 月 1 週）。
> - 年度匯入的檔案早於目前進度時，可能是遊戲讀了舊存檔，也可能是漏匯，由使用者在預覽選擇：
> - **回溯**：回到對應檢查點（12.4）後再套用。預覽推薦有時點、而且年與時點早於這份檔案的檢查點中最晚的一個，使用者可以改選其他檢查點；回溯後重新預覽，確認後套用（2026-10-01 決定）。
> - **直接補匯**：只在該局、該年、該時點、該類型從未匯入過時提供。不回溯，直接套用，並重新驗證受影響的預定出生、繁殖圈、受胎與八系狀態（範圍同資料更正），標記該年度工作完成，結果摘要標示「補匯」。
> - 該時點已匯入過：內容相同 → 提示重複；內容不同 → 選擇回溯或資料更正，不提供直接補匯。
> - 累加匯入與選用匯入不改變年度狀態，不提示回溯。
> - 檔案年份晚於目前遊戲年 → 預覽詢問是否推進年份，確認後先推進再套用，不確認則不套用；晚兩年以上另外警告。
> - **保存**：只存檔名、雜湊、遊戲局、年、時點、類型、套用時間、套用方式（一般、資料更正、直接補匯；資料更正另記被更正的那一筆）與結果摘要，不存原始檔（套用方式與時間 2026-10-01 決定）。
> - **檢查點**：年度匯入套用後自動建立檢查點、依 12.2 自動備份，並標記年度工作完成；累加匯入與選用匯入不建立檢查點、不標記年度工作完成。

**需求規格第 15 章（本計畫驗收的情境；各類型的預覽與套用由 4-3 以後補上）**

> - **IMP-06**：發生任一阻擋錯誤 → 資料與畫面不變。
> - **IMP-07**：同局、同年、同時點、同類型、同雜湊再次匯入 → 提示重複，不重複建立歷程。
> - **IMP-08**：同年、同時點、同類型但內容不同 → 要求確認資料更正，保存原值、新值、來源檔與時間。
> - **IMP-09**：年度匯入的檔案早於目前進度 → 預覽提供回溯到對應檢查點；該時點從未匯入過時，另提供直接補匯。
> - **IMP-11**：匯入完成 → 只保存檔名、雜湊、年份、時點、套用時間、套用方式與結果摘要，不保存原始檔。
> - **IMP-12**：年度匯入套用成功 → 自動建立檢查點並依 12.2 自動備份，不阻止操作；累加匯入與選用匯入 → 不建立檢查點。
> - **IMP-14**：目前 1968 年時匯入 `1969年 1月1週._二歲新馬.txt` → 詢問是否推進到 1969 年；確認後推進再套用，不確認則不套用。
> - **IMP-15**：檔案年份比目前晚兩年以上 → 推進詢問外另顯示警告。
> - **IMP-16**：同一時點先後匯入不同類型（例如 5 月 1 週的繁殖圈名單與種牡馬總表）→ 各自套用，不視為重複或資料更正。
> - **IMP-19**：同年先後匯入兩份內容不同的候選 TXT 或目標種牡馬 TXT → 各自套用，不視為資料更正，檔案早於目前進度也不提示回溯；同一份檔案再次匯入 → 提示重複。
> - **IMP-20**：已匯入 1970 年 5 月繁殖圈名單，才發現漏匯 1970 年 4 月誕生幼駒名單 → 可選直接補匯，不回溯；幼駒正常建立並連結前一年受胎紀錄，該年四月工作標示完成，結果摘要標示補匯。
> - **IMP-21**：早於目前進度、且同局同年同時點同類型已匯入過的年度檔案 → 只提供回溯或資料更正，不提供直接補匯。
> - **CKPT-01**：年度匯入套用成功 → 自動建立檢查點，記錄年、時點、時間與雜湊。
> - **CKPT-08**：直接補匯後 → 檢查點記為目前進度，並註明補匯的年與時點。
> - **DATA-15**：已指定備份資料夾並授權，年度匯入套用成功 → 自動在該資料夾寫入完整備份；未指定、不支援、未授權或寫入失敗 → 自動下載備份檔。

**技術設計 4.2、4.3**

> - 匯入的種類與遊戲內時點（`ImportType`、`GameTiming`）、年度匯入的固定時點與目前進度、兩邊都用到的馬匹屬性與常數（`Sex`、`SurfaceAptitude`、`Vigor`、`Conception`、據點 `Base`），以及匯入紀錄、匯入比對快照與套用計畫的型別（11.1）：`ce-import` 與 `storage` 互不引用，兩邊共用的型別放在核心（4.4）。
> 事件的來源與時點由寫入操作的呼叫端帶入：省略時為手動、時點留空（手動操作由畫面決定要不要讓使用者選，例如轉場，需求規格 8.6）；CE 匯入帶匯入的種類、匯入紀錄的識別與計畫的時點（見 4.4「流程」）。時點是遊戲內的月與週（每月 4 週）（使用者 2026-09-26 決定）。
> `imports` 以 `[gameId+type+year]` 建索引（需求規格 12.5「匯入類型、年與時點」），欄位與規則見 4.4「流程」（CE 匯入子計畫 4-2，使用者 2026-10-01 決定）。
> - **目前遊戲年**（需求規格 12.1）：往後可以改成任何年份；往回不能早於起始年，也不能早於最後紀錄年，也就是這一局事件的最大年份、馬的最大出生年與匯入紀錄的最大年份（匯入紀錄由 CE 匯入子計畫 4-2 加入，免得遊戲年落在目前進度之前），阻止時附可以改的最早年份。
> 9. 關聯：`horses` 的父、母指向 `horses`，出生紀錄的配種指向 `breedings`；`mares`、`horseNumbers` 與 `events` 的馬匹指向 `horses`；`mareYears` 的馬匹指向 `mares`；`stallions` 的馬匹、配種、補系分別指向 `horses`、`breedings`、`restorations`；`breedings` 與 `matingRatings` 的母馬指向 `mares`，種牡馬指向 `horses`；`imports` 的被更正的那一筆（`corrects`），以及 `events` 與 `horseNumbers` 來源裡的匯入紀錄（`source.importId`），指向 `imports`（4.4「流程」）。指向 `mares` 的，現有寫入操作都已要求母馬在 `mares`。事件內容裡的引用不查：取消預定後繼會刪除任用列，事件裡的任用識別本來就可能懸空。
> - **年與時點**：年取建立當下這一局的目前遊戲年，所以回溯後的目前遊戲年一定等於檢查點的年（CKPT-06）。時點由呼叫端傳入：年度匯入由 CE 匯入傳目前進度的時點，直接補匯另傳補匯的年與時點（需求規格 12.4）；手動建立由畫面決定是否帶時點（使用者 2026-09-29 決定）。建立的輸入 `NewCheckpoint` 維持一個型別，不分自動與手動做成聯合型別：會建立自動檢查點的只有 CE 匯入的 `applyImport`，它一定帶時點，由它的測試驗證；改成聯合型別要改既有的 55 處測試（CE 匯入子計畫 4-2，使用者 2026-10-01 決定）。
> - **自動備份的時機**：年度匯入按下「套用」時先 `prepareBackupTarget`，再做匯入的交易、建立檢查點，最後 `saveBackup`（4.4「資料流」第 7 步）；這個順序由 CE 匯入的 `applyImport` 負責（4.4「流程」）。權限要在耗時處理之前申請，備份要在資料寫入之後匯出，所以分成兩個呼叫（使用者 2026-09-30 決定）。自動備份失敗時匯入已經提交，不回復；最近備份時間沒有更新，備份提醒照常出現。回溯維持自動下載（需求規格 12.4），交付函式是 `downloadBackup`，不寫資料夾。
> - **索引**：`archives`（主鍵 `id`）是全域的表，不帶遊戲局欄位，不屬於 `GAME_TABLES`（見「整局資料」）：備份與檢查點不含它，永久刪除此局不碰它，刪除全部存檔時清除（見「危險區」）。一列記：`id` 為原遊戲局的識別（封存後原局已刪除，還原一律換新識別，所以不會重複，也查得到來源）、局名、封存檔的應用版本與結構版本（結構版本決定之後讀不讀得了）、起始年與封存時的目前遊戲年（年份範圍）、封存檔的匯出時間（也是檔名裡的時間）、檔名、各表筆數（總筆數由它加總，不另存；`GAME_TABLES` 加表後舊索引缺少新表的鍵，加總時當作 0，CE 匯入子計畫 4-2 加入），以及驗證摘要：封存檔裡的 `sha256`，與檢查點核對內容的方式相同（需求規格 12.3，使用者 2026-09-30 決定）。

**技術設計 4.4「資料流」**

> | 4-2 流程 | 匯入紀錄、匯入比對快照與套用計畫、單一交易套用、重複、資料更正、目前進度、推進年份、直接補匯、回溯後再套用、檢查點與自動備份；計畫的項目是空的，以空的計畫驗收（見下方「流程」） | IMP-06～09、11、12、14～16、19～21，CKPT-01、08，DATA-15 |
> 7. 按下「套用」時呼叫 `storage` 的套用（`applyImport`）：年度匯入先以 `prepareBackupTarget` 取得交付目標（第一個 `await`，見 4.3「瀏覽器整合」）；接著開一個 rw 交易，先核對遊戲局的更新時間與快照相同，不同時回傳 `changed-since-preview`，由畫面重新預覽；需要時先推進年份，再把計畫逐項交給寫入操作（巢狀交易，見 4.3「寫入操作」），寫入匯入紀錄。交易提交後，年度匯入建立檢查點並依需求規格 12.2 自動備份；這兩步失敗不撤銷匯入，結果附上失敗的原因。
> - 匯入紀錄（需求規格 11.1）加進 `GAME_TABLES`，連同 `PRIMARY_KEYS` 與 `RELATIONS`；事件記匯入紀錄的識別。目前進度由匯入紀錄推導，取年度匯入中最大的年與時點，不另外保存：直接補匯不會讓進度倒退，回溯時匯入紀錄隨檢查點一起回復。欄位見下方「流程」；DATA-02 的別名是一月取代手動名時保存的別名（BRD-09），由 4-3 處理。

**技術設計 4.4「流程」（全文）**

> #### 流程
>
> 由 CE 匯入子計畫 4-2 負責（使用者 2026-10-01 決定）。計畫的項目由 4-3 以後的各塊加入，這一塊以空的計畫驗收。
>
> - **核心的型別與常數**（`core/imports.ts`）：
>   - `AnnualImportType` 是四種年度匯入，`ANNUAL_TIMINGS` 是它們的固定時點：一月 1 月 1 週、四月 4 月 1 週、五月 5 月 1 週、七月 7 月 1 週（需求規格 4.1、11.1）。`importCategory` 回傳年度、累加或選用。
>   - `isGameTiming` 從 `storage/writes.ts` 搬到核心，另加時點的先後比較：先比年，再比月，最後比週。4-1 留下的重複常數一併搬到核心：受胎狀態、芝ダ適性、據點 32～35（`Base`），`ce-import` 與 `storage` 都改為引用核心。
>   - 目前進度 `importProgress`：年度匯入紀錄中最大的年與時點，沒有年度匯入時沒有進度。不分套用方式：補匯的那一筆一定早於進度，資料更正的那一筆不晚於進度，全部一起取最大值結果相同。
> - **匯入紀錄**（`imports`）：一列是一次套用。型別 `ImportRecord` 放在核心，因為 `ce-import` 從快照讀它。
>   - 欄位：識別、遊戲局、類型、年（使用者確認的年份）、時點（年度匯入依類型固定；累加與選用照檔名，解析不了時不存）、檔名、`sha256`（檔案原始位元組的 SHA-256，小寫十六進位）、套用時間、套用方式 `mode`（`normal`、`correction`、`catch-up`）、`corrects`（資料更正時被更正的那一筆，也就是同類型、同年、同時點最新的一筆；需求規格 11.1 的「兩份來源檔與時間」由這個連結取得）、結果摘要 `summary`（這一塊定 `total`、`applied`、`skipped` 三個筆數，之後各塊再加自己的欄位）、確認過的匯入層級警告 `confirmedWarnings`（例如晚兩年以上）。
>   - 主鍵 `id`，加進 `GAME_TABLES` 與 `PRIMARY_KEYS`；`RELATIONS` 加 `imports.corrects`、`events.source.importId`、`horseNumbers.source.importId`，都指向 `imports`。
>   - `EventSource` 的匯入改為 `{ kind: 'import'; importType; importId }`，`importId` 必填：匯入寫的事件一定屬於某一筆匯入紀錄。
>   - 套用本身不另寫事件，匯入紀錄就是歷程；推進年份照 4.3「寫入操作」的目前遊戲年，也不寫事件。最後紀錄年加上匯入紀錄的最大年份（同一處）。
> - **快照**（`ImportSnapshot`，核心）：通用的部分是遊戲局識別、目前遊戲年、更新時間、這一局的匯入紀錄，以及檢查點的摘要（識別、年、時點、建立時間）。`storage` 的 `loadImportSnapshot` 在一個唯讀交易內讀出；各類型要用的資料由後面的塊加入。
> - **雜湊**：`ce-import` 的 `hashImportFile(bytes)` 以 `crypto.subtle` 算 SHA-256。核心維持同步的純函式；`ce-import` 不引用 `storage`，所以不共用備份的雜湊函式。
>
> **判斷**（`ce-import` 的 `judgeImport`，純函式）：輸入檔名、雜湊、類型、年份、檔名解析出的時點與快照。年份不是整數時丟出 `RangeError`，`parseImportFile` 同樣檢查（4-1 留下的「確認類型與年份的介面驗證年份是整數」）。年度匯入的檔名時點與類型的時點不同時附一個只提示的說明。「同一組」指同類型、同年、同時點中套用時間最新的一筆：
>
> | 分類 | 情況 | 結果 |
> | --- | --- | --- |
> | 年度 | 同一組已有，雜湊相同 | 重複，不產生計畫（IMP-07） |
> | 年度 | 同一組已有，雜湊不同 | 資料更正（`corrects` 指向那一筆）；檔案早於目前進度時另外提供回溯（IMP-08、IMP-21） |
> | 年度 | 沒有，晚於進度或還沒有進度 | 一般套用 |
> | 年度 | 沒有，早於進度 | 回溯或直接補匯（IMP-09、IMP-20） |
> | 選用 | 同一組已有，雜湊相同／不同／沒有 | 重複／資料更正／一般套用，不提示回溯 |
> | 累加 | 這一局同類型的任何一筆雜湊相同 | 重複；其他情況一般套用（IMP-19） |
>
> - 重複只和同一組最新的一筆比：先匯入 A、更正成 B，再匯入 A 是把 B 更正回 A。
> - 推進年份（各分類都適用）：檔案年份晚於目前遊戲年時附上推進到的年份，使用者確認才能產生計畫（IMP-14）；晚兩年以上另附 `year-far-ahead` 警告（IMP-15），確認後記在匯入紀錄。
> - 回溯的推薦：有時點、而且年與時點早於這份檔案的檢查點中，年與時點最晚的一個，一樣時取建立時間最新的；找不到時仍提供回溯，只是沒有推薦，由使用者從清單選。手動把遊戲年推到進度之前很遠時，檢查點的年是當時的遊戲年，推薦可能不準，使用者在回溯預覽（CKPT-04）確認。
> - 結果：重複時附那一筆紀錄；其他情況列出可選的做法（一般、資料更正、直接補匯、回溯）、`corrects`、推薦的檢查點、推進年份與提示。
>
> **計畫**（`ImportPlan`，核心；`ce-import` 的 `buildImportPlan(判斷結果, 使用者的選擇, 摘要, 項目)` 產生）：遊戲局識別、快照當下的更新時間 `expectedUpdatedAt`、檔名、雜湊、類型、年、時點、套用方式、`corrects`、推進到的年份 `advanceYear`（不推進時沒有）、確認過的警告、摘要與項目 `items`。每一項對應一個寫入操作；這一塊的型別是 `never[]`，只能是空陣列，從 4-3 起加入聯合型別。選了判斷沒有提供的做法，或需要推進而沒有確認時丟出 `RangeError`（畫面不會送出）。回溯不是計畫的一種：回溯後資料變了，要重新組快照、重新預覽，再產生新的計畫。
>
> **套用**（`storage` 的 `applyImport(db, plan, { now })`，畫面在「套用」的點擊處理裡直接呼叫）：
>
> 1. 年度匯入時第一個 `await` 是 `prepareBackupTarget`；順序放在儲存層，以 `fake-indexeddb` 就能測。累加與選用匯入不備份，不呼叫，免得跳出權限詢問。
> 2. 一個 rw 交易，範圍是 `GAME_TABLES`，巢狀的寫入操作用到的表都在內：
>    - 遊戲局的更新時間不等於 `expectedUpdatedAt` 時回傳 `changed-since-preview`，什麼都不寫。
>    - 有 `advanceYear` 時以 `setCurrentYear` 推進（巢狀交易）；往後推一定會成功，沒有成功時丟出錯誤，整筆回復。
>    - 逐項套用 `items`，事件來源是 `{ kind: 'import', importType, importId }`，時點取計畫的時點。項目被阻止時整筆回復並指出是哪一項，結果型別與測試在 4-3 加入。
>    - 以 `runWrite` 寫入匯入紀錄（識別事先產生），遊戲局的更新時間跟著更新。
> 3. 交易提交後（只有年度匯入）：先 `createCheckpoint`（`auto`，時點是套用後的目前進度，直接補匯另傳補匯的年與時點；資料更正與補匯不改變進度，所以時點仍是原本的進度，CKPT-08），再以第 1 步的目標 `saveBackup`。兩步各自以 try/catch 包住：失敗不撤銷匯入，檢查點失敗也照樣備份，結果附上錯誤訊息（IMP-12、DATA-15）。套用時間同時用作匯入紀錄的套用時間、遊戲局的更新時間、檢查點的建立時間與備份的匯出時間：自動備份成功後最近備份時間等於更新時間，備份提醒不會把這次匯入算成未備份的變更。
> 4. 回傳匯入紀錄、檢查點的結果與備份的結果，或 `changed-since-preview`。遊戲局不存在時丟出錯誤。
>
> - **回溯後再套用**：不加儲存函式，由畫面串接：`readCheckpoint` 驗證並預覽回溯（CKPT-04）→ 確認後 `rollbackToCheckpoint`（交付函式 `downloadBackup`）→ `loadImportSnapshot` → `judgeImport`（回溯後這份檔案晚於進度，成為一般套用）→ 使用者確認新的預覽 → `buildImportPlan` → `applyImport`。舊計畫本來就會被 `changed-since-preview` 擋下；重新預覽也讓使用者看到回溯後的配對結果。驗收測試照這個順序串一遍（IMP-09）。
> - **畫面的串接順序**：`readImportFile` → 使用者確認類型與年份 → `parseImportFile` → `hashImportFile` → `loadImportSnapshot` → `judgeImport` → 預覽與選擇 → `buildImportPlan` → `applyImport`。
> - **測試**：單元測試涵蓋核心的分類、時點先後與目前進度；`judgeImport` 上表的每一格、推進與 `year-far-ahead`、回溯推薦（含時鐘往回調、沒有時點的手動檢查點）與年份不是整數；`buildImportPlan` 的兩種錯誤；`applyImport` 的 `changed-since-preview`、推進年份與寫紀錄在同一交易、`prepareBackupTarget` 是第一個 `await`、檢查點與備份失敗不撤銷、累加與選用匯入不申請權限也不建檢查點；備份驗證的三條關聯；封存索引缺少的鍵當 0。驗收測試（計畫一律用空的 `items`）：IMP-06～09、11、12、14～16、19～21，CKPT-01、CKPT-08、DATA-15；IMP-08 只驗框架的部分（要選資料更正、`corrects` 連到被更正的那一筆，兩筆的檔名、雜湊與時間都在），原值與新值由各類型的事件保存，從 4-3 起驗收；IMP-20 只驗框架的部分（補匯、標記完成、補匯的套用方式），幼駒留給 4-6。

## 本計畫的詮釋

需求規格與技術設計沒有逐字寫出、由本計畫決定的地方。技術設計 4.4「流程」已經和使用者確認；下面是本計畫在程式層級的決定，審查時請逐條對照上一節的原文。

1. **常數搬到核心**（Task 1）：`core/horse.ts` 加上 `Base` 型別與三個判斷 `isSurfaceAptitude`、`isConception`、`isBase`；清單本身不匯出，只匯出判斷。`isBase` 接受 `null`（番号欄空白，4-1 的解析以 `null` 表示）並回傳 `false`，是型別守衛，之後五月名單的牧場可以藉它窄化成 `Base`。`isGameTiming` 原樣從 `storage/writes.ts` 搬到 `core/imports.ts`，檔名解析的月與週範圍也改用它（結果相同）。`records.ts` 改從核心引用 `Base` 並轉出，儲存層其他檔案不改引用；`assertBase` 照舊丟出錯誤，只改用 `isBase` 判斷。
2. **分類、時點與進度**（Task 2）：`AnnualImportType` 以 `Extract` 從 `ImportType` 取出四種年度匯入；`isAnnualImport` 以 `Object.hasOwn(ANNUAL_TIMINGS, type)` 判斷。時間點 `GamePoint` 是年與時點，`compareGamePoints` 先比年、再比月、最後比週。`ImportWarning` 目前只有 `year-far-ahead`（`from` 是推進前的目前遊戲年，`to` 是檔案的年份）。`importProgress` 的時點取類型固定的時點（`ANNUAL_TIMINGS`），不看紀錄裡存的時點，兩者本來就相同。
3. **匯入紀錄表**（Task 3）：`GAME_TABLES` 把 `imports` 加在最後。測試的樣本資料加一筆匯入紀錄；三條關聯「找不到」的情況用既有的拒絕測試，「接得上」另加一個測試（被更正的那一筆、事件與階段馬番号的來源都指向存在的紀錄時通過），這樣把關聯的目標表寫錯也測得出來。`totalRows` 改收 `Partial<RowCounts>`，缺少的鍵當 0。最後紀錄年讀這一局全部的匯入紀錄取最大年份（`[gameId+type+year]` 索引無法跨類型取最大值，一局的匯入紀錄一年只有幾筆）。`EventSource` 的 `importId` 必填，既有測試裡匯入來源的寫法補上 `importId: 'I1'`；樣本資料多一張表、多一列，寫死表數與總筆數的既有測試跟著改。
4. **快照**（Task 4）：檢查點的摘要只帶識別、年、時點（沒有時不帶這個欄位）與建立時間；匯入紀錄原樣放進快照。
5. **判斷與計畫**（Task 5）：
   - 「同一組最新的一筆」以套用時間（ISO 字串）比較。累加匯入和這一局同類型的每一筆比雜湊，不分年份與時點；年度與選用匯入的「同一組」要同年、同時點，兩邊都沒有時點也算同一組，一邊有一邊沒有不算。
   - 可選的做法依序列出：早於進度時回溯排第一（`['rollback', 'catch-up']`、`['rollback', 'correction']`）。只有提供回溯時才推薦檢查點。
   - 檔名時點的提示只在兩個時點都有、而且不同時出現；累加與選用匯入的時點就是檔名的時點，所以只有年度匯入會出現提示。
   - 推進：檔案年份大於目前遊戲年時附 `advanceYear`；大兩年以上附 `year-far-ahead`。`buildImportPlan` 在 `advanceConfirmed` 不是 `true` 時丟出錯誤。判斷有 `corrects` 時一定只能選資料更正（另一個選項是回溯，不是計畫），所以計畫照判斷帶 `corrects`。
   - `parseImportFile` 與 `judgeImport` 的年份不是整數時都丟出 `RangeError`，訊息是「年份不是整數：…」。
6. **套用**（Task 6）：
   - 一個 `now` 用在匯入紀錄的套用時間、遊戲局的更新時間、檢查點的建立時間與備份的匯出時間（技術設計 4.4「流程」）。

   - 目前進度在交易內讀這一局的匯入紀錄算出，給檢查點當時點。

    appliedAt: '2026-10-01T00:00:00.000Z',
    mode: 'normal',
    summary: { total: 0, applied: 0, skipped: 0 },

/** 年度匯入（需求規格 11.1）：每年在固定時點各匯入一次，列入年度工作清單 */
export type AnnualImportType = Extract<
  ImportType,
  'january-two-year-olds' | 'april-foals' | 'may-herd' | 'july-conception'
>

/** 年度匯入的固定時點（需求規格 4.1、11.1）：檔名的時點只用來預選類型 */
export const ANNUAL_TIMINGS: Readonly<Record<AnnualImportType, GameTiming>> = {
  'january-two-year-olds': { month: 1, week: 1 },
  'april-foals': { month: 4, week: 1 },
  'may-herd': { month: 5, week: 1 },
  'july-conception': { month: 7, week: 1 },
}

/** 匯入的分類（需求規格 11.1）：年度；累加（候選 TXT、目標種牡馬 TXT）；選用（十月總表、種牡馬總表） */
export type ImportCategory = 'annual' | 'accumulative' | 'optional'

/** 是不是年度匯入 */
export function isAnnualImport(type: ImportType): type is AnnualImportType {
  return Object.hasOwn(ANNUAL_TIMINGS, type)
}

/** 匯入的分類（需求規格 11.1） */
export function importCategory(type: ImportType): ImportCategory {
  if (isAnnualImport(type)) return 'annual'
  return type === 'candidates' || type === 'target-stallion' ? 'accumulative' : 'optional'
}

/** 遊戲內的一個時間點：年與時點；目前進度、匯入檔與檢查點的先後都用它比較 */
export interface GamePoint {
  year: number
  timing: GameTiming
}

/** 時間點的先後：先比年，再比月，最後比週；a 較早時為負數，相同時為 0 */
export function compareGamePoints(a: GamePoint, b: GamePoint): number {
  return a.year - b.year || a.timing.month - b.timing.month || a.timing.week - b.timing.week
}

/** 套用方式（需求規格 11.1）：一般、資料更正、直接補匯 */
export type ImportMode = 'normal' | 'correction' | 'catch-up'

/** 結果摘要（需求規格 11.1）：檔案的筆數、套用與略過的筆數；之後各類型的計畫再加自己的欄位 */
export interface ImportSummary {
  total: number
  applied: number
  skipped: number
}

/** 匯入層級的警告：檔案年份比目前遊戲年晚兩年以上（需求規格 11.1、IMP-15）；from 是推進前的目前遊戲年 */
export type ImportWarning = { kind: 'year-far-ahead'; from: number; to: number }

/** 匯入紀錄（需求規格 11.1，技術設計 4.4「流程」）：一列是一次套用，不存原始檔 */
export interface ImportRecord {
  id: string
  gameId: string
  type: ImportType
  /** 使用者確認的年份 */
  year: number
  /** 年度匯入依類型固定（ANNUAL_TIMINGS）；累加與選用照檔名，解析不了時留空 */
  timing?: GameTiming
  fileName: string
  /** 檔案原始位元組的 SHA-256（小寫十六進位） */
  sha256: string
  /** 套用時間（ISO 8601） */
  appliedAt: string
  mode: ImportMode
  /** 資料更正時，被更正的那一筆：同類型、同年、同時點最新的一筆 */
  corrects?: string
  summary: ImportSummary
  /** 使用者確認過的匯入層級警告；沒有時留空 */
  confirmedWarnings?: ImportWarning[]
}

/**
 * 目前進度（需求規格 11.1）：年度匯入紀錄中最晚的年與時點，時點取類型固定的時點；沒有年度匯入時沒有進度。
 * 不分套用方式：補匯的那一筆一定早於進度，資料更正的那一筆不晚於進度
 */
export function importProgress(records: readonly ImportRecord[]): GamePoint | undefined {
  let progress: GamePoint | undefined
  for (const record of records) {
    if (!isAnnualImport(record.type)) continue
    const point = { year: record.year, timing: ANNUAL_TIMINGS[record.type] }
    if (progress === undefined || compareGamePoints(point, progress) > 0) progress = point
  }
  return progress
}

import type { ImportSnapshot } from '../core/imports'
import type { WPStudBookDatabase } from './database'
import { loadGame } from './games'

// CE 匯入的快照與套用（技術設計 4.4「資料流」「流程」）

/**
 * 讀出匯入比對快照（技術設計 4.4「資料流」第 4 步）：在一個唯讀交易內讀遊戲局、這一局的匯入紀錄與檢查點的摘要。
 * 遊戲局不存在時丟出錯誤
 */
export async function loadImportSnapshot(
  db: WPStudBookDatabase,
  gameId: string,
): Promise<ImportSnapshot> {
  return db.transaction('r', [db.games, db.imports, db.checkpoints], async () => {
    const game = await loadGame(db, gameId)
    const imports = await db.imports.where('gameId').equals(gameId).toArray()
    const checkpoints = await db.checkpoints.where('gameId').equals(gameId).toArray()
    return {
      gameId,
      currentYear: game.currentYear,
      updatedAt: game.updatedAt,
      imports,
      checkpoints: checkpoints.map(({ id, year, timing, createdAt }) => ({
        id,
        year,
        ...(timing === undefined ? {} : { timing }),
        createdAt,
      })),
    }
  })
}

import {
  ANNUAL_TIMINGS,
  compareGamePoints,
  importCategory,
  importProgress,
  isAnnualImport,
  type GamePoint,
  type GameTiming,
  type ImportCheckpoint,
  type ImportMode,
  type ImportPlan,
  type ImportPlanItem,
  type ImportRecord,
  type ImportSnapshot,
  type ImportSummary,
  type ImportType,
  type ImportWarning,
} from '../core/imports'

// 匯入的判斷與套用計畫（需求規格 11.1，技術設計 4.4「流程」）：重複、資料更正、直接補匯、回溯與推進年份

/** 檔案原始位元組的 SHA-256（小寫十六進位）：判斷同一份檔案用（需求規格 11.1） */
export async function hashImportFile(bytes: Uint8Array<ArrayBuffer>): Promise<string> {
  const digest = new Uint8Array(await crypto.subtle.digest('SHA-256', bytes))
  return Array.from(digest, (byte) => byte.toString(16).padStart(2, '0')).join('')
}

/** 要判斷的檔案：檔名、雜湊、使用者確認的類型與年份，以及檔名解析出的時點（解析不了時留空） */
export interface ImportFile {
  fileName: string
  sha256: string
  type: ImportType
  year: number
  fileTiming?: GameTiming
}

/** 可選的做法（需求規格 11.1）：一般套用、資料更正、直接補匯，或回溯到檢查點後再套用 */
export type ImportOption = ImportMode | 'rollback'

/** 只提示的說明：年度匯入的檔名時點與類型固定的時點不同（需求規格 11.1「提示、不阻止」） */
export interface ImportHint {
  kind: 'timing-mismatch'
  fileTiming: GameTiming
  timing: GameTiming
}

/** 可以產生計畫的判斷結果 */
export interface ReadyImport {
  kind: 'ready'
  gameId: string
  /** 快照當下遊戲局的更新時間 */
  expectedUpdatedAt: string
  file: ImportFile
  /** 記在匯入紀錄的時點：年度匯入依類型固定，其他照檔名 */
  timing?: GameTiming
  options: ImportOption[]
  /** 可選資料更正時，被更正的那一筆 */
  corrects?: string
  /** 可選回溯時推薦的檢查點；找不到時留空，由使用者從清單選 */
  recommendedCheckpoint?: string
  /** 檔案年份晚於目前遊戲年時要推進到的年份；使用者確認才能產生計畫 */
  advanceYear?: number
  /** 確認推進時一併確認的警告 */
  warnings: ImportWarning[]
  hints: ImportHint[]
}

/**
 * 判斷的結果：
 * - duplicate：重複，不產生計畫；record 是重複的那一筆
 * - ready：可以產生計畫，列出可選的做法
 */
export type ImportJudgment = { kind: 'duplicate'; record: ImportRecord } | ReadyImport

/**
 * 判斷重複、資料更正、直接補匯、回溯與推進年份（需求規格 11.1，技術設計 4.4「流程」）。
 * 「同一組」是同類型、同年、同時點中套用時間最新的一筆，年度與選用匯入的重複只和它比；
 * 累加匯入和這一局同類型的每一筆比雜湊。只有年度匯入看目前進度。年份不是整數時丟出 RangeError
 */
export function judgeImport(file: ImportFile, snapshot: ImportSnapshot): ImportJudgment {
  const { type, year } = file
  if (!Number.isInteger(year)) throw new RangeError(`年份不是整數：${year}`)
  const timing = isAnnualImport(type) ? ANNUAL_TIMINGS[type] : file.fileTiming
  const sameType = snapshot.imports.filter((record) => record.type === type)
  let options: ImportOption[] = []
  let corrects: string | undefined
  let recommended: string | undefined
  if (importCategory(type) === 'accumulative') {
    const duplicate = latest(sameType.filter((record) => record.sha256 === file.sha256))
    if (duplicate) return { kind: 'duplicate', record: duplicate }
    options = ['normal']
  } else {
    const group = latest(
      sameType.filter((record) => record.year === year && sameTiming(record.timing, timing)),
    )
    if (group?.sha256 === file.sha256) return { kind: 'duplicate', record: group }
    const point = isAnnualImport(type) ? { year, timing: ANNUAL_TIMINGS[type] } : undefined
    const progress = importProgress(snapshot.imports)
    const earlier =
      point !== undefined && progress !== undefined && compareGamePoints(point, progress) < 0
    if (group) {
      corrects = group.id
      options = earlier ? ['rollback', 'correction'] : ['correction']
    } else {
      options = earlier ? ['rollback', 'catch-up'] : ['normal']
    }
    if (point !== undefined && earlier)
      recommended = recommendCheckpoint(snapshot.checkpoints, point)
  }
  const ahead = year - snapshot.currentYear
  // 累加與選用匯入的時點就是檔名的時點，只有年度匯入會不同
  const hints: ImportHint[] =
    file.fileTiming !== undefined && timing !== undefined && !sameTiming(file.fileTiming, timing)
      ? [{ kind: 'timing-mismatch', fileTiming: file.fileTiming, timing }]
      : []
  return {
    kind: 'ready',
    gameId: snapshot.gameId,
    expectedUpdatedAt: snapshot.updatedAt,
    file,
    ...(timing === undefined ? {} : { timing }),
    options,
    ...(corrects === undefined ? {} : { corrects }),
    ...(recommended === undefined ? {} : { recommendedCheckpoint: recommended }),
    ...(ahead > 0 ? { advanceYear: year } : {}),
    warnings: ahead >= 2 ? [{ kind: 'year-far-ahead', from: snapshot.currentYear, to: year }] : [],
    hints,
  }
}

/** 使用者的選擇：套用方式，以及是否確認推進年份（連同晚兩年以上的警告） */
export interface ImportChoice {
  mode: ImportMode
  advanceConfirmed?: boolean
}

/** 各類型的預覽產生的內容：結果摘要與套用的項目 */
export interface ImportContent {
  summary: ImportSummary
  items: ImportPlanItem[]
}

/**
 * 產生套用計畫（技術設計 4.4「流程」）。選了判斷沒有提供的做法，或需要推進年份而沒有確認時丟出 RangeError：
 * 畫面不會送出這兩種情況。回溯不是計畫的一種：回溯後重新組快照、重新判斷
 */
export function buildImportPlan(
  judgment: ReadyImport,
  choice: ImportChoice,
  content: ImportContent,
): ImportPlan {
  const { file, timing, corrects, advanceYear, warnings } = judgment
  if (!judgment.options.includes(choice.mode)) {
    throw new RangeError(`這份檔案不能選這種套用方式：${choice.mode}`)
  }
  if (advanceYear !== undefined && choice.advanceConfirmed !== true) {
    throw new RangeError(`要先確認推進到 ${advanceYear} 年`)
  }
  return {
    gameId: judgment.gameId,
    expectedUpdatedAt: judgment.expectedUpdatedAt,
    type: file.type,
    year: file.year,
    ...(timing === undefined ? {} : { timing }),
    fileName: file.fileName,
    sha256: file.sha256,
    mode: choice.mode,
    ...(corrects === undefined ? {} : { corrects }),
    ...(advanceYear === undefined ? {} : { advanceYear }),
    ...(warnings.length > 0 ? { confirmedWarnings: [...warnings] } : {}),
    summary: content.summary,
    items: content.items,
  }
}

/** 套用時間最新的一筆 */
function latest(records: readonly ImportRecord[]): ImportRecord | undefined {
  let result: ImportRecord | undefined
  for (const record of records) {
    if (result === undefined || record.appliedAt >= result.appliedAt) result = record
  }
  return result
}

/** 兩個時點相同；都沒有時點也算相同 */
function sameTiming(a: GameTiming | undefined, b: GameTiming | undefined): boolean {
  return a === undefined || b === undefined ? a === b : a.month === b.month && a.week === b.week
}

/**
 * 回溯的推薦（技術設計 4.4「流程」）：有時點、而且年與時點早於這份檔案的檢查點中，
 * 年與時點最晚的一個，一樣時取建立時間最新的；沒有時回傳 undefined
 */
function recommendCheckpoint(
  checkpoints: readonly ImportCheckpoint[],
  point: GamePoint,
): string | undefined {
  const candidates: { id: string; at: GamePoint; createdAt: string }[] = []
  for (const { id, year, timing, createdAt } of checkpoints) {
    if (timing === undefined) continue
    const at = { year, timing }
    if (compareGamePoints(at, point) < 0) candidates.push({ id, at, createdAt })
  }
  candidates.sort((a, b) => compareGamePoints(b.at, a.at) || b.createdAt.localeCompare(a.createdAt))
  return candidates[0]?.id
}

/** 套用的阻止原因：預覽之後遊戲局有變更，由畫面重新預覽（技術設計 4.4「資料流」第 7 步） */
export interface ImportApplyBlock {
  kind: 'changed-since-preview'
}

/** 交易提交後的一步：完成時附結果，失敗時附錯誤訊息；失敗不撤銷匯入 */
export type AfterImport<T> = { status: 'done'; value: T } | { status: 'failed'; error: string }

/** 套用的結果：匯入紀錄；年度匯入另附檢查點與自動備份的結果 */
export interface AppliedImport {
  record: ImportRecord
  checkpoint?: AfterImport<CreatedCheckpoint>
  backup?: AfterImport<SavedBackup>
}

export interface ApplyImportOptions {
  /** 套用時間：匯入紀錄的套用時間、遊戲局的更新時間、檢查點的建立時間與備份的匯出時間；省略時為現在 */
  now?: Date
}

/**
 * 套用匯入（需求規格 11.1、12.2、12.4，技術設計 4.4「流程」）：畫面在「套用」的點擊處理裡直接呼叫。
 * 年度匯入的第一個 await 是 prepareBackupTarget：瀏覽器只在使用者剛操作後的短時間內允許申請權限
 * （技術設計第 7 節）；累加與選用匯入不備份，不呼叫。接著在一個 rw 交易內（GAME_TABLES）：遊戲局的
 * 更新時間不等於計畫的 expectedUpdatedAt 時阻止（changed-since-preview），什麼都不寫；有 advanceYear 時
 * 先推進年份；套用計畫的項目（4-3 起加入）；最後寫入匯入紀錄，遊戲局的更新時間跟著更新。
 * 交易提交後，年度匯入先建立檢查點（auto，時點是套用後的目前進度，直接補匯另記補匯的年與時點），
 * 再以取得的目標儲存備份；兩步各自失敗時不撤銷匯入，結果附上錯誤訊息。遊戲局不存在時丟出錯誤
 */
export async function applyImport(
  db: WPStudBookDatabase,
  plan: ImportPlan,
  options: ApplyImportOptions = {},
): Promise<WriteResult<AppliedImport, ImportApplyBlock>> {
  const target = isAnnualImport(plan.type) ? await prepareBackupTarget(db) : undefined
  const now = options.now ?? new Date()
  const committed = await commitImport(db, plan, now)
  if (committed === undefined) {
    return { status: 'blocked', blocks: [{ kind: 'changed-since-preview' }] }
  }
  const { record, progress } = committed
  // target 只在年度匯入時取得；累加與選用匯入不建立檢查點、不備份（需求規格 11.1、IMP-12）
  if (target === undefined || !isAnnualImport(plan.type)) {
    return { status: 'done', value: { record }, warnings: [] }
  }
  const catchUp = { year: plan.year, timing: ANNUAL_TIMINGS[plan.type] }
  const checkpoint = await settle(() =>
    createCheckpoint(db, plan.gameId, {
      origin: 'auto',
      timing: progress?.timing,
      ...(plan.mode === 'catch-up' ? { catchUp } : {}),
      now,
    }),
  )
  const backup = await settle(() => saveBackup(db, plan.gameId, target, now))
  return { status: 'done', value: { record, checkpoint, backup }, warnings: [] }
}

/**
 * 套用的交易：更新時間不等於計畫的 expectedUpdatedAt 時回傳 undefined，什麼都不寫；
 * 否則推進年份、寫入匯入紀錄，回傳匯入紀錄與套用後的目前進度。計畫的項目從 4-3 起在這裡逐項套用
 */
async function commitImport(
  db: WPStudBookDatabase,
  plan: ImportPlan,
  now: Date,
): Promise<{ record: ImportRecord; progress: GamePoint | undefined } | undefined> {
  const id = crypto.randomUUID()
  const source: EventSource = { kind: 'import', importType: plan.type, importId: id }
  const write: WriteOptions = {
    now,
    source,
    ...(plan.timing === undefined ? {} : { timing: plan.timing }),
  }
  return db.transaction('rw', gameTables(db), async () => {
    const game = await loadGame(db, plan.gameId)
    if (game.updatedAt !== plan.expectedUpdatedAt) return undefined
    if (plan.advanceYear !== undefined) {
      const advanced = await setCurrentYear(db, plan.gameId, plan.advanceYear, write)
      if (advanced.status !== 'done') throw new Error(`推進年份失敗：${plan.advanceYear} 年`)
    }
    const record: ImportRecord = {
      id,
      gameId: plan.gameId,
      type: plan.type,
      year: plan.year,
      ...(plan.timing === undefined ? {} : { timing: plan.timing }),
      fileName: plan.fileName,
      sha256: plan.sha256,
      appliedAt: now.toISOString(),
      mode: plan.mode,
      ...(plan.corrects === undefined ? {} : { corrects: plan.corrects }),
      summary: plan.summary,
      ...(plan.confirmedWarnings === undefined
        ? {}
        : { confirmedWarnings: plan.confirmedWarnings }),
    }
    await runWrite(db, plan.gameId, [db.imports], write, async (context) => {
      await db.imports.add(record)
      return context.done(record)
    })
    const records = await db.imports.where('gameId').equals(plan.gameId).toArray()
    return { record, progress: importProgress(records) }
  })
}

/** 交易提交後的一步：丟出例外時記下錯誤訊息，不撤銷匯入 */
async function settle<T>(step: () => Promise<T>): Promise<AfterImport<T>> {
  try {
    return { status: 'done', value: await step() }
  } catch (error) {
    return { status: 'failed', error: String(error) }
  }
}

 * 判斷是重複或套用被阻止時讓測試失敗

  file: ImportFile,
  choice: ImportChoice = { mode: 'normal' },
  now?: Date,

  return result.value
