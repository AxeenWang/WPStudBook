# 儲存瀏覽器整合 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `src/storage/` 加上瀏覽器整合：備份提醒天數的設定與備份提醒的判斷；下載的輔助函式（也是回溯的交付函式）與持久保存的申請；全部遊戲局共用的備份資料夾（選擇、交付目標、寫入，刪除全部存檔時保留）；匯出、交付後才記錄最近備份時間的 `saveBackup`；並在診斷頁加上儲存整合驗證與 Playwright 測試（需求規格 12.1、12.2，技術設計 4.3「瀏覽器整合」、第 7 節「儲存整合的驗證」）。

**Architecture:** 儲存子計畫 3 拆成四塊，本計畫是第 3 塊（3-1 備份與還原 → 3-2 檢查點與回溯 → 3-3 瀏覽器整合 → 3-4 封存）。新檔都在 `src/storage/`：`backup-reminder.ts`（純函式）、`download.ts`、`persistence.ts`、`backup-folder.ts`、`save-backup.ts`，直接使用瀏覽器 API（技術設計 4.1 把持久保存與備份資料夾劃給 `storage`）。自動備份分兩段：點擊當下 `prepareBackupTarget` 取得交付目標並申請權限，資料寫入之後 `saveBackup` 匯出、交付、記錄。備份資料夾存在全域的 `meta`，`meta` 的列改成依鍵區分的聯合型別。畫面還沒有：開啟時申請持久保存、提醒區與資料夾設定由畫面計畫接上，年度匯入的串接由 CE 匯入計畫接上；本計畫只在技術驗證的診斷頁加一區，以正式函式做實機驗證。core 不改。

**Tech Stack:** TypeScript（strict）、Dexie 4、Vitest（`node` 環境）、fake-indexeddb、Vue 3（只有診斷頁）、Playwright；瀏覽器內建的 Blob、`URL.createObjectURL`、`navigator.storage.persist`、檔案系統存取 API（`showDirectoryPicker`、`queryPermission`、`requestPermission`、`createWritable`）。不新增套件。

## Global Constraints

- 成品：`app/dist/WPStudBook.html` 單一檔案，Windows 最新版 Edge 與 Chrome 以 `file://` 離線使用；執行時不依賴 CDN、網路、本機伺服器或擴充功能。（AGENTS.md）

> - 「永久刪除此局」「刪除全部存檔」放在危險區並顯示筆數：刪除此局要輸入局名確認；刪除全部要輸入畫面上顯示的「刪除全部存檔」，並再次確認（2026-09-29 決定）。刪除全部存檔不清除備份資料夾的設定：它是管理器的設定，不是存檔（2026-09-30 決定）。
> - 顯示保存狀態、最近備份與筆數，並提醒：資料只存在目前瀏覽器的設定檔，換瀏覽器或設定檔、清除網站資料、關閉 InPrivate／無痕視窗，或未取得持久保存時被瀏覽器清除，都會看不到原資料，外部備份不可省略。同一設定檔中以 `file://` 開啟的本機 HTML 共用同一份資料，搬移或複製 HTML 檔仍看得到原資料。

> - **自動備份**：可指定一個備份資料夾，全部遊戲局共用（檔名含局名與時間，不會互相覆蓋），年度匯入套用後自動把完整備份寫入該資料夾。瀏覽器不支援、未指定、未授權或寫入失敗時，改為自動下載備份檔；交出檔案後才更新最近備份時間（2026-09-30 決定；可行性依技術設計第 7 節驗證）。
> - **備份提醒**：上次備份後有未備份的變更時，提醒區顯示距上次備份的天數；超過設定天數（預設 7 天，可調）時醒目提示。從未備份過的局以建立時間代替上次備份：剛建立的局不提醒，第一次寫入後才提醒，顯示「尚未備份」與建立至今的天數（2026-09-30 決定）。
> - **回溯**：驗證檢查點並預覽將捨棄的資料 → 確認後自動下載目前備份 → 單一交易還原。預覽列出目前與檢查點的各類筆數、將捨棄的歷程、將移除的檢查點與目前遊戲年的變化。還原後資料與目前遊戲年回到檢查點，這一局的設定沿用目前的值；較晚的檢查點移除，釘選的也一併移除（回溯前已自動下載目前備份，2026-09-24 決定）。檢查點驗證失敗、下載失敗，或預覽後資料有變更時停止，資料不變。只影響目前遊戲局（2026-09-29 決定）。

**技術設計 4.3 資料表、設定、備份與危險區**

> | `settings` | 一局的設定 | 定年（預設 25 歲）、高齡提醒年齡（18 歲）、種牡馬提醒年齡（26 歲）、檢查點的保留個數（12 個，12.4）、備份提醒天數（7 天，12.2）等；設定全部放在各局，新局選擇只複製設定時整列複製（12.1） |

> | `meta` | 全域資料 | 不屬於任何一局的資料：目前的遊戲局、備份資料夾（見「瀏覽器整合」） |

> - **設定**：定年、高齡提醒年齡、種牡馬提醒年齡、檢查點的保留個數、備份提醒天數都要是 1 以上的整數；不寫事件，新設定從下一次判斷開始生效（MARE-10）。
> - **最近備份時間**：由呼叫端在交出檔案（觸發下載，或寫入備份資料夾成功）後另外記錄，設為匯出時間，只往後不往回；不改更新時間與應用版本，因為記錄備份不是資料變更。用快照的時間而不用記錄的時間：快照之後的修改，更新時間晚於最近備份時間，仍算未備份（需求規格 12.2「備份提醒」）。匯出與記錄分開，是因為 3-3 寫入資料夾失敗時要改為自動下載，確定交出後才記錄。
> - **刪除全部存檔**：輸入的文字要是「刪除全部存檔」，否則阻止；第二道確認由畫面負責（需求規格 12.1，使用者 2026-09-29 決定）。在一個交易內清空資料庫的每一張表（含 `meta`），檢查點的兩張表也包含在內；只保留 `meta` 的備份資料夾，它是管理器的設定，不是存檔（需求規格 12.1、DATA-19，使用者 2026-09-30 決定）。3-4 的封存索引要不要保留由 3-4 決定。回傳刪除的遊戲局數與總筆數；總筆數只算 `GAME_TABLES`，不含檢查點（使用者 2026-09-29 決定）。

**技術設計 4.3「瀏覽器整合」（全文）**

> #### 瀏覽器整合
>
> 下載、持久保存、備份資料夾、自動備份與備份提醒（需求規格 12.2）由儲存子計畫 3-3 負責；封存拆到 3-4（使用者 2026-09-30 決定）。4.1 把持久保存與備份資料夾劃給 `storage`，這裡的函式直接使用瀏覽器 API；畫面、CE 匯入與進入點負責在適當的時機呼叫。
>
> - **下載**：`downloadFile` 以位元組建立 Blob（gzip 為 `application/gzip`，否則 `application/json`），取得 `URL.createObjectURL` 的網址，建立帶 `download` 屬性的 `<a>` 並呼叫 `click()`（不必掛到頁面上），1 分鐘後才 `revokeObjectURL`，免得大檔還沒讀完。觸發下載就算交出：頁面無法得知使用者有沒有存檔（同「備份與還原」的最近備份時間）。`downloadBackup` 下載匯出的備份，簽章符合回溯的交付函式 `deliverBackup`，只交出檔案，不記錄最近備份時間（見「檢查點與回溯」）。環境沒有 `document` 或 `URL` 時丟出例外，回溯因此停止，資料不變。
> - **備份資料夾**：全部遊戲局共用一個，檔名含局名與時間，不會互相覆蓋（使用者 2026-09-30 決定）。資料夾的 `FileSystemDirectoryHandle` 存在 `meta` 的 `backupFolder` 鍵，關閉瀏覽器再開啟後仍能沿用（第 7 節）；`meta` 的列依鍵區分型別：`currentGame` 存字串，`backupFolder` 存資料夾。TypeScript 的 DOM 型別還沒有 `showDirectoryPicker`、`queryPermission`、`requestPermission`，只宣告用到的部分。備份檔不含 `meta`，資料夾不隨備份還原。
>   - 支援：瀏覽器有 `showDirectoryPicker` 才支援。
>   - 選擇：由使用者點擊觸發，以 `showDirectoryPicker({ mode: 'readwrite' })` 選擇後存入，取代原本的資料夾；回傳選好（附資料夾名稱）、使用者取消或不支援，其他錯誤照常丟出。另有讀出目前的資料夾（供畫面顯示名稱）與清除資料夾設定。
>   - 交付目標：`prepareBackupTarget` 要在點擊處理的最前面呼叫，因為瀏覽器只在使用者剛操作後的短時間內允許 `requestPermission`（第 7 節）。依序判斷：不支援時為下載（`unsupported`）；沒有資料夾時為下載（`not-set`）；`queryPermission` 為 `granted` 時為資料夾；否則呼叫 `requestPermission`，`granted` 時為資料夾，拒絕或丟出例外時為下載（`denied`，例外時附錯誤訊息）。不丟例外，最壞是改為下載。
>   - 寫入：`getFileHandle(檔名, { create: true })`、`createWritable()`、寫入位元組、`close()`；中途失敗時 `abort()`，瀏覽器丟掉暫存，不留下寫一半的檔案。資料夾被刪除、改名或磁碟已滿都在這一步失敗。
> - **儲存備份**：`saveBackup` 先以「備份與還原」的匯出取得備份（遊戲局不存在時丟出錯誤，什麼都沒交出），再交付：目標是資料夾時寫入，失敗時改為下載；目標是下載時直接下載。下載丟出例外時照常丟出，不記錄。交出後才以 `recordBackup` 記錄最近備份時間（匯出時間）。回傳備份摘要（DATA-07）、記錄後的遊戲局與實際的交付方式：寫入資料夾（附資料夾名稱），或下載（附原因 `unsupported`、`not-set`、`denied`、`write-failed` 與錯誤訊息；呼叫端自己選擇下載時沒有原因）。自動備份與手動匯出共用；手動匯出要不要也寫資料夾由畫面計畫決定（使用者 2026-09-30 決定）。
> - **自動備份的時機**：年度匯入按下「套用」時先 `prepareBackupTarget`，再做匯入的交易、建立檢查點，最後 `saveBackup`（4.4 第 6 步）。權限要在耗時處理之前申請，備份要在資料寫入之後匯出，所以分成兩個呼叫（使用者 2026-09-30 決定）。自動備份失敗時匯入已經提交，不回復；最近備份時間沒有更新，備份提醒照常出現。回溯維持自動下載（需求規格 12.4），交付函式是 `downloadBackup`，不寫資料夾。
> - **持久保存**：`requestPersistence` 回傳是否支援與是否取得：沒有 `navigator.storage.persist` 時為不支援、未取得；已經持久（`persisted()`）時不再申請；否則回傳 `persist()` 的結果；例外視為未取得，不丟出。結果不存進資料庫：它是這次開啟時瀏覽器的狀態，每次開啟重新申請，由進入點呼叫、畫面顯示（4.1）。
> - **備份提醒**：純函式，由遊戲局、設定、是否取得持久保存與現在時間算出（需求規格 12.2、DATA-14、DATA-16、DATA-18）。放在 `storage`，因為它讀的是 `games` 與 `settings` 的列，與最近備份時間是同一件事；`core` 只放遊戲規則。
>   - 基準時間：最近備份時間，沒有時用建立時間。更新時間晚於基準時間才算有未備份的變更，所以剛建立的局不提醒（使用者 2026-09-30 決定）。時間都是 `toISOString()` 的字串，可以直接比較。
>   - 天數：基準時間到現在經過的完整 24 小時數，不足 0 時取 0（系統時鐘往回調）；以經過時間計，不受時區影響。
>   - 醒目：有未備份的變更，且經過時間超過設定的備份提醒天數乘以 24 小時。
>   - 未取得持久保存：另外回報，提醒區常駐顯示說明，不改變天數的規則。`file://` 下幾乎一定取不到（第 7 節），改成醒目會常態亮起（使用者 2026-09-30 決定）。
>   - 設定：`settings` 的 `backupReminderDays`，預設 7，要是 1 以上的整數（見「寫入操作」的設定）。發布前的舊備份缺這個欄位時不另外處理，同檢查點的保留個數。
> - **刪除全部存檔**：保留 `meta` 的備份資料夾，見「危險區」。
> - **測試**：Vitest 維持 `node` 環境，不加 jsdom。下載以 `vi.stubGlobal` 換掉 `document`（Node 本身有 `Blob` 與 `URL.createObjectURL`），以假計時器確認釋放網址的時間；資料夾的權限與寫入用假的資料夾物件；資料夾存進 `meta` 的來回以純資料物件測（fake-indexeddb 存物件時會丟掉方法）；持久保存以 `vi.stubGlobal` 模擬 `navigator`。不是由點擊直接觸發的下載由 Playwright 測，資料夾與權限詢問在 Edge 手動驗證（第 7 節「儲存整合的驗證」）（使用者 2026-09-30 決定）。

**技術設計 4.4 與第 7 節**

> 6. `storage` 在單一 Dexie 交易內寫入計畫；接著建立檢查點，並依需求規格 12.2 自動備份（按下「套用」時已先取得交付目標，見 4.3「瀏覽器整合」）。
> - 瀏覽器只在使用者剛操作後的短時間內允許重新授權（`requestPermission`）。年度匯入要在使用者按下「套用」時先申請權限，再做交易、檢查點等耗時處理；否則會取不到權限而每次改為自動下載。這個時機與非點擊觸發的自動下載，留給儲存計畫驗證（見下方「儲存整合的驗證」）。

> ### 儲存整合的驗證（儲存子計畫 3-3）
>
> 「決定」留下的兩項（重新授權的時機、不是由點擊直接觸發的下載），以診斷頁的「儲存整合驗證」區驗證，直接呼叫 4.3「瀏覽器整合」的正式函式；它使用另一個資料庫名稱，不碰正式資料，第一次使用時建立一個小的測試局（使用者 2026-09-30 決定）。
>
> - 選擇備份資料夾：`chooseBackupFolder`。
> - 模擬年度匯入的自動備份：點擊當下 `prepareBackupTarget`，等 6 秒（超過瀏覽器約 5 秒的使用者操作有效期）再 `saveBackup`，顯示交付方式、原因與錯誤訊息。
> - 延遲下載：點擊後等 6 秒再 `downloadBackup`，模擬回溯的下載。
>
> | 項目 | 方式與預期 | 不能用時的替代做法 |
> | --- | --- | --- |
> | 延遲下載 | Playwright（Edge、Chromium）：收到下載，檔名符合備份檔名 | 完成後顯示「下載備份」按鈕，由使用者點擊下載 |
> | 未選資料夾時模擬自動備份 | Playwright：改為下載，原因 `not-set` | 同上 |
> | 連續兩次點擊，各觸發一次延遲下載 | Playwright：兩次都下載（每次點擊重設瀏覽器的連續下載限制） | 同上 |
> | 選資料夾後模擬自動備份 | Edge 手動：寫入資料夾 | 改為下載（`saveBackup` 本來的做法） |
> | 關閉 Edge 再開啟後模擬自動備份，允許權限 | Edge 手動：點擊當下詢問權限，允許後 6 秒寫入資料夾 | 同上 |
> | 同上，拒絕權限 | Edge 手動：改為下載，原因 `denied` | 不需要 |
> | 清除資料夾設定後模擬自動備份 | Edge 手動：改為下載，原因 `not-set` | 不需要 |
>
> 手動驗證在 3-3 的實作完成後、合併前進行，結果寫回本節（使用者 2026-09-30 決定）。

## 本計畫的詮釋

需求規格與技術設計沒有逐字寫出、由本計畫決定的地方。技術設計 4.3「瀏覽器整合」已經和使用者確認；下面是本計畫在程式層級的決定，審查時請逐條對照上一節的原文。

1. **設定與備份提醒**（Task 1）：`SettingsRow.backupReminderDays` 必填，`DEFAULT_SETTINGS` 為 7，`updateSettings` 的欄位清單加上它，所以同樣要是 1 以上的整數；`inputs.test.ts` 的設定列補上這個欄位。正式發布前還沒有畫面，不會有少了這個欄位的既有設定列或備份，不另外相容（技術設計「瀏覽器整合」的設定）。`backupReminder(game, settings, persisted, now)` 是純函式，不讀資料庫：呼叫端讀出遊戲局與設定再傳入。「超過設定天數」是經過時間嚴格大於天數乘以 24 小時，剛好相等不醒目；天數取完整的 24 小時數，不四捨五入；`neverBackedUp` 只看有沒有最近備份時間。時間以 `Date.parse` 換成毫秒相減；先後的比較直接比 ISO 字串（技術設計寫明都是 `toISOString()` 的字串）。
2. **下載與持久保存**（Task 2）：`downloadFile(fileName, bytes, compressed)` 的連結不掛到頁面上；釋放網址用 `setTimeout`，延遲 `REVOKE_DELAY_MS`（60000 毫秒）匯出供測試。環境沒有 `document` 時，`document.createElement` 自然丟出的 `TypeError` 不另外包裝。`downloadBackup` 以摘要的 `compressed` 決定內容型別。`requestPersistence` 以 `globalThis.navigator?.storage` 取得，`persisted()` 或 `persist()` 丟出例外都視為未取得；不快取結果。
3. **備份資料夾**（Task 3）：檔案系統存取的型別（`BackupFolderHandle`、`BackupFileHandle`、`BackupFileWritable`）放在 `records.ts`，因為它是 `meta` 那一列存的值；只宣告用到的成員，測試可以直接做出假的資料夾。`meta` 改用 `Table<MetaRow, string>`（同 `events`：`EntityTable` 會把聯合的新增型別攤平），`currentGameId` 依鍵縮小型別後才取值。`BACKUP_FOLDER_KEY` 放在 `backup-folder.ts`，`games.ts` 引用它。`chooseBackupFolder` 只傳 `{ mode: 'readwrite' }`；取消以 `DOMException` 且名稱為 `AbortError` 判斷；`put` 取代原本的資料夾。交付目標的資料夾欄位叫 `folder`。`prepareBackupTarget` 讀取 `meta` 失敗屬於預期外的失敗（第 5 章），照常丟出；「不丟例外」指的是查詢與申請權限，兩者丟出例外都是 `denied`，錯誤訊息用 `String(error)`（例如 `SecurityError: …`）。`writeBackupFile` 以 `create: true` 取得檔案，同名時覆寫；`abort` 本身失敗時忽略，丟出的仍是原本的錯誤。`deleteAllGames` 在同一個交易內先讀出資料夾那一列，清空每一張表後再寫回。fake-indexeddb 存物件時會丟掉方法，所以需要讀到假資料夾的測試以 `storeFakeFolder` 換掉 `db.meta.get`；存取的來回以只有名稱的純資料物件測。
4. **儲存備份**（Task 4）：交付方式的型別 `BackupDelivery` 與目標分開：目標是下載時，交付方式就是目標本身（同樣的欄位）；寫入資料夾失敗時是 `write-failed`，錯誤訊息用 `String(error)`。記錄沿用 `recordBackup`（只往後不往回）。回溯不改：畫面傳 `{ deliverBackup: downloadBackup }`（Task 2 的測試已驗證）。
5. **驗收**（Task 5）：「年度匯入套用成功」以「`prepareBackupTarget` → 寫入操作（`setCurrentYear`）→ `saveBackup`」代表，實際的串接由 CE 匯入計畫接上；「顯示結果」「提醒區顯示」由畫面計畫負責，這裡驗證顯示所需的值。DATA-19 只確認刪除全部存檔後資料夾仍在：之後的自動備份沿用讀出的資料夾，由 DATA-15 驗證。
6. **診斷頁與端對端**（Task 6）：驗證用的程式放在 `src/ui/diagnostics/storage-checks.ts`，資料庫名稱 `wpstudbook-storage-check`，驗證用的局名「驗證用」、起始年 2026。等待時間 `SIMULATED_WORK_MS` 為 6000 毫秒，等待函式可以注入，單元測試不真的等。延遲下載先等待再匯出、下載，對應回溯「確認後先匯出，再交付」。Playwright 測試（`tests/e2e/storage.spec.ts`）不在 `npm test` 內，由 `npm run test:e2e` 執行（先建置）；每個測試最多 60 秒。

```ts
import { describe, expect, it } from 'vitest'
import { GAME } from '../../tests/support/rows'
import { backupReminder } from './backup-reminder'
import { DEFAULT_SETTINGS } from './games'
import type { GameRow, SettingsRow } from './records'

const CREATED = '2026-09-01T00:00:00.000Z'
const BACKED_UP = '2026-09-10T00:00:00.000Z'
const settings: SettingsRow = { gameId: GAME, ...DEFAULT_SETTINGS }

function game(fields: Partial<GameRow> = {}): GameRow {
  return {
    id: GAME,
    name: '測試局',
    startYear: 1968,
    currentYear: 1990,
    createdAt: CREATED,
    updatedAt: CREATED,
    appVersion: '0.0.0-old',
    ...fields,
  }
}

/** 基準時間之後經過 days 天又 ms 毫秒 */
function after(baseline: string, days: number, ms = 0): Date {
  return new Date(Date.parse(baseline) + days * 24 * 60 * 60 * 1000 + ms)
}

describe('backupReminder', () => {
  it('上次備份後沒有變更時不提醒：更新時間等於最近備份時間，過再久也不醒目', () => {
    const row = game({ updatedAt: BACKED_UP, lastBackupAt: BACKED_UP })
    expect(backupReminder(row, settings, true, after(BACKED_UP, 30))).toStrictEqual({
      neverBackedUp: false,
      unbacked: false,
      days: 30,
      overdue: false,
      notPersisted: false,
    })
  })

  it('更新時間晚於最近備份時間就是有未備份的變更，天數從上次備份算，只算完整的 24 小時', () => {
    const row = game({ updatedAt: '2026-09-10T00:00:00.001Z', lastBackupAt: BACKED_UP })
    const hours20 = 20 * 60 * 60 * 1000
    expect(backupReminder(row, settings, true, after(BACKED_UP, 3, hours20))).toStrictEqual({
      neverBackedUp: false,
      unbacked: true,
      days: 3,
      overdue: false,
      notPersisted: false,
    })
  })

  it('經過時間超過設定天數才醒目：剛好 7 天不算，多 1 毫秒就算（DATA-16）', () => {
    const row = game({ updatedAt: '2026-09-11T00:00:00.000Z', lastBackupAt: BACKED_UP })
    expect(backupReminder(row, settings, true, after(BACKED_UP, 7))).toMatchObject({
      days: 7,
      overdue: false,
    })
    expect(backupReminder(row, settings, true, after(BACKED_UP, 7, 1))).toMatchObject({
      days: 7,
      overdue: true,
    })
  })

  it('醒目的天數依這一局的設定', () => {
    const row = game({ updatedAt: '2026-09-11T00:00:00.000Z', lastBackupAt: BACKED_UP })
    const three = { ...settings, backupReminderDays: 3 }
    expect(backupReminder(row, three, true, after(BACKED_UP, 3, 1)).overdue).toBe(true)
```

```ts
import type { GameRow, SettingsRow } from './records'

/** 一天的毫秒數：天數以經過時間計，不以日曆日計 */
const DAY_MS = 24 * 60 * 60 * 1000

/** 一局的備份提醒（需求規格 12.2、DATA-14、DATA-16、DATA-18） */
export interface BackupReminder {
  /** 從未備份過：沒有最近備份時間 */
  neverBackedUp: boolean
  /** 有未備份的變更：更新時間晚於基準時間（最近備份時間，沒有時用建立時間） */
  unbacked: boolean
  /** 基準時間到現在經過的完整天數（24 小時為一天）；系統時鐘往回調時為 0 */
  days: number
  /** 醒目提示：有未備份的變更，且經過時間超過設定的備份提醒天數 */
  overdue: boolean
  /** 未取得持久保存：提醒區常駐顯示說明，不影響天數的判斷 */
  notPersisted: boolean
}

/**
 * 算出一局的備份提醒（技術設計 4.3「瀏覽器整合」）。基準時間是最近備份時間，從未備份時用建立時間，
 * 所以剛建立、還沒寫入的局不提醒。時間都是 toISOString() 的字串，直接比較先後；
 * 天數以經過時間計，不受時區影響。persisted 是 requestPersistence 的結果
 */
export function backupReminder(
  game: GameRow,
  settings: SettingsRow,
  persisted: boolean,
  now: Date = new Date(),
): BackupReminder {
  const baseline = game.lastBackupAt ?? game.createdAt
  const unbacked = game.updatedAt > baseline
  const elapsed = now.getTime() - Date.parse(baseline)
  return {
    neverBackedUp: game.lastBackupAt === undefined,
    unbacked,
    days: Math.max(0, Math.floor(elapsed / DAY_MS)),
    overdue: unbacked && elapsed > settings.backupReminderDays * DAY_MS,
    notPersisted: !persisted,
  }
}
```

```ts
import type { ExportedBackup } from './backup'

/** 觸發下載後過多久才釋放網址：立刻釋放時，大檔可能還沒讀完 */
export const REVOKE_DELAY_MS = 60_000

/**
 * 下載檔案（技術設計 4.3「瀏覽器整合」）：以位元組建立 Blob（gzip 為 application/gzip，否則 application/json），
 * 取得網址，建立帶 download 屬性的 <a> 並點擊（不必掛到頁面上），1 分鐘後才釋放網址。
 * 觸發下載就算交出：頁面無法得知使用者有沒有存檔。環境沒有 document 或 URL 時丟出例外
 */
export function downloadFile(
  fileName: string,
  bytes: Uint8Array<ArrayBuffer>,
  compressed: boolean,
): void {
  const blob = new Blob([bytes], { type: compressed ? 'application/gzip' : 'application/json' })
  const url = URL.createObjectURL(blob)
  const anchor = document.createElement('a')
  anchor.href = url
  anchor.download = fileName
  anchor.click()
  setTimeout(() => URL.revokeObjectURL(url), REVOKE_DELAY_MS)
}

/**
 * 下載匯出的備份。簽章符合回溯的交付函式（RollbackOptions.deliverBackup）：只交出檔案，
 * 不記錄最近備份時間（技術設計 4.3「檢查點與回溯」）
 */
export function downloadBackup(backup: ExportedBackup): void {
  downloadFile(backup.fileName, backup.bytes, backup.summary.compressed)
}
```

```ts
/** 持久保存的申請結果（需求規格 12.2、DATA-14） */
export interface PersistenceStatus {
  /** 瀏覽器有沒有 navigator.storage.persist */
  supported: boolean
  /** 是否取得持久保存 */
  persisted: boolean
}

/**
 * 向瀏覽器申請持久保存（技術設計 4.3「瀏覽器整合」）：已經持久時不再申請；不支援，或申請時丟出例外，
 * 都視為未取得，不丟出。結果不存進資料庫：它是這次開啟時瀏覽器的狀態，每次開啟重新申請
 */
export async function requestPersistence(): Promise<PersistenceStatus> {
  const storage = globalThis.navigator?.storage
  if (typeof storage?.persist !== 'function') return { supported: false, persisted: false }
  try {
    if (await storage.persisted()) return { supported: true, persisted: true }
    return { supported: true, persisted: await storage.persist() }
  } catch {
    return { supported: true, persisted: false }
  }
}
```

```ts
  const aborted: string[] = []

    if (options.query instanceof Error) throw options.query
    return options.query ?? 'granted'
  })
  const requestPermission = vi.fn(async () => {
    if (options.request instanceof Error) throw options.request
    return options.request ?? 'granted'
  })
  const folder: BackupFolderHandle = {
    name,
    queryPermission,
    requestPermission,
    async getFileHandle(fileName) {
      return {
        async createWritable() {
          let written: Uint8Array<ArrayBuffer> | undefined
          return {
            async write(data) {
              if (options.writeError) throw options.writeError
              written = data
            },
            async close() {
              files.set(fileName, written!)
            },
            async abort() {
              aborted.push(fileName)
              if (options.abortError) throw options.abortError
            },
          }
        },
      }
    },
  }
  return { folder, files, aborted, queryPermission, requestPermission }
}
```

```ts
import type { WPStudBookDatabase } from './database'
import type { BackupFolderHandle } from './records'

// 備份資料夾（需求規格 12.2「自動備份」，技術設計 4.3「瀏覽器整合」）：全部遊戲局共用一個，存在全域的 meta

/** meta 表中記錄備份資料夾的鍵 */
export const BACKUP_FOLDER_KEY = 'backupFolder'

/** 申請與查詢的權限：讀寫 */
const READWRITE = { mode: 'readwrite' } as const

/** 瀏覽器的 showDirectoryPicker（TypeScript 的 DOM 型別還沒有它） */
type DirectoryPicker = (options: { mode: 'readwrite' }) => Promise<BackupFolderHandle>

function directoryPicker(): DirectoryPicker | undefined {
  return (globalThis as unknown as { showDirectoryPicker?: DirectoryPicker }).showDirectoryPicker
}

/** 瀏覽器能不能選擇備份資料夾；不能時自動備份改為下載 */
export function supportsBackupFolder(): boolean {
  return typeof directoryPicker() === 'function'
}

/** 選擇備份資料夾的結果：選好（附資料夾名稱）、使用者取消、瀏覽器不支援 */
export type ChooseFolderResult =
  { status: 'chosen'; folderName: string } | { status: 'cancelled' } | { status: 'unsupported' }

/**
 * 選擇備份資料夾：要由使用者的點擊觸發。選好後存進 meta，取代原本的資料夾。
 * 使用者取消（AbortError）時什麼都不改；其他錯誤照常丟出
 */
export async function chooseBackupFolder(db: WPStudBookDatabase): Promise<ChooseFolderResult> {
  const pick = directoryPicker()
  if (!pick) return { status: 'unsupported' }
  let folder: BackupFolderHandle
  try {
    folder = await pick(READWRITE)
  } catch (error) {
    if (error instanceof DOMException && error.name === 'AbortError') return { status: 'cancelled' }
    throw error
  }
  await db.meta.put({ key: BACKUP_FOLDER_KEY, value: folder })
  return { status: 'chosen', folderName: folder.name }
}

/** 目前的備份資料夾，供畫面顯示名稱；沒有時為 undefined */
export async function loadBackupFolder(
  db: WPStudBookDatabase,
): Promise<BackupFolderHandle | undefined> {
  const row = await db.meta.get(BACKUP_FOLDER_KEY)
  return row?.key === BACKUP_FOLDER_KEY ? row.value : undefined
}

/** 清除備份資料夾的設定；之後的自動備份改為下載 */
export async function clearBackupFolder(db: WPStudBookDatabase): Promise<void> {
  await db.meta.delete(BACKUP_FOLDER_KEY)
}

/** 改為下載的原因：瀏覽器不支援、沒有選資料夾、未授權 */
export type DownloadReason = 'unsupported' | 'not-set' | 'denied'

/**
 * 交付目標：寫入備份資料夾，或下載。下載的 reason 是改為下載的原因，呼叫端自己選擇下載時沒有；
 * error 是申請權限時丟出的例外
 */
export type BackupTarget =
  | { kind: 'folder'; folder: BackupFolderHandle }
  | { kind: 'download'; reason?: DownloadReason; error?: string }

/**
 * 取得交付目標：要在點擊處理的最前面呼叫，因為瀏覽器只在使用者剛操作後的短時間內允許 requestPermission
 * （技術設計第 7 節）。依序判斷：不支援、沒有資料夾時改為下載；已授權時寫入資料夾；否則申請權限，
 * 允許時寫入資料夾，拒絕或申請時丟出例外都改為下載（denied，例外時附訊息）。權限的例外不丟出，最壞是改為下載
 */
export async function prepareBackupTarget(db: WPStudBookDatabase): Promise<BackupTarget> {
  if (!supportsBackupFolder()) return { kind: 'download', reason: 'unsupported' }
  const folder = await loadBackupFolder(db)
  if (!folder) return { kind: 'download', reason: 'not-set' }
  try {
    if ((await folder.queryPermission(READWRITE)) === 'granted') return { kind: 'folder', folder }
    if ((await folder.requestPermission(READWRITE)) === 'granted') return { kind: 'folder', folder }
    return { kind: 'download', reason: 'denied' }
  } catch (error) {
    return { kind: 'download', reason: 'denied', error: String(error) }
  }
}

/**
 * 把檔案寫入備份資料夾：已有同名檔案時覆寫。中途失敗時 abort，瀏覽器丟掉暫存，不留下寫一半的檔案，
 * 再把錯誤丟出；資料夾被刪除、改名或磁碟已滿都在這裡失敗
 */
export async function writeBackupFile(
  folder: BackupFolderHandle,
  fileName: string,
  bytes: Uint8Array<ArrayBuffer>,
): Promise<void> {
  const file = await folder.getFileHandle(fileName, { create: true })
  const writable = await file.createWritable()
  try {
    await writable.write(bytes)
    await writable.close()
  } catch (error) {
    await writable.abort().catch(() => undefined)
    throw error
  }
}
```

```ts
import { exportBackup, type BackupSummary, type ExportedBackup } from './backup'
import { writeBackupFile, type BackupTarget, type DownloadReason } from './backup-folder'
import type { WPStudBookDatabase } from './database'
import { downloadBackup } from './download'
import { recordBackup } from './games'
import type { GameRow } from './records'

/**
 * 實際的交付方式：寫入備份資料夾，或下載。下載的 reason 是改為下載的原因（write-failed 是寫入資料夾失敗），
 * 呼叫端自己選擇下載時沒有；error 是丟出的例外
 */
export type BackupDelivery =
  | { kind: 'folder'; folderName: string }
  | { kind: 'download'; reason?: DownloadReason | 'write-failed'; error?: string }

/** 儲存備份的結果：備份摘要（DATA-07）、記錄最近備份時間後的遊戲局與實際的交付方式 */
export interface SavedBackup {
  summary: BackupSummary
  game: GameRow
  delivery: BackupDelivery
}

/**
 * 儲存這一局的備份（需求規格 12.2、DATA-15，技術設計 4.3「瀏覽器整合」）：以 exportBackup 匯出，再交給目標：
 * 資料夾時寫入，失敗時改為下載；下載時直接下載。交出後才以 recordBackup 記錄最近備份時間（匯出時間）；
 * 下載丟出例外時照常丟出，不記錄。自動備份與手動匯出共用：目標由 prepareBackupTarget 在點擊當下取得，
 * 或由呼叫端傳 { kind: 'download' }。遊戲局不存在時丟出錯誤，什麼都不交出
 */
export async function saveBackup(
  db: WPStudBookDatabase,
  gameId: string,
  target: BackupTarget,
  now: Date = new Date(),
): Promise<SavedBackup> {
  const backup = await exportBackup(db, gameId, now)
  const delivery = await deliver(backup, target)
  const game = await recordBackup(db, gameId, backup.summary.exportedAt)
  return { summary: backup.summary, game, delivery }
}

/** 交出備份：寫入資料夾失敗時改為下載 */
async function deliver(backup: ExportedBackup, target: BackupTarget): Promise<BackupDelivery> {
  if (target.kind === 'download') {
    downloadBackup(backup)
    return target
  }
  try {
    await writeBackupFile(target.folder, backup.fileName, backup.bytes)
    return { kind: 'folder', folderName: target.folder.name }
  } catch (error) {
    downloadBackup(backup)
    return { kind: 'download', reason: 'write-failed', error: String(error) }
  }
}
```

```ts
// 使用另一個資料庫名稱，不碰正式資料。每個函式回傳顯示在診斷頁的訊息

/** 驗證用的資料庫名稱 */
export const CHECK_DATABASE = 'wpstudbook-storage-check'

/** 模擬耗時處理的等待時間：超過瀏覽器約 5 秒的使用者操作有效期 */
export const SIMULATED_WORK_MS = 6000

/** 等待 ms 毫秒；測試時換成不等待的函式 */
export type Wait = (ms: number) => Promise<void>

const sleep: Wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms))

/** 驗證用的資料庫 */
export function checkDatabase(): WPStudBookDatabase {
  return createDatabase(CHECK_DATABASE)
}

/** 驗證用的遊戲局：第一次使用時建立 */
export async function checkGame(db: WPStudBookDatabase): Promise<GameRow> {
  return (await listGames(db))[0] ?? createGame(db, { name: '驗證用', startYear: 2026 })
}

/** 選擇備份資料夾（要由點擊觸發） */
export async function chooseFolderMessage(db: WPStudBookDatabase): Promise<string> {
  const result = await chooseBackupFolder(db)
  if (result.status === 'chosen') return `已選擇資料夾「${result.folderName}」`
  return result.status === 'cancelled' ? '已取消選擇' : '此瀏覽器不支援選擇資料夾'
}

/** 清除資料夾設定 */
export async function clearFolderMessage(db: WPStudBookDatabase): Promise<string> {
  await clearBackupFolder(db)
  return '已清除資料夾設定'
}

/**
 * 模擬年度匯入的自動備份：點擊當下先取得交付目標（申請權限），等待 SIMULATED_WORK_MS 模擬匯入的交易與檢查點，
 * 再儲存備份
 */
export async function simulateAutoBackup(
  db: WPStudBookDatabase,
  wait: Wait = sleep,
): Promise<string> {
  const target = await prepareBackupTarget(db)
  const game = await checkGame(db)
  await wait(SIMULATED_WORK_MS)
  const saved = await saveBackup(db, game.id, target)
  return describeDelivery(saved.delivery, saved.summary.fileName)
}

/** 延遲下載：點擊後等待 SIMULATED_WORK_MS 才下載，模擬回溯在確認後匯出、再交付的下載 */
export async function delayedDownload(db: WPStudBookDatabase, wait: Wait = sleep): Promise<string> {
  const game = await checkGame(db)
  await wait(SIMULATED_WORK_MS)
  const backup = await exportBackup(db, game.id)
  downloadBackup(backup)
  return `已下載：${backup.fileName}`
}

/** 交付方式的說明：寫入的資料夾，或改為下載的原因與錯誤訊息 */
export function describeDelivery(delivery: BackupDelivery, fileName: string): string {
  if (delivery.kind === 'folder') return `已寫入資料夾「${delivery.folderName}」：${fileName}`
  if (delivery.reason === undefined) return `已下載：${fileName}`
  const error = delivery.error === undefined ? '' : `，${delivery.error}`
  return `已改為下載（原因：${delivery.reason}${error}）：${fileName}`
}
```

全部任務與整體審查完成後，由控制者建置（`npm run build`），請使用者在 Edge 一般視窗以 `file://` 開 `app/dist/WPStudBook.html`，在「儲存整合驗證」一區依序操作，對照技術設計第 7 節「儲存整合的驗證」的表格：

1. 「選擇備份資料夾」選一個測試用的資料夾，再按「模擬年度匯入的自動備份」：6 秒後訊息是「已寫入資料夾」，資料夾裡出現備份檔。
2. 關閉 Edge 再開啟同一個檔案，按「模擬年度匯入的自動備份」：按下當下跳出權限詢問，允許後 6 秒寫入資料夾。

4. 按「清除資料夾設定」，再按「模擬年度匯入的自動備份」：改為下載，原因是 `not-set`。
5. 按「延遲下載」：6 秒後下載，瀏覽器沒有另外詢問。
