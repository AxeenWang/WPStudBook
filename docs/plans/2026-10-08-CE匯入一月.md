# CE 匯入一月 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 接上一月二歲馬總表的匯入：快照帶出生年為年份減 2 的自家產駒，以能力番号＋出生年、父母＋出生年配對，預覽分列可套用、略過、待核對、警告與錯誤，使用者可替待核對的產駒指定一列；套用時逐項以寫入操作填入總表的正式馬名（被取代的手動名留作別名）、補能力番号、記競走馬馬番号，某一項被阻止時整筆回復並指出是哪一項（需求規格 9.4、11.2、11.3，技術設計 4.3、4.4「一月」）。

**Architecture:** CE 匯入拆成八塊，本計畫是第三塊（4-1 解析 → 4-2 流程 → 4-3 一月 → 4-4 五月 → 4-5 七月 → 4-6 四月 → 4-7 累加匯入 → 4-8 選用匯入）。核心 `core/imports.ts` 加上一月的快照型別（`ImportFoal`、`JanuarySnapshot`）與計畫項目 `FoalNameItem`。`storage/imports.ts` 的 `loadImportSnapshot` 多傳類型與年份，一月另讀產駒；`applyImport` 在交易內逐項呼叫寫入操作。新的寫入操作 `importFoalName`（`storage/foal-writes.ts`）負責一匹產駒的馬名、別名、能力番号與競走馬馬番号。`ce-import/january.ts` 是純函式：`previewJanuary` 配對並產生預覽，`januaryContent` 產生計畫的內容。`ce-import` 與 `storage` 互不引用，只透過核心的型別交接；畫面只負責串接（之後的畫面計畫）。

**Tech Stack:** TypeScript（strict）、Dexie、Vitest（`node` 環境）、`fake-indexeddb`。不新增套件。

**Spec:** `docs/specs/需求規格.md`（9.4、11.1～11.3、第 15 章）、`docs/specs/技術設計.md`（4.3、4.4「流程」「一月」、第 10 節）。

## Global Constraints

- 成品：`app/dist/WPStudBook.html` 單一檔案，Windows 最新版 Edge 與 Chrome 以 `file://` 離線使用；執行時不依賴 CDN、網路、本機伺服器或擴充功能。（AGENTS.md）
- 瀏覽器能力一律用內建 API，不加套件（AGENTS.md、技術設計第 2 章）；Vitest 維持 `environment: 'node'`，不加 jsdom。
- TypeScript strict，維持 TypeScript 6.x。`src/` 的 `lib` 是 ES2022：不要用 `findLast`、`toSorted`、`Object.groupBy` 這類 ES2023 以後的方法。`verbatimModuleSyntax` 已開啟：只當型別用的匯入要寫 `type`。
- 模組邊界（AGENTS.md，ESLint 已設定）：`src/ce-import/` 與 `src/storage/` 在專案模組中只能引用 `src/core/`，兩者互不引用；`src/core/` 不得引用其他模組與 DOM 全域物件。
- 型別檢查的範圍：`src/` 底下的檔案（含測試，以及測試引用的 `tests/support/` 檔案）由 `tsconfig.app.json` 檢查，沒有 Node 的型別；`tests/acceptance/`、`tests/local/` 與只被它們引用的 `tests/support/import-flow.ts` 由 `tsconfig.node.json` 檢查。
- 錯誤處理（技術設計第 5 章、4.3「寫入操作」、4.4「一月」）：規則以回傳值表達（阻止、錯誤、待核對）；畫面不會送出的狀況（指定不合法的列）丟出 `RangeError`；找不到資料列或資料列互相矛盾丟出錯誤；預期外的失敗讓 Dexie 交易回復。
- 本計畫不新增套件。需求規格 9.4、11.3、第 15 章與技術設計 4.3、4.4、第 10 節已和本計畫的設計一起更新（`main` 的 24a64d8 與本計畫的 commit），實作時不再改文件；本計畫的程式與需求規格或技術設計衝突時，以文件為準並回報。

規格隱含、容易出錯的輸入，以及釘住它們的測試（都已在下列任務的測試裡）：

- 一列以能力番号配到一匹產駒，同時父母也符合另一匹還沒有能力番号的產駒 → 這一列不拿來退回配對（Task 4「能力番号未登記的舊產駒……」的 F3 與第 5 行）。

- 已售出的產駒補名 → 牧場處置與其他欄位不變（Task 2 的測試局預設已售出；Task 5 的 IMP-10）。

## 規則依據（原文）

下列引文逐字取自 `docs/specs/需求規格.md` 與 `docs/specs/技術設計.md`。實作與審查都以原文為準；本計畫自己的判斷放在下一節。

**需求規格 5.3、6.2、6.4**

> - **匯入分權**：各時點匯入只更新自己負責的資料（11.2）。
> - 能力番号與出生年都相同：同一匹馬，包含回歸的舊馬，沿用原內部識別。
> - 兩者都相同但馬名或父母明顯不符：衝突，由使用者處理。
> - 幼駒、競走馬、繁殖牝馬、種牡馬各有馬番号。取得新階段馬番号時保存馬番号、階段、遊戲年與來源，舊值留在歷程；同一階段重複出現相同馬番号時不重複記錄。只有馬番号相同、能力番号不同的資料不得合併。
> - 繁殖牝馬與種牡馬馬名經匯入確認後唯讀；匯入時同一身分馬名不同，列為衝突並略過。手動輸入、尚未經匯入確認的馬名可以更正，保存更正歷程（例：11.6 的名稱不符）。
> - 同時保存完整馬名（第 1 欄）與去除 `(外)`、`[地]` 前綴的基本馬名，主要顯示完整馬名，兩者都可搜尋。產駒名稱見 9.4。
> - `(外)`、`[地]` 前綴後面一定接著馬名。只有前綴、沒有馬名時屬於資料異常（5.2）：手動輸入時提示並不建立；匯入時警告並略過該筆，不寫入。

**需求規格 9.4**

> - 正式馬名可手動輸入或由一月總表填入；唯一配對的總表名稱優先，被取代的手動名稱保留為別名與歷程。總表填入後不可再手動修改或清空（遊戲裡的馬名之後不會再改），要更正以更正檔重新匯入一月總表。只有總表取代手動名稱時留別名；手動名稱之間的更正，以及以更正檔把總表名稱改成另一個名稱，舊名只留在歷程（2026-10-07 決定）。
> - 補名後主要顯示正式馬名，追蹤名保留為搜尋別名；識別、母馬、出生年、能力與售出狀態不變。清空正式馬名時回退追蹤名。

**需求規格 11.1、11.2、11.3**

> - **流程**：解析 → 驗證 → 身分配對 → 差異預覽 → 確認 → 單一交易套用 → 結果摘要。預覽分列可套用、略過、待核對、警告、錯誤；有阻擋錯誤時資料不變。
> - 年度匯入與選用匯入：同局、同年、同時點、同類型、同內容雜湊 → 提示重複，不重複建立歷程。同年、同時點、同類型但內容不同 → 確認「資料更正」，保存原值、新值、兩份來源檔與時間，並重新驗證受影響的預定出生、繁殖圈、受胎與八系狀態。
> | 一月二歲馬總表 | 替既有產駒補正式馬名，保存競走馬馬番号 | 新增非管理馬匹、變更持有或售出狀態、改寫父母與出生年 |
> - 用途是得知自家產駒的正式馬名。總表含當年全部 2 歲馬（含電腦 AI 所屬）；出生年＝匯出年減 `年` 欄馬齡（總表全是 2 歲，即匯出年減 2），預覽顯示並由使用者確認。
> - 只和出生年相符的自家產駒配對：以能力番号＋出生年配對；能力番号未登記的舊產駒，才以父馬、母馬、出生年唯一配對（父母名去掉前綴後比較，可忽略前後空白）。配不到任何自家產駒的列是非管理的馬，略過。
> - 唯一配對時填入正式馬名（第 1 欄）與基本馬名（第 77 欄），來源為總表，保存競走馬馬番号與歷程，補入缺少的能力番号。第 1 欄去掉 `(外)`、`[地]` 前綴後與第 77 欄不同時警告，仍以第 77 欄為基本馬名：第 77 欄是 CE 的馬名，其他匯入檔的父母名最可能與它相同（2026-10-07 決定）。
> - **待核對**：沒有唯一配對的自家產駒列入人工確認，原因分為配不到（零筆候選）、無法唯一配對（多筆候選，或候選同時配到另一匹產駒）、未見於總表（已有能力番号，總表沒有那個能力番号）。前兩種可由使用者從總表指定一列（不能已配給別的產駒，出生年要相同），結果與自動配對相同；不處理則維持未命名。未見於總表只列出，不能指定，因為指定的列能力番号一定不同（6.2）（2026-10-07 決定）。
> - 能力番号＋出生年相同但父母明顯不符（6.2）時，列為衝突並略過。已經總表確認的馬名不同時，資料更正改用更正檔的馬名，歷程保存原名與新名（9.4）；其他套用方式列為衝突並略過（6.4）。只有前綴、沒有馬名（第 77 欄空白也算）的列依 6.4 略過並列出。
> - 產駒要到 2 歲才命名，之前只有追蹤名（9.4）。自家產駒尚未滿 2 歲的年份（通常是開局前兩年）配對不到自家產駒屬正常，不警告，仍標記年度工作完成。

**技術設計 4.2、4.3**

> - **同一匹馬**（`identity.ts`）：只傳目前遊戲局的馬匹，馬番号不參與判斷。能力番号由匯入層與手動輸入統一寫法後保存與比對，`0x0000` 是有效值。馬名與父母名稱用基本馬名；還不是正式馬名的名稱（四月的「母馬名の0歳」、未命名的產駒）不傳。手動輸入、尚未經匯入確認的馬名要標 `manualName`：只用來輔助配對，與匯入名稱不同時不算衝突，由匯入名稱取代（需求規格 6.4、9.4、BRD-09）；經匯入確認的馬名不同時仍是衝突（ID-08）。兩邊都有值而且不同才算「明顯不符」，比較時忽略前後空白。以馬名輔助配對時，候選是馬名相符、出生年相同或未填的紀錄；候選兩筆以上，或能力番号與出生年配到兩筆以上，都列為衝突（需求規格 11.5「無法判斷的身分列入衝突」）；輔助配對到的紀錄父母明顯不符也是衝突；以馬名配到的紀錄已有不同的能力番号時也是衝突，不得覆寫。同一匯入檔內重複的能力番号由 `duplicateAbilityNumbers` 列出，只看能力番号、不看出生年，有任何一個時整份停止套用。一月總表以父馬、母馬、出生年配對舊產駒（11.3）屬於匯入層（4.4「一月」）。
> - **既有馬匹**（`KnownHorse`）：父母名優先用保存的匯入名稱，沒有才用連結馬匹經匯入確認的基本馬名；那匹馬的馬名還是手動輸入、尚未經匯入確認時不傳，免得手動名打錯時子女被誤判為衝突（使用者 2026-09-24 決定）。手動輸入的父母名（父母名與父系的來源為手動）同樣不當作匯入名稱，改用連結馬匹經匯入確認的馬名，沒有時不傳（需求規格 6.4，使用者 2026-09-26 決定）；追蹤名與「母馬名の0歳」不是正式馬名，不傳。
> | `horses` | 一匹馬 | 完整馬名與基本馬名、馬名來源（經匯入確認或手動輸入）、別名（被一月總表取代的手動完整馬名，需求規格 9.4；見 4.4「一月」）、能力番号、出生年、性別、父母（內部識別與名稱都保存）、父系、父母名與父系的來源（經匯入確認或手動輸入，需求規格 6.4）、出生紀錄（連結的配種紀錄；八系指定配種所生另記系與代數；自家產駒一定有，沒有連結時是空的）、能力（`SP`、`ST`、七項副能力、匯入的 `サ`、芝與ダート、距離適性、出生時的仔出；需求規格 9.3）、牝系（8.8、9.3）、牧場處置（自家產駒：保留、待售、已售出）、備註 |
> `horseNumbers` 以 `[gameId+horseId]` 建索引。一列是一次取得；同一匹馬同一階段已有相同馬番号時不再新增（需求規格 6.4、MAY-06）。這張表本身就是階段馬番号的歷程，不另寫事件。馬番号以 `normalizeAbilityNumber` 統一寫法（`0x` 加 4 位大寫），格式不符時阻止。儲存子計畫 2-4 只在自家種牡馬接任時寫入種牡馬階段，其他階段由 CE 匯入寫入（使用者 2026-09-28 確認）。
> - **一個操作一個交易**：每個操作在一個 rw 交易內完成：先讀遊戲局確認存在，再從資料列重新組出核心的輸入並重做檢查，最後寫入資料列與事件，並把遊戲局的更新時間設為現在、應用版本設為目前版本（見「備份與還原」）。設定、代表色這類不寫事件的操作也更新，備份提醒（需求規格 12.2）以此判斷有沒有未備份的變更。操作可以包進呼叫端的外層交易（Dexie 的巢狀交易），CE 匯入以此在單一交易內套用多個操作（4.4）。
> - **正式馬名**（需求規格 9.4、BRD-08、BRD-10）：只限自家產駒（有出生紀錄）；市場馬的手動馬名用「手動資料更正」。馬名經匯入確認時阻止，只有前綴、與目前相同時阻止。可以清空，清空後沒有馬名，顯示回退追蹤名；牧場處置不變。事件記原名與新名；手動名之間的更正只留歷程，一月總表取代手動名時的別名見下一條。
> - **一月總表的正式馬名**（需求規格 9.4、11.2、11.3、BRD-09、JAN-05、IMP-10）：`importFoalName`，一月二歲馬總表的計畫項目（4.4「一月」），由 `applyImport` 在匯入的交易內呼叫。只限自家產駒，其他的丟出錯誤。項目帶出生年、完整馬名（第 1 欄）、基本馬名（第 77 欄）、能力番号與競走馬馬番号；這次是不是資料更正由 `applyImport` 依計畫的套用方式傳入。阻止：出生年不同；產駒已有不同的能力番号；這一局另一匹馬已有相同的能力番号與出生年（`findSameHorse`，排除自己，附那一匹，需求規格 6.2）；馬名已經匯入確認、與項目的完整馬名不同，而這次不是資料更正；完整馬名只有前綴，或基本馬名空白；什麼都不用改（馬名、馬名來源與能力番号都相同，競走馬馬番号也已記過）。通過時：完整馬名與基本馬名改用項目的值，馬名來源為經匯入確認；原本是手動輸入的馬名而且與新的完整馬名不同時，把原本的完整馬名加到別名的最後；沒有能力番号時補上；以 `recordHorseNumber` 記競走馬階段的馬番号（相同的不重複記）。不改父母、出生年、性別、能力、出生紀錄與牧場處置，也不碰繁殖圈（11.2、IMP-10）。馬名、馬名來源或能力番号有變時寫事件 `foal-name-imported`：原本的完整馬名（沒有時不記；與新名相同也記，表示經匯入確認）、新的完整馬名與補上的能力番号；只記了馬番号時不寫事件，`horseNumbers` 本身就是歷程（使用者 2026-10-07 決定）。父母是否明顯不符（6.2）只在預覽檢查（4.4「一月」）：項目不帶檔案的父母名，套用前又核對更新時間，預覽之後資料不會改變。

**技術設計 4.4「流程」**

> | 4-3 一月 | 一月二歲馬總表：配對、正式馬名與被取代的手動名、競走馬馬番号、補能力番号；計畫項目的套用與阻止 | IMP-05、10，JAN、BRD-09 |
> - **快照**（`ImportSnapshot`，核心）：通用的部分是遊戲局識別、目前遊戲年、更新時間、這一局的匯入紀錄，以及檢查點的摘要（識別、年、時點、建立時間）。`storage` 的 `loadImportSnapshot(db, gameId, { type, year })` 在一個唯讀交易內讀出，類型與年份是使用者確認的；各類型要用的資料依類型只讀需要的部分，由 4-3 起各塊加入（一月見「一月」）（使用者 2026-10-07 決定）。
> **計畫**（`ImportPlan`，核心；`ce-import` 的 `buildImportPlan(判斷結果, 使用者的選擇, 內容)` 產生，內容是各類型的預覽產生的摘要與項目）：遊戲局識別、快照當下的更新時間 `expectedUpdatedAt`、檔名、雜湊、類型、年、時點、套用方式、`corrects`、推進到的年份 `advanceYear`（不推進時沒有）、確認過的警告、摘要與項目 `items`。每一項對應一個寫入操作，型別 `ImportPlanItem` 是各類型項目的聯合型別（4-2 時沒有項目，4-3 加入一月的 `foal-name`，見「一月」）。選了判斷沒有提供的做法，或需要推進而沒有確認時丟出 `RangeError`（畫面不會送出）。回溯不是計畫的一種：回溯後資料變了，要重新組快照、重新預覽，再產生新的計畫。
> - 逐項套用 `items`：依項目的種類呼叫對應的寫入操作（巢狀交易），事件來源是 `{ kind: 'import', importType, importId }`，時點取計畫的時點，寫入時間是套用時間。某一項回傳阻止時丟出內部的例外，整筆回復，推進年份與前面的項目都不留；`applyImport` 在交易外接住，回傳 `item-blocked`，附第幾項（`index`，從 0 起算）、那一項，與寫入操作的阻止原因（`ImportItemBlock`，各類型寫入操作的阻止原因的聯合型別）。被阻止時不建立檢查點、不備份（CE 匯入子計畫 4-3，使用者 2026-10-07 決定）。
> - **畫面的串接順序**：`readImportFile` → 使用者確認類型與年份 → `parseImportFile` → `hashImportFile` → `loadImportSnapshot` → `judgeImport` → 預覽與選擇（一月是 `previewJanuary`，使用者指定列後重新預覽，再以 `januaryContent` 產生內容）→ `buildImportPlan` → `applyImport`。

**技術設計 4.4「一月」（全文）**

> #### 一月
>
> 由 CE 匯入子計畫 4-3 負責，對應需求規格 9.4、11.2、11.3、JAN、BRD-09、IMP-05、IMP-10（使用者 2026-10-07 決定）。

> - **快照**：類型是一月二歲馬總表時，`loadImportSnapshot` 在同一個唯讀交易內另讀 `january`：出生年（年份減 2）與 `foals`，也就是那一年出生的自家產駒（有出生紀錄的馬），以 `[gameId+birthYear]` 讀出。每匹帶識別、出生年、能力番号、完整馬名、基本馬名與馬名來源、已記的競走馬馬番号，以及父母名的兩種值：經匯入確認的名稱（規則同 4.3「規則輸入快照的彙整」的既有馬匹：保存的匯入名稱優先，沒有時用連結馬匹經匯入確認的基本馬名），與任何已知的名稱（保存的名稱，沒有時用連結馬匹的基本馬名，手動輸入的也算）。型別 `ImportFoal`、`JanuarySnapshot` 放在核心；其他類型不讀產駒。產駒連結的父母找不到時丟出錯誤（資料列互相矛盾，同 4.3「規則輸入快照的彙整」）。只讀一個出生年、用既有的索引，資料量是幾十匹；一律讀全部自家產駒時，每次匯入都要讀這一局所有產駒與父母，之後各塊再加母馬與配種紀錄會越來越重（使用者 2026-10-07 決定）。

>   零筆或多筆從產駒這一邊判斷：總表有一千多列電腦 AI 的馬，從列這一邊看會全部變成人工確認（使用者 2026-10-07 確認）。

>   - 以能力番号配到、經匯入確認的父母名與檔案明顯不符（兩邊都有值而且不同，忽略前後空白）時為錯誤（需求規格 6.2、ID-03）；手動輸入的父母名不比，同 4.2「同一匹馬」。

>   - 第 1 欄只有前綴、沒有馬名，或第 77 欄空白時為錯誤（6.4 的「警告並略過該筆」）。
>   - `splitHorseName(第 1 欄)` 的基本馬名與第 77 欄不同時警告，照樣套用，基本馬名取第 77 欄（使用者 2026-10-07 決定）。
> - **使用者指定**：`previewJanuary(entries, snapshot, mode, picks)` 的 `picks` 是「產駒 → 行號」，畫面每指定一次就重新預覽（一千多列與幾十匹產駒，純函式重算即可），指定後的衝突直接出現在預覽的錯誤裡。指定的產駒要是配不到或無法唯一配對的待核對產駒，那一列要在檔案裡、不能已配給別的產駒（自動配對或其他指定），出生年要與產駒相同，否則丟出 `RangeError`（畫面不會送出）；未見於總表的產駒不能指定（需求規格 11.3，使用者 2026-10-07 決定）。

>   - 可套用：有變更的對的列數。
>   - 略過：非管理的列，加上配成對但什麼都不用改的列。
>   - 錯誤：錯誤的列數。
>   - 待核對：還沒處理的產駒匹數；未見於總表的產駒沒有列，所以以匹計。
>   - 警告：可套用的列中有警告的列數，是可套用的一部分。

## 本計畫的詮釋

需求規格與技術設計沒有逐字寫出、由本計畫決定的地方。技術設計 4.4「一月」已經和使用者確認；下面是本計畫在程式層級的決定，審查時請逐條對照上一節的原文。

1. **快照**（Task 1）：`loadImportSnapshot(db, gameId, scope)` 的 `scope` 是 `ImportScope`（`type`、`year`）；`ce-import` 的 `ImportFile` 也符合這個形狀，畫面與測試直接傳檔案。產駒以 `[gameId+birthYear]` 讀出後只留有出生紀錄的；父母以 `bulkGet` 一次讀出；競走馬馬番号以 `[gameId+horseId]` 的 `anyOf` 讀出，只取 `racehorse` 階段。父母名的兩種值：`confirmed` 在保存的名稱存在而且父母名來源不是手動時取保存的名稱，否則取連結馬匹經匯入確認的基本馬名（同 `buildKnownHorses`）；`known` 取保存的名稱，沒有時取連結馬匹的基本馬名（手動的也算）。產駒依資料庫讀出的順序（識別）排列。其他類型的快照沒有 `january` 這個欄位。
2. **寫入操作**（Task 2）：
   - `importFoalName(db, gameId, item, options)`；「是不是資料更正」是選項 `FoalImportOptions` 的 `correction`（擴充 `WriteOptions`），由 `applyImport` 傳入。
   - 阻止原因一次列全：出生年、既有的能力番号、同一匹馬（一律以項目的能力番号與出生年查，排除自己）、經匯入確認的馬名不同（比完整馬名與基本馬名）、只有前綴或基本馬名空白。
   - 「什麼都不用改」在記馬番号之後判斷：`recordHorseNumber` 沒有記（已有同一階段的相同馬番号）才算不變，這時什麼都沒寫，回傳 `unchanged`。只記了馬番号時回傳原本的馬匹、不寫事件，遊戲局的更新時間照常更新（記馬番号是資料變更）。
   - 別名加在最後，不去重：只有手動名被取代時才加，被取代之後馬名就經匯入確認，同一匹馬不會再加第二次。事件的 `abilityNumber` 只在這次補上時記。
3. **逐項套用**（Task 3）：項目依 `kind` 以 `switch` 分派。某一項被阻止時在交易內丟出模組內部的 `ItemStopped`，`applyImport` 以 `.catch` 在交易外接住，轉成 `item-blocked`；`index` 從 0 起算。寫入操作回傳待確認時丟出一般的錯誤（一月沒有要確認的警告）。`commitImport` 的回傳改成 `committed`（匯入紀錄與目前進度）或阻止原因，原本以 `undefined` 表示 `changed-since-preview`。
4. **預覽**（Task 4）：
   - 第 1 步以「能力番号/出生年」的字串為鍵查列（檔內能力番号不會重複，解析已經擋下）。

/**
 * 一月的快照（技術設計 4.4「一月」）：出生年為 birthYear 的自家產駒（有出生紀錄），帶父母名的兩種值與
 * 已記的競走馬馬番号。在 loadImportSnapshot 的交易內呼叫
 */
async function loadJanuary(
  db: WPStudBookDatabase,
  gameId: string,
  birthYear: number,
): Promise<JanuarySnapshot> {
  const rows = await db.horses
    .where('[gameId+birthYear]')
    .equals([gameId, birthYear])
    .filter((horse) => horse.birth !== undefined)
    .toArray()
  const parentIds = new Set<string>()
  for (const horse of rows) {
    if (horse.sireId !== undefined) parentIds.add(horse.sireId)
    if (horse.damId !== undefined) parentIds.add(horse.damId)
  }
  const parents = new Map<string, HorseRow>()
  for (const parent of await db.horses.bulkGet([...parentIds])) {
    if (parent) parents.set(parent.id, parent)
  }
  const numbers = await db.horseNumbers
    .where('[gameId+horseId]')
    .anyOf(rows.map((horse) => [gameId, horse.id]))
    .filter((row) => row.stage === 'racehorse')
    .toArray()
  const foals = rows.map((horse): ImportFoal => {
    const manual = horse.pedigreeSource === 'manual'
    return {
      id: horse.id,
      birthYear,
      ...(horse.abilityNumber === undefined ? {} : { abilityNumber: horse.abilityNumber }),
      ...(horse.fullName === undefined ? {} : { fullName: horse.fullName }),
      ...(horse.baseName === undefined ? {} : { baseName: horse.baseName }),
      ...(horse.nameSource === undefined ? {} : { nameSource: horse.nameSource }),
      sire: parentNames(parents, horse.sireName, horse.sireId, manual),
      dam: parentNames(parents, horse.damName, horse.damId, manual),
      racehorseNumbers: numbers.filter((row) => row.horseId === horse.id).map((row) => row.number),
    }
  })
  return { birthYear, foals }
}

/**
 * 父馬或母馬的兩種名稱（技術設計 4.4「一月」）：經匯入確認的名稱同 4.3 的既有馬匹（buildKnownHorses），
 * 保存的名稱是手動輸入時不算；任何已知的名稱是保存的名稱，沒有時用連結馬匹的基本馬名。
 * 連結的馬匹不在 parents 中時丟出錯誤
 */
function parentNames(
  parents: ReadonlyMap<string, HorseRow>,
  name: string | undefined,
  id: string | undefined,
  manual: boolean,
): ImportParentNames {
  const parent = id === undefined ? undefined : parents.get(id)
  if (id !== undefined && parent === undefined) throw new Error(`找不到馬匹：${id}`)
  const linked = parent?.nameSource === 'import' ? parent.baseName : undefined
  const confirmed = manual || name === undefined ? linked : name
  const known = name ?? parent?.baseName
  return {
    ...(confirmed === undefined ? {} : { confirmed }),
    ...(known === undefined ? {} : { known }),
  }
}

/**
 * 一月總表的正式馬名（需求規格 9.4、11.3、BRD-09、JAN-05、IMP-10；技術設計 4.3「一月總表的正式馬名」）：
 * 一月二歲馬總表的計畫項目，由 applyImport 在匯入的交易內呼叫。完整馬名與基本馬名改用項目的值，馬名來源為
 * 經匯入確認；原本是手動輸入的馬名而且和新的完整馬名不同時，原本的完整馬名加到別名的最後；沒有能力番号時補上；
 * 以 recordHorseNumber 記競走馬階段的馬番号（相同的不重複記）。不改父母、出生年、性別、能力、出生紀錄與牧場處置。
 * 馬名、馬名來源或能力番号有變時寫事件 foal-name-imported；只記了馬番号時不寫事件，horseNumbers 本身就是歷程。
 * 馬匹找不到、屬於其他局或不是自家產駒時丟出錯誤；馬番号沒有統一寫法時丟出 RangeError
 */
export async function importFoalName(
  db: WPStudBookDatabase,
  gameId: string,
  item: FoalNameItem,
  options: FoalImportOptions = {},
): Promise<WriteResult<HorseRow, FoalImportBlock>> {
  return runWrite(db, gameId, [db.horses, db.horseNumbers], options, async (context) => {
    const current = await loadFoal(context, item.horseId)
    const blocks: FoalImportBlock[] = []
    if (current.birthYear !== item.birthYear) blocks.push({ kind: 'birth-year' })
    if (current.abilityNumber !== undefined && current.abilityNumber !== item.abilityNumber) {
      blocks.push({ kind: 'ability-number' })
    }
    const same = await findSameHorse(context, item.abilityNumber, item.birthYear, current.id)
    if (same) blocks.push({ kind: 'same-horse', horseId: same.id })
    const renamed = current.fullName !== item.fullName || current.baseName !== item.baseName
    if (current.nameSource === 'import' && renamed && options.correction !== true) {
      blocks.push({ kind: 'name-confirmed' })
    }
    if (splitHorseName(item.fullName) === null || item.baseName.trim() === '') {
      blocks.push({ kind: 'horse-name' })
    }
    if (blocks.length > 0) return { status: 'blocked', blocks }
    const confirms = renamed || current.nameSource !== 'import'
    const fills = current.abilityNumber === undefined
    const recorded = await recordHorseNumber(context, current.id, 'racehorse', item.horseNumber)
    if (!confirms && !fills) {
      return recorded === undefined
        ? { status: 'blocked', blocks: [{ kind: 'unchanged' }] }
        : context.done(current)
    }
    const manualName = current.nameSource === 'manual' ? current.fullName : undefined
    const aliased = manualName !== undefined && manualName !== item.fullName
    const foal: HorseRow = {
      ...current,
      fullName: item.fullName,
      baseName: item.baseName,
      nameSource: 'import',
      ...(aliased ? { aliases: [...(current.aliases ?? []), manualName] } : {}),
      abilityNumber: item.abilityNumber,
    }
    await db.horses.put(foal)
    await context.addEvent({
      kind: 'foal-name-imported',
      horseId: current.id,
      ...(current.fullName === undefined ? {} : { from: current.fullName }),
      to: item.fullName,
      ...(fills ? { abilityNumber: item.abilityNumber } : {}),
    })
    return context.done(foal)
  })
}

import type { FoalNameItem, ImportFoal, ImportMode, ImportSnapshot } from '../core/imports'
import type { ImportContent } from './flow'
import type { TwoYearOldEntry } from './formats'

// 一月二歲馬總表的配對與預覽（需求規格 9.4、11.3；技術設計 4.4「一月」）

/** 配對方式：能力番号＋出生年、父母＋出生年，或使用者指定 */
export type JanuaryMatch = 'ability-number' | 'parents' | 'picked'

/**
 * 一對要做的變更（技術設計 4.4「一月」）：
 * - name：馬名或馬名來源有變時，原本的完整馬名（沒有時留空）、新的完整馬名，與原本的手動名會不會留作別名
 * - abilityNumber：補上的能力番号；產駒原本就有時留空
 * - horseNumber：新的競走馬馬番号；已記過時留空
 */
export interface JanuaryChanges {
  name?: { from?: string; to: string; alias: boolean }
  abilityNumber?: string
  horseNumber?: string
}

/**
 * 警告：第 1 欄去掉前綴後的基本馬名 split 與第 77 欄 baseName 不同（JAN-09）；照樣套用，基本馬名取第 77 欄
 */
export interface JanuaryWarning {
  kind: 'base-name'
  split: string
  baseName: string
}

/** 配成的一對：產駒與檔案的一列（行號）；有變更時帶套用的項目 */
export interface JanuaryPair {
  foalId: string
  line: number
  match: JanuaryMatch
  changes: JanuaryChanges
  warnings: JanuaryWarning[]
  /** 套用的項目；什麼都不用改時留空 */
  item?: FoalNameItem
}

/**
 * 錯誤的原因（技術設計 4.4「一月」），錯誤的對不套用：
 * - sire、dam：以能力番号配到，經匯入確認的父馬或母馬名與檔案明顯不符（需求規格 6.2）
 * - name-confirmed：馬名已經匯入確認、與這一列不同，而這次不是資料更正（6.4）
 * - horse-name：第 1 欄只有前綴、沒有馬名，或第 77 欄空白（6.4）
 */
export type JanuaryErrorReason = 'sire' | 'dam' | 'name-confirmed' | 'horse-name'

/** 錯誤的一對：產駒、行號、配對方式與原因 */
export interface JanuaryError {
  foalId: string
  line: number
  match: JanuaryMatch
  reasons: JanuaryErrorReason[]
}

/**

 * - no-candidate：配不到，以父母＋出生年沒有候選列
 * - ambiguous：無法唯一配對，候選兩列以上，或候選列也配到別的產駒
 * - not-in-file：未見於總表，已有能力番号而檔案沒有那個能力番号；不能指定
 */
export type JanuaryPendingReason = 'no-candidate' | 'ambiguous' | 'not-in-file'

/** 待核對的產駒；candidates 是候選列的行號，不含已指定給別的產駒的列 */

  candidates: number[]

/**

  errors: number
  pending: number
  warnings: number

/** 一月的預覽（技術設計 4.4「一月」） */
export interface JanuaryPreview {
  /** 出生年（年份減 2），供使用者確認（需求規格 11.3） */
  birthYear: number
  /** 檔案的列數 */
  total: number
  pairs: JanuaryPair[]
  errors: JanuaryError[]
  pending: JanuaryPending[]
  counts: JanuaryCounts

/**
 * 一月二歲馬總表的配對與預覽（需求規格 11.3，技術設計 4.4「一月」）。快照要有一月的資料，否則丟出錯誤。
 * 先以能力番号＋出生年配對；還沒有能力番号的產駒，與沒配到的列，以父母＋出生年退回配對，兩邊都唯一時配成一對；
 * 沒配成對的產駒列入待核對，其他的列是非管理的馬，只計入略過。picks 是使用者指定的「產駒 → 行號」：
 * 產駒要是配不到或無法唯一配對的待核對產駒，那一列要在檔案裡、沒有配給別的產駒、出生年與產駒相同，
 * 否則丟出 RangeError（畫面不會送出）。配成的對（含指定的）再檢查錯誤：父母不符只查以能力番号配到的
 */
export function previewJanuary(
  entries: readonly TwoYearOldEntry[],
  snapshot: ImportSnapshot,
  mode: ImportMode,
  picks: ReadonlyMap<string, number> = new Map(),
): JanuaryPreview {
  const { january } = snapshot
  if (january === undefined) throw new Error('快照沒有一月二歲馬總表的資料')
  const { birthYear, foals } = january
  const matched = new Map<string, { entry: TwoYearOldEntry; match: JanuaryMatch }>()
  const used = new Set<number>()
  const pair = (foalId: string, entry: TwoYearOldEntry, match: JanuaryMatch) => {
    matched.set(foalId, { entry, match })
    used.add(entry.line)
  }

  // 1. 能力番号＋出生年
  const byNumber = new Map(entries.map((entry) => [numberKey(entry), entry]))
  for (const foal of foals) {
    const entry = foal.abilityNumber === undefined ? undefined : byNumber.get(numberKey(foal))
    if (entry) pair(foal.id, entry, 'ability-number')
  }

  // 2. 父母＋出生年：還沒有能力番号的產駒，與第 1 步沒配到的列
  const free = entries.filter((entry) => !used.has(entry.line))
  const options = foals
    .filter((foal) => foal.abilityNumber === undefined)
    .map((foal) => ({ foal, rows: free.filter((entry) => parentsMatch(foal, entry)) }))
  const claims = new Map<number, number>()
  for (const { rows } of options) {
    for (const entry of rows) claims.set(entry.line, (claims.get(entry.line) ?? 0) + 1)
  }
  const unresolved = new Map<string, JanuaryPending>()
  for (const { foal, rows } of options) {
    const [only] = rows
    if (rows.length === 1 && only !== undefined && claims.get(only.line) === 1) {
      pair(foal.id, only, 'parents')
    } else {
      const reason = rows.length === 0 ? 'no-candidate' : 'ambiguous'
      const candidates = rows.map((entry) => entry.line)
      unresolved.set(foal.id, { foalId: foal.id, reason, candidates })
    }
  }

  // 3. 已有能力番号、第 1 步沒配到：未見於總表
  for (const foal of foals) {
    if (foal.abilityNumber !== undefined && !matched.has(foal.id)) {
      unresolved.set(foal.id, { foalId: foal.id, reason: 'not-in-file', candidates: [] })
    }
  }

  // 4. 使用者指定
  const byLine = new Map(entries.map((entry) => [entry.line, entry]))
  const byId = new Map(foals.map((foal) => [foal.id, foal]))
  for (const [foalId, line] of picks) {
    const waiting = unresolved.get(foalId)
    const foal = byId.get(foalId)
    if (waiting === undefined || waiting.reason === 'not-in-file' || foal === undefined) {
      throw new RangeError(`這匹產駒不能指定列：${foalId}`)
    }
    const entry = byLine.get(line)
    if (entry === undefined) throw new RangeError(`檔案沒有第 ${line} 行`)
    if (used.has(line)) throw new RangeError(`第 ${line} 行已配給別的產駒`)
    if (entry.birthYear !== foal.birthYear) throw new RangeError(`第 ${line} 行的出生年與產駒不同`)
    pair(foalId, entry, 'picked')
    unresolved.delete(foalId)
  }

  // 5. 配成的對檢查錯誤，產生變更與項目
  const pairs: JanuaryPair[] = []
  const errors: JanuaryError[] = []
  for (const foal of foals) {
    const found = matched.get(foal.id)
    if (found === undefined) continue
    const { entry, match } = found
    const reasons = errorReasons(foal, entry, match, mode)
    if (reasons.length > 0) errors.push({ foalId: foal.id, line: entry.line, match, reasons })
    else pairs.push(pairOf(foal, entry, match))
  }
  const pending = foals.flatMap((foal) => {
    const waiting = unresolved.get(foal.id)
    if (waiting === undefined) return []
    return [{ ...waiting, candidates: waiting.candidates.filter((line) => !used.has(line)) }]
  })
  const applicable = pairs.filter((item) => item.item !== undefined)
  return {
    birthYear,
    total: entries.length,
    pairs,
    errors,
    pending,
    counts: {
      applicable: applicable.length,
      skipped: entries.length - applicable.length - errors.length,
      errors: errors.length,
      pending: pending.length,
      warnings: applicable.filter((item) => item.warnings.length > 0).length,
    },
  }
}

/**
 * 一月的內容（技術設計 4.4「一月」）：每一個可套用的對一個項目，不必改的對不產生項目。
 * 摘要的 total 是列數，applied、skipped 是可套用與略過的列數，另填待核對、警告與錯誤的筆數
 */
export function januaryContent(preview: JanuaryPreview): ImportContent {
  const { applicable, skipped, pending, warnings, errors } = preview.counts
  return {
    summary: { total: preview.total, applied: applicable, skipped, pending, warnings, errors },
    items: preview.pairs.flatMap((pair) => (pair.item === undefined ? [] : [pair.item])),
  }
}

/** 能力番号＋出生年的鍵 */
function numberKey(horse: { abilityNumber?: string; birthYear: number }): string {
  return `${horse.abilityNumber}/${horse.birthYear}`
}

/** 檔案的父母名去掉前綴的基本馬名；空白或只有前綴時為 undefined */
function parentName(text: string): string | undefined {
  return splitHorseName(text.trim())?.baseName
}

/** 名稱比較忽略前後空白 */
function sameName(a: string, b: string): boolean {
  return a.trim() === b.trim()
}

/** 明顯不符：兩邊都有值而且不同；只有一邊有值不算 */
function clearlyDiffers(known: string | undefined, incoming: string | undefined): boolean {
  return known !== undefined && incoming !== undefined && !sameName(known, incoming)
}

/** 以父母＋出生年退回配對：產駒父母的任何已知名稱都要有，而且與檔案相同 */
function parentsMatch(foal: ImportFoal, entry: TwoYearOldEntry): boolean {
  const sire = parentName(entry.sireName)
  const dam = parentName(entry.damName)
  const { known: knownSire } = foal.sire
  const { known: knownDam } = foal.dam
  return (
    entry.birthYear === foal.birthYear &&
    knownSire !== undefined &&
    knownDam !== undefined &&
    sire !== undefined &&
    dam !== undefined &&
    sameName(knownSire, sire) &&
    sameName(knownDam, dam)
  )
}

/** 配成一對之後的錯誤（技術設計 4.4「一月」）；父母不符只查以能力番号配到的 */
function errorReasons(
  foal: ImportFoal,
  entry: TwoYearOldEntry,
  match: JanuaryMatch,
  mode: ImportMode,
): JanuaryErrorReason[] {
  const reasons: JanuaryErrorReason[] = []
  if (match === 'ability-number') {
    if (clearlyDiffers(foal.sire.confirmed, parentName(entry.sireName))) reasons.push('sire')
    if (clearlyDiffers(foal.dam.confirmed, parentName(entry.damName))) reasons.push('dam')
  }
  const renamed = foal.fullName !== entry.fullName || foal.baseName !== entry.baseName
  if (foal.nameSource === 'import' && renamed && mode !== 'correction') {
    reasons.push('name-confirmed')
  }
  if (splitHorseName(entry.fullName) === null || entry.baseName.trim() === '') {
    reasons.push('horse-name')
  }
  return reasons
}

/** 沒有錯誤的一對：要做的變更、第 77 欄的警告，有變更時附套用的項目 */
function pairOf(foal: ImportFoal, entry: TwoYearOldEntry, match: JanuaryMatch): JanuaryPair {
  const confirms =
    foal.fullName !== entry.fullName ||
    foal.baseName !== entry.baseName ||
    foal.nameSource !== 'import'
  const fills = foal.abilityNumber === undefined
  const records = !foal.racehorseNumbers.includes(entry.horseNumber)
  const alias = foal.nameSource === 'manual' && foal.fullName !== entry.fullName
  const name = {
    ...(foal.fullName === undefined ? {} : { from: foal.fullName }),
    to: entry.fullName,
    alias,
  }
  const changes: JanuaryChanges = {
    ...(confirms ? { name } : {}),
    ...(fills ? { abilityNumber: entry.abilityNumber } : {}),
    ...(records ? { horseNumber: entry.horseNumber } : {}),
  }
  const split = splitHorseName(entry.fullName)?.baseName
  const warnings: JanuaryWarning[] =
    split !== undefined && split !== entry.baseName
      ? [{ kind: 'base-name', split, baseName: entry.baseName }]
      : []
  const item: FoalNameItem = {
    kind: 'foal-name',
    horseId: foal.id,
    birthYear: foal.birthYear,
    fullName: entry.fullName,
    baseName: entry.baseName,
    abilityNumber: entry.abilityNumber,
    horseNumber: entry.horseNumber,
  }
  return {
    foalId: foal.id,
    line: entry.line,
    match,
    changes,
    warnings,
    ...(confirms || fills || records ? { item } : {}),
  }
}

 */

  mode?: ImportMode
  picks?: ReadonlyMap<string, number>

/** 一月的預覽：判斷結果、選的套用方式與預覽 */
export interface JanuaryFlow {
  judgment: ReadyImport
  mode: ImportMode
  preview: JanuaryPreview
}

/**
 * 照畫面的串接預覽一月二歲馬總表（技術設計 4.4「流程」「一月」）：組出 CP932 的檔案、讀檔、解析、算雜湊、
 * 組快照、判斷，再以 previewJanuary 預覽。讀不出來、解析失敗或判斷是重複時讓測試失敗
 */
export async function previewJanuaryFile(
  db: WPStudBookDatabase,
  rows: readonly ExportValues[],
  options: JanuaryOptions = {},
): Promise<JanuaryFlow> {
  const year = options.year ?? 1990
  const fileName = `${year}年 1月1週._二歲新馬.txt`
  const bytes = cp932(exportText('two-year-old', rows))
  const read = readImportFile(bytes, fileName)
  if (read.status !== 'ok') throw new Error(read.reason)
  const parsed = parseImportFile(read.text, 'january-two-year-olds', year)
  if (parsed.status !== 'ok' || parsed.format !== 'two-year-old') throw new Error('解析失敗')
  const file: ImportFile = {
    fileName,
    sha256: await hashImportFile(bytes),
    type: 'january-two-year-olds',
    year,
    fileTiming: { month: 1, week: 1 },
  }
  const snapshot = await loadImportSnapshot(db, GAME, file)
  const judgment = judgeImport(file, snapshot)
  if (judgment.kind !== 'ready') throw new Error(judgment.kind)
  const mode =
    options.mode ?? judgment.options.find((option): option is ImportMode => option !== 'rollback')
  if (mode === undefined) throw new Error('只能回溯')
  const preview = previewJanuary(parsed.entries, snapshot, mode, options.picks)
  return { judgment, mode, preview }
}

/** 接著產生計畫（確認推進年份）並套用；套用被阻止時讓測試失敗 */
export async function applyJanuaryFile(
  db: WPStudBookDatabase,
  rows: readonly ExportValues[],
  options: JanuaryOptions = {},
): Promise<{ preview: JanuaryPreview; applied: AppliedImport }> {
  const { judgment, mode, preview } = await previewJanuaryFile(db, rows, options)
  const plan = buildImportPlan(judgment, { mode, advanceConfirmed: true }, januaryContent(preview))
  const result = await applyImport(db, plan)
  if (result.status !== 'done') throw new Error(JSON.stringify(result))
  return { preview, applied: result.value }
}
