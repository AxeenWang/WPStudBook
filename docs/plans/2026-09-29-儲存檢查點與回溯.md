# 儲存檢查點與回溯 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `src/storage/` 加上檢查點與回溯：檢查點的兩張資料表與保留個數的設定；建立檢查點（內容是這一局的備份檔）與超過保留個數時的清除；釘選與註記；驗證檢查點並預覽將捨棄的資料；交出目前備份後以單一交易回溯（需求規格 12.4、技術設計 4.3「檢查點與回溯」）。

**Architecture:** 儲存子計畫 3 拆成三塊，本計畫是第 2 塊（3-1 備份與還原 → 3-2 檢查點與回溯 → 3-3 封存與瀏覽器整合）。檢查點的內容就是 3-1 的備份檔：`backup.ts` 抽出 `encodeBackup` 給匯出與檢查點共用，驗證沿用 `readBackup`。新檔 `checkpoints.ts` 負責建立、列出、釘選、註記、驗證預覽與回溯；回溯沿用 `game-data.ts` 的 `deleteGameData`、`addGameData`（同一局、識別不變）。檢查點的兩張表不屬於 `GAME_TABLES`：備份不含檢查點，回溯清掉整局資料時要留下它們；刪除一局時由 `deleteGame` 另外刪。下載不在本計畫：回溯接收呼叫端的交付函式，真正的下載由 3-3 提供。core 不改。

**Tech Stack:** TypeScript（strict）、Dexie 4、Vitest、fake-indexeddb；瀏覽器內建的 `CompressionStream`、`DecompressionStream`、`crypto.subtle`（沿用 3-1）。不新增套件。

## Global Constraints

- 成品：`app/dist/WPStudBook.html` 單一檔案，Windows 最新版 Edge 與 Chrome 以 `file://` 離線使用；執行時不依賴 CDN、網路、本機伺服器或擴充功能。（AGENTS.md）
- gzip 與 SHA-256 一律用瀏覽器內建的 API，不加套件（AGENTS.md、技術設計第 2 章）；本計畫只經由 3-1 的 `encodeBackup`、`readBackup` 使用它們。
- TypeScript strict，維持 TypeScript 6.x。`src/` 的 `lib` 是 ES2022：不要用 `findLast`、`toSorted`、`Object.groupBy` 這類 ES2023 以後的方法。`verbatimModuleSyntax` 已開啟：只當型別用的匯入要寫 `type`。位元組一律寫 `Uint8Array<ArrayBuffer>`，照計畫的程式。
- 模組邊界：`src/storage/` 在專案模組中只能引用 `src/core/`，不得引用 `src/ce-import/`、`src/ui/`，也不得引用 Vue、Pinia、Vue Router、Reka UI。（AGENTS.md，ESLint 已設定）`checkpoints.ts` 引用 `games.ts`，所以 `games.ts` 不能反過來引用 `checkpoints.ts`（`deleteGame` 直接刪兩張檢查點表）。
- 錯誤處理（技術設計第 5 章、4.3「檢查點與回溯」）：讀取檢查點遇到內容異常時回傳拒絕原因，不丟例外；回溯遇到預覽後的變更回傳 `blocked`；畫面不會送出的狀況（找不到遊戲局或檢查點、檢查點屬於其他局、檢查點在預覽後不見）丟出附識別的 `Error`；時點或補匯的年不合法丟出 `RangeError`。交付函式丟出的錯誤原樣往外傳。

## 規則依據（原文）

下列引文逐字取自 `docs/specs/需求規格.md` 與 `docs/specs/技術設計.md`。實作與審查都以原文為準；本計畫自己的判斷放在下一節。

**需求規格 11.1 共通規則**

> - **回溯**：回到對應檢查點（12.4）後再套用。
> - **直接補匯**：只在該局、該年、該時點、該類型從未匯入過時提供。不回溯，直接套用，並重新驗證受影響的預定出生、繁殖圈、受胎與八系狀態（範圍同資料更正），標記該年度工作完成，結果摘要標示「補匯」。
> - **檢查點**：年度匯入套用後自動建立檢查點、依 12.2 自動備份，並標記年度工作完成；累加匯入與選用匯入不建立檢查點、不標記年度工作完成。

**需求規格 12.1、12.2**

> - 「永久刪除此局」「刪除全部存檔」放在危險區並顯示筆數：刪除此局要輸入局名確認；刪除全部要輸入畫面上顯示的「刪除全部存檔」，並再次確認（2026-09-29 決定）。
> - 完整備份與移轉用 JSON／JSON.GZ（支援 Compression Streams 時優先 `.json.gz`，否則 `.json`）。資料契約含格式識別、結構版本、應用版本、匯出時間、遊戲局摘要、各集合與筆數、SHA-256；識別存字串，正規化集合，不內嵌血緣樹。備份不含檢查點：檢查點只供本機回溯，還原成的新局從之後的年度匯入重新累積（2026-09-24 決定）。

**需求規格 12.4 檢查點與回溯（全文）**

> - **建立**：年度匯入（11.1）套用後自動建立；直接補匯時檢查點記為目前進度，並註明補匯的年與時點。可隨時手動建立並加註（例如遊戲存檔名稱），註記事後可以修改（2026-09-29 決定）。
> - **內容**：遊戲局完整資料，格式同備份檔（12.2），gzip 壓縮存於 IndexedDB，記錄年（建立當下的目前遊戲年）、時點、時間與 SHA-256（2026-09-29 決定）。
> - **保留**：最近 12 個未釘選的檢查點（每年 4 份年度匯入，約 3 年），個數可在這一局的設定調整；釘選的不計入，也不自動清除。建立檢查點時才清除超過個數的最舊者，取消釘選或調低個數不會立即刪除（2026-09-29 決定）。
> - **回溯**：驗證檢查點並預覽將捨棄的資料 → 確認後自動下載目前備份 → 單一交易還原。預覽列出目前與檢查點的各類筆數、將捨棄的歷程、將移除的檢查點與目前遊戲年的變化。還原後資料與目前遊戲年回到檢查點，這一局的設定沿用目前的值；較晚的檢查點移除，釘選的也一併移除（回溯前已自動下載目前備份，2026-09-24 決定）。檢查點驗證失敗、下載失敗，或預覽後資料有變更時停止，資料不變。只影響目前遊戲局（2026-09-29 決定）。
> - **刪除**：永久刪除此局（12.1）時一併刪除它的檢查點（2026-09-29 決定）。

**需求規格第 15 章（本計畫驗收的情境）**

> - **CKPT-01**：年度匯入套用成功 → 自動建立檢查點，記錄年、時點、時間與雜湊。
> - **CKPT-02**：手動建立 → 可加註說明；註記事後可以修改。
> - **CKPT-03**：建立檢查點後，未釘選的超過保留個數（預設 12 個）→ 清除最舊的未釘選者；釘選的不計入也不清除。
> - **CKPT-04**：回溯 → 先驗證檢查點並預覽將捨棄的資料，確認後自動下載目前備份，再還原。
> - **CKPT-05**：檢查點驗證失敗、目前備份下載失敗，或預覽後資料有變更 → 停止回溯，資料不變。
> - **CKPT-06**：回溯後 → 資料與遊戲年回到檢查點、設定沿用目前的值，較晚的檢查點（含釘選的）被移除。
> - **CKPT-07**：回溯 → 只影響目前遊戲局。
> - **CKPT-08**：直接補匯後 → 檢查點記為目前進度，並註明補匯的年與時點。

**技術設計 4.3 資料表、設定與整局資料**

> - 檢查點：整局資料以備份檔的格式（gzip）存入檢查點內容表，年、時點、時間與 SHA-256 等中繼資料另存一張表（12.4）；見「檢查點與回溯」。

資料表（節錄）：

> | `settings` | 一局的設定 | 定年（預設 25 歲）、高齡提醒年齡（18 歲）、種牡馬提醒年齡（26 歲）、檢查點的保留個數（12 個，12.4）等；設定全部放在各局，新局選擇只複製設定時整列複製（12.1） |

> | `checkpoints` | 一個檢查點的中繼資料（需求規格 12.4） | 建立方式（年度匯入後自動、手動）、年、時點、補匯的年與時點、建立時間、SHA-256、註記、是否釘選；不屬於 `GAME_TABLES`（見「檢查點與回溯」） |

> | `checkpointContents` | 一個檢查點的內容 | 檢查點、與備份檔相同的位元組；不屬於 `GAME_TABLES` |

> - **設定**：定年、高齡提醒年齡、種牡馬提醒年齡、檢查點的保留個數都要是 1 以上的整數；不寫事件，新設定從下一次判斷開始生效（MARE-10）。
> - **整局資料**：`GAME_TABLES` 列出一局的資料表，匯出、還原、回溯、檢查點的內容、刪除與計算筆數都用這份清單。不屬於一局資料的表明示排除：全域的 `meta`，以及檢查點的兩張表（備份不含檢查點，回溯要清掉整局資料而留下檢查點，刪除一局時另外刪）；測試確認每一張表不是在 `GAME_TABLES`，就是在排除清單裡，之後加表時一併更新（使用者 2026-09-29 決定）。讀出整局在單一唯讀交易內完成，得到一致的快照（需求規格 12.2）。

**技術設計 4.3「檢查點與回溯」（全文）**

> #### 檢查點與回溯
>
> 檢查點與回溯（需求規格 11.1、12.4）由儲存子計畫 3-2 負責，沿用「備份與還原」的整局讀寫與備份格式（使用者 2026-09-29 決定）。
>
> - **資料表**：中繼資料與內容分成兩張表，都不屬於 `GAME_TABLES`（見「整局資料」）。以設計目標的單局 3 萬列估算，內容 gzip 後約 1 MB，12 個約 12 MB；IndexedDB 只能整列讀寫，分表後開啟清單與釘選只讀寫幾 KB（使用者 2026-09-29 決定）。
>   - `checkpoints`（主鍵 `id`，索引 `gameId`）：遊戲局、建立方式（年度匯入後自動、手動）、年、時點（選填）、補匯的年與時點（直接補匯時，CKPT-08）、建立時間、SHA-256（內容檔案裡的 `sha256`）、註記（選填）、是否釘選（只讀取不建索引，存布林值）。
>   - `checkpointContents`（主鍵 `checkpointId`，索引 `gameId`）：內容的位元組。
> - **內容**：與備份檔相同的位元組，建立時間就是檔案的匯出時間。匯出與檢查點共用同一個編碼函式（組出內容、雜湊與壓縮），沒有 `CompressionStream` 時同樣存未壓縮的 JSON。驗證沿用備份的讀取與驗證，結構升版後，舊檢查點在回溯時逐版遷移（使用者 2026-09-29 決定）。
> - **年與時點**：年取建立當下這一局的目前遊戲年，所以回溯後的目前遊戲年一定等於檢查點的年（CKPT-06）。時點由呼叫端傳入：年度匯入由 CE 匯入傳目前進度的時點，直接補匯另傳補匯的年與時點（需求規格 12.4）；手動建立由畫面決定是否帶時點（使用者 2026-09-29 決定）。
> - **建立**：先取現在時間作為建立時間，再以唯讀交易讀出整局（一致快照）；編碼在交易外進行，再以一個 rw 交易寫入兩張表並清除超過保留個數的檢查點，回傳新的檢查點與被清除的檢查點。時點不是 1～12 月、1～4 週，或補匯的年不是整數時丟出 `RangeError`；註記去除前後空白，空白時不存。建立檢查點不是資料變更，不改遊戲局的更新時間與應用版本（同「最近備份時間」）。檢查點的建立與年度匯入的交易分開，因為瀏覽器的非同步 API 不能放在 Dexie 交易內；匯入提交後、檢查點寫入前關閉頁面時，那次匯入沒有檢查點。
> - **保留**：這一局未釘選的檢查點依建立時間由新到舊，超過保留個數（`settings` 的 `checkpointLimit`，預設 12，要是 1 以上的整數）的連同內容刪除；釘選的不計入也不刪除。只在建立時清除：取消釘選或調低個數不會立即刪除，免得使用者剛取消釘選的檢查點當場消失（使用者 2026-09-29 決定）。
> - **管理**：列出一局的檢查點（只讀中繼資料，由新到舊）、釘選與取消釘選（不觸發清除）、事後修改註記（空白時移除），都不改遊戲局的更新時間；找不到遊戲局、檢查點，或檢查點屬於其他局時丟出錯誤。不提供手動刪除單一檢查點（使用者 2026-09-29 決定）。
> - **驗證與預覽**：以一個唯讀交易讀出遊戲局、檢查點、內容、目前整局資料與較晚的檢查點；交易外依「讀取與驗證」驗證內容，再核對檢查點的 `sha256` 等於檔案的 `sha256`、檔案的遊戲局識別等於這一局。不通過時回傳拒絕與原因，資料不變（CKPT-05）：備份的拒絕原因之外，另有內容不見與內容對不上。通過時回傳驗證過的檢查點（已遷移到目前的結構）與預覽（CKPT-04）：檢查點本身、目前遊戲年的變化、各表目前與檢查點的筆數、將捨棄的事件（目前有而檢查點沒有的事件，依寫入時間排序）、將移除的較晚檢查點（建立時間晚於這個檢查點，含釘選的），以及預覽當下遊戲局的更新時間。每個寫入操作都寫事件，所以將捨棄的事件就是將捨棄的操作；設定、代表色這類操作不寫事件，預覽列不出來：設定在回溯時沿用目前的值，代表色隨系位置回到檢查點（使用者 2026-09-29 決定）。找不到遊戲局、檢查點，或檢查點屬於其他局時丟出錯誤。
> - **回溯**：先以「匯出」匯出目前這一局，交給呼叫端傳入的交付函式（下載由 3-3 的輔助函式負責）；交付函式丟出錯誤時回溯停止，資料不變。接著在一個 rw 交易內（`GAME_TABLES` 與檢查點的兩張表）：遊戲局的更新時間要等於預覽時的值，否則阻止，因為預覽或備份之後有變更時，交付的備份不一定含有將捨棄的全部資料；目標檢查點要還在，否則丟出錯誤；以 `deleteGameData` 刪除整局，再以 `addGameData` 寫回檢查點的資料，識別不變；刪除較晚的檢查點與內容。回傳回溯後的遊戲局與被移除的檢查點（需求規格 12.4、CKPT-06、CKPT-07）。先驗證預覽再下載，是因為預覽本來就要解開檢查點，驗證失敗時也不會白下載一份；資料變動前一定已交出備份（使用者 2026-09-29 決定）。
>   - `games` 那一列：目前遊戲年取檢查點（CKPT-06）；局名、起始年、建立時間與還原來源沿用目前的列，它們描述的是這一局本身，不是遊戲進度；應用版本為目前版本；更新時間為回溯的時間，因為回溯本身就是資料變更；最近備份時間沿用目前的列，它只往後不往回，目前的列一定不早於檢查點的列（使用者 2026-09-29 決定）。
>   - 不記錄最近備份時間：交付的備份是回溯前的狀態，不含回溯後的資料；記錄下來時，匯出時間與回溯的更新時間是同一個時間，更新時間不晚於最近備份時間，備份提醒就不會請使用者備份回溯後的狀態。交付後被阻止時那次備份不記錄，最多多提醒一次。
>   - `settings` 沿用目前的列：定年、提醒年齡與保留個數是管理器的設定，新設定從下一次判斷開始生效（MARE-10），不是遊戲的歷程（使用者 2026-09-29 決定）。系統對照表、系位置（含代表色）與其他資料取檢查點。
>   - 回溯不寫事件：歷程整個回到檢查點，回溯前的完整狀態在交付的備份裡。

**技術設計 4.3「危險區」（全文）**

> #### 危險區
>
> - **筆數**：回傳一局 `GAME_TABLES` 各表的筆數與總筆數，供確認前顯示（需求規格 12.1「顯示筆數」）；檢查點的個數由畫面從檢查點清單另外顯示（使用者 2026-09-29 決定）。
> - **永久刪除此局**：輸入的局名去掉前後空白後要等於局名，否則阻止，什麼都不刪；名稱核對放在儲存層，畫面漏掉也刪不掉。在一個 rw 交易內從 `GAME_TABLES` 刪除這一局的資料列，連同這一局的檢查點與內容（需求規格 12.4，使用者 2026-09-29 決定）；`meta` 的目前遊戲局指向這一局時一併清除，由畫面請使用者重新選局。不寫事件，因為這一局已不存在。回傳刪除的各表筆數；找不到遊戲局時丟出錯誤。
> - **刪除全部存檔**：輸入的文字要是「刪除全部存檔」，否則阻止；第二道確認由畫面負責（需求規格 12.1，使用者 2026-09-29 決定）。在一個交易內清空資料庫的每一張表（含 `meta`），檢查點的兩張表也包含在內；3-3 的封存索引要不要保留由 3-3 決定。回傳刪除的遊戲局數與總筆數。

## 本計畫的詮釋

需求規格與技術設計沒有逐字寫出、由本計畫決定的地方。技術設計 4.3「檢查點與回溯」已經和使用者確認；下面是本計畫在程式層級的決定，審查時請逐條對照上一節的原文。

1. **資料表與設定**（Task 1）：`records.ts` 加上 `CheckpointOrigin`（`'auto' | 'manual'`）、`CatchUpImport`（`year`、`timing`）、`CheckpointRow` 與 `CheckpointContentRow`；時點沿用 `GameTiming`。選填欄位（`timing`、`catchUp`、`note`）沒有值時不存在；`pinned` 必填，建立時為 `false`。`SettingsRow.checkpointLimit` 必填，`DEFAULT_SETTINGS` 為 12，`updateSettings` 的欄位清單加上它，所以同樣要是 1 以上的整數；`inputs.test.ts` 的設定列補上這個欄位。正式發布前還沒有畫面，不會有少了這個欄位的既有設定列或備份，不另外相容；第一次發布後改欄位同樣要升版並寫遷移（技術設計 4.3）。`deleteGame` 在同一個交易內以 `gameId` 刪兩張檢查點表，不經 `checkpoints.ts`（見 Global Constraints 的模組邊界），回傳值仍是 `GAME_TABLES` 各表的筆數；名稱不符時什麼都不刪，檢查點也留著。`deleteAllGames` 不改：它清空 `db.tables` 的每一張，測試加一個檢查點確認也被清掉，但不算進回傳的總筆數。涵蓋測試把排除清單 `EXCLUDED_TABLES` 寫在測試檔，並把 `GAME_TABLES` 與它合起來和資料庫的表比對，兩邊有遺漏或重疊都會失敗。
2. **編碼共用與建立**（Task 2）：`encodeBackup(data, exportedAt)` 從 `exportBackup` 原樣抽出（組出內容、雜湊與壓縮），回傳位元組、檔案裡的 `sha256` 與是否壓縮；`exportBackup` 的輸出不變，測試比對兩者的位元組。`writes.ts` 的 `isGameTiming` 改為匯出，`createCheckpoint` 以它檢查時點與補匯的時點；技術設計寫的是 `RangeError`，所以這裡丟 `RangeError`（`runWrite` 對時點丟的是 `Error`，不改）。檢查在讀取之前，不合法時什麼都不讀、不寫。年取 `readGameData` 快照裡 `games` 那一列的目前遊戲年。寫入交易用 `loadSettings` 取保留個數，遊戲局在讀取與寫入之間被刪除時由它丟出錯誤。清除用 `listCheckpoints`（依建立時間由新到舊）篩掉釘選的，`slice(checkpointLimit)` 之後的連同內容刪除，回傳的被清除清單也是由新到舊；建立時間相同的極端情況不另外排序，測試一律用不同的時間。
3. **釘選與註記**（Task 3）：`setCheckpointPinned` 與目前相同時也照常寫入（結果相同，不另外判斷）。`updateCheckpointNote` 複製一份再 `put`，空白時 `delete` 掉 `note`，不留 `undefined`。`loadCheckpoint`（不匯出）先 `loadGame`，所以遊戲局不存在時丟的是「找不到遊戲局」；檢查點不存在或屬於其他局時丟「找不到這一局的檢查點：<識別>」。
4. **驗證與預覽**（Task 4）：`readCheckpoint` 的唯讀交易涵蓋 `GAME_TABLES` 與兩張檢查點表，讀取在同一個快照內。`readBackup` 用預設的遷移表與目前的結構版本；它的拒絕原因原樣回傳。`sha256` 比對的是遷移後的檔案：遷移函式以 `...from` 沿用其他欄位（3-1 的假遷移也是這樣），`sha256` 不變。通過時的結果是 `{ status: 'ok', verified }`，`verified` 只有 `data` 與 `preview`，檢查點本身在 `preview.checkpoint`。將捨棄的事件以識別比對，依寫入時間排序（相同時保留原本的順序）；較晚的檢查點是建立時間嚴格晚於這個檢查點的，由新到舊。回溯後的目前遊戲年取檢查點資料裡 `games` 那一列，與檢查點的年相同。
5. **回溯**（Task 5）：交付函式可以是同步或非同步，`await` 它的結果；它丟出的錯誤不包成拒絕原因，原樣往外傳（對儲存層是預期外的失敗，畫面顯示錯誤）。匯出的時間與回溯後的更新時間都是 `now`；因為不記錄最近備份時間，兩者相同不影響備份提醒。`games` 那一列寫成 `{ ...current, currentYear, appVersion, updatedAt }`：`GameRow` 只有局名、起始年、建立時間、最近備份時間與還原來源這些其他欄位，所以就是技術設計的「其他欄位沿用目前的列」，目前的列沒有的選填欄位也不會從檢查點帶進來。被移除的檢查點在交易內重新計算，預覽之後才建立的較晚檢查點也一併移除。目標檢查點在預覽之後不見時，備份已經交出，丟出錯誤，資料不變。完成時 `warnings` 一律是空的。
6. **驗收**（Task 6）：「年度匯入套用成功」以 `origin: 'auto'` 呼叫 `createCheckpoint` 代表，實際的呼叫由 CE 匯入計畫接上；「自動下載目前備份」以測試的交付函式代表，真正的下載由 3-3 提供。CKPT-01 的雜湊以 `sha256Hex` 獨立重算，不經受測的函式。CKPT-03 以預設的 12 個驗證，再調低到 10 個，確認下一次建立時才清除。

import { encodeBackup } from './backup'
import type { WPStudBookDatabase } from './database'
import { readGameData } from './game-data'
import { loadGame, loadSettings } from './games'
import type { CatchUpImport, CheckpointOrigin, CheckpointRow, GameTiming } from './records'
import { isGameTiming } from './writes'

// 檢查點與回溯（需求規格 11.1、12.4，技術設計 4.3「檢查點與回溯」）

export interface NewCheckpoint {
  /** 年度匯入後自動建立，或手動建立 */
  origin: CheckpointOrigin
  /** 遊戲內的時點：年度匯入後是目前進度的時點；手動建立時可以省略 */
  timing?: GameTiming
  /** 直接補匯時，補匯的年與時點（CKPT-08） */
  catchUp?: CatchUpImport
  /** 註記；去除前後空白，空白時不存 */
  note?: string
  /** 建立時間；省略時為現在 */
  now?: Date
}

/** 建立的檢查點，與因此被清除的檢查點 */
export interface CreatedCheckpoint {
  checkpoint: CheckpointRow
  removed: CheckpointRow[]
}

/**
 * 建立檢查點（需求規格 12.4、CKPT-01、CKPT-02、CKPT-08）：先取 now 作為建立時間，再以唯讀交易讀出整局（一致快照），
 * 在交易外編成備份檔，最後以一個 rw 交易寫入中繼資料與內容，並清除超過保留個數的檢查點。
 * 年是建立當下這一局的目前遊戲年。不改遊戲局的更新時間與應用版本：建立檢查點不是資料變更。
 * 時點不是 1～12 月、1～4 週，或補匯的年不是整數時丟出 RangeError，什麼都不寫；遊戲局不存在時丟出錯誤
 */
export async function createCheckpoint(
  db: WPStudBookDatabase,
  gameId: string,
  input: NewCheckpoint,
): Promise<CreatedCheckpoint> {
  const { origin, timing, catchUp } = input
  if (timing !== undefined && !isGameTiming(timing)) {
    throw new RangeError(`遊戲內的時點不符：${timing.month} 月 ${timing.week} 週`)
  }
  if (catchUp !== undefined && !(Number.isInteger(catchUp.year) && isGameTiming(catchUp.timing))) {
    const { year, timing: at } = catchUp
    throw new RangeError(`補匯的年與時點不符：${year} 年 ${at.month} 月 ${at.week} 週`)
  }
  const createdAt = (input.now ?? new Date()).toISOString()
  const data = await readGameData(db, gameId)
  const { bytes, sha256 } = await encodeBackup(data, createdAt)
  const note = input.note?.trim()
  const checkpoint: CheckpointRow = {
    id: crypto.randomUUID(),
    gameId,
    origin,
    year: data.games[0]!.currentYear,
    ...(timing === undefined ? {} : { timing }),
    ...(catchUp === undefined ? {} : { catchUp }),
    createdAt,
    sha256,
    ...(note ? { note } : {}),
    pinned: false,
  }
  const tables = [db.games, db.settings, db.checkpoints, db.checkpointContents]
  return db.transaction('rw', tables, async () => {
    const { checkpointLimit } = await loadSettings(db, gameId)
    await db.checkpoints.add(checkpoint)
    await db.checkpointContents.add({ checkpointId: checkpoint.id, gameId, bytes })
    const unpinned = (await listCheckpoints(db, gameId)).filter((row) => !row.pinned)
    const removed = unpinned.slice(checkpointLimit)
    await deleteCheckpoints(db, removed)
    return { checkpoint, removed }
  })
}

/** 一局的檢查點（只讀中繼資料），依建立時間由新到舊。遊戲局不存在時丟出錯誤 */
export async function listCheckpoints(
  db: WPStudBookDatabase,
  gameId: string,
): Promise<CheckpointRow[]> {
  return db.transaction('r', [db.games, db.checkpoints], async () => {
    await loadGame(db, gameId)
    const rows = await db.checkpoints.where('gameId').equals(gameId).toArray()
    return rows.sort((a, b) => b.createdAt.localeCompare(a.createdAt))
  })
}

/** 刪除檢查點的中繼資料與內容 */
async function deleteCheckpoints(
  db: WPStudBookDatabase,
  rows: readonly CheckpointRow[],
): Promise<void> {
  const ids = rows.map((row) => row.id)
  await db.checkpoints.bulkDelete(ids)
  await db.checkpointContents.bulkDelete(ids)
}

 * 讀取檢查點的拒絕原因（CKPT-05）：備份的拒絕原因（BackupRejection），另加
 * - content-missing：內容不見了
 * - content-mismatch：內容檔案的 sha256 或遊戲局識別與檢查點不符
 */
export type CheckpointRejection =
  BackupRejection | { kind: 'content-missing' } | { kind: 'content-mismatch' }

/** 回溯的預覽（CKPT-04） */
export interface RollbackPreview {
  checkpoint: CheckpointRow
  /** 目前遊戲年：目前的值與回溯後的值 */
  currentYear: { from: number; to: number }
  /** 各表的筆數：目前與檢查點 */
  counts: { current: RowCounts; checkpoint: RowCounts }
  /** 將捨棄的事件：目前有而檢查點沒有的，依寫入時間排序 */
  discardedEvents: EventRow[]
  /** 將移除的較晚檢查點（建立時間晚於這個檢查點，含釘選的），由新到舊 */
  removedCheckpoints: CheckpointRow[]
  /** 預覽當下遊戲局的更新時間；回溯時核對 */
  updatedAt: string
}

/** 驗證過的檢查點：data 已遷移到目前的結構 */
export interface VerifiedCheckpoint {
  data: GameData
  preview: RollbackPreview
}

export type CheckpointReadResult =
  | { status: 'ok'; verified: VerifiedCheckpoint }
  | { status: 'rejected'; reason: CheckpointRejection }

/**
 * 驗證檢查點並預覽回溯（需求規格 12.4、CKPT-04、CKPT-05）：以一個唯讀交易讀出遊戲局、檢查點、內容、
 * 目前整局資料與較晚的檢查點；交易外以 readBackup 驗證內容，再核對檔案的 sha256 與遊戲局識別。
 * 不通過時回傳拒絕原因，不丟例外，資料不變；通過時回傳遷移到目前結構的資料與預覽。
 * 找不到遊戲局、檢查點，或檢查點屬於其他局時丟出錯誤
 */
export async function readCheckpoint(
  db: WPStudBookDatabase,
  gameId: string,
  checkpointId: string,
): Promise<CheckpointReadResult> {
  const tables = [...gameTables(db), db.checkpoints, db.checkpointContents]
  const { checkpoint, content, current, later } = await db.transaction('r', tables, async () => {
    const checkpoint = await loadCheckpoint(db, gameId, checkpointId)
    return {
      checkpoint,
      content: await db.checkpointContents.get(checkpointId),
      current: await readGameData(db, gameId),
      later: await laterCheckpoints(db, checkpoint),
    }
  })
  if (!content) return { status: 'rejected', reason: { kind: 'content-missing' } }
  const read = await readBackup(content.bytes)
  if (read.status === 'rejected') return read
  const { file } = read.backup
  if (file.sha256 !== checkpoint.sha256 || file.game.id !== gameId) {
    return { status: 'rejected', reason: { kind: 'content-mismatch' } }
  }
  const data = file.collections
  const kept = new Set(data.events.map((event) => event.id))
  const discardedEvents = current.events
    .filter((event) => !kept.has(event.id))
    .sort((a, b) => a.recordedAt.localeCompare(b.recordedAt))
  const preview: RollbackPreview = {
    checkpoint,
    currentYear: { from: current.games[0]!.currentYear, to: data.games[0]!.currentYear },
    counts: { current: countRows(current), checkpoint: countRows(data) },
    discardedEvents,
    removedCheckpoints: later,
    updatedAt: current.games[0]!.updatedAt,
  }
  return { status: 'ok', verified: { data, preview } }
}

/** 這一局建立時間晚於這個檢查點的檢查點（含釘選的），由新到舊 */
async function laterCheckpoints(
  db: WPStudBookDatabase,
  checkpoint: CheckpointRow,
): Promise<CheckpointRow[]> {
  const rows = await listCheckpoints(db, checkpoint.gameId)
  return rows.filter((row) => row.createdAt > checkpoint.createdAt)
}

/** 回溯的阻止原因：預覽之後遊戲局有變更，交付的備份不一定含有將捨棄的全部資料 */
export interface RollbackBlock {
  kind: 'changed-since-preview'
}

export interface RollbackOptions {
  /** 交出目前這一局的備份（下載由 3-3 的輔助函式負責）；丟出錯誤時回溯停止，資料不變 */
  deliverBackup: (backup: ExportedBackup) => Promise<void> | void
  /** 回溯的時間：備份的匯出時間與回溯後的更新時間；省略時為現在 */
  now?: Date
}

/** 回溯的結果：回溯後的遊戲局與被移除的較晚檢查點 */
export interface RolledBack {
  game: GameRow
  removed: CheckpointRow[]
}

/**
 * 回溯到驗證過的檢查點（需求規格 12.4、CKPT-04、CKPT-06、CKPT-07）：先以 exportBackup 匯出目前這一局，
 * 交給 deliverBackup；它丟出錯誤時回溯停止，資料不變。接著在一個 rw 交易內：遊戲局的更新時間要等於預覽時的值，
 * 否則阻止，什麼都不寫；以 deleteGameData 刪除整局，再以 addGameData 寫回檢查點的資料（識別不變）；
 * 刪除較晚的檢查點與內容，含釘選的。games 那一列：目前遊戲年取檢查點，應用版本為目前版本，更新時間為 now，
 * 其他欄位（局名、起始年、建立時間、最近備份時間、還原來源）沿用目前的列；settings 沿用目前的列。
 * 不記錄最近備份時間：交付的備份是回溯前的狀態。不寫事件。找不到遊戲局，或檢查點已不在時丟出錯誤
 */
export async function rollbackToCheckpoint(
  db: WPStudBookDatabase,
  verified: VerifiedCheckpoint,
  options: RollbackOptions,
): Promise<WriteResult<RolledBack, RollbackBlock>> {
  const { data, preview } = verified
  const { checkpoint } = preview
  const { gameId } = checkpoint
  const now = options.now ?? new Date()
  await options.deliverBackup(await exportBackup(db, gameId, now))
  const tables = [...gameTables(db), db.checkpoints, db.checkpointContents]
  return db.transaction('rw', tables, async () => {
    const current = await loadGame(db, gameId)
    if (current.updatedAt !== preview.updatedAt) {
      return { status: 'blocked', blocks: [{ kind: 'changed-since-preview' }] }
    }
    await loadCheckpoint(db, gameId, checkpoint.id)
    const settings = await loadSettings(db, gameId)
    const game: GameRow = {
      ...current,
      currentYear: data.games[0]!.currentYear,
      appVersion: APP_VERSION,
      updatedAt: now.toISOString(),
    }
    await deleteGameData(db, gameId)
    await addGameData(db, { ...data, games: [game], settings: [settings] })
    const removed = await laterCheckpoints(db, checkpoint)
    await deleteCheckpoints(db, removed)
    return { status: 'done', value: { game, removed }, warnings: [] }
  })
}
