**需求規格 5 決策原則**

> - **使用者決定**：建立哪些系、選市場親馬、後繼去留、賣出母馬、何時補血或補系、是否刻意混血。

> | 會打亂自家循環的差錯 | 阻止保存，不能確認後繼續 | 指定配種或後繼的系、代數與規則不符 |
> - **歷史只新增或更正**：賣出、引退、接替、轉場、改名、種牡馬更換與資料更正都保存事件，不靜默改寫或刪除。

**需求規格 6.4 馬番号與馬名**

> - 幼駒、競走馬、繁殖牝馬、種牡馬各有馬番号。取得新階段馬番号時保存馬番号、階段、遊戲年與來源，舊值留在歷程；同一階段重複出現相同馬番号時不重複記錄。只有馬番号相同、能力番号不同的資料不得合併。

**需求規格 7.6、7.7 補系與種牡馬**

> - **補系結束**：補系產駒接上後繼時結束並解除暫停：補公系為產出的那一代有了種牡馬紀錄（指定預定後繼即可）；補母系為補系任務產出的那一代母馬群成立（2026-09-23 決定）。
> - **現任**：每系每代同時只有一匹在崗種牡馬；交接期間同系上下兩代可同時在崗。狀態為在崗、已被取代、退出生產行列、已引退；退出生產行列與已引退都由使用者標示；種牡馬總表不偵測離場（11.8）。
> - **預定後繼**：每系可指定一匹，就緒狀態為尚未誕生、競走中、已引退待指定、正式供用。尚未出生時可指定已受胎、產駒尚未出生的八系指定配種；產駒出生後不自動改指，由使用者確認，產駒為牝時提醒預定後繼失效。正式接任後，相關母馬下次配種改為指定配種並列為高優先待辦。同一系同時只有一匹預定後繼，要改指定時先取消原本的；產駒出生後確認時再核對一次（9.6），產駒為牝時不能確認，由使用者取消（2026-09-28 決定）。
> - **來源**：自家種牡馬由使用者從既有馬匹選取接任，沿用能力番号、出生年與內部識別，可輸入種牡馬馬番号。市場種牡馬手動建立或由目標種牡馬 TXT 匯入（11.9）。
> - **更換現任**：由使用者執行，保存前任、後任、生效年與原因（弟弟較優、前任引退、無法供用、斷血補系、遊戲依史實引退、其他）；前任的配種、產駒與血緣保持原連結。同父弟弟可取代哥哥，不要求同母（不適用母馬姊妹規則）。該代第一次有種牡馬接任時不需原因；那一代已有接任過的種牡馬（在崗、已被取代、退出生產行列或已引退）時才是更換，要填原因（2026-09-28 決定）。
> - **兄弟比較**：同系同代有兩匹以上同父兄弟成為種牡馬時，並排比較 `SP`、`ST`、七項副能力、`サ`、適性、距離適性、年齡與狀態，由使用者決定現任，系統不判定優劣。此流程只接受同父兄弟，選入不同系或不同代一律阻止；被取代者標示已被取代。保留原現任時不寫任何紀錄，落選的一方不標示已被取代；他原本是預定後繼時，由使用者另外取消（2026-09-28 決定）。

**需求規格 8 繁殖牝馬**

> 繁殖圈是據點 `32`～`35` 在養的母馬。「來源」與「目前狀態」分開保存並可同時顯示：來源為結構化事件（市場創系、市場補血、市場混血、市場補系、所屬競走馬引退轉入、其他，可附備註）；狀態為生產中或已離圈（售出、定年引退）。
> - 某代第一匹自家母駒以暫定保留或正式保留轉入時，該代立即成立；成立後不可回溯，母馬離圈只改目前狀態。
> - 姊妹互相取代仍屬同一代。同系可同時有多代生產中母馬，逐匹交接。
> - 分開保存自身父系所屬與所屬母馬群。產駒的系只看父馬。自家母駒的自身父系由父馬固定，不得改宣告。
> - 自家母駒（非自由配種所生）引退轉為繁殖牝馬時，除了五月匯入（11.5），也可以從產駒手動轉入：系統依出生紀錄帶入系與代數，並依 8.9 判定接替狀態，規則與五月匯入相同。
> - 同父同母的多匹母駒可先後轉入成為候選，第二匹不得阻止；判定需父母都相同。
> - 狀態：暫定保留、候選、正式保留、已被取代、已售出。自家母駒轉入時，姊妹不在圈內 → 暫定保留；已有姊妹在圈 → 候選。
> - 暫定保留、候選、正式保留都可列入任務；已被取代、已售出不列入。
> - 系統並排比較姊妹的出生年、父母、能力與狀態，由使用者決定；決定後同一父母組合只有一匹正式保留，被取代者保留紀錄。

**需求規格 9 配種與產駒**

> - **登記與更正**：手動登記只限當年。產駒出生前可以更正當年的配種類型與種牡馬，更正時重做 10.2、10.3 的檢查；受胎狀態不限年份，可以補登或更正，也可以清回尚無結果。已有產駒連到這筆紀錄時，不能更正配種類型與種牡馬，受胎狀態也不能改成 `受胎` 以外（2026-09-27 決定）。被尚未出生的預定後繼指定的受胎配種（7.7）同樣不能更正配種類型與種牡馬，受胎狀態也不能改成 `受胎` 以外；要改時先取消預定後繼（2026-09-28 決定）。
> - 手動建立時，母馬前一年有 `受胎` 紀錄就連結該紀錄，父馬取自紀錄；沒有 `受胎` 紀錄（例如購入時已受胎，或狀態還沒改成 `受胎`）時警告並確認，確認後比照自由配種產駒，與 11.4 的待核對相同（2026-09-27 決定）。產駒建立後才把母馬前一年的紀錄改成 `受胎` 時，可以重新連結出生紀錄：父馬取自紀錄，產駒已記的父馬不同時阻止；連到八系指定配種時取得系與代數，原本待售的牧場處置改為保留（2026-09-28 決定）。
> - 牧場處置：八系指定配種所生預設保留；自由配種所生（含比照自由配種者）一律待售，只能是待售或已售出（9.5）（2026-09-27 決定）。
> 一律待售、不可成為八系後繼、不取得八系的系，不因性別、能力或母馬所屬群改變；父母、出生年與名稱照常保存，售出後仍可從母馬紀錄查到。
> - 母駒引退並出現在五月繁殖圈名單（11.5），或由使用者從產駒手動轉入（8.4）時，由系統依出生紀錄判定系與代數並加入母馬群，姊妹取捨依 8.9。公駒須由使用者指定才成為現任或預定後繼。
> - 進入母馬群或接任前再次核對父母、系與代數，不符時阻止。

**需求規格 11.5 五月繁殖圈名單**

**技術設計 4.2 姊妹、種牡馬與正式後繼**

> - **姊妹接替**（`sisters.ts`）：同父同母以父母的內部識別判斷，任一方不明就不算姊妹。「在圈」指在繁殖圈內，被取代但還沒賣出的姊妹也算。選定正式保留時，只把在圈而且列入任務的姊妹改為已被取代。輸入有在圈但狀態是已售出的母馬時丟 `RangeError`。儲存層不把接替狀態改成已售出：自家母駒售出或定年引退時保留離圈前的接替狀態，已售出由在圈狀態表示，畫面在售出時顯示已售出；姊妹判斷只看在圈的母馬，結果不變。撤銷誤登記的離圈時就能回到原本的接替狀態（需求規格 8.5）（使用者 2026-09-26 決定）。
> - **種牡馬**（`stallions.ts`）：兄弟比較以比較對象（通常是現任）為準，選入的要同系、同代、同父，任一方的父馬不明就不算同父。選定現任只把同系同代原本在崗的一匹改為已被取代；前任、後任、生效年與原因由儲存層保存。市場種牡馬替換零代種牡馬，或補公系補入零代市場種牡馬（需求規格 7.6）時，比較他本身的父系與該系目前的子系統，父系不明時不警告；他的子系統沒登錄在對照表、查不到親系統時，仍回報親系統不同，讓畫面提示補登。現任的提醒年齡由設定帶入，預設 26 歲。`StallionStatus` 的 `retired` 是種牡馬已引退；預定後繼的「已引退待指定」（競走馬已引退、還沒接任）對應 `status` 留空，不是 `retired`，否則 `chooseIncumbent` 會拒絕接任。
> - **正式後繼**（`successor.ts`）：用出生紀錄連結的配種紀錄的規則快照（實際種牡馬的系與代數、母馬當時的身分）核對，不用母馬目前的用途，因為用途修改從下一次配種才生效（需求規格 8.4）。除了父母與重算的系與代數，也以 10.3 確認這次配種是出生紀錄那一代的指定配對，所以偏離規則配到別系種牡馬的產駒會被阻止（5.2；10.3「刻意偏離請登記為自由配種」，使用者 2026-09-23 確認）。沒有配種紀錄、或配到八系以外種牡馬的產駒比照自由配種。`verifySuccessor` 的第二個參數是要進入的母馬群，或要接任、指定為預定後繼的系與代數，與出生紀錄不符時阻止。補公系所生的產駒，配種紀錄的規則快照要記 `restoration`，以補公系配對核對（需求規格 7.6）；補母系所生的產駒是一般指定配對，照常核對。

**技術設計 4.3 資料表與彙整**

> | `mares` | 進過自家繁殖圈的母馬 | 用途（自家、替代第 q 系 N 代、第 1 系起點用、待指定用途、自由配種所生）、在圈狀態（生產中、售出、定年引退）、接替狀態（離圈時保留離圈前的值，4.2）、是否使該代成立、來源（8.1）、據點、例外補入原因（7.3） |

> | `horseNumbers` | 一匹馬在一個生命階段取得的馬番号（需求規格 6.4） | 馬匹、階段（幼駒、競走馬、繁殖牝馬、種牡馬）、馬番号（寫法同能力番号）、取得時的目前遊戲年、來源與時點 |
> `horseNumbers` 以 `[gameId+horseId]` 建索引。一列是一次取得；同一匹馬同一階段已有相同馬番号時不再新增（需求規格 6.4、MAY-06）。這張表本身就是階段馬番号的歷程，不另寫事件。馬番号以 `normalizeAbilityNumber` 統一寫法（`0x` 加 4 位大寫），格式不符時阻止。儲存子計畫 2-4 只在自家種牡馬接任時寫入種牡馬階段，其他階段由 CE 匯入寫入（使用者 2026-09-28 確認）。
> 預定後繼沿用 `stallions` 的任用列：狀態留空；尚未誕生時存受胎的配種紀錄 `breedingId`，確認出生後改存 `horseId` 並拿掉 `breedingId`；就緒存在 `readiness`。取消預定後繼時刪除那一列，歷程留在事件：狀態留空的列代表目前的指定，保留已取消的列要多一種狀態，快照與「每系一匹」都得跳過它（使用者 2026-09-28 決定）。
> - **自家母駒與出生紀錄的一致性**：在圈的自家母駒，母馬群的系與代數要等於出生紀錄的系與代數；在圈的自由配種所生要有出生紀錄，而且沒有系與代數。不符時丟 `RangeError`（資料列互相矛盾）。只查在圈的，與列入任務需要馬匹資料的範圍相同（使用者 2026-09-28 確認）。
> - **種牡馬紀錄**（`StallionRecord`）：某系某代的任用。兄弟比較選入的馬也要組出：格位取他在那一格的任用，沒有任用時取出生紀錄的系與代數；狀態取任用的，沒有任用時留空（需求規格 7.7、LINE-31）。
> - **正式後繼**（`SuccessorCandidate`）：產駒的父母，加上出生紀錄連結的配種紀錄的規則快照；沒有配種紀錄、自由配種、沒有規則快照，或出生紀錄沒有系與代數（例如偏離規則、配到八系以外的種牡馬，4.2）時，比照自由配種（使用者 2026-09-24 確認）。

**技術設計 4.3「寫入操作」（全文）**

> #### 寫入操作
>
> 使用者的操作與之後 CE 匯入的套用，都經由儲存層的寫入操作（使用者 2026-09-26 確認）。共用的做法：
>
> - **一個操作一個交易**：每個操作在一個 rw 交易內完成：先讀遊戲局確認存在，再從資料列重新組出核心的輸入並重做檢查，最後寫入資料列與事件，並把遊戲局的更新時間設為現在。設定、代表色這類不寫事件的操作也更新，備份提醒（需求規格 12.2）以此判斷有沒有未備份的變更。操作可以包進呼叫端的外層交易（Dexie 的巢狀交易），CE 匯入以此在單一交易內套用多個操作（4.4）。
> - **結果**：完成時附寫入的結果與確認過的警告；阻止時附原因；有警告而呼叫端沒有帶確認時回傳待確認並附警告。阻止與待確認都什麼都不寫。畫面先呼叫一次取得警告，使用者確認後帶確認再呼叫；儲存層在交易內重做檢查，畫面漏掉檢查也存不進違規資料（需求規格 5.2）。確認過的警告存在這次操作的事件上。
> - **錯誤**：使用者的輸入或操作違反規則時回傳阻止；畫面不會送出的狀況（找不到資料列、屬於其他局、對已撤銷的宣告再撤銷）丟出帶識別的錯誤；資料列內容互相矛盾時丟 `RangeError`。
> - **事件**：會留下年份的操作一律寫事件，事件的年份是操作當時的目前遊戲年；遊戲年變更本身不寫事件。對象欄位填事件關於的馬匹、系位置或子系統，例如種牡馬狀態變更同時填系位置與馬匹；母馬的事件只填馬匹，因為替代母馬不屬於她替代的系（需求規格 8.3）。事件另記來源與時點（見「資料表」）。
> - **手動建立的馬**：完整馬名必填，只有前綴時阻止（需求規格 6.4）；馬名來源為手動輸入。能力番号與出生年選填：能力番号格式不符時阻止；出生年晚於目前遊戲年時阻止；能力番号與出生年都和這一局既有的馬相同時阻止並指出那匹馬（6.2：同一匹馬，應選既有的）。父母名與父系選填：父母名去掉前綴後存基本馬名，只有前綴時阻止；有填時，父母名與父系的來源為手動輸入（6.4：只輔助身分配對，匯入時改用匯入值，經匯入確認前可以更正）。
> - **系統名稱**：子系統、親系統、分出來源與父系都經 `normalizeSystemName`，必填的欄位空白時阻止。
> - **親系統重複的警告**：修改對照表、開啟新系、變更系統名稱或補入、替換零代種牡馬後，親系統因此改變的已開啟的系，與其他系目前的親系統相同時警告並確認（需求規格 7.2、LINE-03）。
>
> 各操作的規則：
>
> - **目前遊戲年**（需求規格 12.1）：往後可以改成任何年份；往回不能早於起始年，也不能早於最後紀錄年，也就是這一局事件的最大年份與馬的最大出生年，阻止時附可以改的最早年份。
> - **設定**：定年、高齡提醒年齡、種牡馬提醒年齡都要是 1 以上的整數；不寫事件，新設定從下一次判斷開始生效（MARE-10）。
> - **系統對照表**（需求規格 7.2）：新增時子系統不能已登錄，分出來源不能是自己；修改親系統（升格）或分出來源時（分出來源省略表示不變，傳 `null` 才清除），事件記原值、新值與年份。不提供刪除，也不改子系統名稱：打錯時新增正確的一筆，沒有系在用的那一筆不影響任何判斷。
> - **開啟新系**（需求規格 7.1、7.3）：該系要在任務看板的可開啟分支中（4.2；補公系進行中的系不能開分支）。填子系統、親系統、代表色（`#rrggbb`，自動分配由畫面預填）與零代市場種牡馬：新建，或選既有的市場馬（沒有出生紀錄、不是牝馬），因為補公系可以沿用建系時的零代種牡馬，兩處共用同一種輸入。子系統沒登錄時新增一筆，已登錄但親系統不同時改為填入的親系統。寫入系位置（開啟年為目前遊戲年）、零代的在崗任用與開啟事件。開啟後不提供撤銷（7.1 位置固定），開錯時以系統名稱變更與零代種牡馬替換更正。
> - **系統名稱變更**（需求規格 7.1、7.2、LINE-06）：系要已開啟，新名稱要與目前不同；可一併填親系統，照對照表的規則新增或修改，沒填而對照表查不到時親系統未知。事件記原名稱、新名稱與年份；「該系用過的舊名」（7.2）由開啟與名稱變更的事件查得。
> - **代表色**：只檢查格式，不寫事件。
> - **補入或替換零代市場種牡馬**（需求規格 7.6、7.7）：對象是某系建系的零代，或某次未撤銷的補公系宣告。那一格已有在崗或已指定的種牡馬時阻止（先標示前任引退，再替換）；選的馬已在這一格任用過時阻止。格是空的（補公系第一次選定）不需原因；只剩已離場的是替換，附 7.7 的原因（弟弟較優、前任引退、無法供用、斷血補系、遊戲依史實引退、其他，可附說明），生效年為目前遊戲年。以 `checkMarketStallionSystem` 比對他的父系，子系統不同時警告並確認，確認後該系的子系統改為他的父系並寫名稱變更事件，事件也記上這匹種牡馬；父系不明時不比較。
> - **種牡馬狀態**（需求規格 7.7）：在崗或已被取代的種牡馬可以標示退出生產行列或已引退；更正回在崗只在同一格沒有其他在崗時可以，否則阻止（換人用更換現任）。原本已被取代、誤標為退出或引退的，可以更正回已被取代，只在同一格另有在崗時可以（使用者 2026-09-26 決定）；其他情況的已被取代只由更換現任設定，預定後繼的取消也不在這裡。同一匹馬同時有建系與補公系的零代任用時，引退逐任用標示（使用者 2026-09-26 決定），要不要一次標示全部由畫面決定。這些操作都維持每格（某系某代的一般任用，或同一次補公系的任用）最多一匹在崗；彙整八系快照時遇到同一格有兩匹以上在崗，丟 `RangeError`。
> - **斷血補系**（需求規格 7.6）：宣告時原因必填，在交易內組出八系快照以 `checkRestoration` 檢查，年度為目前遊戲年；補入的零代市場種牡馬另外選定。撤銷時設為已撤銷並寫事件，不因已有補系的配種或產駒而阻止：配種紀錄的規則快照自帶補公系標記，補入的任用留著，快照略過已撤銷宣告底下的任用；撤銷後可以重新宣告。
> - **母馬的用途**（需求規格 7.3、8.3、8.4）：新增市場母馬、修改用途與從任務買回時，畫面傳任務看板上的一條配對（產出的系與代數）或待指定用途，不直接傳替代的系與代數。交易內組出八系快照，以 `listBoard` 從任務（含暫停中的）與可開啟分支的配對中找產出相同的那一條，找不到時阻止；一個產出只有一條配對，已宣告補公系時就是補公系配對。由配對推出：母馬群是起點時為第 1 系起點用，否則為替代配對母馬群的系與代數；種牡馬是零代而且不是建系起點（建立新系、補公系）時為例外補入，警告並確認、原因必填，其他情況不保存原因。替代母馬以 `checkSubstituteMare` 檢查親系統（8.3），同一代的其他替代母馬包含已離圈的、不含她自己；撞到時警告並確認，自身父系未知時只在完成的結果帶提示。
> - **新增市場母馬**（需求規格 8.4、MARE-05、MARE-29、MARE-31）：馬匹照手動建立的馬，性別為牝；在圈，不使該代成立；據點選填，事件一併記下初次據點。來源由配對推出：補公系配對，或配對的母馬群已宣告補母系（未撤銷）時為市場補系；否則建系起點、推進原系與建立新系為市場創系，循環為市場補血；待指定用途由使用者選市場混血或其他；都可附備註。已售出的母馬中，基本馬名相同、能力番号與出生年也不矛盾（兩邊都有值而且不同才算矛盾）時，警告可能是買回並列出那些母馬：使用者確認不是買回就照常建立；是買回時畫面改用買回操作，不建立新馬。
> - **修改用途**（需求規格 8.4、MARE-28）：只限在圈的市場母馬（替代、起點用、待指定用途）；自家母駒與自由配種所生的系與代數由出生紀錄決定，不提供。與目前相同時阻止。來源記的是購入時的目的（8.1），不隨用途改變。已有的配種紀錄保留自己的規則快照，新用途從下一次配種生效，不另外處理。
> - **賣出**（需求規格 8.5、MARE-08）：只限在圈的母馬；已達定年時阻止（4.6「無法再生產的母馬不能賣出」），出生年不明時可以賣出。這條只適用於手動賣出；五月缺席的判定由 CE 匯入計畫接上，缺席時的馬齡可能已達定年。
> - **更正離圈原因**（需求規格 8.5、11.5、MARE-32）：已離圈的母馬可以改為售出、定年引退，或撤銷回到生產中；與目前相同時阻止。撤銷不建立回歸事件；自家母駒回到保留的接替狀態（4.2），原本是正式保留而圈內已有另一匹正式保留的姊妹時改為候選。
> - **買回與回歸**（需求規格 8.5、8.9、ID-04、MARE-30、CAND-07）：只限已離圈的母馬。自家母駒沿用出生紀錄的系與代數，接替狀態以 `entrySisterStatus` 重新判定，成為暫定保留時 `establishedGeneration` 設為 true（不改回）；自由配種所生只恢復生產中。市場母馬沒有傳用途時沿用原用途，不重做 8.3 檢查；從任務買回時傳配對，照「母馬的用途」處理，事件記原用途與新用途。自家母駒與自由配種所生不接受用途。可以一併填據點。
> - **轉場**（需求規格 8.6、MARE-19）：只限在圈的母馬，與目前相同時阻止；事件記原據點（原本不知道時留空）與新據點，年份、時點與來源在事件的共用欄位。
> - **今年計畫**（需求規格 8.7、MARE-22）：只限在圈的母馬，年份為目前遊戲年；沒有值視為待定，與目前相同時阻止。不限用途。
> - **活力更正**（需求規格 8.7、MARE-13、MARE-14）：指定年份與五月或七月的快照，數值是 0～100 的整數，是否増強另外指定（`100` 也可以不増強）；年份不能晚於目前遊戲年。快照原本沒有值時也可以填入，不提供清除。與目前相同時阻止。
> - **手動資料更正**（需求規格 6.4、ID-08、ID-13）：只限沒有出生紀錄、馬名還是手動輸入的市場馬（市場母馬與零代市場種牡馬），經匯入確認的唯讀。可以更正完整馬名、能力番号、出生年、父母名與自身父系：省略表示不變，`null` 表示清除，完整馬名不能清除；檢查同手動建立的馬，同一匹馬的比對排除自己；什麼都沒改時阻止。替代母馬的自身父系改了時重做 8.3 檢查。零代市場種牡馬改了父系時不重做 7.7 的比對：那只在補入或替換當下比對，要改系的名稱用系統名稱變更。

> - **牧場處置**（需求規格 9.3、9.5、BRD-15、BRD-26）：只限自家產駒；出生紀錄沒有系與代數的產駒不能改為保留；與目前相同時阻止。
> - **總合評價與爆發力**（需求規格 9.2、BRD-17、BRD-18）：記在目前遊戲年；母馬要是這一局的母馬，不限在圈；種牡馬是內部馬匹或外部名稱（去掉前綴存基本馬名），同一匹種牡馬以內部識別與外部名稱登記時算不同的組合。評價與爆發力至少填一項，爆發力要是 0 以上的整數（使用者 2026-09-27 決定）。同一組同一年已有時整組取代，與目前相同時阻止；跨年另起一列，舊值保留。
> - **重新連結出生紀錄**（需求規格 9.3、BRD-27）：只限沒有連結配種紀錄的自家產駒（有出生紀錄、沒有 `breedingId`），其他的丟出錯誤。母馬「出生年減 1」那一年的配種紀錄要是 `受胎`，否則阻止並附那一筆與它的狀態；產駒已記的父馬與紀錄不同時阻止。母馬不必在圈。連結後出生紀錄記配種紀錄，八系指定配種所生另記規則快照的預計產出；產駒沒有父馬時補上紀錄的父馬。連到八系指定配種、原本待售時，牧場處置改為保留，比照建立產駒的預設（原本待售是沒有連結時強制的）；已售出不變，連到自由配種也不變。事件記配種紀錄與牧場處置的變化（使用者 2026-09-28 決定）。
> - **自家母駒轉入**（需求規格 8.4、8.9、9.6、11.5、LINE-17、MARE-07）：只限這一局還沒進過繁殖圈（`mares` 沒有這一列）的自家牝駒，其他的丟出錯誤；已在 `mares` 的用「買回與回歸」。以 `buildSuccessorCandidate` 組出核對輸入：八系指定配種所生以 `verifySuccessor` 核對（目標是出生紀錄的系與代數），不符時阻止；通過時用途為自家，母馬群依出生紀錄，接替狀態以 `entrySisterStatus` 判定，暫定保留時 `establishedGeneration` 設為 true。自由配種所生或比照自由配種（核對輸入為 free）：生產中，用途為自由配種所生，不分群、沒有接替狀態。需求規格 8.4 的手動轉入只提非自由配種所生，但五月匯入（11.5）用同一個操作，所以儲存層兩種都接受；畫面是否對自由配種所生提供手動轉入由畫面計畫決定。來源為所屬競走馬引退轉入，可附備註；據點選填。不設年齡門檻，不改牧場處置。事件記用途與母馬群、接替狀態與據點（使用者 2026-09-28 確認）。
> - **選定正式保留**（需求規格 8.9、MARE-12、MARE-24）：只限在圈的自家母駒，其他的丟出錯誤。以 `chooseKeptSister` 套用：她改為正式保留，同父同母、在圈而且列入任務的姊妹改為已被取代；沒有姊妹時也可以選（暫定保留改為正式保留）；沒有任何變化時阻止。選為正式保留時 `establishedGeneration` 設為 true，不改回（8.2：正式保留會使該代成立）。狀態有變的每匹母馬各寫一筆事件，記原狀態、新狀態與選定的母馬。之後改保留另一匹，對她再做一次（使用者 2026-09-28 確認）。
> - **預定後繼的指定**（需求規格 7.6、7.7、9.6、LINE-40～42）：對象是已出生的自家公駒，或已受胎、產駒還沒出生的八系指定配種；其他對象（牝駒、市場馬、不是 `受胎` 或不是指定配種的紀錄）丟出錯誤。系與代數不由畫面選：公駒取出生紀錄，配種取規則快照的預計產出；以 `verifySuccessor` 核對，不符時阻止（未出生時以配種紀錄的父母與規則快照組出核對輸入）。同一系已有預定後繼時阻止並指出那一筆，改指定要先取消；公駒在那一格已有任用時阻止；配種已有產駒出生時阻止，改為指定那匹產駒。就緒預設競走中，也可以直接指定為已引退待指定。指定後那一格就有種牡馬紀錄：以他為種牡馬的任務依任務看板的規則出現，暫停到他接任；那一代是補公系產出的那一代時，補公系也在此時結束（需求規格 7.6「指定預定後繼即可」）（使用者 2026-09-28 決定）。
> - **預定後繼的確認出生、就緒與取消**（需求規格 7.7、LINE-42）：確認出生只限尚未出生的預定後繼：連到那筆配種的產駒還沒有時阻止，產駒是牝時阻止（預定後繼失效，由使用者取消）；公駒以 `verifySuccessor` 再核對，通過後改存馬匹、拿掉配種紀錄，就緒為競走中。就緒在競走中與已引退待指定之間切換，只限已出生的預定後繼，和目前相同時阻止。取消只限預定後繼（狀態留空），刪除那一列並寫事件；已接任的改用「種牡馬狀態」（使用者 2026-09-28 決定）。
> - **正式接任與更換現任**（需求規格 7.7、9.6、PED-08、LINE-22、LINE-30、STL-03）：對象是自家公駒，格位取出生紀錄的系與代數，不由畫面選；不是自家公駒時丟出錯誤。以 `verifySuccessor` 核對，不符時阻止。他在那一格是預定後繼或已被取代時沿用那一列；已退出生產行列或已引退時阻止（先用「種牡馬狀態」更正）；已在崗時阻止；沒有任用時新增一列。那一格另有接任過的任用（在崗、已被取代、退出生產行列、已引退）時是更換現任，要附 7.7 的原因；第一次接任不需原因；同一格其他還沒接任的預定後繼不算。以 `chooseIncumbent` 套用：他改為在崗並拿掉就緒，同一格原本在崗的改為已被取代；上一代的現任（交接期間可同時在崗）與這一系其他的預定後繼不動，前任的配種、產駒與血緣保持原連結。生效年為目前遊戲年。種牡馬馬番号選填，寫法不符時阻止，有填時記一筆種牡馬階段。事件記格位、原因與被取代的馬。兄弟比較只提供讀取（見「規則輸入快照的彙整」的種牡馬紀錄），由畫面以 `checkBrothers` 檢查；接任不另外檢查同父，因為其他原因的更換本來就不要求同父。保留原現任時不寫任何紀錄（使用者 2026-09-28 決定）。

## 本計畫的詮釋

需求規格與技術設計沒有逐字寫出、由本計畫決定的地方。技術設計 4.3「寫入操作」已經和使用者確認；下面是本計畫在程式層級的決定，審查時請逐條對照上一節的原文。

1. **PR #10 延後的兩項 Minor**（Task 1，使用者選的兩項）：`FoalExistsBlock` 從 `breeding-writes.ts` 移到 `writes.ts`，`foal-writes.ts` 原本私有的 `loadFoal` 也移到 `writes.ts` 對外匯出，錯誤訊息不變。「讀母馬並檢查在圈」抽成 `writes.ts` 的 `loadMareInHerd(context, horseId, reason)`，訊息是「不在繁殖圈內的母馬」接上 `reason`，所以原本的訊息一字不變；換掉的是 `sellMare`、`moveMare`、`setMarePlan` 與配種的登記、更正（原本的 `mareInHerd` 刪掉）。`mare-writes.ts` 的 `marketMareInHerd` 從規則資料列讀、另外檢查用途，不在這次的範圍。行為不變。
2. **階段馬番号與型別**（Task 2）：`HorseStage` 是 `foal`、`racehorse`、`broodmare`、`stallion`。`recordHorseNumber` 在同一匹馬同一階段已有相同馬番号的任何一列時不再新增（不只看最新一列），回傳 `undefined`；傳入的馬番号要是 `normalizeAbilityNumber` 統一過的寫法，不是時丟出 `RangeError`（呼叫端先統一寫法，格式不符由呼叫端阻止）。`WriteContext` 多帶這次操作的 `source` 與 `timing`（沒有時點時沒有這個欄位），讓事件以外的紀錄（階段馬番号、重新連結補上的父母名來源）用同一個來源。本計畫所有的事件種類先在這個任務定義。
3. **一致性檢查**（Task 3）：放在 `buildEightLineSnapshot`，彙整前逐匹檢查；只查在圈的自家母駒與自由配種所生，在圈的自由配種所生因此也要有馬匹資料。訊息是「母馬的用途與出生紀錄的系與代數不一致」。既有測試的自家母駒原本沒有出生紀錄，改用 `rows.ts` 新增的 `ownFoalRow` 產生帶出生紀錄的馬匹；`snapshot.test.ts` 的 `horsesOf` 依母馬的用途補上出生紀錄。
4. **9.6 的共用核對**（Task 4，`checkOwnSuccessor`）：放在 `writes.ts`，轉入、指定、確認出生與接任共用。自由配種所生（核對輸入為 `free`）直接回傳 `free-breeding`，不呼叫 core：core 對它只回傳這一項、不看目標，這時也沒有出生紀錄的系與代數可以當目標。目標省略時就是出生紀錄本身。
5. **自家母駒轉入**（Task 4）：核對輸入用 2-1 的 `loadSuccessorCandidate`（在寫入交易內成為子交易）。姊妹用 `loadSisters`，她自己還沒有母馬列，所以不會算到自己。據點在交易開始前檢查（同 `returnMare`）。事件的 `placement` 用 `placementOf`；自由配種所生沒有 `sisterStatus`，沒有據點時沒有 `location`。
6. **選定正式保留**（Task 5）：不另外檢查在圈：不在圈時 core 的 `chooseKeptSister` 丟出 `RangeError`，訊息與前置檢查一樣（突變檢查確認前置檢查是多餘的，所以刪掉）。傳給 core 的是她自己（`buildOwnMares`）加上 `loadSisters` 的結果：父母任一方不明時 `loadSisters` 讀不到她，所以另外放；讀到兩次不影響結果。狀態有變的每一匹都重新讀母馬列再寫。回傳的順序照 core 的變更順序，選定的在前。
7. **重新連結**（Task 6）：`foal-writes.ts` 的 `linkedSire` 改成 `sireOf`（沒有父馬時回傳 `undefined`），建立產駒與重新連結共用。前一年沒有受胎紀錄時只回傳 `no-conception-record`；`sire-mismatch` 與 `mare-entered` 一起列出。`mare-entered`：牝駒已轉入繁殖圈（`mares` 有這一列，不論在圈與否）而要連到八系指定配種時阻止，因為她的用途是自由配種所生，連上後出生紀錄有了系與代數，會違反 Task 3 的一致性檢查；連到自由配種不影響用途，可以。補上外部父馬名、原本沒有父母名的來源時，來源依 `context.source`（同 `addFoal`）。規則快照的預計產出只在八系指定配種時取用，寫法同 `addFoal`。
8. **指定與取消預定後繼**（Task 7）：9.6 核對不符時只回傳核對的阻止（自由配種所生沒有格位，無法再查同一系）。「每系一匹」查這一局同一系所有代數的任用中狀態留空的一列；「已接任」查同一匹馬狀態不是留空的任用（尚未出生時沒有馬匹，只對得到尚未出生的預定後繼，不算）。尚未出生時用 `buildSuccessorCandidate` 以配種紀錄組出一匹暫時的產駒列來核對。`loadBreeding`、`linkedFoal` 從 `breeding-writes.ts` 改成對外匯出。就緒的值在交易開始前檢查。

10. **被預定後繼引用的配種**（Task 9）：查這一局任用列中 `breedingId` 等於這筆配種的一列（確認出生後任用改存馬匹，就不再引用）；任用表沒有 `breedingId` 索引，以 `gameId` 讀出後篩選。阻止排在 `foal-exists` 之後、內容檢查之前。受胎狀態的交易加上 `stallions`。

```ts
import { normalizeAbilityNumber } from '../core/identity'
import type { HorseNumberRow, HorseStage } from './records'
import type { WriteContext } from './writes'

// 階段馬番号（需求規格 6.4；技術設計 4.3「資料表」）

/**
 * 記一筆階段馬番号（需求規格 6.4）：年份為目前遊戲年，來源與時點取自這次操作。
 * 同一匹馬同一階段已有相同馬番号時不再記，回傳 undefined（MAY-06）。
 * number 要是已統一寫法的馬番号（normalizeAbilityNumber 的結果），不是時丟出 RangeError。
 * 在 runWrite 的交易內呼叫，交易要包含 horseNumbers
 */
export async function recordHorseNumber(
  context: WriteContext,
  horseId: string,
  stage: HorseStage,
  number: string,
): Promise<HorseNumberRow | undefined> {
  if (normalizeAbilityNumber(number) !== number) {
    throw new RangeError(`馬番号沒有統一寫法：${number}`)
  }
  const { db, game } = context
  const existing = await db.horseNumbers
    .where('[gameId+horseId]')
    .equals([game.id, horseId])
    .filter((row) => row.stage === stage && row.number === number)
    .first()
  if (existing) return undefined
  const row: HorseNumberRow = {
    id: crypto.randomUUID(),
    gameId: game.id,
    horseId,
    stage,
    number,
    year: game.currentYear,
    source: context.source,
    ...(context.timing === undefined ? {} : { timing: context.timing }),
  }
  await db.horseNumbers.add(row)
  return row
}
```

```ts
function assertBirthPlacement(mare: MareRow, horses: ReadonlyMap<string, HorseRow>): void {
  if (mare.herd !== 'in-herd' || (mare.usage !== 'own' && mare.usage !== 'free')) return
  const horse = horses.get(mare.horseId)
```

```ts
/** 進入母馬群或接任前的核對不符（需求規格 9.6、PED-08）；mismatches 是 core 的核對結果 */
export interface SuccessorCheckBlock {
  kind: 'successor'
  mismatches: SuccessorBlock[]
}

/**
 * 進入母馬群、指定為預定後繼或接任前，再次核對自家產駒（需求規格 9.6）：通過時回傳出生紀錄的系與代數。
 * target 是要進入或接任的系與代數，省略時為出生紀錄本身（系與代數不由畫面選）。
 * 自由配種所生或比照自由配種沒有出生紀錄的系與代數，一律阻止（9.5：不可成為八系後繼）
 */
export function checkOwnSuccessor(
  candidate: SuccessorCandidate,
  target?: LineGeneration,
): Prepared<LineGeneration, SuccessorCheckBlock> {
  const { origin } = candidate
  if (origin.kind === 'free') {
    // core 對自由配種所生只回傳 free-breeding，不看目標
    return {
      ok: false,
      blocks: [{ kind: 'successor', mismatches: [{ mismatch: 'free-breeding' }] }],
    }
  }
  const mismatches = verifySuccessor(candidate, target ?? origin.recorded)
  if (mismatches.length > 0) return { ok: false, blocks: [{ kind: 'successor', mismatches }] }
  return { ok: true, value: origin.recorded }
}
```

```ts
// 自家母駒的寫入操作：轉入繁殖圈與選定正式保留（需求規格 8.4、8.9、9.6；技術設計 4.3「寫入操作」）

/** 自家母駒轉入的輸入 */
export interface TransferFillyInput {
  /** 據點；還不知道時省略 */
  location?: Base
  /** 來源（所屬競走馬引退轉入）的備註；只有空白時不寫 */
  note?: string
}

/** 母馬的用途、母馬群、接替狀態與是否使該代成立 */
type EntryGroup = Pick<
  MareRow,
  'usage' | 'groupLine' | 'groupGeneration' | 'sisterStatus' | 'establishedGeneration'
>

/**
 * 自家母駒轉入繁殖圈（需求規格 8.4、8.9、9.6、11.5、LINE-17、MARE-07）：
 * 八系指定配種所生以 9.6 再核對（目標是出生紀錄的系與代數），不符時阻止；通過時用途為自家，
 * 母馬群依出生紀錄，接替狀態以 entrySisterStatus 判定（姊妹不在圈內 → 暫定保留；已有姊妹在圈 → 候選），
 * 暫定保留時該代成立（establishedGeneration 為 true）。自由配種所生或比照自由配種（沒有連結配種紀錄）：
 * 生產中，用途為自由配種所生，不分群、沒有接替狀態（11.5）。來源為所屬競走馬引退轉入；
 * 不設年齡門檻，不改牧場處置。事件 mare-transferred 記用途與母馬群、接替狀態與據點。
 * 馬匹找不到、屬於其他局、不是自家產駒或不是牝駒，已經進過繁殖圈（改用買回），或據點不是 32～35 時丟出錯誤。
 */
export async function transferFilly(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  input: TransferFillyInput = {},
  options: WriteOptions = {},
): Promise<WriteResult<MareRow, SuccessorCheckBlock>> {
  if (input.location !== undefined) assertBase(input.location)
  return runWrite(db, gameId, [db.horses, db.mares, db.breedings], options, async (context) => {
    const horse = await loadFoal(context, horseId)
    if (horse.sex !== 'female') throw new Error(`只有牝駒可以轉入繁殖圈：${horseId}`)
    if (await db.mares.get(horseId)) throw new Error(`已經進過繁殖圈的母馬要用買回：${horseId}`)
    const candidate = await loadSuccessorCandidate(db, gameId, horseId)
    let group: EntryGroup
    if (candidate.origin.kind === 'free') {
      group = { usage: 'free', establishedGeneration: false }
    } else {
      const checked = checkOwnSuccessor(candidate)
      if (!checked.ok) return { status: 'blocked', blocks: checked.blocks }
      const sisters = await loadSisters(db, gameId, horse.sireId, horse.damId)
      const sisterStatus = entrySisterStatus(
        { id: horseId, sireId: horse.sireId, damId: horse.damId },
        sisters,
      )
      group = {
        usage: 'own',
        groupLine: checked.value.line,
        groupGeneration: checked.value.generation,
        sisterStatus,
        establishedGeneration: sisterStatus === 'provisional',
      }
    }
    const note = input.note?.trim() ?? ''
    const mare: MareRow = {
      horseId,
      gameId,
      ...group,
      herd: 'in-herd',
      source: { kind: 'retired-racehorse', ...(note === '' ? {} : { note }) },
      ...(input.location === undefined ? {} : { location: input.location }),
    }
    await db.mares.add(mare)
    await context.addEvent({
      kind: 'mare-transferred',
      horseId,
      placement: placementOf(mare),
      ...(mare.sisterStatus === undefined ? {} : { sisterStatus: mare.sisterStatus }),
      ...(mare.location === undefined ? {} : { location: mare.location }),
    })
    return context.done(mare)
  })
}
```

```ts
/**
 * 選定正式保留（需求規格 8.9、MARE-12、MARE-24）：以 chooseKeptSister 套用，她改為正式保留，
 * 同父同母、在圈而且列入任務的姊妹改為已被取代；已被取代、已售出與不在圈內的姊妹不變。沒有姊妹時也可以選。
 * 選為正式保留時該代成立（establishedGeneration 設為 true，不改回，8.2）。沒有任何變化時阻止。
 * 狀態有變的每匹母馬各寫一筆事件 sister-status-changed，記原狀態、新狀態與選定的母馬；
 * 回傳狀態有變的母馬，選定的那一匹在前。之後改保留另一匹，對她再做一次。
 * 母馬或她的馬匹找不到、屬於其他局，或不是自家母駒時丟出錯誤；不在圈內時 chooseKeptSister 丟出 RangeError
 * （畫面只列出在圈的姊妹）。
 */
export async function keepSister(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  options: WriteOptions = {},
): Promise<WriteResult<MareRow[], UnchangedBlock>> {
  return runWrite(db, gameId, [db.horses, db.mares], options, async (context) => {
    const mare = await loadMare(context, horseId)
    if (mare.usage !== 'own') throw new Error(`只有自家母駒有接替狀態：${horseId}`)
    const horse = await db.horses.get(horseId)
    if (!horse) throw new Error(`找不到馬匹：${horseId}`)
    // 父母任一方不明時 loadSisters 讀不到她自己，所以另外放進去；讀到兩次不影響結果（同一匹不算姊妹）
    const sisters = await loadSisters(db, gameId, horse.sireId, horse.damId)
    const changes = chooseKeptSister(horseId, [...buildOwnMares([mare], [horse]), ...sisters])
    if (changes.length === 0) return { status: 'blocked', blocks: [{ kind: 'unchanged' }] }
    const saved: MareRow[] = []
    for (const change of changes) {
      const current = await loadMare(context, change.id)
      const next: MareRow = {
        ...current,
        sisterStatus: change.to,
        ...(change.to === 'kept' ? { establishedGeneration: true } : {}),
      }
      await db.mares.put(next)
      await context.addEvent({
        kind: 'sister-status-changed',
        horseId: change.id,
        from: change.from,
        to: change.to,
        keptHorseId: horseId,
      })
      saved.push(next)
    }
    return context.done(saved)
  })
}
```

```ts
/**
 * 重新連結出生紀錄（需求規格 9.3、BRD-27）：產駒建立後才把母馬前一年的紀錄改成 `受胎` 時使用。
 * 只限沒有連結配種紀錄的自家產駒；母馬「出生年減 1」那一年的配種紀錄要是 `受胎`，產駒已記的父馬要和紀錄相同。
 * 連結後出生紀錄記配種紀錄，八系指定配種所生另記規則快照的預計產出；父馬取自紀錄（原本沒有時補上），
 * 補上外部父馬名而原本沒有父母名的來源時，來源依事件的來源（同 addFoal）。
 * 連到八系指定配種、原本待售時牧場處置改為保留，比照 addFoal 的預設（原本待售是沒有連結時強制的）；
 * 已售出不變，連到自由配種也不變。已轉入繁殖圈的牝駒連到八系指定配種時阻止。母馬不必在圈。
 * 事件 foal-linked 記配種紀錄與牧場處置的變化。
 * 馬匹找不到、屬於其他局、不是自家產駒或已經連結配種紀錄時丟出錯誤；自家產駒缺少母馬或出生年時丟出 RangeError。
 */
export async function relinkFoal(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  options: WriteOptions = {},
): Promise<WriteResult<HorseRow, RelinkBlock>> {
  return runWrite(db, gameId, [db.horses, db.breedings, db.mares], options, async (context) => {
    const foal = await loadFoal(context, horseId)
    if (foal.birth?.breedingId !== undefined) throw new Error(`產駒已經連結配種紀錄：${horseId}`)
    const { damId, birthYear } = foal
    if (damId === undefined || birthYear === undefined) {
      throw new RangeError(`自家產駒缺少母馬或出生年：${horseId}`)
    }
    const breeding = await db.breedings
      .where('[gameId+mareId+year]')
      .equals([gameId, damId, birthYear - 1])
      .first()
    if (breeding?.conception !== '受胎') {
      const block: RelinkBlock = {
        kind: 'no-conception-record',
        ...(breeding === undefined ? {} : { breedingId: breeding.id }),
        ...(breeding?.conception === undefined ? {} : { conception: breeding.conception }),
      }
      return { status: 'blocked', blocks: [block] }
    }
    const placement = breeding.kind === 'designated' ? breeding.rule?.output : undefined
    const recorded = sireOf(foal)
    const blocks: RelinkBlock[] = []
    if (recorded && !sameSire(breeding, recorded)) {
      blocks.push({ kind: 'sire-mismatch', breedingId: breeding.id })
    }
    if (placement && (await db.mares.get(horseId))) blocks.push({ kind: 'mare-entered' })
    if (blocks.length > 0) return { status: 'blocked', blocks }

    const importing = context.source.kind === 'import'
    const addsPedigree = breeding.sireName !== undefined && foal.pedigreeSource === undefined
    const keep = placement !== undefined && foal.disposition === 'for-sale'
    const next: HorseRow = {
      ...foal,
      ...sireOf(breeding),
      ...(addsPedigree ? { pedigreeSource: importing ? 'import' : 'manual' } : {}),
      birth: { breedingId: breeding.id, ...(placement === undefined ? {} : { placement }) },
      ...(keep ? { disposition: 'keep' } : {}),
    }
    await db.horses.put(next)
    await context.addEvent({
      kind: 'foal-linked',
      horseId,
      breedingId: breeding.id,
      ...(keep ? { disposition: { from: 'for-sale', to: 'keep' } } : {}),
    })
    return context.done(next)
  })
```

```ts
/** 預定後繼的對象：已出生的自家公駒，或已受胎、產駒還沒出生的八系指定配種 */
export type SuccessorTarget = { horseId: string } | { breedingId: string }

/** 指定預定後繼的輸入 */
export interface DesignateSuccessorInput {
  target: SuccessorTarget
  /** 已出生的公駒的就緒狀態；省略時為競走中。尚未出生時不接受 */

/**
 * 指定預定後繼的阻止原因：
 * - successor：9.6 的核對不符（例如自由配種所生）
 * - line-has-successor：這一系已有預定後繼 stallionId；每系一匹，改指定要先取消（需求規格 7.7）
 * - already-appointed：公駒在那一格已有接任過的任用 stallionId
 * - foal-exists：指定的配種已有產駒 horseId 出生，改為指定那匹產駒
 */
export type DesignateSuccessorBlock =
  | SuccessorCheckBlock
  | { kind: 'line-has-successor'; stallionId: string }
  | { kind: 'already-appointed'; stallionId: string }
  | FoalExistsBlock

/** 就緒狀態的兩種值：競走中、已引退待指定 */
const READINESS: readonly StallionReadiness[] = ['racing', 'retired-awaiting']

/** 預定後繼的格位與對象：已出生時是馬匹，尚未出生時是受胎的配種紀錄 */
type ResolvedTarget = { slot: LineGeneration } & ({ horseId: string } | { breedingId: string })

/**
 * 指定預定後繼（需求規格 7.6、7.7、9.6、LINE-40～42）：對象是已出生的自家公駒，
 * 或已受胎、產駒還沒出生的八系指定配種。系與代數不由畫面選：公駒取出生紀錄，配種取規則快照的預計產出；
 * 以 9.6 核對，不符時阻止（尚未出生時以配種紀錄的父母與規則快照組出核對輸入）。
 * 同一系已有預定後繼、公駒在那一格已有接任過的任用、配種已有產駒出生時阻止。
 * 新增一列狀態留空的任用：已出生時存馬匹與就緒（預設競走中），尚未出生時存配種紀錄。
 * 那一格因此有種牡馬紀錄，以他為種牡馬的任務依任務看板的規則出現並暫停到他接任，補公系也可能因此結束。
 * 事件 successor-designated 記系位置、代數與對象。
 * 馬匹或配種紀錄找不到、屬於其他局，對象是牝駒、市場馬、不是受胎或不是八系指定配種的紀錄，
 * 尚未出生時傳了就緒，或就緒不是兩種之一時丟出錯誤。
 */
export async function designateSuccessor(
  db: WPStudBookDatabase,
  gameId: string,
  input: DesignateSuccessorInput,
  options: WriteOptions = {},
): Promise<WriteResult<StallionRow, DesignateSuccessorBlock>> {
  const { target, readiness } = input
  if (readiness !== undefined && !READINESS.includes(readiness)) {
    throw new Error(`就緒狀態不符：${readiness}`)
  }
  return runWrite(db, gameId, [db.horses, db.breedings, db.stallions], options, async (context) => {
    const resolved =
      'horseId' in target
        ? await coltTarget(context, target.horseId)
        : await unbornTarget(context, target.breedingId, readiness)
    if (!resolved.ok) return { status: 'blocked', blocks: resolved.blocks }
    const { slot } = resolved.value
    const horseId = 'horseId' in resolved.value ? resolved.value.horseId : undefined
    const lineRows = await db.stallions
      .where('gameId')
      .equals(gameId)
      .filter((row) => row.line === slot.line)
      .toArray()
    const blocks: DesignateSuccessorBlock[] = []
    const pending = lineRows.find((row) => row.status === undefined)
    if (pending) blocks.push({ kind: 'line-has-successor', stallionId: pending.id })
    // 尚未出生時 horseId 是 undefined，只對得到尚未出生的預定後繼（狀態留空），不會算成已接任
    const appointed = lineRows.find((row) => row.horseId === horseId && row.status !== undefined)
    if (appointed) blocks.push({ kind: 'already-appointed', stallionId: appointed.id })
    if (blocks.length > 0) return { status: 'blocked', blocks }

    const row: StallionRow = {
      id: crypto.randomUUID(),
      gameId,
      line: slot.line,
      generation: slot.generation,
      ...('horseId' in resolved.value
        ? { horseId: resolved.value.horseId, readiness: readiness ?? 'racing' }
        : { breedingId: resolved.value.breedingId }),
    }
    await db.stallions.add(row)
    await context.addEvent({
      kind: 'successor-designated',
      line: row.line,
      ...(row.horseId === undefined ? {} : { horseId: row.horseId }),
      stallionId: row.id,
      generation: row.generation,
      ...(row.breedingId === undefined ? {} : { breedingId: row.breedingId }),
      ...(row.readiness === undefined ? {} : { readiness: row.readiness }),
    })
    return context.done(row)
  })
}

/**
 * 取消預定後繼（需求規格 7.7、LINE-42）：刪除那一列任用並寫事件 successor-cancelled，歷程留在事件
 * （技術設計 4.3）。任用找不到、屬於其他局或已接任（改用 setStallionStatus）時丟出錯誤。
 */
export async function cancelSuccessor(
  db: WPStudBookDatabase,
  gameId: string,
  stallionId: string,
  options: WriteOptions = {},
): Promise<WriteResult<StallionRow, never>> {
  return runWrite(db, gameId, [db.stallions], options, async (context) => {
    const row = await loadPending(context, stallionId)
    await db.stallions.delete(stallionId)
    await context.addEvent({
      kind: 'successor-cancelled',
      line: row.line,
      ...(row.horseId === undefined ? {} : { horseId: row.horseId }),
      stallionId,
      generation: row.generation,
      ...(row.breedingId === undefined ? {} : { breedingId: row.breedingId }),
    })
    return context.done(row)
  })
}

/** 已出生的公駒：以 9.6 核對，格位是出生紀錄的系與代數。不是公駒時丟出錯誤 */
async function coltTarget(
  context: WriteContext,
  horseId: string,
): Promise<Prepared<ResolvedTarget, DesignateSuccessorBlock>> {
  const horse = await loadFoal(context, horseId)
  if (horse.sex !== 'male') throw new Error(`只有公駒可以當預定後繼：${horseId}`)
  const checked = checkOwnSuccessor(
    await loadSuccessorCandidate(context.db, context.game.id, horseId),
  )
  return checked.ok ? { ok: true, value: { slot: checked.value, horseId } } : checked
}

/**
 * 尚未出生的產駒：配種紀錄要是受胎的八系指定配種、還沒有產駒；以配種紀錄組出的核對輸入做 9.6 核對，
 * 格位是規則快照的預計產出。傳了就緒，或紀錄不是受胎的八系指定配種時丟出錯誤
 */
async function unbornTarget(
  context: WriteContext,
  breedingId: string,
  readiness: StallionReadiness | undefined,
): Promise<Prepared<ResolvedTarget, DesignateSuccessorBlock>> {
  if (readiness !== undefined) throw new Error(`尚未出生的預定後繼沒有就緒狀態：${breedingId}`)
  const breeding = await loadBreeding(context, breedingId)
  if (breeding.kind !== 'designated' || breeding.conception !== '受胎') {
    throw new Error(`不是受胎的八系指定配種：${breedingId}`)
  }
  const foal = await linkedFoal(context, breeding)
  if (foal) return { ok: false, blocks: [{ kind: 'foal-exists', horseId: foal.id }] }
  const checked = checkOwnSuccessor(unbornCandidate(breeding))
  return checked.ok ? { ok: true, value: { slot: checked.value, breedingId } } : checked
}

/**
 * 尚未出生的產駒的核對輸入：父母取自配種紀錄，出生紀錄的系與代數取規則快照的預計產出
 * （技術設計 4.3「預定後繼的指定」）
 */
function unbornCandidate(breeding: BreedingRow): SuccessorCandidate {
  const placement = breeding.rule?.output
  return buildSuccessorCandidate(
    {
      id: breeding.id,
      gameId: breeding.gameId,
      sireId: breeding.sireId,
      damId: breeding.mareId,
      birth: { breedingId: breeding.id, ...(placement === undefined ? {} : { placement }) },
    },
    breeding,
  )
}

/** 這一局的預定後繼（狀態留空的任用）；找不到、屬於其他局或已接任時丟出錯誤 */
async function loadPending(context: WriteContext, stallionId: string): Promise<StallionRow> {
  const row = await context.db.stallions.get(stallionId)
  if (!row || row.gameId !== context.game.id) throw new Error(`找不到種牡馬的任用：${stallionId}`)
  if (row.status !== undefined) throw new Error(`已接任的種牡馬不是預定後繼：${stallionId}`)
  return row
}
```

```ts
 * 事件 successor-born 記系位置、馬匹與配種紀錄。任用找不到、屬於其他局、已接任或已出生時丟出錯誤。
 */
export async function confirmSuccessorBirth(
  db: WPStudBookDatabase,
  gameId: string,
  stallionId: string,
  options: WriteOptions = {},
): Promise<WriteResult<StallionRow, ConfirmBirthBlock>> {
  return runWrite(db, gameId, [db.horses, db.breedings, db.stallions], options, async (context) => {
    const { breedingId, ...row } = await loadPending(context, stallionId)
    if (breedingId === undefined) throw new Error(`預定後繼已經出生：${stallionId}`)
    const foal = await linkedFoal(context, await loadBreeding(context, breedingId))
    const blocks: ConfirmBirthBlock[] = []
    if (!foal) blocks.push({ kind: 'not-born' })
    else if (foal.sex === 'female') blocks.push({ kind: 'foal-female', horseId: foal.id })
    if (!foal || blocks.length > 0) return { status: 'blocked', blocks }
    const checked = checkOwnSuccessor(await loadSuccessorCandidate(db, gameId, foal.id), {
      line: row.line,
      generation: row.generation,
    })
    if (!checked.ok) return { status: 'blocked', blocks: checked.blocks }
    const next: StallionRow = { ...row, horseId: foal.id, readiness: 'racing' }
    await db.stallions.put(next)
    await context.addEvent({
      kind: 'successor-born',
      line: next.line,
      horseId: foal.id,
      stallionId,
      breedingId,
    })
    return context.done(next)
  })
}

 * 事件 successor-readiness-changed 記原狀態與新狀態。任用找不到、屬於其他局、已接任或尚未出生，
 * 或就緒不是兩種之一時丟出錯誤；已出生的預定後繼缺少就緒狀態時丟出 RangeError。
 */
export async function setSuccessorReadiness(
  db: WPStudBookDatabase,
  gameId: string,
  stallionId: string,
  readiness: StallionReadiness,
  options: WriteOptions = {},
): Promise<WriteResult<StallionRow, UnchangedBlock>> {
  if (!READINESS.includes(readiness)) throw new Error(`就緒狀態不符：${readiness}`)
  return runWrite(db, gameId, [db.stallions], options, async (context) => {
    const row = await loadPending(context, stallionId)
    const { horseId, readiness: from } = row
    if (horseId === undefined) throw new Error(`尚未出生的預定後繼沒有就緒狀態：${stallionId}`)
    if (from === undefined) throw new RangeError(`預定後繼缺少就緒狀態：${stallionId}`)
    if (from === readiness) return { status: 'blocked', blocks: [{ kind: 'unchanged' }] }
    const next: StallionRow = { ...row, readiness }
    await db.stallions.put(next)
    await context.addEvent({
      kind: 'successor-readiness-changed',
      line: row.line,
      horseId,
      stallionId,
      from,
      to: readiness,
    })
    return context.done(next)
  })
}
```

```ts
 * 沒有任用、出生紀錄也沒有系與代數的馬（例如自由配種所生）不能比較，丟出錯誤

export function buildBrotherRecords(
  horses: readonly HorseRow[],
  stallions: readonly StallionRow[],
): StallionRecord[] {
  return horses.map((horse) => {

    return { id: horse.id, placement, sireId: horse.sireId, status: row?.status }
```

```ts
 * 格位取出生紀錄的系與代數，不由畫面選；以 9.6 核對，不符時阻止。他在那一格是預定後繼或已被取代時沿用那一列，
 * 已退出生產行列或已引退時阻止（先用 setStallionStatus 更正），已在崗時阻止，沒有任用時新增一列。
 * 那一格另有接任過的任用（在崗、已被取代、退出生產行列、已引退）時是更換現任，要附 7.7 的原因；
 * 第一次接任不需原因；同一格其他還沒接任的預定後繼不算。以 chooseIncumbent 套用：他改為在崗並拿掉就緒，
 * 同一格原本在崗的改為已被取代；上一代的現任（交接期間可同時在崗）與這一系其他的預定後繼不動。
 * 種牡馬馬番号去掉前後空白、統一寫法，有填時記一筆種牡馬階段。事件 stallion-appointed 記格位、原因與被取代的馬，
 * 生效年是事件的年份。兄弟比較後保留原現任時不呼叫這個操作，不寫任何紀錄。
 * 馬匹找不到、屬於其他局、不是自家產駒或不是公駒時丟出錯誤。
 */
export async function appointStallion(
  db: WPStudBookDatabase,
  gameId: string,
  input: AppointStallionInput,
  options: WriteOptions = {},
): Promise<WriteResult<AppointedStallion, AppointStallionBlock>> {
  const tables = [db.horses, db.breedings, db.stallions, db.horseNumbers]
  return runWrite(db, gameId, tables, options, async (context) => {
    const { horseId } = input
    const horse = await loadFoal(context, horseId)
    if (horse.sex !== 'male') throw new Error(`只有公駒可以接任種牡馬：${horseId}`)
    const checked = checkOwnSuccessor(await loadSuccessorCandidate(db, gameId, horseId))
    const numberText = input.horseNumber?.trim() ?? ''
    const horseNumber = numberText === '' ? undefined : normalizeAbilityNumber(numberText)
    const blocks: AppointStallionBlock[] = checked.ok ? [] : [...checked.blocks]
    if (horseNumber === null) blocks.push({ kind: 'horse-number' })
    if (!checked.ok || horseNumber === null) return { status: 'blocked', blocks }

    const slot = checked.value
    // 自家產駒至少 1 代，這一格不會有補公系補入的零代任用
    const rows = await db.stallions
      .where('[gameId+line+generation]')
      .equals([gameId, slot.line, slot.generation])
      .toArray()
    const own = rows.find((row) => row.horseId === horseId)
    if (own?.status === 'withdrawn' || own?.status === 'retired') {
      blocks.push({ kind: 'stallion-ended' })
    } else if (own?.status === 'active') {
      blocks.push({ kind: 'unchanged' })
    }
    const replacing = rows.some((row) => row !== own && row.status !== undefined)
    if (replacing && input.reason === undefined) blocks.push({ kind: 'reason-required' })
    if (blocks.length > 0) return { status: 'blocked', blocks }

    const current: StallionRow = own ?? {
      id: crypto.randomUUID(),
      gameId,
      line: slot.line,
      generation: slot.generation,
      horseId,
    }
    const slotRows = own ? rows : [...rows, current]
    const changes = chooseIncumbent(horseId, slotRows.flatMap(stallionRecordOf))
    const appointment: StallionRow = { ...current, status: 'active' }
    delete appointment.readiness
    const replaced = slotRows.flatMap((row): StallionRow[] =>
      changes.some((change) => change.id === row.horseId && change.to === 'replaced')
        ? [{ ...row, status: 'replaced' }]
        : [],
    )
    await db.stallions.bulkPut([appointment, ...replaced])
    if (horseNumber !== undefined) {
      await recordHorseNumber(context, horseId, 'stallion', horseNumber)
    }
    await context.addEvent({
      kind: 'stallion-appointed',
      line: slot.line,
      horseId,
      stallionId: appointment.id,
      generation: slot.generation,
      ...(input.reason === undefined ? {} : { reason: reasonOf(input.reason) }),
      replacedHorseIds: replaced.flatMap((row) => row.horseId ?? []),
    })
    return context.done({ appointment, replaced })
  })
}
```

```ts
/** 任用列在 chooseIncumbent 用的種牡馬紀錄；尚未出生的預定後繼沒有馬匹，不列入 */
function stallionRecordOf(row: StallionRow): StallionRecord[] {
  if (row.horseId === undefined) return []
  return [
    {
      id: row.horseId,
      placement: { line: row.line, generation: row.generation },
      status: row.status,
    },
  ]
}
```
