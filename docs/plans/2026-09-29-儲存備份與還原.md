# 儲存備份與還原 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `src/storage/` 加上備份與還原：遊戲局的應用版本、最近備份時間與還原來源；整局資料的讀出、重新產生識別、寫入與刪除；備份檔（JSON／JSON.GZ、SHA-256）的匯出；讀取備份時的解壓、版本、雜湊、遷移、欄位、重複、關聯與筆數驗證；還原成新遊戲局；危險區的刪除一局與刪除全部（技術設計 4.3「備份與還原」「危險區」）。

**Architecture:** 儲存子計畫 3 拆成三塊，本計畫是第 1 塊（3-1 備份與還原 → 3-2 檢查點與回溯 → 3-3 封存與瀏覽器整合）。`game-data.ts` 以 `GAME_TABLES` 為準，負責整局資料的讀寫，之後的檢查點與封存也會沿用。`backup.ts` 負責備份檔：匯出只讀，產生檔名、位元組與摘要，不觸發下載；讀取時依序檢查，不通過就回傳拒絕原因、不丟例外；還原時識別全部重新產生，在一個交易內寫成新遊戲局。危險區的刪除放在 `games.ts`，名稱核對在儲存層。core 不改。

**Tech Stack:** TypeScript（strict）、Dexie 4、Vitest、fake-indexeddb；瀏覽器內建的 `CompressionStream`、`DecompressionStream`、`crypto.subtle`。不新增套件。

## Global Constraints

- 成品：`app/dist/WPStudBook.html` 單一檔案，Windows 最新版 Edge 與 Chrome 以 `file://` 離線使用；執行時不依賴 CDN、網路、本機伺服器或擴充功能。（AGENTS.md）
- gzip 與 SHA-256 一律用瀏覽器內建的 `CompressionStream`、`DecompressionStream` 與 `crypto.subtle`，不加套件（AGENTS.md、技術設計第 2 章）。Node 24 的測試環境也有這些 API。
- TypeScript strict，維持 TypeScript 6.x。`src/` 的 `lib` 是 ES2022：不要用 `findLast`、`toSorted`、`Object.groupBy` 這類 ES2023 以後的方法。`verbatimModuleSyntax` 已開啟：只當型別用的匯入要寫 `type`。位元組一律寫 `Uint8Array<ArrayBuffer>`，照計畫的程式。
- 模組邊界：`src/storage/` 在專案模組中只能引用 `src/core/`，不得引用 `src/ce-import/`、`src/ui/`，也不得引用 Vue、Pinia、Vue Router、Reka UI。（AGENTS.md，ESLint 已設定）
- 錯誤處理（技術設計第 5 章、4.3「備份與還原」）：讀取備份遇到資料來源異常時回傳拒絕原因，不丟例外；使用者的輸入不符（刪除時的局名、固定字）回傳 `blocked`；畫面不會送出的狀況（找不到遊戲局、缺少某一版的遷移）丟出附識別的 `Error`；局名空白丟出 `RangeError`（同 `createGame`）。

> - **未知值不是零值**：空白、未知、`0` 與布林否保持不同語意，匯入、備份、還原都不互相轉換。

**需求規格 12.1 遊戲局**

> - 多個遊戲局彼此隔離，所有操作只作用於目前遊戲局。保存名稱、應用版本（最後寫入這一局的管理器版本）、起始年、目前遊戲年、建立與更新時間、最近備份時間。

**需求規格 12.2 IndexedDB 與備份**

> - IndexedDB 是日常資料庫，只更新受影響的紀錄；主要資料不存 localStorage。
> - 完整備份與移轉用 JSON／JSON.GZ（支援 Compression Streams 時優先 `.json.gz`，否則 `.json`）。資料契約含格式識別、結構版本、應用版本、匯出時間、遊戲局摘要、各集合與筆數、SHA-256；識別存字串，正規化集合，不內嵌血緣樹。備份不含檢查點：檢查點只供本機回溯，還原成的新局從之後的年度匯入重新累積（2026-09-24 決定）。
> - 匯出建立一致快照，完成後顯示檔名、局、筆數、大小、版本與時間。
> - 匯入備份依序完成解析、版本、欄位、關聯、筆數與預覽，全部通過才寫入，一律還原為新遊戲局；要取代舊局時，還原後再到危險區刪除舊局（2026-09-24 決定）。舊版本逐版遷移並留紀錄；未來版本、截斷、錯誤 gzip、重複識別、缺少關聯時拒絕，資料不變。大型檔案顯示進度。
> - **備份提醒**：上次備份後有未備份的變更時，提醒區顯示距上次備份的天數；超過設定天數（預設 7 天，可調）時醒目提示。

> 瀏覽器內建能力直接使用，不加套件：CP932 解碼（`TextDecoder`）、gzip（`CompressionStream`）、SHA-256（`crypto.subtle`）。只有測試用的 CP932 範例檔需要在 Node 產生，因此加入開發用套件 `iconv-lite`。
> - 結構版本用 Dexie 的版本升級管理；備份檔的結構版本與遷移沿用同一套版本號。正式發布前結構版本維持 1，各計畫直接修改版本 1 的結構；第一次發布後才以版本升級變更。
> | `games` | 遊戲局 | 名稱、應用版本（最後寫入這一局的管理器版本）、起始年、目前遊戲年、建立與更新時間、最近備份時間（需求規格 12.1）；還原而來的局另記還原來源（見「備份與還原」） |
> - **一個操作一個交易**：每個操作在一個 rw 交易內完成：先讀遊戲局確認存在，再從資料列重新組出核心的輸入並重做檢查，最後寫入資料列與事件，並把遊戲局的更新時間設為現在、應用版本設為目前版本（見「備份與還原」）。設定、代表色這類不寫事件的操作也更新，備份提醒（需求規格 12.2）以此判斷有沒有未備份的變更。操作可以包進呼叫端的外層交易（Dexie 的巢狀交易），CE 匯入以此在單一交易內套用多個操作（4.4）。

**技術設計 4.3「備份與還原」（全文）**

> #### 備份與還原
>
> 備份、還原與危險區（需求規格 12.1、12.2）由儲存子計畫 3-1 負責；檢查點（3-2）與封存、瀏覽器整合（3-3）沿用這裡的整局讀寫與備份格式（使用者 2026-09-29 確認）。
>
> - **整局資料**：`GAME_TABLES` 列出 `meta` 以外每一張有遊戲局欄位的表，匯出、還原、刪除與計算筆數都用這份清單；測試確認它涵蓋 `meta` 以外的每一張表，之後加表時一併更新。讀出整局在單一唯讀交易內完成，得到一致的快照（需求規格 12.2）。
> - **應用版本**：取 `package.json` 的 `version`，由 Vite 的 `define` 注入（Vitest 共用同一份設定）。建立遊戲局、還原與每個寫入操作都把遊戲局的應用版本設為目前版本（需求規格 12.1「最後寫入這一局的管理器版本」）。
> - **備份檔**：一個 JSON 物件，欄位依序為格式識別 `format`（`wpstudbook-backup`）、結構版本 `schemaVersion`（Dexie 的版本號）、應用版本、匯出時間、遊戲局摘要（識別、局名、起始年、目前遊戲年）、各集合的筆數 `counts`、集合 `collections`（`GAME_TABLES` 每張表一個陣列，資料列原樣）與 `sha256`。雜湊是 `sha256` 以外的欄位依上述順序 `JSON.stringify` 後，UTF-8 位元組的 SHA-256（小寫十六進位）；驗證時拿掉 `sha256` 重新序列化再比對，`JSON.parse` 保留欄位順序，所以結果一致。留空的欄位在資料列裡本來就不存在，`0`、空字串與 `false` 原樣保留（DATA-03）；寫入操作不留下值為 `undefined` 的欄位。JSON 不縮排；有 `CompressionStream` 時 gzip 成 `.json.gz`，否則輸出 `.json`（DATA-06）。
> - **匯出**：先取現在時間作為匯出時間，再以唯讀交易讀出整局；序列化、雜湊與壓縮在交易外進行，因為它們是瀏覽器的非同步 API，不能放在 Dexie 交易內。檔名為 `WPStudBook_<局名>_<目前遊戲年>年_<YYYYMMDD-HHmmss>` 加副檔名，時間用本機時間，局名裡 Windows 檔名不允許的字元（`\ / : * ? " < > |` 與控制字元）換成 `_`。回傳檔名、位元組與摘要：檔名、局名、各集合筆數與總筆數、大小、結構版本、應用版本、匯出時間與是否壓縮（DATA-07）。匯出只讀，不觸發下載；下載由畫面或 3-3 的自動備份負責。
> - **最近備份時間**：由呼叫端在交出檔案（觸發下載，或寫入備份資料夾成功）後另外記錄，設為匯出時間，只往後不往回；不改更新時間與應用版本，因為記錄備份不是資料變更。用快照的時間而不用記錄的時間：快照之後的修改，更新時間晚於最近備份時間，仍算未備份（需求規格 12.2「備份提醒」）。匯出與記錄分開，是因為 3-3 寫入資料夾失敗時要改為自動下載，確定交出後才記錄。
> - **讀取與驗證**：依序檢查，任一步不通過就回傳拒絕與原因，資料不變（DATA-04）。這屬於第 5 章的資料來源異常，以回傳結果表達，不丟例外。
>   1. 解壓：開頭是 `1F 8B` 時以 `DecompressionStream` 解壓，失敗為錯誤或截斷的 gzip，瀏覽器不支援解壓時也拒絕；其他開頭當作未壓縮的 JSON。
>   2. 解析：UTF-8 嚴格解碼後 `JSON.parse`，失敗為截斷或不是 JSON。
>   3. 格式：格式識別相符、結構版本是 1 以上的整數，否則不是備份檔。
>   4. 版本：結構版本大於目前版本時為未來版本，附版本號。
>   5. 雜湊：依「備份檔」重算並比對，在遷移前進行。
>   6. 遷移：較舊的結構版本逐版套用遷移函式。結構版本 1 是第一版，目前沒有遷移；遷移表可由參數傳入，測試以假的遷移驗證（DATA-05）。
>   7. 欄位：集合剛好是 `GAME_TABLES`，多或少都拒絕；每一列是物件，主鍵欄位存在且型別正確，遊戲局欄位等於這一局；`games` 與 `settings` 各一列，遊戲局摘要與 `games` 那一列一致。不逐欄驗證型別與列舉值：檔案完整性由雜湊保證，全面驗證要隨每次改表同步。
>   8. 重複：各表主鍵不重複，所有 `id` 跨表也不重複，因為還原時所有識別共用一張新舊對照表。
>   9. 關聯：`horses` 的父、母指向 `horses`，出生紀錄的配種指向 `breedings`；`mares`、`horseNumbers` 與 `events` 的馬匹指向 `horses`；`mareYears` 的馬匹指向 `mares`；`stallions` 的馬匹、配種、補系分別指向 `horses`、`breedings`、`restorations`；`breedings` 與 `matingRatings` 的母馬指向 `mares`，種牡馬指向 `horses`。指向 `mares` 的，現有寫入操作都已要求母馬在 `mares`。事件內容裡的引用不查：取消預定後繼會刪除任用列，事件裡的任用識別本來就可能懸空。
>   10. 筆數：`counts` 的鍵與各集合的筆數相符。
>
>   通過時回傳驗證過的備份與預覽：局名、起始年與目前遊戲年、匯出時間、結構版本、應用版本、各集合筆數與總筆數。可傳進度回呼，回報解壓、解析、驗證等步驟（需求規格 12.2「大型檔案顯示進度」）。
> - **還原**：一律還原成新遊戲局（需求規格 12.2），在一個 rw 交易內寫入全部資料表，失敗時整筆回復。
>   - 識別重新產生：遊戲局與各列的 `id` 換成新的 UUID，任何欄位（含事件內容）中整個字串等於舊識別的值一律換成新的，懸空的引用保持原值。原局通常還在同一個瀏覽器裡（12.2「還原後再到危險區刪除舊局」），保留原識別會撞到它（使用者 2026-09-29 決定）。
>   - 局名用呼叫端傳的，沒傳時用備份的局名；空白時丟 `RangeError`，同建立遊戲局；可以與既有的局重複，由畫面預填。
>   - 建立時間為還原的時間，更新時間沿用備份的（資料最後修改的時間）；應用版本為目前版本；最近備份時間為備份的匯出時間，因為內容與備份檔相同，沒有未備份的變更。
>   - 還原來源記檔名、匯出時間、原局名、備份的應用版本與結構版本；結構版本比目前舊就是經過遷移，這就是 DATA-05 的紀錄。
>   - 寫入時依集合回報進度（已寫筆數與總筆數）。不切換目前遊戲局，回傳新局，由畫面決定。

**技術設計 4.3「危險區」（全文）**

> #### 危險區
>
> - **筆數**：回傳一局 `GAME_TABLES` 各表的筆數與總筆數，供確認前顯示（需求規格 12.1「顯示筆數」）。
> - **永久刪除此局**：輸入的局名去掉前後空白後要等於局名，否則阻止，什麼都不刪；名稱核對放在儲存層，畫面漏掉也刪不掉。在一個 rw 交易內從 `GAME_TABLES` 刪除這一局的資料列；`meta` 的目前遊戲局指向這一局時一併清除，由畫面請使用者重新選局。不寫事件，因為這一局已不存在。回傳刪除的各表筆數；找不到遊戲局時丟出錯誤。
> - **刪除全部存檔**：輸入的文字要是「刪除全部存檔」，否則阻止；第二道確認由畫面負責（需求規格 12.1，使用者 2026-09-29 決定）。在一個交易內清空資料庫的每一張表（含 `meta`），之後加入的檢查點表與封存索引也包含在內，要保留的表由加入它的計畫決定。回傳刪除的遊戲局數與總筆數。

## 本計畫的詮釋

需求規格與技術設計沒有逐字寫出、由本計畫決定的地方。技術設計 4.3「備份與還原」「危險區」已經和使用者確認；下面是本計畫在程式層級的決定，審查時請逐條對照上一節的原文。

1. **應用版本**（Task 1）：`src/storage/version.ts` 的 `APP_VERSION` 取 `vite.config.ts` 的 `define` 注入的 `__APP_VERSION__`，值是 `package.json` 的 `version`。`declare const __APP_VERSION__` 寫在 `version.ts` 裡，不放 `env.d.ts`：`src/` 與 `tests/` 分屬兩個 tsconfig，寫在模組裡兩邊都看得到。`vite.config.test.ts` 確認注入的就是 `package.json` 的 `version`。`GameRow.appVersion` 是必填：`createGame` 與測試的 `addTestGame` 都帶目前版本；`setCurrentYear` 回傳的遊戲局也帶目前版本，與 `done()` 寫入的值一致。
2. **最近備份時間**（Task 1）：`recordBackup` 放在 `games.ts`，直接開交易，不經 `runWrite`（`runWrite` 的 `done()` 會改更新時間與應用版本）。ISO 字串是同一種寫法（`toISOString`），直接比大小；相同或較早時不寫入，回傳原本的遊戲局。
3. **整局資料**（Task 2）：`GameData` 的鍵與 `GAME_TABLES` 同序；`readGameData` 的各表依 `gameId` 索引讀出，所以各表依主鍵排序。`remapIds` 的 `newId` 收到舊識別，預設忽略它、產生新的 UUID；測試傳 `(old) => 'new-' + old`，期望值才能寫死。新舊對照只收各列的 `id`：`mares` 與 `mareYears` 以 `horseId` 為主鍵，跟著馬匹一起換。`addGameData` 自己開 rw 交易（包進外層時成為子交易），識別已存在時 `bulkAdd` 失敗，整筆回復。`deleteGameData` 遇到不存在的遊戲局時筆數都是 0、不丟錯誤，因為刪除一局會先用 `loadGame` 確認；`countGameRows` 則丟出錯誤。`countRows`、`totalRows` 供摘要與驗證共用。樣本局的任用識別（`G-P`）刻意與馬匹（`G-S`）不同：`stallionRow` 預設兩者相同，會被 Task 5 的跨表重複檢查擋下。
4. **匯出**（Task 3）：`SCHEMA_VERSION` 放在 `database.ts`，Dexie 的版本號改用它。`exportBackup` 的時間參數放在第三個位置（同 `createGame`）。是否壓縮依 `typeof CompressionStream === 'function'`，測試以 `vi.stubGlobal` 模擬不支援。檔名逐字檢查不允許的字元，控制字元以 `char < ' '` 判斷，不用正規表示式。
5. **讀取的前段**（Task 4）：拒絕原因是有型別的聯合（Task 5 再加四種）。雜湊以解構拿掉 `sha256` 後重新序列化，所以 `sha256` 在檔案裡的位置不影響結果。遷移表與目前的結構版本都可以從參數傳入，測試用來模擬較舊的檔案；缺少某一版的遷移是程式錯誤，丟出 `Error`，不是拒絕原因。`isObject` 把陣列也算成物件：陣列沒有 `format` 等欄位，後面的檢查一定會擋下，突變檢查確認 `Array.isArray` 是多餘的條件，所以刪掉。預覽的 `schemaVersion` 是檔案原本的版本。
6. **集合的內容檢查**（Task 5）：拒絕的位置以 `path` 字串表示，例如 `collections.horses[3].id`，一次包含集合、資料列與欄位；重複以主鍵值表示，複合主鍵以 `+` 連接。`PRIMARY_KEYS` 與 `database.ts` 的主鍵相同。遊戲局欄位要等於 `games` 那一列的 `id`；摘要比對 `id`、局名、起始年、目前遊戲年。跨表重複只看 `id` 欄位：`mares` 的 `horseId` 本來就等於 `horses` 的 `id`，不算重複。關聯的目標用目標表的第一個主鍵欄位比對：`horses`、`breedings`、`restorations` 是 `id`，`mares` 是 `horseId`。引用欄位沒有值時略過。筆數同時比對 `GAME_TABLES` 與 `counts` 多出來的鍵；`counts` 不是物件時，從 `games` 開始就對不上。
7. **還原**（Task 6）：`restoreBackup` 接收 `readBackup` 通過的 `VerifiedBackup`，不再重新驗證。新局以重新產生識別後的 `games` 那一列為底，覆寫局名、建立時間、應用版本、最近備份時間與還原來源；備份本身如果來自還原的局，原本的還原來源會被取代。進度由 `addGameData` 回報。
8. **危險區**（Task 7）：`deleteGame`、`deleteAllGames` 放在 `games.ts`，回傳 `WriteResult`，完成時 `warnings` 一律是空的；不經 `runWrite`，因為不更新遊戲局也不寫事件。局名與固定字都先去掉前後空白再比對。刪除全部回傳的筆數只算 `GAME_TABLES`，不含 `meta`，但清空的是 `db.tables` 的每一張。
9. **驗收**（Task 8）：DATA-02 的期望值用 `JSON.parse` 的 reviver 換識別，不經過 `remapIds`。突變檢查發現，用 `remapIds` 算期望值時，巢狀欄位沒換也會通過。DATA-05 以注入的遷移驗證；DATA-06 以 `vi.stubGlobal` 驗證；DATA-10 只驗證名稱核對，「位於危險區」與第二道確認屬於畫面。

```ts
    return { ...game, lastBackupAt: exportedAt }
```

```ts
import type { Table } from 'dexie'
import type { WPStudBookDatabase } from './database'
import type {
  BreedingRow,
  EventRow,
  GameRow,
  HorseNumberRow,
  HorseRow,
  LineRow,
  MareRow,
  MareYearRow,
  MatingRatingRow,
  RestorationRow,
  SettingsRow,
  StallionRow,
  SystemRow,
} from './records'

// 整局資料的讀出、寫入與刪除（技術設計 4.3「備份與還原」）：備份、還原與危險區共用

/** 一局的全部資料：GAME_TABLES 每張表一個陣列，資料列原樣 */
export interface GameData {
  games: GameRow[]
  settings: SettingsRow[]
  horses: HorseRow[]
  lines: LineRow[]
  systems: SystemRow[]
  mares: MareRow[]
  mareYears: MareYearRow[]
  stallions: StallionRow[]
  restorations: RestorationRow[]
  breedings: BreedingRow[]
  matingRatings: MatingRatingRow[]
  events: EventRow[]
  horseNumbers: HorseNumberRow[]
}

export type GameTableName = keyof GameData

/**
 * 屬於一局的資料表：meta 以外的每一張。games 以 id 歸屬，其他以 gameId 歸屬。
 * 匯出、還原、刪除與計算筆數都用這份清單；加表時一併更新（測試會檢查）
 */
export const GAME_TABLES: readonly GameTableName[] = [
  'games',
  'settings',
  'horses',
  'lines',
  'systems',
  'mares',
  'mareYears',
  'stallions',
  'restorations',
  'breedings',
  'matingRatings',
  'events',
  'horseNumbers',
]

/** 各表的筆數 */
export type RowCounts = Record<GameTableName, number>

/** GAME_TABLES 對應的 Dexie 資料表，供開交易使用 */
export function gameTables(db: WPStudBookDatabase): Table[] {
  return GAME_TABLES.map((name) => db.table(name))
}

/**
 * 讀出一局的全部資料（需求規格 12.2「一致快照」）：在單一唯讀交易內完成。
 * 陣列的順序照 GAME_TABLES。遊戲局不存在時丟出錯誤
 */
export async function readGameData(db: WPStudBookDatabase, gameId: string): Promise<GameData> {
  return db.transaction('r', gameTables(db), async () => {
    const game = await db.games.get(gameId)
    if (!game) throw new Error(`找不到遊戲局：${gameId}`)
    const data: Partial<Record<GameTableName, unknown[]>> = {}
    for (const name of GAME_TABLES) {
      data[name] =
        name === 'games' ? [game] : await db.table(name).where('gameId').equals(gameId).toArray()
    }
    return data as GameData
  })
}

/**
 * 重新產生整局的識別（技術設計 4.3「備份與還原」）：遊戲局與各列的 id 換成 newId 產生的新識別
 * （預設是新的 UUID），任何欄位（含事件內容）中整個字串等於舊識別的值一律換成新的；懸空的引用保持原值。
 * 回傳新的資料，不改傳入的資料
 */
export function remapIds(
  data: GameData,
  newId: (oldId: string) => string = () => crypto.randomUUID(),
): GameData {
  const ids = new Map<string, string>()
  for (const name of GAME_TABLES) {
    for (const row of data[name] as readonly object[]) {
      if ('id' in row && typeof row.id === 'string') ids.set(row.id, newId(row.id))
    }
  }
  const remap = (value: unknown): unknown => {
    if (typeof value === 'string') return ids.get(value) ?? value
    if (Array.isArray(value)) return value.map(remap)
    if (value !== null && typeof value === 'object') {
      return Object.fromEntries(Object.entries(value).map(([key, item]) => [key, remap(item)]))
    }
    return value
  }
  return remap(data) as GameData
}

/**
 * 把整局資料寫進資料庫（一個 rw 交易；包進外層交易時成為子交易）。
 * 識別要是這個資料庫裡還沒有的：還原先以 remapIds 重新產生。
 * onProgress 在每張表寫完後收到已寫筆數與總筆數
 */
export async function addGameData(
  db: WPStudBookDatabase,
  data: GameData,
  onProgress?: (written: number, total: number) => void,
): Promise<void> {
  const total = totalRows(countRows(data))
  let written = 0
  await db.transaction('rw', gameTables(db), async () => {
    for (const name of GAME_TABLES) {
      const rows = data[name] as readonly unknown[]
      await db.table(name).bulkAdd(rows)
      written += rows.length
      onProgress?.(written, total)
    }
  })
}

/**
 * 從 GAME_TABLES 刪除一局的全部資料列（一個 rw 交易），回傳各表刪除的筆數。
 * 不碰 meta；遊戲局不存在時什麼都不刪，筆數都是 0
 */
export async function deleteGameData(db: WPStudBookDatabase, gameId: string): Promise<RowCounts> {
  return db.transaction('rw', gameTables(db), async () => {
    const counts = {} as RowCounts
    for (const name of GAME_TABLES) {
      if (name === 'games') {
        counts.games = (await db.games.get(gameId)) ? 1 : 0
        await db.games.delete(gameId)
      } else {
        counts[name] = await db.table(name).where('gameId').equals(gameId).delete()
      }
    }
    return counts
  })
}

/** 一局在 GAME_TABLES 各表的筆數（需求規格 12.1「顯示筆數」）；遊戲局不存在時丟出錯誤 */
export async function countGameRows(db: WPStudBookDatabase, gameId: string): Promise<RowCounts> {
  return db.transaction('r', gameTables(db), async () => {
    if (!(await db.games.get(gameId))) throw new Error(`找不到遊戲局：${gameId}`)
    const counts = {} as RowCounts
    for (const name of GAME_TABLES) {
      counts[name] =
        name === 'games' ? 1 : await db.table(name).where('gameId').equals(gameId).count()
    }
    return counts
  })
}

/** 整局資料各表的筆數 */
export function countRows(data: GameData): RowCounts {
  const counts = {} as RowCounts
  for (const name of GAME_TABLES) counts[name] = data[name].length
  return counts
}

/** 各表筆數的合計 */
export function totalRows(counts: RowCounts): number {
  return GAME_TABLES.reduce((sum, name) => sum + counts[name], 0)
}
```

```ts
/** 備份檔的格式識別 */
export const BACKUP_FORMAT = 'wpstudbook-backup'

/** 備份檔裡的遊戲局摘要 */

  name: string
  startYear: number
  currentYear: number

/** 備份檔的內容：欄位順序就是 JSON 的順序，sha256 是其他欄位的雜湊 */

  appVersion: string

  counts: RowCounts
  collections: GameData

/** 匯出完成時顯示的摘要（DATA-07） */
export interface BackupSummary {
  fileName: string
  gameName: string
  counts: RowCounts
  total: number
  /** 檔案大小（位元組） */
  size: number
  schemaVersion: number
  appVersion: string
  exportedAt: string
  /** 是否 gzip 壓縮；瀏覽器不支援 CompressionStream 時為 false，輸出 .json（DATA-06） */
  compressed: boolean

/** 匯出的備份：檔名、檔案內容與摘要 */
export interface ExportedBackup {
  fileName: string
  bytes: Uint8Array<ArrayBuffer>
  summary: BackupSummary
}

/**
 * 匯出一局的完整備份（需求規格 12.2、DATA-07）：先取 now 作為匯出時間，再以唯讀交易讀出整局（一致快照），
 * 序列化、雜湊與壓縮在交易外進行。有 CompressionStream 時 gzip 成 .json.gz，否則輸出 .json（DATA-06）。
 * 只讀：不觸發下載，也不記錄最近備份時間，呼叫端交出檔案後以 recordBackup 記錄。遊戲局不存在時丟出錯誤
 */
export async function exportBackup(
  db: WPStudBookDatabase,
  gameId: string,
  now: Date = new Date(),
): Promise<ExportedBackup> {
  const exportedAt = now.toISOString()
  const data = await readGameData(db, gameId)
  const game = data.games[0]!
  const counts = countRows(data)
  const body: Omit<BackupFile, 'sha256'> = {
    format: BACKUP_FORMAT,
    schemaVersion: SCHEMA_VERSION,
    appVersion: APP_VERSION,
    exportedAt,
    game: {
      id: game.id,
      name: game.name,
      startYear: game.startYear,
      currentYear: game.currentYear,
    },
    counts,
    collections: data,
  }
  const text = JSON.stringify({ ...body, sha256: await sha256Hex(JSON.stringify(body)) })
  const compressed = typeof CompressionStream === 'function'
  const plain = new TextEncoder().encode(text)
  const bytes = compressed ? await gzip(plain) : plain
  const fileName = backupFileName(game.name, game.currentYear, now, compressed)
  return {
    fileName,
    bytes,
    summary: {
      fileName,
      gameName: game.name,
      counts,
      total: totalRows(counts),
      size: bytes.length,
      schemaVersion: SCHEMA_VERSION,
      appVersion: APP_VERSION,
      exportedAt,
      compressed,
    },
  }
}

/** Windows 檔名不允許的字元（另外還有控制字元） */
const UNSAFE_FILE_CHARS = '\\/:*?"<>|'

/**
 * 備份檔名（技術設計 4.3）：WPStudBook_<局名>_<目前遊戲年>年_<YYYYMMDD-HHmmss>，加 .json.gz 或 .json；
 * 時間用本機時間，局名裡 Windows 檔名不允許的字元與控制字元換成 _
 */
export function backupFileName(
  gameName: string,
  currentYear: number,
  at: Date,
  compressed: boolean,
): string {
  const pad = (value: number) => String(value).padStart(2, '0')
  const date = `${at.getFullYear()}${pad(at.getMonth() + 1)}${pad(at.getDate())}`
  const time = `${pad(at.getHours())}${pad(at.getMinutes())}${pad(at.getSeconds())}`
  const name = Array.from(gameName, (char) =>
    char < ' ' || UNSAFE_FILE_CHARS.includes(char) ? '_' : char,
  ).join('')
  return `WPStudBook_${name}_${currentYear}年_${date}-${time}${compressed ? '.json.gz' : '.json'}`
}

/** 文字的 UTF-8 位元組的 SHA-256，小寫十六進位 */
export async function sha256Hex(text: string): Promise<string> {
  const digest = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(text))
  return Array.from(new Uint8Array(digest), (byte) => byte.toString(16).padStart(2, '0')).join('')
}

/** 以 CompressionStream 壓縮成 gzip */
async function gzip(bytes: Uint8Array<ArrayBuffer>): Promise<Uint8Array<ArrayBuffer>> {
  const stream = new Blob([bytes]).stream().pipeThrough(new CompressionStream('gzip'))
  return new Uint8Array(await new Response(stream).arrayBuffer())
}
```

```ts
/**
 * 讀取備份檔的拒絕原因（DATA-04）：
 * - gzip：錯誤或截斷的 gzip
 * - gzip-unsupported：檔案是 gzip，但瀏覽器不支援 DecompressionStream
 * - not-json：截斷或不是 JSON（UTF-8 嚴格解碼或 JSON.parse 失敗）
 * - not-backup：格式識別不符，或結構版本不是 1 以上的整數
 * - future-version：結構版本比目前新；version 是檔案的結構版本
 * - hash：雜湊不符
 */
export type BackupRejection =
  | { kind: 'gzip' }
  | { kind: 'gzip-unsupported' }
  | { kind: 'not-json' }
  | { kind: 'not-backup' }
  | { kind: 'future-version'; version: number }
  | { kind: 'hash' }

/** 還原前的預覽（需求規格 12.2）；schemaVersion 是檔案原本的結構版本 */
export interface BackupPreview {
  gameName: string
  startYear: number
  currentYear: number
  exportedAt: string
  schemaVersion: number
  appVersion: string
  counts: RowCounts
  total: number
}

/** 驗證過的備份：內容已遷移到目前的結構版本 */
export interface VerifiedBackup {
  file: BackupFile
  preview: BackupPreview
}

export type BackupReadResult =
  { status: 'ok'; backup: VerifiedBackup } | { status: 'rejected'; reason: BackupRejection }

/** 讀取備份的步驟：解壓、解析、驗證 */
export type BackupReadStep = 'decompress' | 'parse' | 'verify'

/** 把某一版的備份內容遷移到下一版 */
export type BackupMigration = (file: BackupFile) => BackupFile

/** 逐版遷移，鍵是遷移前的結構版本。結構版本 1 是第一版，目前沒有遷移（技術設計 4.3） */
export const BACKUP_MIGRATIONS: Readonly<Record<number, BackupMigration>> = {}

export interface ReadBackupOptions {
  /** 遷移表；省略時為 BACKUP_MIGRATIONS */
  migrations?: Readonly<Record<number, BackupMigration>>
  /** 目前的結構版本；省略時為 SCHEMA_VERSION */
  currentVersion?: number
  /** 每一步開始時收到步驟（需求規格 12.2「大型檔案顯示進度」） */
  onProgress?: (step: BackupReadStep) => void
}

/**
 * 讀取並驗證備份檔（需求規格 12.2、DATA-04、DATA-05）：依序解壓、解析、格式、版本、雜湊、遷移，
 * 任一步不通過就回傳拒絕與原因，不丟例外（第 5 章的資料來源異常）。開頭是 1F 8B 時當作 gzip，
 * 其他當作未壓縮的 JSON。雜湊在遷移前比對。只讀，不碰資料庫
 */
export async function readBackup(
  bytes: Uint8Array<ArrayBuffer>,
  options: ReadBackupOptions = {},
): Promise<BackupReadResult> {
  const { migrations = BACKUP_MIGRATIONS, currentVersion = SCHEMA_VERSION, onProgress } = options
  const reject = (reason: BackupRejection): BackupReadResult => ({ status: 'rejected', reason })
  let plain = bytes
  if (bytes[0] === 0x1f && bytes[1] === 0x8b) {
    onProgress?.('decompress')
    if (typeof DecompressionStream !== 'function') return reject({ kind: 'gzip-unsupported' })
    try {
      plain = await gunzip(bytes)
    } catch {
      return reject({ kind: 'gzip' })
    }
  }
  onProgress?.('parse')
  let parsed: unknown
  try {
    parsed = JSON.parse(new TextDecoder('utf-8', { fatal: true }).decode(plain))
  } catch {
    return reject({ kind: 'not-json' })
  }
  onProgress?.('verify')
  if (!isObject(parsed) || parsed.format !== BACKUP_FORMAT) return reject({ kind: 'not-backup' })
  const version = parsed.schemaVersion
  if (typeof version !== 'number' || !Number.isInteger(version) || version < 1) {
    return reject({ kind: 'not-backup' })
  }
  if (version > currentVersion) return reject({ kind: 'future-version', version })
  const { sha256, ...body } = parsed
  if (sha256 !== (await sha256Hex(JSON.stringify(body)))) return reject({ kind: 'hash' })
  let file = parsed as unknown as BackupFile
  for (let from = version; from < currentVersion; from++) {
    const migrate = migrations[from]
    if (!migrate) throw new Error(`缺少結構版本 ${from} 的遷移`)
    file = migrate(file)
  }
  return { status: 'ok', backup: { file, preview: previewOf(file, version) } }
}

/** 預覽：局名、起始年與目前遊戲年、匯出時間、檔案原本的結構版本、應用版本、各集合筆數與總筆數 */
function previewOf(file: BackupFile, schemaVersion: number): BackupPreview {
  return {
    gameName: file.game.name,
    startYear: file.game.startYear,
    currentYear: file.game.currentYear,
    exportedAt: file.exportedAt,
    schemaVersion,
    appVersion: file.appVersion,
    counts: file.counts,
    total: totalRows(file.counts),
  }
}

/** 以 DecompressionStream 解開 gzip；錯誤或截斷時丟出例外 */
async function gunzip(bytes: Uint8Array<ArrayBuffer>): Promise<Uint8Array<ArrayBuffer>> {
  const stream = new Blob([bytes]).stream().pipeThrough(new DecompressionStream('gzip'))
  return new Uint8Array(await new Response(stream).arrayBuffer())
}

/** 是不是 null 以外的物件；陣列也算，缺少的欄位由之後的檢查擋下 */
function isObject(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null
}
```

```ts
  // 欄位：集合剛好是 GAME_TABLES，每一列是物件、主鍵欄位的型別正確、屬於這一局；摘要與 games 那一列一致
  const collections: unknown = file.collections
  if (!isObject(collections)) return { kind: 'field', path: 'collections' }
  for (const name of Object.keys(collections)) {
    if (!GAME_TABLES.includes(name as GameTableName)) {
      return { kind: 'field', path: `collections.${name}` }
    }
  }
  for (const name of GAME_TABLES) {
    if (!Array.isArray(collections[name])) return { kind: 'field', path: `collections.${name}` }
  }
  const tables = collections as Record<GameTableName, Record<string, unknown>[]>
  for (const name of ['games', 'settings'] as const) {
    if (tables[name].length !== 1) return { kind: 'field', path: `collections.${name}` }
  }
  const game = tables.games[0]!
  for (const name of GAME_TABLES) {
    for (const [index, row] of tables[name].entries()) {
      const path = `collections.${name}[${index}]`
      if (!isObject(row)) return { kind: 'field', path }
      for (const [field, type] of PRIMARY_KEYS[name]) {
        if (typeof row[field] !== type) return { kind: 'field', path: `${path}.${field}` }
      }
      if (name !== 'games' && row.gameId !== game.id) {
        return { kind: 'field', path: `${path}.gameId` }
      }
    }
  }
  const summary: unknown = file.game
  const fields = ['id', 'name', 'startYear', 'currentYear'] as const
  if (!isObject(summary) || fields.some((field) => summary[field] !== game[field])) {
    return { kind: 'field', path: 'game' }
  }
  // 重複：各表主鍵不重複，所有 id 跨表也不重複（還原時共用一張新舊對照表）
  const ids = new Set<unknown>()
  for (const name of GAME_TABLES) {
    const keys = new Set<string>()
    for (const row of tables[name]) {
      const key = PRIMARY_KEYS[name].map(([field]) => String(row[field])).join('+')
      if (keys.has(key)) return { kind: 'duplicate-id', collection: name, id: key }
      keys.add(key)
      if (row.id === undefined) continue
      if (ids.has(row.id)) return { kind: 'duplicate-id', collection: name, id: String(row.id) }
      ids.add(row.id)
    }
  }
  // 關聯：資料列層級的引用都找得到
  for (const [name, field, target] of RELATIONS) {
    const [keyField] = PRIMARY_KEYS[target][0]!
    const targets = new Set(tables[target].map((row) => row[keyField]))
    for (const [index, row] of tables[name].entries()) {
      const value = field
        .split('.')
        .reduce<unknown>((item, part) => (isObject(item) ? item[part] : undefined), row)
      if (value !== undefined && !targets.has(value)) {
        const path = `collections.${name}[${index}].${field}`
        return { kind: 'missing-relation', path, value: String(value) }
      }
    }
  }
  // 筆數：counts 的鍵與各集合的筆數相符
  const counts: unknown = file.counts
  const declared = isObject(counts) ? counts : {}
  for (const name of new Set([...GAME_TABLES, ...Object.keys(declared)])) {
    if (declared[name] !== (tables as Record<string, unknown[]>)[name]?.length) {
      return { kind: 'count', collection: name }
    }
  }
  return undefined
```

```ts
export interface RestoreOptions {
  /** 備份檔名，記在還原來源 */
  fileName: string
  /** 新局的局名；省略時用備份的局名 */
  name?: string
  /** 還原的時間；省略時為現在 */
  now?: Date
  /** 每張表寫完後收到已寫筆數與總筆數（需求規格 12.2「大型檔案顯示進度」） */
  onProgress?: (written: number, total: number) => void
}

/**
 * 把驗證過的備份還原成新遊戲局（需求規格 12.2）：在一個 rw 交易內寫入全部資料表，失敗時整筆回復。
 * 識別全部重新產生（remapIds），原局還在也不相撞。新局的局名用 name（去除前後空白），省略時用備份的局名，
 * 可以與既有的局重複；建立時間為還原的時間，更新時間沿用備份的；應用版本為目前版本；
 * 最近備份時間為備份的匯出時間（內容與備份檔相同）；還原來源記檔名、匯出時間、原局名、
 * 備份的應用版本與檔案原本的結構版本（DATA-05）。不切換目前遊戲局。局名空白時丟出 RangeError，什麼都不寫
 */
export async function restoreBackup(
  db: WPStudBookDatabase,
  backup: VerifiedBackup,
  options: RestoreOptions,
): Promise<GameRow> {
  const { file, preview } = backup
  const name = (options.name ?? file.game.name).trim()
  if (name === '') throw new RangeError('局名不能空白')
  const data = remapIds(file.collections)
  const game: GameRow = {
    ...data.games[0]!,
    name,
    createdAt: (options.now ?? new Date()).toISOString(),
    appVersion: APP_VERSION,
    lastBackupAt: file.exportedAt,
    restoredFrom: {
      fileName: options.fileName,
      exportedAt: file.exportedAt,
      gameName: file.game.name,
      appVersion: file.appVersion,
      schemaVersion: preview.schemaVersion,
    },
  }
  await addGameData(db, { ...data, games: [game] }, options.onProgress)
  return game
}
```

```ts
export async function deleteGame(
  db: WPStudBookDatabase,
  gameId: string,
  typedName: string,

    const counts = await deleteGameData(db, gameId)
    if ((await currentGameId(db)) === gameId) await db.meta.delete(CURRENT_GAME_KEY)
    return { status: 'done', value: counts, warnings: [] }

 * 什麼都不刪；第二道確認由畫面負責。在一個交易內清空資料庫的每一張表（含 meta）
 */
export async function deleteAllGames(
  db: WPStudBookDatabase,
  typedPhrase: string,
): Promise<WriteResult<DeletedAll, DeleteAllBlock>> {
  return db.transaction('rw', db.tables, async () => {
    if (typedPhrase.trim() !== DELETE_ALL_PHRASE) {
      return { status: 'blocked', blocks: [{ kind: 'phrase-mismatch' }] }
    }
    const games = await db.games.count()
    let rows = 0
    for (const table of gameTables(db)) rows += await table.count()
    for (const table of db.tables) await table.clear()
    return { status: 'done', value: { games, rows }, warnings: [] }
  })
}
```
