# 儲存母馬 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `src/storage/` 加上母馬的寫入操作：新增市場母馬（用途由任務配對推出、例外補入、8.3 親系統檢查、同名買回提示）、修改用途、賣出、更正離圈原因（含撤銷離圈）、買回與回歸、轉場、今年計畫、活力更正與手動資料更正；並讓事件記下來源與時點、加上母馬年度資料表與手動父母名，順手處理 PR #8 延後的四項 Minor（技術設計 4.3「寫入操作」）。

**Architecture:** 儲存子計畫 2（事件與寫入操作）拆成四塊，本計畫是第 2 塊（2-1 寫入基礎、系與補系 → 2-2 母馬 → 2-3 配種與產駒 → 2-4 後繼與接替）。寫入操作沿用 2-1 的做法：每個操作一個 rw 交易（`runWrite`），交易內從資料列重新組出 core 的輸入並重做檢查，回傳 `done`、`blocked` 或 `unconfirmed`，阻止與待確認時什麼都不寫。市場母馬的用途不由畫面直接給系與代數，而是由任務看板上的配對推出（`mare-assignment.ts`，新增、修改用途與買回共用）。規則判斷仍然交給 core：看板用 `listBoard`，8.3 用 `checkSubstituteMare`，姊妹用 `entrySisterStatus`，馬齡用 `ageInYear`，core 本身不改。

**Tech Stack:** TypeScript（strict）、Dexie 4、Vitest、fake-indexeddb。不新增套件。

**需求規格 4.6、5.2、5.3 引退、阻止與資料原則**

> - 無法再生產的母馬不能賣出；24 歲受胎者會佔用隔年名額，所以 24 歲是最後值得配種的年齡。
> | 策略選擇或受市場限制 | 警告並要求確認，保存確認紀錄 | 活血少於 8 種、4 代內有重複的馬、血統資料不足、八系親系統重複、替代母馬的親系統與其他系或同代其他替代母馬重複、零代種牡馬例外配市場母馬、替換種牡馬的系統不符 |
> | 資料來源異常 | 停止該檔或該筆套用，資料不變 | 欄數或必要欄位不符、牧場範圍異常、身分衝突、無法辨識的狀態文字 |
> - **未知值不是零值**：空白、未知、`0` 與布林否保持不同語意，匯入、備份、還原都不互相轉換。
> - **歷史只新增或更正**：賣出、引退、接替、轉場、改名、種牡馬更換與資料更正都保存事件，不靜默改寫或刪除。

**6.2、6.4 身分與馬名**

> - 既有紀錄沒有能力番号（例如手動新增）：唯一馬名相符，且出生年相同或未填時，才輔助配對並補入；既有紀錄已有不同能力番号時為衝突，不得覆寫。
> - 繁殖牝馬與種牡馬馬名經匯入確認後唯讀；匯入時同一身分馬名不同，列為衝突並略過。手動輸入、尚未經匯入確認的馬名可以更正，保存更正歷程（例：11.6 的名稱不符）。
> - 手動新增時填的父母名與自身父系比照手動馬名：只輔助身分配對，與匯入值不同不算衝突，匯入時改用匯入值。經匯入確認前，手動新增的馬名、能力番号、出生年、父母名與自身父系都可以更正並保存歷程（2026-09-26 決定）。
> - 同時保存完整馬名（第 1 欄）與去除 `(外)`、`[地]` 前綴的基本馬名，主要顯示完整馬名，兩者都可搜尋。產駒名稱見 9.4。
> - `(外)`、`[地]` 前綴後面一定接著馬名。只有前綴、沒有馬名時屬於資料異常（5.2）：手動輸入時提示並不建立；匯入時警告並略過該筆，不寫入。

**7.3、7.6 零代種牡馬的例外補入、補血與補母系**

> - **零代種牡馬原則只配自家母馬**：建立新系與補系補公系（7.6）的零代市場種牡馬，原則上配自家母馬，讓新系第一代帶有原系的血。自家母馬不足（例如一直生不出母駒、快要斷血）時，可例外從市場補入替代母馬：警告並確認，保存原因（10.3）；產駒代數依 8.2 仍是任務的產出代數，只要替代母馬的親系統符合 8.3，活血一樣能湊滿。建系起點不受此限。
> - **補血**：市場母馬為零代，從任務新增並登記為替代第 q 系 N 代（8.4）；產駒依 8.2 承接下一代，不改既有代數。
> - **補母系**：第 q 系 N 代母馬群從未成立、也生不出母駒時使用；已成立的母馬群不足時用補血，不補母系。宣告後，配第 q 系 N 代母馬群的任務照常出現，可在底下登記替代第 q 系 N 代的市場母馬；登記、代數與親系統檢查都與補血相同，來源記為市場補系（2026-09-23 決定）。

**8.1～8.9 繁殖牝馬**

> 繁殖圈是據點 `32`～`35` 在養的母馬。「來源」與「目前狀態」分開保存並可同時顯示：來源為結構化事件（市場創系、市場補血、市場混血、市場補系、所屬競走馬引退轉入、其他，可附備註）；狀態為生產中或已離圈（售出、定年引退）。
> - 某代第一匹自家母駒以暫定保留或正式保留轉入時，該代立即成立；成立後不可回溯，母馬離圈只改目前狀態。
> - 市場母馬記錄替代的系與代數（建系起點記為第 1 系起點用）；自身父系可為八系以外或留空，不得改寫成替代系。畫面顯示「替代第 q 系」或「第 1 系起點用」，不得顯示為她屬於該系。
> - 替代母馬的親系統會跟後代 3 代前的其他祖先撞在一起時，警告並確認（10.3），因為活血會少於 8 種。判斷方式：自身父系經系統對照表取得的親系統，符合下列任一項：
>   - 與第 q 系以外任一已成立系目前的親系統相同。
>   - 與同一代、替代其他系的市場母馬親系統相同（她們會一起出現在後代的 3 代前）。替代同一系的母馬之間不比較。
> - 與第 q 系相同（最理想），或八系與同代其他替代母馬都沒用到的親系統（例如某系升格後留下的舊親系統），都能湊滿 8 種，不警告。自身父系留空或對照表查不到時無法判斷，只提示、不要求確認。
> - **新增入口**：任務看板每條配對的目標種牡馬底下，全年提供「手動新增」與「從候選 TXT 匯入」（11.7），包含建系起點、可開啟但尚未開啟的分支與暫停中的任務。系統依配對帶入替代的系與代數，使用者不另外選擇；例：第 1 系 4 代種牡馬底下新增 → 替代第 2 系 4 代；建系起點新增 → 第 1 系起點用。來源預設市場購入，據點由使用者選。零代市場種牡馬的配對（建立新系、補系補公系）原則配自家母馬，底下的新增標示為「例外補入」，需確認並填寫原因（7.3）。
> - 不經任務新增的母馬（例如混血用或尚未決定）從「待指定用途」清單新增，使用者指定前不進入配種任務。
> - 手動新增的能力番号、出生年、父母與自身父系可留空，由五月繁殖圈名單補齊；填了的父母與自身父系，匯入時依 6.4 改用匯入值。手動新增的馬名與已售出的母馬相同時，提示是否為買回；確認後依 8.5 處理，不建立新馬。
> - **修改用途**：市場母馬的用途可隨時在卡片上修改（改掛到另一條配對，或改為待指定用途），五月繁殖圈名單的預覽是最後把關（11.5）。已有八系指定配種紀錄者，舊紀錄保留規則快照，新用途從下一次配種生效。自家母駒的系與代數由出生紀錄決定，不能修改。
> - 玩家只能賣出母馬，不能讓她引退：卡片只提供「賣出」（顯示影響並保存事件），不提供退役操作。賣出可以事先在管理器登記，也可以不登記，由五月匯入依缺席判定。引退只因定年，由五月匯入判定（11.5），可人工更正。
> - **撤銷離圈**：誤登記的賣出或定年引退可以撤銷，回到生產中，不建立回歸事件；自家母駒回到離圈前的接替狀態，但圈內已有另一匹正式保留的姊妹時改為候選（8.9）（2026-09-26 決定）。
> - 定年可調，預設 25 歲。達定年減 1 歲（預設 24 歲）時提示「最後值得配種的年齡」；達定年時不列入任務。
> - **買回**：已售出的母馬再進入繁殖圈（五月繁殖圈名單或候選 TXT 以能力番号＋出生年配對到，或手動新增時確認）→ 恢復生產中並建立回歸事件，沿用原識別與血緣。自家母駒沿用出生紀錄的系與代數，姊妹狀態依 8.9 重新判定；市場母馬沿用原用途，從任務新增或匯入時改用該配對的用途，預覽顯示原用途與新用途。
> - 離圈只改狀態；母馬與其產駒、配種、接替紀錄永久保留，仍是血緣表中的祖先。
> 據點依繋養牧場番号顯示（第 3 章），`33` 不得分成兩個。據點變更保存原據點、新據點、年、時點與來源；手動變更時時點可以留空（2026-09-26 決定）。繁殖牝馬資料不使用馬主番号。
> - 三種狀態：不適用、待更新、已確認數值；匯入的 `0` 是有效值。
> - 保存 0～100 目前總活力與活力増強中；只有前置 `*` 才是増強，`100` 不代表増強。
> - 每年保存 5 月與 7 月兩份快照，顯示最新一份，兩份可查；人工更正保存歷程。
> - 今年計畫：待定、八系指定配種、自由配種、等待活力、輪休，可篩選。活力建議門檻可調，只影響提示與排序。
> - 仔出 0～15 整數，空白為未取得；11～15 標示「CE 擴充值」但合法。
> - 仔出、繁殖年數、繁殖頭數按年保存，顯示最新值。
> - 狀態：暫定保留、候選、正式保留、已被取代、已售出。自家母駒轉入時，姊妹不在圈內 → 暫定保留；已有姊妹在圈 → 候選。
> - 被取代的姊妹缺席五月名單時記為售出。她之後被買回（8.5）時依回歸當下重新判定：其他姊妹都已離圈 → 暫定保留；仍有姊妹在圈 → 候選。使用者可改選正式保留（例：妹妹一直生不出母駒，買回姊姊並賣出妹妹），每次決定保存事件。

**11.5、11.7 之後的匯入會呼叫本計畫的操作**

> - **用途把關**：預覽列出今年新進與回歸的市場母馬，包括上次五月匯入後以手動或候選 TXT 登記的，以及名單上第一次出現的，並顯示目前用途。套用前可改掛到另一條配對或改為待指定用途（8.4）。這是修正登記錯誤的最後把關；購入母馬通常到隔年五月才第一次配種，所以此時修改不影響已執行的配種。
> - **回歸**：已離圈的母馬再出現（例如買回）→ 恢復生產中並建立回歸事件，沿用原識別、血緣、自身父系、母馬群與代數；姊妹狀態依 8.9 重新判定。五月前已由候選 TXT 或手動新增登記買回者，沿用已登記的結果。
> - **已登記賣出卻仍在名單**：列入待核對，由使用者撤銷賣出紀錄或視為買回。
> - 父馬、母馬、父系空白時補齊，手動輸入、尚未經匯入確認的改用匯入值（6.4）；與其他既有值不同 → 衝突並略過。父系不得寫成替代系。
> - 只建立勾選者；已在圈者略過；已售出者依 8.5 買回，預覽標示「買回」並顯示原用途與新用途（自家母駒沿用出生紀錄的系與代數）。原牧場只記為來源，據點由使用者選。

**12.1、12.5 遊戲年與索引**

> - 目前遊戲年只由使用者更新（手動，或匯入時確認推進），不依電腦日期；更新前顯示影響並確認。手動往回改時，不能早於起始年，也不能早於這一局最後一筆紀錄的年份（歷程事件的年份與馬的出生年）：多推了一年、還沒留下新紀錄時可以改回；要回到舊存檔的狀態，用檢查點回溯（12.4）（2026-09-26 決定）。

**第 15 章的情境**

> - **ID-04**：已售出或定年引退的母馬以相同能力番号與出生年出現在五月繁殖圈名單 → 沿用原識別並建立回歸事件。
> - **ID-08**：經匯入確認的繁殖牝馬馬名不能手動修改，手動輸入、尚未經匯入確認的馬名可以更正並保存歷程；匯入時同一身分馬名不同 → 衝突並略過。
> - **ID-13**：手動新增的母馬填了父母名與自身父系，五月名單的值不同 → 不算衝突，改用匯入值；經匯入確認前，這些欄位與馬名、能力番号、出生年都可以手動更正並保存歷程。
> - **LINE-29**：替代第 q 系的市場母馬，親系統與第 q 系以外的已成立系相同 → 警告並確認，確認後可保存；與第 q 系相同，或八系與同代其他替代母馬都沒用到 → 不警告。
> - **LINE-38**：替代第 5 系 3 代與替代第 7 系 3 代的市場母馬，親系統是同一個八系都沒用到的親系統 → 登記第二匹時警告並確認（兩匹會一起出現在第 1～4 系 6 代的 3 代前）；兩匹都替代第 5 系 → 不比較、不警告。
> - **LINE-39**：第 5 系 12 代母馬群從未成立並宣告補母系 → 出現「第 1 系 12 代 × 第 5 系 12 代母馬群 → 第 1 系 13 代」，可登記替代第 5 系 12 代的市場母馬，來源記為市場補系；母馬群已成立時不能補母系，改用補血。
> - **MARE-05**：在「第 6 系 6 代種牡馬 × 第 3 系 6 代母馬」任務的種牡馬底下新增市場母馬（手動或候選 TXT）→ 記為替代第 3 系 6 代、來源市場，只出現在第 3 系 6 代母馬群，不宣告屬於第 3 系。
> - **MARE-08**：母馬卡片 → 只有「賣出」、沒有「退役」；賣出後離開母馬群，紀錄可查。
> - **MARE-13**：活力 `0`、`73`、`100` → 都能保存並以活力條顯示；空白顯示「待更新」，不視為 0。
> - **MARE-14**：匯入 `*13` → 13 且増強中；`13` → 13 且非増強；不帶 `*` 的 `100` → 非増強。
> - **MARE-19**：據點在 `32`～`35` 間變更 → 保存原據點、新據點、年、時點與來源。
> - **MARE-22**：今年計畫 → 可設為待定、八系指定配種、自由配種、等待活力、輪休並篩選。
> - **MARE-26**：從「待指定用途」清單新增母馬 → 標示待指定用途，指定前不進入任務。
> - **MARE-28**：已有八系指定配種紀錄的市場母馬修改用途 → 舊紀錄保留規則快照，新用途從下一次配種生效；自家母駒不能修改系與代數。
> - **MARE-29**：手動新增的母馬馬名與已售出的母馬相同 → 提示是否為買回；確認後沿用原識別並建立回歸事件，不建立新馬。
> - **MARE-30**：妹妹已售出後買回被取代的姊姊 → 姊姊回歸為暫定保留，可改選正式保留；妹妹仍在圈時姊姊為候選。
> - **MARE-31**：在零代市場種牡馬的配對（建立新系、補系補公系）底下新增母馬 → 標示「例外補入」，需確認並填寫原因；建系起點新增起點母馬不需確認。
> - **MARE-32**：誤按賣出後撤銷 → 回到生產中與原本的接替狀態（例：正式保留），不建立回歸事件；圈內已有另一匹正式保留的姊妹時改為候選。
> - **CAND-07**：已售出的母馬出現在候選 TXT → 預覽標示買回，恢復生產中並建立回歸事件；自家母駒沿用原系與代數，市場母馬改用這次配對的用途，預覽顯示原用途與新用途。
> - **MAY-05**：父馬、母馬、父系空白 → 補齊；手動輸入、尚未經匯入確認 → 改用匯入值（ID-13）；與其他既有值不同 → 衝突並略過，父系不寫成替代系。

**技術設計 4.2 姊妹接替**

> - **姊妹接替**（`sisters.ts`）：同父同母以父母的內部識別判斷，任一方不明就不算姊妹。「在圈」指在繁殖圈內，被取代但還沒賣出的姊妹也算。選定正式保留時，只把在圈而且列入任務的姊妹改為已被取代。輸入有在圈但狀態是已售出的母馬時丟 `RangeError`。儲存層不把接替狀態改成已售出：自家母駒售出或定年引退時保留離圈前的接替狀態，已售出由在圈狀態表示，畫面在售出時顯示已售出；姊妹判斷只看在圈的母馬，結果不變。撤銷誤登記的離圈時就能回到原本的接替狀態（需求規格 8.5）（使用者 2026-09-26 決定）。

**技術設計 4.3「寫入操作」（全文）**

> #### 寫入操作
>
> 使用者的操作與之後 CE 匯入的套用，都經由儲存層的寫入操作（使用者 2026-09-26 確認）。共用的做法：
>
> - **一個操作一個交易**：每個操作在一個 rw 交易內完成：先讀遊戲局確認存在，再從資料列重新組出核心的輸入並重做檢查，最後寫入資料列與事件，並把遊戲局的更新時間設為現在。設定、代表色這類不寫事件的操作也更新，備份提醒（需求規格 12.2）以此判斷有沒有未備份的變更。操作可以包進呼叫端的外層交易（Dexie 的巢狀交易），CE 匯入以此在單一交易內套用多個操作（4.4）。
> - **結果**：完成時附寫入的結果與確認過的警告；阻止時附原因；有警告而呼叫端沒有帶確認時回傳待確認並附警告。阻止與待確認都什麼都不寫。畫面先呼叫一次取得警告，使用者確認後帶確認再呼叫；儲存層在交易內重做檢查，畫面漏掉檢查也存不進違規資料（需求規格 5.2）。確認過的警告存在這次操作的事件上。
> - **錯誤**：使用者的輸入或操作違反規則時回傳阻止；畫面不會送出的狀況（找不到資料列、屬於其他局、對已撤銷的宣告再撤銷）丟出帶識別的錯誤；資料列內容互相矛盾時丟 `RangeError`。
> - **事件**：會留下年份的操作一律寫事件，事件的年份是操作當時的目前遊戲年；遊戲年變更本身不寫事件。對象欄位填事件關於的馬匹、系位置或子系統，例如種牡馬狀態變更同時填系位置與馬匹；母馬的事件只填馬匹，因為替代母馬不屬於她替代的系（需求規格 8.3）。事件另記來源與時點（見「資料表」）。
> - **手動建立的馬**：完整馬名必填，只有前綴時阻止（需求規格 6.4）；馬名來源為手動輸入。能力番号與出生年選填：能力番号格式不符時阻止；出生年晚於目前遊戲年時阻止；能力番号與出生年都和這一局既有的馬相同時阻止並指出那匹馬（6.2：同一匹馬，應選既有的）。父母名與父系選填：父母名去掉前綴後存基本馬名，只有前綴時阻止；有填時，父母名與父系的來源為手動輸入（6.4：只輔助身分配對，匯入時改用匯入值，經匯入確認前可以更正）。
> - **系統名稱**：子系統、親系統、分出來源與父系都經 `normalizeSystemName`，必填的欄位空白時阻止。
> - **親系統重複的警告**：修改對照表、開啟新系、變更系統名稱或補入、替換零代種牡馬後，親系統因此改變的已開啟的系，與其他系目前的親系統相同時警告並確認（需求規格 7.2、LINE-03）。
>
> 各操作的規則：
>
> - **目前遊戲年**（需求規格 12.1）：往後可以改成任何年份；往回不能早於起始年，也不能早於最後紀錄年，也就是這一局事件的最大年份與馬的最大出生年，阻止時附可以改的最早年份。
> - **設定**：定年、高齡提醒年齡、種牡馬提醒年齡都要是 1 以上的整數；不寫事件，新設定從下一次判斷開始生效（MARE-10）。
> - **系統對照表**（需求規格 7.2）：新增時子系統不能已登錄，分出來源不能是自己；修改親系統（升格）或分出來源時（分出來源省略表示不變，傳 `null` 才清除），事件記原值、新值與年份。不提供刪除，也不改子系統名稱：打錯時新增正確的一筆，沒有系在用的那一筆不影響任何判斷。
> - **開啟新系**（需求規格 7.1、7.3）：該系要在任務看板的可開啟分支中（4.2；補公系進行中的系不能開分支）。填子系統、親系統、代表色（`#rrggbb`，自動分配由畫面預填）與零代市場種牡馬：新建，或選既有的市場馬（沒有出生紀錄、不是牝馬），因為補公系可以沿用建系時的零代種牡馬，兩處共用同一種輸入。子系統沒登錄時新增一筆，已登錄但親系統不同時改為填入的親系統。寫入系位置（開啟年為目前遊戲年）、零代的在崗任用與開啟事件。開啟後不提供撤銷（7.1 位置固定），開錯時以系統名稱變更與零代種牡馬替換更正。
> - **系統名稱變更**（需求規格 7.1、7.2、LINE-06）：系要已開啟，新名稱要與目前不同；可一併填親系統，照對照表的規則新增或修改，沒填而對照表查不到時親系統未知。事件記原名稱、新名稱與年份；「該系用過的舊名」（7.2）由開啟與名稱變更的事件查得。
> - **代表色**：只檢查格式，不寫事件。
> - **補入或替換零代市場種牡馬**（需求規格 7.6、7.7）：對象是某系建系的零代，或某次未撤銷的補公系宣告。那一格已有在崗或已指定的種牡馬時阻止（先標示前任引退，再替換）；選的馬已在這一格任用過時阻止。格是空的（補公系第一次選定）不需原因；只剩已離場的是替換，附 7.7 的原因（弟弟較優、前任引退、無法供用、斷血補系、遊戲依史實引退、其他，可附說明），生效年為目前遊戲年。以 `checkMarketStallionSystem` 比對他的父系，子系統不同時警告並確認，確認後該系的子系統改為他的父系並寫名稱變更事件，事件也記上這匹種牡馬；父系不明時不比較。
> - **種牡馬狀態**（需求規格 7.7）：在崗或已被取代的種牡馬可以標示退出生產行列或已引退；更正回在崗只在同一格沒有其他在崗時可以，否則阻止（換人用更換現任）。原本已被取代、誤標為退出或引退的，可以更正回已被取代，只在同一格另有在崗時可以（使用者 2026-09-26 決定）；其他情況的已被取代只由更換現任設定，預定後繼的取消也不在這裡。同一匹馬同時有建系與補公系的零代任用時，引退逐任用標示（使用者 2026-09-26 決定），要不要一次標示全部由畫面決定。這些操作都維持每格（某系某代的一般任用，或同一次補公系的任用）最多一匹在崗；彙整八系快照時遇到同一格有兩匹以上在崗，丟 `RangeError`。
> - **斷血補系**（需求規格 7.6）：宣告時原因必填，在交易內組出八系快照以 `checkRestoration` 檢查，年度為目前遊戲年；補入的零代市場種牡馬另外選定。撤銷時設為已撤銷並寫事件，不因已有補系的配種或產駒而阻止：配種紀錄的規則快照自帶補公系標記，補入的任用留著，快照略過已撤銷宣告底下的任用；撤銷後可以重新宣告。
> - **母馬的用途**（需求規格 7.3、8.3、8.4）：新增市場母馬、修改用途與從任務買回時，畫面傳任務看板上的一條配對（產出的系與代數）或待指定用途，不直接傳替代的系與代數。交易內組出八系快照，以 `listBoard` 從任務（含暫停中的）與可開啟分支的配對中找產出相同的那一條，找不到時阻止；一個產出只有一條配對，已宣告補公系時就是補公系配對。由配對推出：母馬群是起點時為第 1 系起點用，否則為替代配對母馬群的系與代數；種牡馬是零代而且不是建系起點（建立新系、補公系）時為例外補入，警告並確認、原因必填，其他情況不保存原因。替代母馬以 `checkSubstituteMare` 檢查親系統（8.3），同一代的其他替代母馬包含已離圈的、不含她自己；撞到時警告並確認，自身父系未知時只在完成的結果帶提示。
> - **新增市場母馬**（需求規格 8.4、MARE-05、MARE-29、MARE-31）：馬匹照手動建立的馬，性別為牝；在圈，不使該代成立；據點選填。來源由配對推出：補公系配對，或配對的母馬群已宣告補母系（未撤銷）時為市場補系；否則建系起點、推進原系與建立新系為市場創系，循環為市場補血；待指定用途由使用者選市場混血或其他；都可附備註。已售出的母馬中，基本馬名相同、能力番号與出生年也不矛盾（兩邊都有值而且不同才算矛盾）時，警告可能是買回並列出那些母馬：使用者確認不是買回就照常建立；是買回時畫面改用買回操作，不建立新馬。
> - **修改用途**（需求規格 8.4、MARE-28）：只限在圈的市場母馬（替代、起點用、待指定用途）；自家母駒與自由配種所生的系與代數由出生紀錄決定，不提供。與目前相同時阻止。來源記的是購入時的目的（8.1），不隨用途改變。已有的配種紀錄保留自己的規則快照，新用途從下一次配種生效，不另外處理。
> - **賣出**（需求規格 8.5、MARE-08）：只限在圈的母馬；已達定年時阻止（4.6「無法再生產的母馬不能賣出」），出生年不明時可以賣出。這條只適用於手動賣出；五月缺席的判定由 CE 匯入計畫接上，缺席時的馬齡可能已達定年。
> - **更正離圈原因**（需求規格 8.5、11.5、MARE-32）：已離圈的母馬可以改為售出、定年引退，或撤銷回到生產中；與目前相同時阻止。撤銷不建立回歸事件；自家母駒回到保留的接替狀態（4.2），原本是正式保留而圈內已有另一匹正式保留的姊妹時改為候選。
> - **買回與回歸**（需求規格 8.5、8.9、ID-04、MARE-30、CAND-07）：只限已離圈的母馬。自家母駒沿用出生紀錄的系與代數，接替狀態以 `entrySisterStatus` 重新判定，成為暫定保留時 `establishedGeneration` 設為 true（不改回）；自由配種所生只恢復生產中。市場母馬沒有傳用途時沿用原用途，不重做 8.3 檢查；從任務買回時傳配對，照「母馬的用途」處理，事件記原用途與新用途。自家母駒與自由配種所生不接受用途。可以一併填據點。
> - **轉場**（需求規格 8.6、MARE-19）：只限在圈的母馬，與目前相同時阻止；事件記原據點（原本不知道時留空）與新據點，年份、時點與來源在事件的共用欄位。
> - **今年計畫**（需求規格 8.7、MARE-22）：只限在圈的母馬，年份為目前遊戲年；沒有值視為待定，與目前相同時阻止。不限用途。
> - **活力更正**（需求規格 8.7、MARE-13、MARE-14）：指定年份與五月或七月的快照，數值是 0～100 的整數，是否増強另外指定（`100` 也可以不増強）；年份不能晚於目前遊戲年。快照原本沒有值時也可以填入，不提供清除。與目前相同時阻止。
> - **手動資料更正**（需求規格 6.4、ID-08、ID-13）：只限沒有出生紀錄、馬名還是手動輸入的市場馬（市場母馬與零代市場種牡馬），經匯入確認的唯讀。可以更正完整馬名、能力番号、出生年、父母名與自身父系：省略表示不變，`null` 表示清除，完整馬名不能清除；檢查同手動建立的馬，同一匹馬的比對排除自己；什麼都沒改時阻止。替代母馬的自身父系改了時重做 8.3 檢查。零代市場種牡馬改了父系時不重做 7.7 的比對：那只在補入或替換當下比對，要改系的名稱用系統名稱變更。

## 本計畫的詮釋

需求規格與技術設計沒有逐字寫出、由本計畫決定的地方。技術設計 4.3「寫入操作」已經和使用者確認；下面是本計畫在程式層級的決定，審查時請逐條對照上一節的原文。

1. **事件的來源與時點**（`records.ts`、`writes.ts`）：`EventBase` 加必有的 `source` 與選填的 `timing`，`EventContent` 也去掉這兩個欄位，由 `runWrite` 的 `addEvent` 統一填入：`WriteOptions.source` 省略時為 `{ kind: 'manual' }`，`timing` 省略時事件沒有這個欄位。時點要是 1～12 月、1～4 週的整數，不符時在交易開始前丟出錯誤（畫面與匯入只會送出合法的時點）。匯入的種類先列出八種（`ImportType`），本計畫的操作都是手動；連到匯入紀錄的識別由 CE 匯入計畫加入。2-1 測試裡事件的整列比對因此多了 `source: { kind: 'manual' }`。
2. **手動父母名**（`writes.ts`、`inputs.ts`）：`NewHorseInput` 加選填的 `sireName`、`damName`，去掉前後空白與 `(外)`、`[地]` 前綴後存基本馬名；只有前綴時阻止（`parent-name`，依父、母各列一筆）。父母名或父系三項有任何一項時，`pedigreeSource` 記為 `'manual'`，都沒有時不寫。`buildKnownHorses` 遇到手動的父母名時當作沒有匯入名稱，改用連結馬匹經匯入確認的馬名（沒有連結時不傳）。驗證拆成 `checkHorseInput`（驗證並統一寫法）與 `manualHorseRow`（組資料列），`prepareNewHorse` 照舊由兩者組成；阻止原因的順序是馬名、能力番号、出生年、父、母、同一匹馬。
3. **母馬年度資料**（`records.ts`、`database.ts`）：兩份活力快照是平的欄位 `mayVigor`、`julyVigor`，仔出、繁殖年數、繁殖頭數分別是 `offspringQuality`、`breedingYears`、`foalCount`，今年計畫是 `plan`，沒有值視為待定。本計畫只寫今年計畫與活力；仔出、繁殖年數與頭數由五月匯入寫入。
4. **用途的解析**（`mare-assignment.ts`）：`resolveAssignment` 是作用在 `readRuleRows` 資料列上的純函式。配對從 `listBoard` 的任務（含暫停中的）與可開啟分支的配對中，找產出系與代數都相同的第一條；找不到時只回傳 `no-pairing`。例外補入的原因去掉前後空白，空白時只回傳 `reason-required`；不是例外補入時不保存原因。警告的順序是例外補入在前、8.3 在後。建系起點的用途是 `start`、第 1 系 0 代。待指定用途不做 8.3，也不推來源。
5. **8.3 親系統檢查**（`substituteWarnings`）：只查替代母馬，起點母馬不查。同一代的其他替代母馬用 `buildSubstituteMares`，包含已離圈的、不含她自己（`horseId`）。撞到時一筆 `substitute-parent-system` 警告，附 core 的衝突清單；自身父系未知時只在完成的結果帶 `parentSystemUnknown: true`，不存。
6. **可能是買回**（`mare-writes.ts`）：只比對在圈狀態是售出的母馬（需求規格 8.4「與已售出的母馬相同時」），定年引退的不列。基本馬名要完全相同；能力番号或出生年兩邊都有值而且不同時就不是同一匹。符合的母馬識別排序後放進 `possible-buyback`；使用者確認不是買回時照常建立，這筆警告存在事件的 `confirmedWarnings`。
7. **據點**：據點不是 32～35 時，在交易開始前以 `assertBase` 丟出錯誤（畫面只提供這四個）；新增、買回與轉場都檢查。
8. **修改用途**：先解析用途，解析失敗時只回傳那些阻止；解析成功而用途與所屬母馬群都和目前相同時阻止（`unchanged`），例外補入的原因不同也算相同。換用途用 `withPlacement`：換掉系與代數，例外補入時寫原因，不是時清掉原因。母馬的來源不變。
9. **賣出**：今年的馬齡用 core 的 `ageInYear`（目前遊戲年減出生年）；已達定年時阻止並附馬齡。出生年不明時可以賣出。自家母駒的接替狀態保留離圈前的值，不改成 `sold`（技術設計 4.2）。
10. **更正離圈原因**：`to` 可以是售出、定年引退或 `in-herd`（撤銷）。改為售出或定年引退時接替狀態不動。撤銷時只有「原本是正式保留、而同父同母的姊妹中有在圈的正式保留」會改為候選（姊妹用 `loadSisters` 讀）；事件記接替狀態的變化，沒有變化時不記。
11. **買回與回歸**：自家母駒一律重新判定接替狀態，事件記原狀態與新狀態（兩者相同也記）；只有判定為暫定保留時把 `establishedGeneration` 設為 true。從任務買回時，用途與所屬母馬群有變才記 `usage`；例外補入的原因跟著解析結果寫。據點有填而且和目前不同才寫，事件記原據點（原本不知道時沒有）與新據點。達定年的母馬也可以買回（不列入任務由 `mareListedInTasks` 處理）。
12. **轉場、今年計畫**：轉場與今年計畫只限在圈的母馬；和目前相同時阻止。今年計畫的事件原本沒有值時不記 `from`。
13. **活力更正**：已離圈的母馬也可以更正（補歷史資料）。數值與年份的阻止一起列出，兩者都通過才比較是否和目前相同。那一年的資料列不存在時新增，其他欄位保留。
14. **手動資料更正**：更正後的輸入以目前的值為底（省略不變、`null` 清除），整組交給 `checkHorseInput`，同一匹馬的比對排除自己（Task 8 加上 `exceptHorseId`）。比對「有沒有改」看六個欄位在統一寫法之後的值。其他欄位（性別、父母的內部連結等）保留。8.3 只在自身父系有改、而且她是替代母馬（不論在不在圈）時重做。
15. **PR #8 的 Minor**：`changeSystem` 的分出來源省略時不變，`null` 或只有空白時清除；`saveLineSubsystem` 加選填的 `horseId`，零代種牡馬的補入與替換傳入那匹馬；`readRuleRows` 加選填的第三個參數，寫入操作傳入交易開始時讀到的遊戲局；`updateSettings` 補上設定不存在的測試（程式不變）。
16. **驗收測試**：只驗證儲存層寫入負責的部分；匯入的配對與畫面的顯示由後續計畫補上。事件識別是亂數，同一次或同一個測試裡的事件在表裡的順序不固定，測試依對象、種類篩選或用 `toContainEqual`。

import { listBoard } from '../core/board'
import type { DesignatedPairing } from '../core/designated'
import type { LinePosition } from '../core/lines'
import { checkSubstituteMare } from '../core/substitute'
import { buildSubstituteMares } from './inputs'
import { buildRuleSnapshot, type RuleRows, type RuleSnapshot } from './loaders'
import type { Base, MarePlacement, MareSourceKind, WriteWarning } from './records'
import type { Prepared } from './writes'

// 市場母馬的用途：由任務看板的配對推出用途、例外補入與來源，並做 8.3 親系統檢查
// （需求規格 7.3、8.3、8.4；技術設計 4.3「母馬的用途」）。新增市場母馬、修改用途與買回共用

/** 母馬的用途：任務看板上的一條配對（產出第 line 系第 generation 代），或待指定用途 */
export type MareAssignment =
  { kind: 'pairing'; line: LinePosition; generation: number } | { kind: 'unassigned' }

/**
 * 用途的阻止原因：
 * - no-pairing：產出這一系這一代的配對現在不在任務看板上（任務與可開啟分支的配對都沒有）
 * - reason-required：零代市場種牡馬的配對底下例外補入，要填原因（需求規格 7.3、MARE-31）
 */
export type AssignmentBlock = { kind: 'no-pairing' } | { kind: 'reason-required' }

/** 要解析用途的母馬：已有的母馬帶識別，8.3 檢查時不和自己比較；新增的留空 */
export interface AssignedMare {
  horseId?: string
  /** 自身父系所屬：她父馬的子系統 */
  sireSystem?: string
}

/** 8.3 親系統檢查的結果 */
export interface SubstituteWarnings {
  /** 撞到時的警告，要確認 */
  warnings: WriteWarning[]
  /** 自身父系空白或對照表查不到，無法判斷：只提示、不要求確認 */
  parentSystemUnknown: boolean
}

/** 解析後的用途 */
export interface ResolvedAssignment extends SubstituteWarnings {
  placement: MarePlacement
  /** 由配對推出的母馬來源；待指定用途為 null，由使用者選 */
  sourceKind: MareSourceKind | null
  /** 例外補入的原因（去掉前後空白）；不是例外補入時留空 */
  exceptionReason?: string
}

/**
 * 解析市場母馬的用途（技術設計 4.3「母馬的用途」）。配對要在任務看板的任務（含暫停中的）
 * 或可開啟分支的配對中，一個產出只有一條配對，已宣告補公系時就是補公系配對。由配對推出：
 * 母馬群是起點時為第 1 系起點用，否則為替代配對母馬群的系與代數；種牡馬是零代而且不是建系起點時
 * 為例外補入，警告並確認、原因必填；替代母馬另做 8.3 親系統檢查。
 * rows 是在寫入交易內以 readRuleRows 讀到的資料列。
 */
export function resolveAssignment(
  rows: RuleRows,
  assignment: MareAssignment,
  mare: AssignedMare,
  exceptionReason: string | undefined,
): Prepared<ResolvedAssignment, AssignmentBlock> {
  if (assignment.kind === 'unassigned') {
    return {
      ok: true,
      value: {
        placement: { usage: 'unassigned' },
        sourceKind: null,
        warnings: [],
        parentSystemUnknown: false,
      },
    }
  }
  const snapshot = buildRuleSnapshot(rows)
  const pairing = findPairing(snapshot, assignment.line, assignment.generation)
  if (!pairing) return { ok: false, blocks: [{ kind: 'no-pairing' }] }
  const exception = pairing.sire.generation === 0 && pairing.kind !== 'start'
  const reason = exceptionReason?.trim() ?? ''
  if (exception && reason === '') return { ok: false, blocks: [{ kind: 'reason-required' }] }

  const { mares } = pairing
  const placement: MarePlacement =
    mares.kind === 'start'
      ? { usage: 'start', groupLine: 1, groupGeneration: 0 }
      : { usage: 'substitute', groupLine: mares.line, groupGeneration: mares.generation }
  const check =
    mares.kind === 'group'
      ? substituteWarnings(rows, snapshot, mares.line, mares.generation, mare)
      : { warnings: [], parentSystemUnknown: false }
  const warnings: WriteWarning[] = [
    ...(exception ? [{ kind: 'exception-entry' as const, ...pairing.output }] : []),
    ...check.warnings,
  ]
  return {
    ok: true,
    value: {
      placement,
      sourceKind: sourceKindOf(pairing, rows),
      ...(exception ? { exceptionReason: reason } : {}),
      warnings,
      parentSystemUnknown: check.parentSystemUnknown,
    },
  }
}

/**
 * 替代第 forLine 系第 forGeneration 代的市場母馬的親系統檢查（需求規格 8.3）：
 * 同一代的其他替代母馬包含已離圈的，不含她自己。撞到時警告並確認；自身父系未知時只提示
 */
export function substituteWarnings(
  rows: RuleRows,
  snapshot: RuleSnapshot,
  forLine: LinePosition,
  forGeneration: number,
  mare: AssignedMare,
): SubstituteWarnings {
  const others = buildSubstituteMares(rows.mares, rows.horses, forGeneration, mare.horseId)
  const check = checkSubstituteMare(
    { forLine, forGeneration, ownSireSystem: mare.sireSystem },
    snapshot.systemTable,
    snapshot.lineSystems,
    others,
  )
  return {
    warnings:
      check.conflicts.length > 0
        ? [
            {
              kind: 'substitute-parent-system',
              line: forLine,
              generation: forGeneration,
              conflicts: check.conflicts,
            },
          ]
        : [],
    parentSystemUnknown: check.unknown,
  }
}

/** 任務（含暫停中的）與可開啟分支的配對中，產出第 line 系第 generation 代的那一條 */
function findPairing(
  snapshot: RuleSnapshot,
  line: LinePosition,
  generation: number,
): DesignatedPairing | undefined {
  const board = listBoard(snapshot.eightLines)
  return [
    ...board.tasks.map((task) => task.pairing),
    ...board.openableBranches.flatMap((branch) => branch.pairings),
  ].find((pairing) => pairing.output.line === line && pairing.output.generation === generation)
}

/**
 * 由配對推出的母馬來源（需求規格 8.1、7.6）：補公系配對，或配對的母馬群已宣告補母系（未撤銷）時
 * 為市場補系；否則建系起點、推進原系與建立新系為市場創系，循環為市場補血
 */
function sourceKindOf(pairing: DesignatedPairing, rows: RuleRows): MareSourceKind {
  const { mares } = pairing
  const damRestored =
    mares.kind === 'group' &&
    rows.restorations.some(
      (row) =>
        !row.revoked &&
        row.side === 'dam' &&
        row.line === mares.line &&
        row.generation === mares.generation,
    )
  if (pairing.kind === 'restore' || damRestored) return 'market-restoration'
  return pairing.kind === 'cycle' ? 'market-supplement' : 'market-founding'
}

const BASES: readonly Base[] = [32, 33, 34, 35]

/** 據點要是繋養牧場番号 32～35（第 3 章）；畫面只提供這四個，其他值丟出錯誤 */
export function assertBase(location: Base): void {
  if (!BASES.includes(location)) throw new Error(`據點不符：${location}`)
}

```ts
import type { WPStudBookDatabase } from './database'
import { readRuleRows, ruleTables, type RuleRows } from './loaders'
import {
  assertBase,
  resolveAssignment,
  type AssignmentBlock,
  type MareAssignment,
} from './mare-assignment'
import type { Base, HorseRow, MareRow, WriteWarning } from './records'
import {
  confirmation,
  gate,
  prepareNewHorse,
  runWrite,
  type NewHorseBlock,
  type NewHorseInput,
  type WriteOptions,
  type WriteResult,
} from './writes'

// 市場母馬的寫入操作：新增與修改用途（需求規格 8.3、8.4；技術設計 4.3「寫入操作」）

/** 新增市場母馬的輸入 */
export interface MarketMareInput {
  horse: NewHorseInput
  assignment: MareAssignment
  /** 待指定用途時的來源：市場混血或其他，省略時為其他；從配對新增時由配對推出，不看這一欄 */
  sourceKind?: 'market-crossbreed' | 'other'
  /** 來源的備註；只有空白時不寫 */
  sourceNote?: string
  /** 據點；還不知道時留空 */
  location?: Base
  /** 例外補入的原因（需求規格 7.3）；不是例外補入時不保存 */
  exceptionReason?: string
}

/** 新增市場母馬的阻止原因：馬匹的輸入不符，或用途不符 */
export type AddMareBlock = NewHorseBlock | AssignmentBlock

/** 新增的母馬；parentSystemUnknown 為 true 時提示 8.3 無法判斷 */
export interface AddedMare {
  horse: HorseRow
  mare: MareRow
  parentSystemUnknown: boolean
}

/**
 * 新增市場母馬（需求規格 8.4、MARE-05、MARE-26、MARE-29、MARE-31）：馬匹照手動建立的馬，性別為牝；
 * 在圈，不使該代成立。用途與來源由 resolveAssignment 推出，待指定用途的來源由使用者選。
 * 已售出的母馬中，基本馬名相同、能力番号與出生年也不矛盾時，警告可能是買回（使用者確認不是買回才建立；
 * 是買回時畫面改用買回操作）。事件 mare-added。據點不是 32～35 時丟出錯誤。
 */
export async function addMarketMare(
  db: WPStudBookDatabase,
  gameId: string,
  input: MarketMareInput,
  options: WriteOptions = {},
): Promise<WriteResult<AddedMare, AddMareBlock>> {
  if (input.location !== undefined) assertBase(input.location)
  return runWrite(db, gameId, ruleTables(db), options, async (context) => {
    const rows = await readRuleRows(db, gameId, context.game)
    const prepared = await prepareNewHorse(context, input.horse, 'female')
    const resolved = resolveAssignment(
      rows,
      input.assignment,
      { sireSystem: prepared.ok ? prepared.value.sireSystem : undefined },
      input.exceptionReason,
    )
    if (!prepared.ok || !resolved.ok) {
      const blocks: AddMareBlock[] = [
        ...(prepared.ok ? [] : prepared.blocks),
        ...(resolved.ok ? [] : resolved.blocks),
      ]
      return { status: 'blocked', blocks }
    }
    const horse = prepared.value
    const { placement, sourceKind, exceptionReason, parentSystemUnknown } = resolved.value
    const buyback = buybackCandidates(rows, horse)
    const warnings: WriteWarning[] = [
      ...resolved.value.warnings,
      ...(buyback.length > 0 ? [{ kind: 'possible-buyback' as const, horseIds: buyback }] : []),
    ]
    const stop = gate([], warnings, context.confirmed)
    if (stop) return stop

    const note = input.sourceNote?.trim() ?? ''
    const mare: MareRow = {
      horseId: horse.id,
      gameId,
      ...placement,
      herd: 'in-herd',
      establishedGeneration: false,
      source: { kind: sourceKind ?? input.sourceKind ?? 'other', ...(note === '' ? {} : { note }) },
      ...(input.location === undefined ? {} : { location: input.location }),
      ...(exceptionReason === undefined ? {} : { exceptionReason }),
    }
    await db.horses.add(horse)
    await db.mares.add(mare)
    await context.addEvent({
      kind: 'mare-added',
      horseId: horse.id,
      placement,
      mareSource: mare.source,
      ...(exceptionReason === undefined ? {} : { exceptionReason }),
      ...confirmation(warnings),
    })
    return context.done({ horse, mare, parentSystemUnknown }, warnings)
  })
}

/**
 * 可能是買回的已售出母馬（需求規格 8.4、MARE-29）：基本馬名相同，
 * 能力番号與出生年也不矛盾（兩邊都有值而且不同才算矛盾）；依識別排序
 */
function buybackCandidates(rows: RuleRows, horse: HorseRow): string[] {
  const horses = new Map(rows.horses.map((row) => [row.id, row]))
  const differs = <T>(a: T | undefined, b: T | undefined) =>
    a !== undefined && b !== undefined && a !== b
  return rows.mares
    .filter((mare) => mare.herd === 'sold')
    .map((mare) => horses.get(mare.horseId))
    .filter(
      (sold): sold is HorseRow =>
        sold !== undefined &&
        sold.baseName === horse.baseName &&
        !differs(sold.abilityNumber, horse.abilityNumber) &&
        !differs(sold.birthYear, horse.birthYear),
    )
    .map((sold) => sold.id)
    .sort()
}

/** 母馬目前的用途與所屬母馬群 */
export function placementOf(mare: MareRow): MarePlacement {
  return {
    usage: mare.usage,
    ...(mare.groupLine === undefined ? {} : { groupLine: mare.groupLine }),
    ...(mare.groupGeneration === undefined ? {} : { groupGeneration: mare.groupGeneration }),
  }
}

/** 兩個用途是否相同：用途與所屬母馬群的系與代數都相同 */
export function samePlacement(a: MarePlacement, b: MarePlacement): boolean {
  return (
    a.usage === b.usage && a.groupLine === b.groupLine && a.groupGeneration === b.groupGeneration
  )
}

/** 換成新用途的母馬資料列：換掉所屬母馬群；例外補入時寫原因，不是時清掉原因 */
export function withPlacement(
  mare: MareRow,
  placement: MarePlacement,
  exceptionReason: string | undefined,
): MareRow {
  const next: MareRow = { ...mare, ...placement }
  if (placement.groupLine === undefined) delete next.groupLine
  if (placement.groupGeneration === undefined) delete next.groupGeneration
  if (exceptionReason === undefined) delete next.exceptionReason
  else next.exceptionReason = exceptionReason
  return next
}

/** 修改用途的輸入 */
export interface MareUsageInput {
  assignment: MareAssignment
  /** 改成例外補入時的原因（需求規格 7.3）；不是例外補入時不保存 */
  exceptionReason?: string
}

/** 修改用途的阻止原因：用途不符，或和目前相同 */
export type MareUsageBlock = AssignmentBlock | { kind: 'unchanged' }

/** 修改用途後的母馬；parentSystemUnknown 為 true 時提示 8.3 無法判斷 */
export interface ChangedMare {
  mare: MareRow
  parentSystemUnknown: boolean
}

/**
 * 修改市場母馬的用途（需求規格 8.4、MARE-28）：改掛到另一條配對，或改為待指定用途；
 * 用途的解析、例外補入與 8.3 檢查同新增，8.3 不和她自己比較。和目前相同時阻止。
 * 來源記的是購入時的目的（8.1），不隨用途改變；已有的配種紀錄保留自己的規則快照，新用途從下一次配種生效。
 * 事件 mare-usage-changed 記原用途與新用途。
 * 母馬找不到、屬於其他局、不是市場母馬（自家母駒、自由配種所生）或不在圈內時丟出錯誤。
 */
export async function changeMareUsage(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  input: MareUsageInput,
  options: WriteOptions = {},
): Promise<WriteResult<ChangedMare, MareUsageBlock>> {
  return runWrite(db, gameId, ruleTables(db), options, async (context) => {
    const rows = await readRuleRows(db, gameId, context.game)
    const current = marketMareInHerd(rows, horseId)
    const horse = rows.horses.find((row) => row.id === horseId)
    const resolved = resolveAssignment(
      rows,
      input.assignment,
      { horseId, sireSystem: horse?.sireSystem },
      input.exceptionReason,
    )
    const from = placementOf(current)
    const blocks: MareUsageBlock[] = []
    if (!resolved.ok) blocks.push(...resolved.blocks)
    else if (samePlacement(from, resolved.value.placement)) blocks.push({ kind: 'unchanged' })
    if (!resolved.ok || blocks.length > 0) return { status: 'blocked', blocks }
    const { placement, exceptionReason, warnings, parentSystemUnknown } = resolved.value
    const stop = gate([], warnings, context.confirmed)
    if (stop) return stop
    const mare = withPlacement(current, placement, exceptionReason)
    await db.mares.put(mare)
    await context.addEvent({
      kind: 'mare-usage-changed',
      horseId,
      from,
      to: placement,
      ...(exceptionReason === undefined ? {} : { exceptionReason }),
      ...confirmation(warnings),
    })
    return context.done({ mare, parentSystemUnknown }, warnings)
  })
}

/** 在圈的市場母馬；找不到、屬於其他局、不是市場母馬或不在圈內時丟出錯誤 */
function marketMareInHerd(rows: RuleRows, horseId: string): MareRow {
  const mare = rows.mares.find((row) => row.horseId === horseId)
  if (!mare) throw new Error(`找不到母馬：${horseId}`)
  if (mare.usage === 'own' || mare.usage === 'free') {
    throw new Error(`自家母駒的系與代數由出生紀錄決定，不能修改用途：${horseId}`)
  }
  if (mare.herd !== 'in-herd') throw new Error(`不在繁殖圈內的母馬不能修改用途：${horseId}`)
  return mare
}
```

import { ageInYear } from '../core/mares'
import type { SisterStatus } from '../core/sisters'
import type { WPStudBookDatabase } from './database'
import { loadSettings } from './games'
import { loadSisters } from './loaders'
import type { HerdStatus, MareRow } from './records'
import { gate, runWrite, type WriteContext, type WriteOptions, type WriteResult } from './writes'

// 母馬的在圈狀態：賣出與更正離圈原因（需求規格 8.5、8.9；技術設計 4.3「寫入操作」）

/** 賣出的阻止原因：已達定年（需求規格 4.6「無法再生產的母馬不能賣出」）；age 是今年的馬齡 */
export interface SellBlock {
  kind: 'retirement-age'
  age: number
}

/**
 * 賣出母馬（需求規格 8.5、MARE-08）：在圈狀態改為售出；自家母駒的接替狀態保留離圈前的值（技術設計 4.2）。
 * 已達定年時阻止，出生年不明時可以賣出。這條只適用於手動賣出，五月缺席的判定由 CE 匯入計畫接上。
 * 事件 mare-departed。母馬找不到、屬於其他局或不在圈內時丟出錯誤。
 */
export async function sellMare(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  options: WriteOptions = {},
): Promise<WriteResult<MareRow, SellBlock>> {
  return runWrite(db, gameId, [db.mares, db.horses, db.settings], options, async (context) => {
    const current = await loadMare(context, horseId)
    if (current.herd !== 'in-herd') throw new Error(`不在繁殖圈內的母馬不能賣出：${horseId}`)
    const horse = await db.horses.get(horseId)
    const { retirementAge } = await loadSettings(db, gameId)
    const blocks: SellBlock[] = []
    if (horse?.birthYear !== undefined) {
      const age = ageInYear(horse.birthYear, context.game.currentYear)
      if (age >= retirementAge) blocks.push({ kind: 'retirement-age', age })
    }
    const stop = gate(blocks, [], context.confirmed)
    if (stop) return stop
    const mare: MareRow = { ...current, herd: 'sold' }
    await db.mares.put(mare)
    await context.addEvent({ kind: 'mare-departed', horseId, reason: 'sold' })
    return context.done(mare)
  })
}

/** 和目前相同時的阻止原因 */
export interface UnchangedBlock {
  kind: 'unchanged'
}

/**
 * 更正離圈原因（需求規格 8.5「可人工更正」、11.5、MARE-32）：已離圈的母馬改為售出、定年引退，
 * 或撤銷回到生產中（誤登記時用，不建立回歸事件）；和目前相同時阻止。
 * 撤銷時自家母駒回到保留的接替狀態（技術設計 4.2）；原本是正式保留、而圈內已有另一匹正式保留的姊妹時
 * 改為候選，維持同一父母組合只有一匹正式保留（8.9）。事件 mare-departure-corrected。
 * 母馬找不到、屬於其他局或還在圈內時丟出錯誤。
 */
export async function correctDeparture(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  to: HerdStatus,
  options: WriteOptions = {},
): Promise<WriteResult<MareRow, UnchangedBlock>> {
  return runWrite(db, gameId, [db.mares, db.horses], options, async (context) => {
    const current = await loadMare(context, horseId)
    const from = current.herd
    if (from === 'in-herd') throw new Error(`母馬在繁殖圈內，沒有離圈可以更正：${horseId}`)
    const blocks: UnchangedBlock[] = to === from ? [{ kind: 'unchanged' }] : []
    const stop = gate(blocks, [], context.confirmed)
    if (stop) return stop
    const sisterStatus = to === 'in-herd' ? await revokedSisterStatus(context, current) : undefined
    const mare: MareRow = {
      ...current,
      herd: to,
      ...(sisterStatus === undefined ? {} : { sisterStatus: sisterStatus.to }),
    }
    await db.mares.put(mare)
    await context.addEvent({
      kind: 'mare-departure-corrected',
      horseId,
      from,
      to,
      ...(sisterStatus === undefined ? {} : { sisterStatus }),
    })
    return context.done(mare)
  })
}

/** 這一局的母馬；找不到或屬於其他局時丟出錯誤 */
async function loadMare(context: WriteContext, horseId: string): Promise<MareRow> {
  const mare = await context.db.mares.get(horseId)
  if (!mare || mare.gameId !== context.game.id) throw new Error(`找不到母馬：${horseId}`)
  return mare
}

/**
 * 撤銷離圈時自家母駒的接替狀態變化：原本是正式保留、而圈內已有另一匹正式保留的姊妹時改為候選；
 * 其他情況不變，回傳 undefined。她自己還在圈外，不會算到自己
 */
async function revokedSisterStatus(
  context: WriteContext,
  mare: MareRow,
): Promise<{ from: SisterStatus; to: SisterStatus } | undefined> {
  if (mare.usage !== 'own' || mare.sisterStatus !== 'kept') return undefined
  const horse = await context.db.horses.get(mare.horseId)
  const sisters = await loadSisters(context.db, context.game.id, horse?.sireId, horse?.damId)
  const keptInHerd = sisters.some((sister) => sister.inHerd && sister.status === 'kept')
  return keptInHerd ? { from: 'kept', to: 'candidate' } : undefined
}

/** 買回與回歸的輸入 */
export interface ReturnMareInput {
  /** 從任務買回時的新用途；只限市場母馬，省略時沿用原用途 */
  assignment?: MareAssignment
  /** 改成例外補入時的原因（需求規格 7.3）；不是例外補入時不保存 */
  exceptionReason?: string
  /** 回到的據點；省略時不變 */
  location?: Base
}

/** 買回後的母馬；parentSystemUnknown 為 true 時提示 8.3 無法判斷 */
export interface ReturnedMare {
  mare: MareRow
  parentSystemUnknown: boolean
}

/**
 * 已離圈（售出或定年引退）的母馬買回或回歸（需求規格 8.5、8.9、ID-04、MARE-29、MARE-30、CAND-07）：
 * 恢復生產中，沿用原識別與血緣。自家母駒沿用出生紀錄的系與代數，接替狀態以 entrySisterStatus 重新判定
 * （其他姊妹都不在圈 → 暫定保留；仍有姊妹在圈 → 候選），成為暫定保留時 establishedGeneration 設為 true；
 * 自由配種所生只恢復生產中。市場母馬沒有傳用途時沿用原用途，不重做 8.3 檢查；從任務買回時傳配對，
 * 照 resolveAssignment 處理。可以一併填據點。事件 mare-returned 記原離圈狀態，以及接替狀態、用途與據點的變化。
 * 母馬找不到、屬於其他局或還在圈內、自家母駒或自由配種所生傳了用途、據點不是 32～35 時丟出錯誤。
 */
export async function returnMare(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  input: ReturnMareInput = {},
  options: WriteOptions = {},
): Promise<WriteResult<ReturnedMare, AssignmentBlock>> {
  if (input.location !== undefined) assertBase(input.location)
  return runWrite(db, gameId, ruleTables(db), options, async (context) => {
    const rows = await readRuleRows(db, gameId, context.game)
    const current = rows.mares.find((row) => row.horseId === horseId)
    if (!current) throw new Error(`找不到母馬：${horseId}`)
    const from = current.herd
    if (from === 'in-herd') throw new Error(`母馬在繁殖圈內，不能買回：${horseId}`)
    const own = current.usage === 'own' || current.usage === 'free'
    if (own && input.assignment !== undefined) {
      throw new Error(`自家母駒與自由配種所生的母馬沿用出生紀錄，不接受用途：${horseId}`)
    }
    const horse = rows.horses.find((row) => row.id === horseId)
    const resolved =
      input.assignment === undefined
        ? undefined
        : resolveAssignment(
            rows,
            input.assignment,
            { horseId, sireSystem: horse?.sireSystem },
            input.exceptionReason,
          )
    if (resolved && !resolved.ok) return { status: 'blocked', blocks: resolved.blocks }
    const assigned = resolved?.value
    const warnings = assigned?.warnings ?? []
    const stop = gate([], warnings, context.confirmed)
    if (stop) return stop

    const sisterStatus = current.usage === 'own' ? reenteredSisterStatus(rows, current) : undefined
    const location = locationChange(current.location, input.location)
    const placed = assigned
      ? withPlacement(current, assigned.placement, assigned.exceptionReason)
      : current
    const mare: MareRow = {
      ...placed,
      herd: 'in-herd',
      ...(sisterStatus === undefined ? {} : { sisterStatus: sisterStatus.to }),
      ...(sisterStatus?.to === 'provisional' ? { establishedGeneration: true } : {}),
      ...(location === undefined ? {} : { location: location.to }),
    }
    const previous = placementOf(current)
    const usage =
      assigned && !samePlacement(previous, assigned.placement)
        ? { from: previous, to: assigned.placement }
        : undefined
    await db.mares.put(mare)
    await context.addEvent({
      kind: 'mare-returned',
      horseId,
      from,
      ...(sisterStatus === undefined ? {} : { sisterStatus }),
      ...(usage === undefined ? {} : { usage }),
      ...(assigned?.exceptionReason === undefined
        ? {}
        : { exceptionReason: assigned.exceptionReason }),
      ...(location === undefined ? {} : { location }),
      ...confirmation(warnings),
    })
    return context.done(
      { mare, parentSystemUnknown: assigned?.parentSystemUnknown ?? false },
      warnings,
    )
  })
}

/**
 * 自家母駒回到繁殖圈時重新判定的接替狀態（需求規格 8.9）：
 * 其他姊妹都不在圈 → 暫定保留；仍有姊妹在圈 → 候選
 */
function reenteredSisterStatus(
  rows: RuleRows,
  mare: MareRow,
): { from: SisterStatus; to: SisterStatus } {
  const horse = rows.horses.find((row) => row.id === mare.horseId)
  const to = entrySisterStatus(
    { id: mare.horseId, sireId: horse?.sireId, damId: horse?.damId },
    buildOwnMares(rows.mares, rows.horses),
  )
  return { from: ownSisterStatus(mare), to }
}

/** 據點的變化：沒有填新據點或和目前相同時為 undefined；原本不知道據點時沒有 from */
export function locationChange(
  current: Base | undefined,
  next: Base | undefined,
): { from?: Base; to: Base } | undefined {
  if (next === undefined || next === current) return undefined
  return current === undefined ? { to: next } : { from: current, to: next }
}

import type { WPStudBookDatabase } from './database'
import type { MarePlan, MareRow, MareYearRow, Vigor, VigorMonth } from './records'
import { runWrite, type WriteContext, type WriteOptions, type WriteResult } from './writes'

// 母馬年度資料的寫入操作：今年計畫與活力的人工更正（需求規格 8.7；技術設計 4.3「寫入操作」）

/** 和目前相同時的阻止原因 */
export interface UnchangedYearBlock {
  kind: 'unchanged'
}

/**
 * 設定今年計畫（需求規格 8.7、MARE-22）：年份為目前遊戲年，那一年的資料列不存在時新增；
 * 沒有值視為待定，和目前相同時阻止。不限用途。事件 mare-plan-changed 記原計畫與新計畫。
 * 母馬找不到、屬於其他局或不在圈內時丟出錯誤。
 */
export async function setMarePlan(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  plan: MarePlan,
  options: WriteOptions = {},
): Promise<WriteResult<MareYearRow, UnchangedYearBlock>> {
  return runWrite(db, gameId, [db.mares, db.mareYears], options, async (context) => {
    const mare = await loadMare(context, horseId)
    if (mare.herd !== 'in-herd') throw new Error(`不在繁殖圈內的母馬沒有今年計畫：${horseId}`)
    const current = await loadYear(context, horseId, context.game.currentYear)
    if ((current.plan ?? 'pending') === plan) {
      return { status: 'blocked', blocks: [{ kind: 'unchanged' }] }
    }
    const next: MareYearRow = { ...current, plan }
    await db.mareYears.put(next)
    await context.addEvent({
      kind: 'mare-plan-changed',
      horseId,
      ...(current.plan === undefined ? {} : { from: current.plan }),
      to: plan,
    })
    return context.done(next)
  })
}

/** 活力的人工更正：哪一年、五月或七月的快照，以及新的值 */
export interface VigorCorrection {
  year: number
  month: VigorMonth
  vigor: Vigor
}

/**
 * 活力更正的阻止原因：
 * - vigor-range：數值不是 0～100 的整數
 * - year：年份不是整數，或晚於目前遊戲年
 * - unchanged：和目前相同
 */
export type VigorBlock = { kind: 'vigor-range' } | { kind: 'year' } | { kind: 'unchanged' }

/**
 * 活力快照的人工更正（需求規格 8.7、MARE-13、MARE-14）：數值是 0～100 的整數，是否増強另外指定
 * （100 也可以不増強）；年份不能晚於目前遊戲年。快照原本沒有值時也可以填入，不提供清除；和目前相同時阻止。
 * 事件 vigor-corrected 記快照的年份、月份、原值與新值。母馬找不到或屬於其他局時丟出錯誤。
 */
export async function correctVigor(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  correction: VigorCorrection,
  options: WriteOptions = {},
): Promise<WriteResult<MareYearRow, VigorBlock>> {
  return runWrite(db, gameId, [db.mares, db.mareYears], options, async (context) => {
    await loadMare(context, horseId)
    const { year, month, vigor } = correction
    const blocks: VigorBlock[] = []
    if (!(Number.isInteger(vigor.value) && vigor.value >= 0 && vigor.value <= 100)) {
      blocks.push({ kind: 'vigor-range' })
    }
    const yearValid = Number.isInteger(year) && year <= context.game.currentYear
    if (!yearValid) blocks.push({ kind: 'year' })
    if (blocks.length > 0) return { status: 'blocked', blocks }
    const current = await loadYear(context, horseId, year)
    const field = month === 5 ? 'mayVigor' : 'julyVigor'
    const from = current[field]
    if (from?.value === vigor.value && from.boosted === vigor.boosted) {
      return { status: 'blocked', blocks: [{ kind: 'unchanged' }] }
    }
    const to: Vigor = { value: vigor.value, boosted: vigor.boosted }
    const next: MareYearRow = { ...current, [field]: to }
    await db.mareYears.put(next)
    await context.addEvent({
      kind: 'vigor-corrected',
      horseId,
      snapshotYear: year,
      month,
      ...(from === undefined ? {} : { from }),
      to,
    })
    return context.done(next)
  })
}

/** 這一局的母馬；找不到或屬於其他局時丟出錯誤 */
async function loadMare(context: WriteContext, horseId: string): Promise<MareRow> {
  const mare = await context.db.mares.get(horseId)

import type { WPStudBookDatabase } from './database'
import { buildRuleSnapshot, readRuleRows, ruleTables } from './loaders'
import { substituteWarnings, type SubstituteWarnings } from './mare-assignment'
import type { HorseFieldValues, HorseRow } from './records'
import { damRoleOf } from './snapshot'
import {
  checkHorseInput,
  confirmation,
  gate,
  manualHorseRow,
  runWrite,
  type NewHorseBlock,
  type NewHorseInput,
  type WriteOptions,
  type WriteResult,
} from './writes'

// 手動資料的更正（需求規格 6.4、ID-08、ID-13；技術設計 4.3「寫入操作」）

/** 手動資料更正的輸入：省略的欄位不變，null 表示清除；完整馬名不能清除 */
export interface HorseCorrectionInput {
  fullName?: string
  abilityNumber?: string | null
  birthYear?: number | null
  sireName?: string | null
  damName?: string | null
  sireSystem?: string | null
}

/** 手動資料更正的阻止原因：輸入不符（同手動建立的馬），或什麼都沒改 */
export type HorseCorrectionBlock = NewHorseBlock | { kind: 'unchanged' }

/** 更正後的馬匹；parentSystemUnknown 為 true 時提示 8.3 無法判斷 */
export interface CorrectedHorse {
  horse: HorseRow
  parentSystemUnknown: boolean
}

/** 可以更正、事件會記下的欄位 */
const FIELDS = [
  'fullName',
  'abilityNumber',
  'birthYear',
  'sireName',
  'damName',
  'sireSystem',
] as const

/**
 * 更正手動輸入、尚未經匯入確認的馬匹資料（需求規格 6.4、ID-08、ID-13）：只限這一局沒有出生紀錄、
 * 馬名還是手動輸入的市場馬（市場母馬與零代市場種牡馬）。檢查同手動建立的馬（checkHorseInput），
 * 同一匹馬的比對排除自己；什麼都沒改時阻止。基本馬名跟著完整馬名重算；父母名或父系還有值時來源維持手動。
 * 替代母馬的自身父系改了時重做 8.3 檢查；零代市場種牡馬改了父系時不重做 7.7 的比對
 * （只在補入或替換當下比對，要改系的名稱用系統名稱變更）。
 * 事件 horse-corrected 只記有改的欄位的原值與新值，沒有值記 null。
 * 馬匹找不到、屬於其他局、有出生紀錄或經匯入確認時丟出錯誤。
 */
export async function correctHorse(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  input: HorseCorrectionInput,
  options: WriteOptions = {},
): Promise<WriteResult<CorrectedHorse, HorseCorrectionBlock>> {
  return runWrite(db, gameId, ruleTables(db), options, async (context) => {
    const current = await db.horses.get(horseId)
    if (!current || current.gameId !== gameId) throw new Error(`找不到馬匹：${horseId}`)
    if (current.birth !== undefined || current.nameSource !== 'manual') {
      throw new Error(`只有手動輸入、尚未經匯入確認的市場馬可以更正：${horseId}`)
    }
    const checked = await checkHorseInput(context, mergedInput(current, input), horseId)
    const blocks: HorseCorrectionBlock[] = checked.ok ? [] : [...checked.blocks]
    const next = checked.ok ? corrected(current, checked.value) : current
    const changed = FIELDS.filter((field) => current[field] !== next[field])
    if (checked.ok && changed.length === 0) blocks.push({ kind: 'unchanged' })
    if (blocks.length > 0) return { status: 'blocked', blocks }

    const check = changed.includes('sireSystem')
      ? await recheckSubstitute(context.db, gameId, next)
      : { warnings: [], parentSystemUnknown: false }
    const stop = gate([], check.warnings, context.confirmed)
    if (stop) return stop
    await db.horses.put(next)
    const values = (row: HorseRow) =>
      Object.fromEntries(changed.map((field) => [field, row[field] ?? null])) as HorseFieldValues
    await context.addEvent({
      kind: 'horse-corrected',
      horseId,
      from: values(current),
      to: values(next),
      ...confirmation(check.warnings),
    })
    return context.done(
      { horse: next, parentSystemUnknown: check.parentSystemUnknown },
      check.warnings,
    )
  })
}

/** 更正後的完整輸入：省略的欄位用目前的值，null 表示清除 */
function mergedInput(current: HorseRow, input: HorseCorrectionInput): NewHorseInput {
  const pick = <T>(change: T | null | undefined, value: T | undefined) =>
    change === undefined ? value : (change ?? undefined)
  return {
    fullName: input.fullName ?? current.fullName ?? '',
    abilityNumber: pick(input.abilityNumber, current.abilityNumber),
    birthYear: pick(input.birthYear, current.birthYear),
    sireName: pick(input.sireName, current.sireName),
    damName: pick(input.damName, current.damName),
    sireSystem: pick(input.sireSystem, current.sireSystem),
  }
}

/** 換上更正後欄位的資料列：手動欄位與它們的來源重新組出，其他欄位（性別、父母的連結等）不變 */
function corrected(current: HorseRow, fields: Parameters<typeof manualHorseRow>[2]): HorseRow {
  const rest: HorseRow = { ...current }
  delete rest.abilityNumber
  delete rest.birthYear
  delete rest.sireName
  delete rest.damName
  delete rest.sireSystem
  delete rest.pedigreeSource
  return { ...rest, ...manualHorseRow(current.gameId, current.id, fields, current.sex) }
}

/** 替代母馬的自身父系改了時重做 8.3 親系統檢查；不是替代母馬時沒有警告 */
async function recheckSubstitute(
  db: WPStudBookDatabase,
  gameId: string,
  horse: HorseRow,
): Promise<SubstituteWarnings> {
  const rows = await readRuleRows(db, gameId)
  const mare = rows.mares.find((row) => row.horseId === horse.id)
  const role = mare ? damRoleOf(mare) : null
  if (role?.kind !== 'substitute') return { warnings: [], parentSystemUnknown: false }
  return substituteWarnings(rows, buildRuleSnapshot(rows), role.forLine, role.forGeneration, {
    horseId: horse.id,
    sireSystem: horse.sireSystem,
  })
}
