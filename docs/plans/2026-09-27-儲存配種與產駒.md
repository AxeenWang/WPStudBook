# 儲存配種與產駒 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `src/storage/` 加上配種與產駒的寫入操作：配種紀錄的登記與更正（八系指定配種的 10.3 阻止、在崗種牡馬、例外補入、8.3 與 10.2 的確認，以及自由配種）、受胎狀態與預定出生、建立產駒（連結前一年的受胎紀錄、同母同年只一匹）、正式馬名與牧場處置、總合評價與爆發力；並處理 PR #9 延後的兩項 Minor（技術設計 4.3「寫入操作」）。

**Architecture:** 儲存子計畫 2（事件與寫入操作）拆成四塊，本計畫是第 3 塊（2-1 寫入基礎、系與補系 → 2-2 母馬 → 2-3 配種與產駒 → 2-4 後繼與接替）。寫入操作沿用 2-1、2-2 的做法：每個操作一個 rw 交易（`runWrite`），交易內從資料列重新組出 core 的輸入並重做檢查，回傳 `done`、`blocked` 或 `unconfirmed`，阻止與待確認時什麼都不寫。指定配種由畫面傳任務看板上一條配對的產出與實際種牡馬，交易內以 `listBoard` 找配對、`checkDesignatedBreeding` 比對、`checkPedigree` 做血統檢查，結果存進配種紀錄的規則快照。產駒的能力、牝系、牧場處置與備註放在 `horses`；總合評價與爆發力是新的 `matingRatings` 表。規則判斷仍然交給 core，core 本身不改。

**Tech Stack:** TypeScript（strict）、Dexie 4、Vitest、fake-indexeddb。不新增套件。

## 規則依據（原文）

下列引文逐字取自 `docs/specs/需求規格.md` 與 `docs/specs/技術設計.md`。實作與審查都以原文為準；本計畫自己的判斷放在下一節。

**需求規格 4.7 能力數值**

> - 七項副能力（力量、瞬發力、勝負根性、柔軟性、精神力、賢明度、健康）等級 `G`～`S+`。非官方換算從 `G=0` 起每升一級加 1（`G+=1`、`F=2`…`S=14`、`S+=15`），七項合計即 `サ`（0～105）。
> - 芝、ダート適性：`◎ > ○ > △ > ×`。
> - 仔出（`子出`）：繁殖牝馬隱藏值，正常 0～10，使用者以 CE 使用 11～15，越高越容易出好馬。
> - 總合評價 `S > A > B > C > D` 與爆發力屬於「種牡馬＋繁殖牝馬」組合，隨年度與活力増強變動；2026-05-29 起遊戲內全年可用「配合シミュレート」查詢。

**5.2、5.3 阻止、警告與資料原則**

> | 會打亂自家循環的差錯 | 阻止保存，不能確認後繼續 | 指定配種或後繼的系、代數與規則不符 |
> | 策略選擇或受市場限制 | 警告並要求確認，保存確認紀錄 | 活血少於 8 種、4 代內有重複的馬、血統資料不足、八系親系統重複、替代母馬的親系統與其他系或同代其他替代母馬重複、零代種牡馬例外配市場母馬、替換種牡馬的系統不符 |
> - **未知值不是零值**：空白、未知、`0` 與布林否保持不同語意，匯入、備份、還原都不互相轉換。
> - **歷史只新增或更正**：賣出、引退、接替、轉場、改名、種牡馬更換與資料更正都保存事件，不靜默改寫或刪除。

**6.4 馬名**

> - 同時保存完整馬名（第 1 欄）與去除 `(外)`、`[地]` 前綴的基本馬名，主要顯示完整馬名，兩者都可搜尋。產駒名稱見 9.4。
> - `(外)`、`[地]` 前綴後面一定接著馬名。只有前綴、沒有馬名時屬於資料異常（5.2）：手動輸入時提示並不建立；匯入時警告並略過該筆，不寫入。

**7.3、7.4、7.6～7.8 八系的配對、種牡馬與自由配種**

> - **零代種牡馬原則只配自家母馬**：建立新系與補系補公系（7.6）的零代市場種牡馬，原則上配自家母馬，讓新系第一代帶有原系的血。自家母馬不足（例如一直生不出母駒、快要斷血）時，可例外從市場補入替代母馬：警告並確認，保存原因（10.3）；產駒代數依 8.2 仍是任務的產出代數，只要替代母馬的親系統符合 8.3，活血一樣能湊滿。建系起點不受此限。
> - 任務直接帶出系與代數，不能自由改變配對。每筆指定配種保存規則快照：距離、雙方系與代數、實際種牡馬與母馬、預計產出、血統檢查結果。
> - **補公系**：第 p 系 N 代沒有種牡馬可以延續時，以該系零代市場種牡馬代替第 p 系 N 代種牡馬，配原本指定的配對系 N 代母馬群，產出第 p 系 N+1 代（例：第 5 系零代 × 第 1 系 12 代母馬群 → 第 5 系 13 代）。宣告後，第 p 系 N+1 代的指定配對固定為補公系配對，之後重試得到第 p 系 N 代種牡馬也不另列一般任務；要用他配種請登記為自由配種，或更正補系宣告。第 p 系 N 代已有在崗或已指定的種牡馬時不能補公系（等待目標種牡馬不算斷血，7.8）（2026-09-23 決定）；第 p 系還沒到達 N 代（N 代沒有種牡馬紀錄，母馬群也沒成立，應原地重試或對 N−1 代補公系），或 N+1 代已有種牡馬紀錄時，也不能補公系（2026-09-24 決定）。
> - **現任**：每系每代同時只有一匹在崗種牡馬；交接期間同系上下兩代可同時在崗。狀態為在崗、已被取代、退出生產行列、已引退；退出生產行列與已引退都由使用者標示；種牡馬總表不偵測離場（11.8）。
> - 等待期間可登記自由配種，資料照常保存，但不計入八系完成度、不推進代數。

**8.2、8.3、8.5、8.8 代數、替代母馬、定年與牝系**

> - **產駒的系與代數**：產駒屬於父馬所在的系位置（建立新系時為該新系），代數為父母代數較大者加 1，市場馬為零代。例：第 2 系零代 × 第 1 系 1 代母馬 → 第 2 系 2 代；第 1 系 1 代 × 市場母馬 → 第 1 系 2 代。建系、循環、補血、補系都適用。
> - **替代母馬的代數**：替代母馬本身是零代，但計算產駒代數時以她替代的代數計（例：替代第 1 系 2 代的市場母馬以 2 代計）。因此指定配種中，市場母馬所生的產駒一律是任務的產出代數，例如例外補入時，第 3 系零代 × 替代第 1 系 2 代的市場母馬 → 第 3 系 3 代（7.3）。起點母馬以零代計。
> - 替代母馬的親系統會跟後代 3 代前的其他祖先撞在一起時，警告並確認（10.3），因為活血會少於 8 種。判斷方式：自身父系經系統對照表取得的親系統，符合下列任一項：
>   - 與第 q 系以外任一已成立系目前的親系統相同。
>   - 與同一代、替代其他系的市場母馬親系統相同（她們會一起出現在後代的 3 代前）。替代同一系的母馬之間不比較。
> - 定年可調，預設 25 歲。達定年減 1 歲（預設 24 歲）時提示「最後值得配種的年齡」；達定年時不列入任務。
> - 牝系保存名稱，空白為不屬具名牝系，可依有無與名稱篩選。
> - 暫定保留、候選、正式保留都可列入任務；已被取代、已售出不列入。

**9.1～9.5 配種與產駒**

> - 每匹母馬每年一筆：配種類型（八系指定、自由配種；建系期依 7.3 分支進行的配種也屬八系指定）、實際種牡馬、受胎狀態、預定生產年、產駒連結、規則快照、血統檢查與確認紀錄。可事先登記，或由七月匯入自動建立（11.6）。
> | `空胎` | 沒有進行受胎作業 | 否 |
> | `受胎` | 受胎成功 | 是，隔年 4 月 1 週 |
> | `不受胎` | 作業後失敗 | 否 |
> | `未確認` | 作業後結果未定 | 否，不推定結果 |
> - 正式結果以七月受胎名單為準；五月狀態只在預覽顯示，介面顯示「待 7 月確認」。七月仍為 `未確認` 時保留並警告可能異常。
> - **登記與更正**：手動登記只限當年。產駒出生前可以更正當年的配種類型與種牡馬，更正時重做 10.2、10.3 的檢查；受胎狀態不限年份，可以補登或更正，也可以清回尚無結果。已有產駒連到這筆紀錄時，不能更正配種類型與種牡馬，受胎狀態也不能改成 `受胎` 以外（2026-09-27 決定）。
> 使用者可隨時為一組種牡馬＋繁殖牝馬新增或編輯評價（`S`～`D`）與爆發力並記錄遊戲年。不強制每年登記；同年編輯直接更新，跨年舊值保留。兩者屬於配種組合，不是母馬固定能力。爆發力是 0 以上的整數（2026-09-27 決定）。
> - 由四月匯入或手動建立，規則相同，以內部識別連結母馬。同一母馬同一出生年最多一匹，第二筆阻止並指出既有產駒。
> - 手動建立時，母馬前一年有 `受胎` 紀錄就連結該紀錄，父馬取自紀錄；沒有 `受胎` 紀錄（例如購入時已受胎，或狀態還沒改成 `受胎`）時警告並確認，確認後比照自由配種產駒，與 11.4 的待核對相同。要讓八系指定配種的產駒成為後繼，先把受胎狀態改成 `受胎` 再建立（2026-09-27 決定）。
> - 空胎或不受胎年度記為輪空，不建立產駒，並與未登記年度區分。
> - 保存：性別、出生年、`SP`、`ST`、七項副能力、`サ`、芝與ダート適性、距離適性、仔出、父系、牝系、牧場處置（保留、待售、已售出）、備註。
> - 牧場處置：八系指定配種所生預設保留；自由配種所生（含比照自由配種者）一律待售，只能是待售或已售出（9.5）（2026-09-27 決定）。
> - 七項齊全時計算 `サ`，與匯入值不符時警告。芝、ダート分開保存並產生場地型摘要（不取代原值）。距離適性保存匯入文字。`SP` 可依高低排序，`ST` 只依數值排序。
> - 未命名產駒顯示追蹤名（用實際出生年，非配種年）。
> - 正式馬名可手動輸入或由一月總表填入；唯一配對的總表名稱優先，被取代的手動名稱保留為別名與歷程。總表填入後不可再手動修改或清空（遊戲裡的馬名之後不會再改），要更正以更正檔重新匯入一月總表。
> - 補名後主要顯示正式馬名，追蹤名保留為搜尋別名；識別、母馬、出生年、能力與售出狀態不變。清空正式馬名時回退追蹤名。
> 一律待售、不可成為八系後繼、不取得八系的系，不因性別、能力或母馬所屬群改變；父母、出生年與名稱照常保存，售出後仍可從母馬紀錄查到。

**10.1～10.3 血統檢查**

> 市場馬缺少完整血統，建系期不計算活血，也不因此警告。
> - 指定配種前，依已知血統與系統對照表預估活血種數，並檢查 4 代內重複的馬。
> - **4 代內**：父母、祖父母、曾祖父母、高祖父母，共 30 個位置；只在第 5 代重複（例如 4×5、5×5）不算。
> - **顯示**：沒有未知位置時顯示活血種數；有未知位置時，已知種數達 6 種以上顯示「至少 N 種（成立）」，並列出還缺的系與決定它的未知祖先；未達 6 種顯示「資料不足」。
> - 少於 8 種、4 代內重複或資料不足時，警告並確認，不阻止（使用者可能刻意混血）；確認與預估結果存入配種紀錄。
> - 例外：未知位置只來自建系期的市場種牡馬或替代母馬（主要在產出 5 代）時，只提示不要求確認。
>   - **種牡馬**：第 p 系 g−1 代現任種牡馬；建立新系時為指定位置的零代市場種牡馬；斷血補系補入公系時為該系零代市場種牡馬。
>   - **繁殖牝馬**：第 q 系 g−1 代母馬群（含替代母馬）；建系起點為第 1 系起點母馬群。種牡馬是零代市場種牡馬時（建立新系、補系補公系），選到市場母馬屬例外補入，警告並確認、保存原因，不阻止（7.3）。
> - 實際選擇不符時一律阻止，並指出錯誤的一方與正確的系、代數（例：新系誤配較舊一代母馬會永久落後一代）。
> - 替代母馬的親系統與其他 7 系、或同代替代其他系的市場母馬相同時，警告並確認（判斷方式見 8.3）。
> - 種牡馬要是那一格目前在崗的一匹：已被取代、退出生產行列、已引退或還沒正式供用的預定後繼，系與代數相同也阻止；補公系配對要用補入的零代市場種牡馬。母馬要列入任務：已達定年或已被取代的姊妹不能登記指定配種；自由配種不受此限（2026-09-27 決定）。

**技術設計 4.2 產駒名稱與正式後繼**

> - **正式後繼**（`successor.ts`）：用出生紀錄連結的配種紀錄的規則快照（實際種牡馬的系與代數、母馬當時的身分）核對，不用母馬目前的用途，因為用途修改從下一次配種才生效（需求規格 8.4）。除了父母與重算的系與代數，也以 10.3 確認這次配種是出生紀錄那一代的指定配對，所以偏離規則配到別系種牡馬的產駒會被阻止（5.2；10.3「刻意偏離請登記為自由配種」，使用者 2026-09-23 確認）。沒有配種紀錄、或配到八系以外種牡馬的產駒比照自由配種。`verifySuccessor` 的第二個參數是要進入的母馬群，或要接任、指定為預定後繼的系與代數，與出生紀錄不符時阻止。補公系所生的產駒，配種紀錄的規則快照要記 `restoration`，以補公系配對核對（需求規格 7.6）；補母系所生的產駒是一般指定配對，照常核對。

**技術設計 4.3「寫入操作」（全文）**

> #### 寫入操作
>
> 使用者的操作與之後 CE 匯入的套用，都經由儲存層的寫入操作（使用者 2026-09-26 確認）。共用的做法：
>
> - **一個操作一個交易**：每個操作在一個 rw 交易內完成：先讀遊戲局確認存在，再從資料列重新組出核心的輸入並重做檢查，最後寫入資料列與事件，並把遊戲局的更新時間設為現在。設定、代表色這類不寫事件的操作也更新，備份提醒（需求規格 12.2）以此判斷有沒有未備份的變更。操作可以包進呼叫端的外層交易（Dexie 的巢狀交易），CE 匯入以此在單一交易內套用多個操作（4.4）。
> - **結果**：完成時附寫入的結果與確認過的警告；阻止時附原因；有警告而呼叫端沒有帶確認時回傳待確認並附警告。阻止與待確認都什麼都不寫。畫面先呼叫一次取得警告，使用者確認後帶確認再呼叫；儲存層在交易內重做檢查，畫面漏掉檢查也存不進違規資料（需求規格 5.2）。確認過的警告存在這次操作的事件上。
> - **錯誤**：使用者的輸入或操作違反規則時回傳阻止；畫面不會送出的狀況（找不到資料列、屬於其他局、對已撤銷的宣告再撤銷）丟出帶識別的錯誤；資料列內容互相矛盾時丟 `RangeError`。
> - **事件**：會留下年份的操作一律寫事件，事件的年份是操作當時的目前遊戲年；遊戲年變更本身不寫事件。對象欄位填事件關於的馬匹、系位置或子系統，例如種牡馬狀態變更同時填系位置與馬匹；母馬的事件只填馬匹，因為替代母馬不屬於她替代的系（需求規格 8.3）。事件另記來源與時點（見「資料表」）。
> - **手動建立的馬**：完整馬名必填，只有前綴時阻止（需求規格 6.4）；馬名來源為手動輸入。能力番号與出生年選填：能力番号格式不符時阻止；出生年晚於目前遊戲年時阻止；能力番号與出生年都和這一局既有的馬相同時阻止並指出那匹馬（6.2：同一匹馬，應選既有的）。父母名與父系選填：父母名去掉前綴後存基本馬名，只有前綴時阻止；有填時，父母名與父系的來源為手動輸入（6.4：只輔助身分配對，匯入時改用匯入值，經匯入確認前可以更正）。
> - **系統名稱**：子系統、親系統、分出來源與父系都經 `normalizeSystemName`，必填的欄位空白時阻止。
> - **親系統重複的警告**：修改對照表、開啟新系、變更系統名稱或補入、替換零代種牡馬後，親系統因此改變的已開啟的系，與其他系目前的親系統相同時警告並確認（需求規格 7.2、LINE-03）。
>
> 各操作的規則：
>
> - **目前遊戲年**（需求規格 12.1）：往後可以改成任何年份；往回不能早於起始年，也不能早於最後紀錄年，也就是這一局事件的最大年份與馬的最大出生年，阻止時附可以改的最早年份。
> - **設定**：定年、高齡提醒年齡、種牡馬提醒年齡都要是 1 以上的整數；不寫事件，新設定從下一次判斷開始生效（MARE-10）。
> - **系統對照表**（需求規格 7.2）：新增時子系統不能已登錄，分出來源不能是自己；修改親系統（升格）或分出來源時（分出來源省略表示不變，傳 `null` 才清除），事件記原值、新值與年份。不提供刪除，也不改子系統名稱：打錯時新增正確的一筆，沒有系在用的那一筆不影響任何判斷。
> - **開啟新系**（需求規格 7.1、7.3）：該系要在任務看板的可開啟分支中（4.2；補公系進行中的系不能開分支）。填子系統、親系統、代表色（`#rrggbb`，自動分配由畫面預填）與零代市場種牡馬：新建，或選既有的市場馬（沒有出生紀錄、不是牝馬），因為補公系可以沿用建系時的零代種牡馬，兩處共用同一種輸入。子系統沒登錄時新增一筆，已登錄但親系統不同時改為填入的親系統。寫入系位置（開啟年為目前遊戲年）、零代的在崗任用與開啟事件。開啟後不提供撤銷（7.1 位置固定），開錯時以系統名稱變更與零代種牡馬替換更正。
> - **系統名稱變更**（需求規格 7.1、7.2、LINE-06）：系要已開啟，新名稱要與目前不同；可一併填親系統，照對照表的規則新增或修改，沒填而對照表查不到時親系統未知。事件記原名稱、新名稱與年份；「該系用過的舊名」（7.2）由開啟與名稱變更的事件查得。
> - **代表色**：只檢查格式，不寫事件。
> - **補入或替換零代市場種牡馬**（需求規格 7.6、7.7）：對象是某系建系的零代，或某次未撤銷的補公系宣告。那一格已有在崗或已指定的種牡馬時阻止（先標示前任引退，再替換）；選的馬已在這一格任用過時阻止。格是空的（補公系第一次選定）不需原因；只剩已離場的是替換，附 7.7 的原因（弟弟較優、前任引退、無法供用、斷血補系、遊戲依史實引退、其他，可附說明），生效年為目前遊戲年。以 `checkMarketStallionSystem` 比對他的父系，子系統不同時警告並確認，確認後該系的子系統改為他的父系並寫名稱變更事件，事件也記上這匹種牡馬；父系不明時不比較。
> - **種牡馬狀態**（需求規格 7.7）：在崗或已被取代的種牡馬可以標示退出生產行列或已引退；更正回在崗只在同一格沒有其他在崗時可以，否則阻止（換人用更換現任）。原本已被取代、誤標為退出或引退的，可以更正回已被取代，只在同一格另有在崗時可以（使用者 2026-09-26 決定）；其他情況的已被取代只由更換現任設定，預定後繼的取消也不在這裡。同一匹馬同時有建系與補公系的零代任用時，引退逐任用標示（使用者 2026-09-26 決定），要不要一次標示全部由畫面決定。這些操作都維持每格（某系某代的一般任用，或同一次補公系的任用）最多一匹在崗；彙整八系快照時遇到同一格有兩匹以上在崗，丟 `RangeError`。
> - **斷血補系**（需求規格 7.6）：宣告時原因必填，在交易內組出八系快照以 `checkRestoration` 檢查，年度為目前遊戲年；補入的零代市場種牡馬另外選定。撤銷時設為已撤銷並寫事件，不因已有補系的配種或產駒而阻止：配種紀錄的規則快照自帶補公系標記，補入的任用留著，快照略過已撤銷宣告底下的任用；撤銷後可以重新宣告。
> - **母馬的用途**（需求規格 7.3、8.3、8.4）：新增市場母馬、修改用途與從任務買回時，畫面傳任務看板上的一條配對（產出的系與代數）或待指定用途，不直接傳替代的系與代數。交易內組出八系快照，以 `listBoard` 從任務（含暫停中的）與可開啟分支的配對中找產出相同的那一條，找不到時阻止；一個產出只有一條配對，已宣告補公系時就是補公系配對。由配對推出：母馬群是起點時為第 1 系起點用，否則為替代配對母馬群的系與代數；種牡馬是零代而且不是建系起點（建立新系、補公系）時為例外補入，警告並確認、原因必填，其他情況不保存原因。替代母馬以 `checkSubstituteMare` 檢查親系統（8.3），同一代的其他替代母馬包含已離圈的、不含她自己；撞到時警告並確認，自身父系未知時只在完成的結果帶提示。
> - **新增市場母馬**（需求規格 8.4、MARE-05、MARE-29、MARE-31）：馬匹照手動建立的馬，性別為牝；在圈，不使該代成立；據點選填，事件一併記下初次據點。來源由配對推出：補公系配對，或配對的母馬群已宣告補母系（未撤銷）時為市場補系；否則建系起點、推進原系與建立新系為市場創系，循環為市場補血；待指定用途由使用者選市場混血或其他；都可附備註。已售出的母馬中，基本馬名相同、能力番号與出生年也不矛盾（兩邊都有值而且不同才算矛盾）時，警告可能是買回並列出那些母馬：使用者確認不是買回就照常建立；是買回時畫面改用買回操作，不建立新馬。
> - **修改用途**（需求規格 8.4、MARE-28）：只限在圈的市場母馬（替代、起點用、待指定用途）；自家母駒與自由配種所生的系與代數由出生紀錄決定，不提供。與目前相同時阻止。來源記的是購入時的目的（8.1），不隨用途改變。已有的配種紀錄保留自己的規則快照，新用途從下一次配種生效，不另外處理。
> - **賣出**（需求規格 8.5、MARE-08）：只限在圈的母馬；已達定年時阻止（4.6「無法再生產的母馬不能賣出」），出生年不明時可以賣出。這條只適用於手動賣出；五月缺席的判定由 CE 匯入計畫接上，缺席時的馬齡可能已達定年。
> - **更正離圈原因**（需求規格 8.5、11.5、MARE-32）：已離圈的母馬可以改為售出、定年引退，或撤銷回到生產中；與目前相同時阻止。撤銷不建立回歸事件；自家母駒回到保留的接替狀態（4.2），原本是正式保留而圈內已有另一匹正式保留的姊妹時改為候選。
> - **買回與回歸**（需求規格 8.5、8.9、ID-04、MARE-30、CAND-07）：只限已離圈的母馬。自家母駒沿用出生紀錄的系與代數，接替狀態以 `entrySisterStatus` 重新判定，成為暫定保留時 `establishedGeneration` 設為 true（不改回）；自由配種所生只恢復生產中。市場母馬沒有傳用途時沿用原用途，不重做 8.3 檢查；從任務買回時傳配對，照「母馬的用途」處理，事件記原用途與新用途。自家母駒與自由配種所生不接受用途。可以一併填據點。
> - **轉場**（需求規格 8.6、MARE-19）：只限在圈的母馬，與目前相同時阻止；事件記原據點（原本不知道時留空）與新據點，年份、時點與來源在事件的共用欄位。
> - **今年計畫**（需求規格 8.7、MARE-22）：只限在圈的母馬，年份為目前遊戲年；沒有值視為待定，與目前相同時阻止。不限用途。
> - **活力更正**（需求規格 8.7、MARE-13、MARE-14）：指定年份與五月或七月的快照，數值是 0～100 的整數，是否増強另外指定（`100` 也可以不増強）；年份不能晚於目前遊戲年。快照原本沒有值時也可以填入，不提供清除。與目前相同時阻止。
> - **手動資料更正**（需求規格 6.4、ID-08、ID-13）：只限沒有出生紀錄、馬名還是手動輸入的市場馬（市場母馬與零代市場種牡馬），經匯入確認的唯讀。可以更正完整馬名、能力番号、出生年、父母名與自身父系：省略表示不變，`null` 表示清除，完整馬名不能清除；檢查同手動建立的馬，同一匹馬的比對排除自己；什麼都沒改時阻止。替代母馬的自身父系改了時重做 8.3 檢查。零代市場種牡馬改了父系時不重做 7.7 的比對：那只在補入或替換當下比對，要改系的名稱用系統名稱變更。
> - **配種的登記：指定配種**（需求規格 7.4、9.1、10.2、10.3）：只登記目前遊戲年，一匹母馬一年一筆，已有時阻止並指出那一筆（改用更正）；母馬要在圈。畫面傳任務看板上的一條配對（產出的系與代數）與實際種牡馬。交易內組出八系快照，以 `listBoard` 從任務（含暫停中的）找產出相同的那一條，找不到時阻止；還沒開啟的分支沒有零代種牡馬，不算。母馬沒有列入任務（`mareListedInTasks`：已達定年、已被取代的姊妹）時阻止。以 `checkDesignatedBreeding` 比對，種牡馬的系與代數取他的任用（優先在崗的，沒有任用時為八系以外），不符時阻止；系與代數相符、但不是那一格在崗的任用時也阻止（10.3「現任種牡馬」）：一般配對看該系該代不屬於補系的任用，補公系配對看那一次補公系的任用。零代種牡馬配替代母馬（例外補入）時警告並確認，原因沒有傳時沿用母馬的例外補入原因，兩邊都空時阻止（使用者 2026-09-27 決定）；替代母馬重做 8.3 親系統檢查（同「母馬的用途」）。10.2 以 `loadMating` 讀血統樹、以 `checkPedigree` 檢查：要確認的警告（`hintOnly` 為否）警告並確認，只提示的放在完成的結果裡。規則快照記距離、種牡馬的系與代數、母馬當時的身分、預計產出、補公系標記與 `checkPedigree` 的完整結果（當時的快照，之後對照表變更不回頭更新）；例外補入原因與確認過的警告另存在配種紀錄上。登記不改今年計畫。
> - **配種的登記：自由配種**（需求規格 7.8、9.1）：種牡馬是內部馬匹或外部名稱（去掉前綴存基本馬名，只有前綴時阻止）；不做規則與血統檢查，母馬只要在圈，不看用途與馬齡。
> - **配種的更正**（需求規格 9.1、BRD-25）：只限目前遊戲年的紀錄，已有產駒的出生紀錄連到這一筆時阻止，內容與目前相同時阻止。指定與自由可以互換，檢查全部照登記重做，受胎狀態不變；事件記原內容與新內容。
> - **受胎狀態**（需求規格 9.1、BRD-02）：四種狀態原樣保存，也可以清回沒有結果；不限年份，母馬不必在圈。與目前相同時阻止；已有產駒連到這一筆時，改成 `受胎` 以外（含清空）阻止。不建立產駒。
> - **建立產駒**（需求規格 9.3、9.5、11.4、BRD-06）：母馬要是這一局的母馬（`mares` 有這一列），在圈與否不限；性別與出生年必填，出生年不能晚於目前遊戲年。同一母馬同一出生年已有產駒時阻止並指出那一匹。母馬「出生年減 1」那一年的配種紀錄是 `受胎` 時連結：父馬取自配種紀錄，有傳父馬而不一致時阻止；八系指定配種所生的出生紀錄記規則快照的預計產出，牧場處置為保留；自由配種所生沒有系與代數，處置為待售。沒有 `受胎` 紀錄時警告並確認，確認後不連結，父馬用輸入的（可以不知道），出生紀錄是空的，處置為待售，比照自由配種（使用者 2026-09-27 決定）。能力番号照手動建立的馬檢查；能力值不合法時阻止：`SP`、`ST` 為 0 以上的整數，`サ` 為 0～105 的整數，芝與ダート為 `◎○△×` 之一，出生時的仔出為 0～15 的整數，距離適性原樣存文字。七項副能力齊全、也帶了 `サ` 而不符時警告並確認（BRD-11）。父母名與父系的來源依事件的來源：手動為手動輸入，匯入為經匯入確認。牝駒不進繁殖圈，轉入母馬群由後繼的計畫處理。
> - **正式馬名**（需求規格 9.4、BRD-08、BRD-10）：只限自家產駒（有出生紀錄）；市場馬的手動馬名用「手動資料更正」。馬名經匯入確認時阻止，只有前綴、與目前相同時阻止。可以清空，清空後沒有馬名，顯示回退追蹤名；牧場處置不變。事件記原名與新名；手動名之間的更正只留歷程，一月總表取代手動名時的別名由 CE 匯入計畫處理。
> - **牧場處置**（需求規格 9.3、9.5、BRD-15、BRD-26）：只限自家產駒；出生紀錄沒有系與代數的產駒不能改為保留；與目前相同時阻止。
> - **總合評價與爆發力**（需求規格 9.2、BRD-17、BRD-18）：記在目前遊戲年；母馬要是這一局的母馬，不限在圈；種牡馬是內部馬匹或外部名稱（去掉前綴存基本馬名），同一匹種牡馬以內部識別與外部名稱登記時算不同的組合。評價與爆發力至少填一項，爆發力要是 0 以上的整數（使用者 2026-09-27 決定）。同一組同一年已有時整組取代，與目前相同時阻止；跨年另起一列，舊值保留。

## 本計畫的詮釋

需求規格與技術設計沒有逐字寫出、由本計畫決定的地方。技術設計 4.3「寫入操作」已經和使用者確認；下面是本計畫在程式層級的決定，審查時請逐條對照上一節的原文。

1. **共用的阻止型別與母馬讀取**（Task 1，PR #9 的 Minor）：「和目前相同」的阻止型別集中成 `writes.ts` 的 `UnchangedBlock`，`herd-writes.ts` 與 `mare-year-writes.ts` 各自的一份刪掉（`UnchangedYearBlock` 改用它），`horse-writes.ts`、`mare-writes.ts`、`line-writes.ts` 的 `{ kind: 'unchanged' }` 也改用它；兩份一樣的 `loadMare` 集中成 `writes.ts` 的 `loadMare`。行為不變。新增市場母馬有填據點時，`mare-added` 事件記 `location`，沒有填時不記。PR #9 的第三項 Minor（`sellMare` 的定年比較抽成 core 述詞）使用者決定不做。
2. **資料表的欄位**（Task 2）：產駒的能力是 `horses` 的 `ability`（`speed`、`stamina`、`subAbilities`、`subTotal`、`turf`、`dirt`、`distance`、`offspringQuality`，都選填），另有 `femaleLine`、`disposition`（`keep`、`for-sale`、`sold`）、`note`。規則快照的 `pedigree` 是 core 的 `PedigreeCheck`，必有；既有測試裡帶規則快照的配種測資補上建系期的空結果。事件記的配種內容 `BreedingValue` 只有類型、實際種牡馬、指定配種的預計產出與例外補入原因，不含整份規則快照。
3. **種牡馬的輸入**（Task 3，`resolveSire`）：內部馬匹要是這一局的馬、不是牝馬（性別不明可以）；外部名稱去掉前後空白與前綴，存基本馬名，空白或只有前綴時阻止（`sire-name`）。`sameSire` 比對有值的那一項：內部識別相同，或外部名稱相同。
4. **登記與更正**（Task 3）：登記時今年已有紀錄的阻止（`already-registered`，附那一筆的識別）和內容的阻止一起列出。更正往年的紀錄時只回傳 `past-year`，不再檢查其他。已有產駒以 `[gameId+damId]` 查母馬的馬，看出生紀錄的 `breedingId`。更正保留受胎狀態；「和目前相同」比對 `BreedingValue` 的類型、種牡馬、預計產出與例外補入原因，例外補入原因不同也算有改。登記與更正都要母馬在圈，不在圈時丟出錯誤。交易範圍是規則輸入快照的資料表加上 `breedings`。
5. **指定配種**（Task 4）：配對只從 `listBoard` 的任務找產出相同的一條（含暫停中的），不看可開啟分支；找不到時只回傳 `no-pairing`。種牡馬在那一格在崗時，比對用配對規定的系與代數；否則用他的任用（優先在崗的，否則第一筆），沒有任用時是八系以外。那一格：一般配對是該系該代 `restorationId` 留空的任用；補公系配對是同系、斷血代數為產出減 1、未撤銷的補公系宣告底下的任用。`sire-not-active` 只在 `checkDesignatedBreeding` 沒有種牡馬一方的阻止時加上。母馬列入任務用 `snapshot.ts` 的 `mareListed`（原本的 `listed` 改名匯出）。阻止的順序：`mare-not-listed`、`rule`（core 的順序）、`sire-not-active`、`reason-required`。例外補入以 core 的 `zero-sire-market-mare` 警告判斷；原因取輸入的，沒有傳時取母馬的 `exceptionReason`，去掉前後空白；傳了空字串不回退，會阻止。種牡馬找不到或屬於其他局時丟出錯誤；牝馬不會有任用，比對時就是八系以外。警告的順序：`exception-entry`、`substitute-parent-system`、`pedigree`。
6. **血統檢查**（Task 4、5）：`loadMating` 在寫入交易內讀（成為子交易）。`checkPedigree` 的產出代數用配對的產出；`hintOnly` 為否的警告種類依 core 的順序放進一筆 `pedigree` 警告；規則快照存 `checkPedigree` 的完整結果，包括只提示的。建系期存 `{ estimate: null, duplicates: [], warnings: [] }`。Task 4 先把結果存進規則快照，Task 5 才讓要確認的項目警告並確認。
7. **受胎狀態**（Task 6）：傳 `null` 清回沒有結果；和目前相同（包括原本就沒有結果時清空）阻止；已有產駒時只能維持 `受胎`。狀態文字不是四種之一時在交易開始前丟出錯誤（匯入層會先驗證，畫面只給四種）。事件原本沒有結果時沒有 `from`，清空時沒有 `to`。`expectedFoaling` 回傳受胎隔年與 4 月 1 週，其他狀態回傳 `null`。
8. **建立產駒**（Task 7）：母馬用 `loadMare`（任何在圈狀態）。阻止的順序：`foal-exists`、`birth-year`、`ability-number`、`same-horse`、`ability`（依 `speed`、`stamina`、`subAbilities`、`subTotal`、`turf`、`dirt`、`offspringQuality`）、`sire-name`、`sire-mismatch`。出生年不合法時不查同一匹馬、不查配種紀錄。只看母馬「出生年減 1」那一年的配種紀錄，狀態是 `受胎` 才連結；沒有連結時警告附那一筆的識別與狀態（有紀錄時）。`サ` 的警告只在七項齊全而且帶了 `サ` 時。`ability` 去掉沒有填的項目與空白的距離適性，全部沒有時不存；牝系與備註去掉前後空白，空白時不存；父系經 `normalizeSystemName`。`pedigreeSource` 只在有外部父馬名或父系時寫，事件來源是匯入時為 `import`。牝駒不寫進 `mares`。
9. **正式馬名與牧場處置**（Task 8）：`nameFoal` 只寫手動的馬名（`nameSource: 'manual'`）；經匯入確認時只回傳 `name-confirmed`。清空時刪掉完整馬名、基本馬名與馬名來源。牧場處置不是三種之一時在交易開始前丟出錯誤；自家產駒缺少處置時丟出 `RangeError`。已售出可以改回保留或待售（更正誤登記）；出生紀錄沒有系與代數的產駒不能改為保留。
10. **總合評價與爆發力**（Task 9）：總合評價不是 `S`～`D` 時在交易開始前丟出錯誤。阻止的順序：`empty`、`burst`、`sire-name`；「和目前相同」在前面都通過後才判斷。同一組同一年已有時整組取代，沒有填的項目清掉。
11. **驗收測試**：只驗證儲存層寫入負責的部分；匯入的配對與畫面的顯示由後續計畫補上。事件識別是亂數，同一個測試裡的事件在表裡的順序不固定，測試依對象、種類篩選或用 `toContainEqual`。

```ts
import type { WPStudBookDatabase } from './database'
import { ruleTables } from './loaders'
import type { BreedingRow, BreedingValue, HorseRow, MareRow, WriteWarning } from './records'
import {
  confirmation,
  gate,
  loadMare,
  resolveSire,
  runWrite,
  type Prepared,
  type SireInput,
  type SireNameBlock,
  type UnchangedBlock,
  type WriteContext,
  type WriteOptions,
  type WriteResult,
} from './writes'

// 配種紀錄的寫入操作：登記、更正與受胎狀態（需求規格 7.4、9.1、10.2、10.3；技術設計 4.3「寫入操作」）

/** 配種的輸入：自由配種傳實際種牡馬（內部馬匹或外部名稱） */
export type BreedingInput = { kind: 'free'; sire: SireInput }

/** 配種內容的阻止原因，登記與更正共用 */
export type BreedingCheckBlock = SireNameBlock

/** 已有產駒的出生紀錄連到這筆配種紀錄（需求規格 9.1、BRD-25）；horseId 是那匹產駒 */
export interface FoalExistsBlock {
  kind: 'foal-exists'
  horseId: string
}

/** 登記配種的阻止原因：內容不符，或這匹母馬今年已有配種紀錄（改用更正），breedingId 是那一筆 */
export type RegisterBreedingBlock =
  BreedingCheckBlock | { kind: 'already-registered'; breedingId: string }

/**
 * 更正配種的阻止原因：內容不符；past-year 是往年的紀錄，只能更正今年的；已有產駒；和目前相同
 */
export type CorrectBreedingBlock =
  BreedingCheckBlock | { kind: 'past-year' } | FoalExistsBlock | UnchangedBlock

/** 登記或更正後的配種紀錄；parentSystemUnknown 為 true 時提示 8.3 無法判斷 */
export interface SavedBreeding {
  breeding: BreedingRow
  parentSystemUnknown: boolean
}

/** 驗證過、還沒寫入的配種內容 */
interface CheckedBreeding {
  fields: Pick<BreedingRow, 'kind' | 'sireId' | 'sireName' | 'rule' | 'exceptionReason'>
  warnings: WriteWarning[]
  parentSystemUnknown: boolean
}

/** 配種的寫入操作要讀寫的資料表：規則輸入快照的資料表與配種紀錄 */
function breedingTables(db: WPStudBookDatabase) {
  return [...ruleTables(db), db.breedings]
}

/**
 * 登記目前遊戲年的配種（需求規格 9.1）：一匹母馬一年一筆，已有時阻止並指出那一筆（改用更正）。
 * 自由配種（7.8）：種牡馬是內部馬匹或外部名稱，不做規則與血統檢查，母馬只要在圈，不看用途與馬齡。
 * 登記不改今年計畫。事件 breeding-registered。
 * 母馬找不到、屬於其他局或不在圈內，或種牡馬找不到、屬於其他局或是牝馬時丟出錯誤。
 */
export async function registerBreeding(
  db: WPStudBookDatabase,
  gameId: string,
  mareId: string,
  input: BreedingInput,
  options: WriteOptions = {},
): Promise<WriteResult<SavedBreeding, RegisterBreedingBlock>> {
  return runWrite(db, gameId, breedingTables(db), options, async (context) => {
    await mareInHerd(context, mareId)
    const year = context.game.currentYear
    const existing = await db.breedings
      .where('[gameId+mareId+year]')
      .equals([gameId, mareId, year])
      .first()
    const checked = await checkBreeding(context, input)
    const blocks: RegisterBreedingBlock[] = [
      ...(existing ? [{ kind: 'already-registered' as const, breedingId: existing.id }] : []),
      ...(checked.ok ? [] : checked.blocks),
    ]
    if (!checked.ok || blocks.length > 0) return { status: 'blocked', blocks }
    const { fields, warnings, parentSystemUnknown } = checked.value
    const stop = gate([], warnings, context.confirmed)
    if (stop) return stop
    const breeding: BreedingRow = {
      id: crypto.randomUUID(),
      gameId,
      mareId,
      year,
      ...fields,
      ...confirmation(warnings),
    }
    await db.breedings.add(breeding)
    await context.addEvent({
      kind: 'breeding-registered',
      horseId: mareId,
      breedingId: breeding.id,
      breeding: breedingValue(breeding),
      ...confirmation(warnings),
    })
    return context.done({ breeding, parentSystemUnknown }, warnings)
  })
}

/**
 * 更正目前遊戲年的配種（需求規格 9.1、BRD-25）：類型與種牡馬可以換，檢查照登記重做；受胎狀態不變。
 * 往年的紀錄只回傳 past-year；已有產駒的出生紀錄連到這一筆、內容和目前相同時阻止。
 * 事件 breeding-corrected 記原內容與新內容。
 * 配種紀錄找不到或屬於其他局，或母馬、種牡馬的狀況同登記時丟出錯誤。
 */
export async function correctBreeding(
  db: WPStudBookDatabase,
  gameId: string,
  breedingId: string,
  input: BreedingInput,
  options: WriteOptions = {},
): Promise<WriteResult<SavedBreeding, CorrectBreedingBlock>> {
  return runWrite(db, gameId, breedingTables(db), options, async (context) => {
    const current = await loadBreeding(context, breedingId)
    if (current.year !== context.game.currentYear) {
      return { status: 'blocked', blocks: [{ kind: 'past-year' }] }
    }
    await mareInHerd(context, current.mareId)
    const blocks: CorrectBreedingBlock[] = []
    const foal = await linkedFoal(context, current)
    if (foal) blocks.push({ kind: 'foal-exists', horseId: foal.id })
    const checked = await checkBreeding(context, input)
    if (!checked.ok) blocks.push(...checked.blocks)
    else if (sameBreeding(breedingValue(current), breedingValue(checked.value.fields))) {
      blocks.push({ kind: 'unchanged' })
    }
    if (!checked.ok || blocks.length > 0) return { status: 'blocked', blocks }
    const { fields, warnings, parentSystemUnknown } = checked.value
    const stop = gate([], warnings, context.confirmed)
    if (stop) return stop
    const breeding: BreedingRow = {
      id: current.id,
      gameId,
      mareId: current.mareId,
      year: current.year,
      ...(current.conception === undefined ? {} : { conception: current.conception }),
      ...fields,
      ...confirmation(warnings),
    }
    await db.breedings.put(breeding)
    await context.addEvent({
      kind: 'breeding-corrected',
      horseId: current.mareId,
      breedingId,
      from: breedingValue(current),
      to: breedingValue(breeding),
      ...confirmation(warnings),
    })
    return context.done({ breeding, parentSystemUnknown }, warnings)
  })
}

/** 驗證配種的內容，不寫入 */
async function checkBreeding(
  context: WriteContext,
  input: BreedingInput,
): Promise<Prepared<CheckedBreeding, BreedingCheckBlock>> {
  const sire = await resolveSire(context, input.sire)
  if (!sire.ok) return sire
  return {
    ok: true,
    value: { fields: { kind: 'free', ...sire.value }, warnings: [], parentSystemUnknown: false },
  }
}

/** 在圈的母馬；找不到、屬於其他局或不在圈內時丟出錯誤 */
async function mareInHerd(context: WriteContext, mareId: string): Promise<MareRow> {
  const mare = await loadMare(context, mareId)
  if (mare.herd !== 'in-herd') throw new Error(`不在繁殖圈內的母馬不能登記配種：${mareId}`)
  return mare
}

/** 這一局的配種紀錄；找不到或屬於其他局時丟出錯誤 */
async function loadBreeding(context: WriteContext, breedingId: string): Promise<BreedingRow> {
  const breeding = await context.db.breedings.get(breedingId)
  if (!breeding || breeding.gameId !== context.game.id) {
    throw new Error(`找不到配種紀錄：${breedingId}`)
  }
  return breeding
}

/** 出生紀錄連到這筆配種紀錄的產駒；交易要包含 horses */
async function linkedFoal(
  context: WriteContext,
  breeding: BreedingRow,
): Promise<HorseRow | undefined> {
  return context.db.horses
    .where('[gameId+damId]')
    .equals([context.game.id, breeding.mareId])
    .filter((horse) => horse.birth?.breedingId === breeding.id)
    .first()
}

/** 事件記的配種內容：類型、實際種牡馬、指定配種的預計產出與例外補入的原因 */
function breedingValue(
  breeding: Pick<BreedingRow, 'kind' | 'sireId' | 'sireName' | 'rule' | 'exceptionReason'>,
): BreedingValue {
  return {
    kind: breeding.kind,
    ...(breeding.sireId === undefined ? {} : { sireId: breeding.sireId }),
    ...(breeding.sireName === undefined ? {} : { sireName: breeding.sireName }),
    ...(breeding.rule === undefined ? {} : { output: breeding.rule.output }),
    ...(breeding.exceptionReason === undefined
      ? {}
      : { exceptionReason: breeding.exceptionReason }),
  }
}

/** 兩次配種的內容是否相同 */
function sameBreeding(a: BreedingValue, b: BreedingValue): boolean {
  return (
    a.kind === b.kind &&
    a.sireId === b.sireId &&
    a.sireName === b.sireName &&
    a.output?.line === b.output?.line &&
    a.output?.generation === b.output?.generation &&
    a.exceptionReason === b.exceptionReason
  )
}
```

```ts
/**
 * 八系指定配種的檢查（需求規格 7.3、8.3、10.2、10.3；技術設計 4.3「配種的登記：指定配種」）：
 * 交易內重新組出八系快照，從任務看板的任務找配對，再比對母馬、種牡馬與例外補入；
 * 都通過後做 8.3 與血統檢查，組出規則快照
 */
async function checkDesignated(
  context: WriteContext,
  mare: MareRow,
  input: DesignatedBreedingInput,
): Promise<Prepared<CheckedBreeding, BreedingCheckBlock>> {
  const { db, game } = context
  const rows = await readRuleRows(db, game.id, game)
  const snapshot = buildRuleSnapshot(rows)
  const pairing = listBoard(snapshot.eightLines)
    .tasks.map((task) => task.pairing)
    .find(
      (candidate) =>
        candidate.output.line === input.output.line &&
        candidate.output.generation === input.output.generation,
    )
  if (!pairing) return { ok: false, blocks: [{ kind: 'no-pairing' }] }
  const sire = await db.horses.get(input.sireId)
  if (!sire || sire.gameId !== game.id) throw new Error(`找不到馬匹：${input.sireId}`)

  const blocks: BreedingCheckBlock[] = []
  const horses = new Map(rows.horses.map((horse) => [horse.id, horse]))
  if (!mareListed(mare, horses, game.currentYear, mareAgeSettings(rows.settings))) {
    blocks.push({ kind: 'mare-not-listed' })
  }
  const role = damRoleOf(mare)
  const active = slotStallions(rows, pairing).some(
    (row) => row.horseId === input.sireId && row.status === 'active',
  )
  const check = checkDesignatedBreeding(
    pairing,
    active ? pairing.sire : sirePlacement(rows.stallions, input.sireId),
    role ?? { kind: 'unassigned' },
  )
  blocks.push(...check.blocks.map((rule) => ({ kind: 'rule' as const, rule })))
  if (!active && check.blocks.every((block) => block.side !== 'sire')) {
    blocks.push({ kind: 'sire-not-active' })
  }
  const exception = check.warnings.length > 0
  const reason = (input.exceptionReason ?? mare.exceptionReason ?? '').trim()
  if (exception && reason === '') blocks.push({ kind: 'reason-required' })
  if (blocks.length > 0 || role === null) return { ok: false, blocks }

  const substitute =
    role.kind === 'substitute'
      ? substituteWarnings(rows, snapshot, role.forLine, role.forGeneration, {
          horseId: mare.horseId,
          sireSystem: horses.get(mare.horseId)?.sireSystem,
        })
      : { warnings: [], parentSystemUnknown: false }
  const mating = await loadMating(db, game.id, input.sireId, mare.horseId)
  const pedigree = checkPedigree(
    pairing.output.generation,
    mating,
    snapshot.systemTable,
    snapshot.lineSystems,
  )
  const warnings: WriteWarning[] = [
    ...(exception ? [{ kind: 'exception-entry' as const, ...pairing.output }] : []),
    ...substitute.warnings,
  ]
  return {
    ok: true,
    value: {
      fields: {
        kind: 'designated',
        sireId: input.sireId,
        rule: {
          distance: pairing.distance,
          sire: pairing.sire,
          dam: role,
          output: pairing.output,
          ...(pairing.kind === 'restore' ? { restoration: true as const } : {}),
          pedigree,
        },
        ...(exception ? { exceptionReason: reason } : {}),
      },
      warnings,
      parentSystemUnknown: substitute.parentSystemUnknown,
    },
  }
}

/**
 * 配對指定的那一格種牡馬任用（10.3）：一般配對是該系該代不屬於補系的任用；
 * 補公系配對是那一次（未撤銷的）補公系的任用
 */
function slotStallions(rows: RuleRows, pairing: DesignatedPairing): StallionRow[] {
  const { line, generation } = pairing.sire
  if (pairing.kind !== 'restore') {
    return rows.stallions.filter(
      (row) =>
        row.restorationId === undefined && row.line === line && row.generation === generation,
    )
  }
  const restoration = rows.restorations.find(
    (row) =>
      !row.revoked &&
      row.side === 'sire' &&
      row.line === line &&
      row.generation === pairing.output.generation - 1,
  )
  return rows.stallions.filter(
    (row) => restoration !== undefined && row.restorationId === restoration.id,
  )
}

/** 種牡馬在八系中的系與代數（10.3 比對用）：取他的任用，優先在崗的；沒有任用時為八系以外 */
function sirePlacement(stallions: readonly StallionRow[], horseId: string): LineGeneration | null {
  const posts = stallions.filter((row) => row.horseId === horseId)
  const post = posts.find((row) => row.status === 'active') ?? posts[0]
  return post ? { line: post.line, generation: post.generation } : null
}
```

```ts
/** 循環期牧場的血統：覆寫 S14、D24 的欄位（例如父母），以及血統上其他的馬 */
export interface CyclePedigree {
  sire?: Partial<HorseRow>
  dam?: Partial<HorseRow>
  ancestors?: readonly HorseRow[]
}

/**
 * 測試用的循環期牧場，目前遊戲年 1990：八系都已開啟（系1子～系8子，親系統 系1親～系8親）。
 * 第 1 系 4 代種牡馬 S14 在崗，第 2 系 4 代自家母駒 D24（1985 年生）在圈並使該代成立；

 */
export async function cyclePhaseHerd(pedigree: CyclePedigree = {}): Promise<WPStudBookDatabase> {
  const db = testDatabase()
  await addTestGame(db)
  await db.lines.bulkAdd(LINE_POSITIONS.map((line) => lineRow(line, subsystemOfLine(line))))
  await db.systems.bulkAdd(eightLineSystems().table.map((entry) => ({ gameId: GAME, ...entry })))
  await db.horses.bulkAdd([
    horseRow('S14', {
      sex: 'male',
      birth: { placement: { line: 1, generation: 4 } },
      ...pedigree.sire,
    }),
    horseRow('D24', {
      sex: 'female',
      birthYear: 1985,
      birth: { placement: { line: 2, generation: 4 } },
      ...pedigree.dam,
    }),
    ...(pedigree.ancestors ?? []),
  ])
  await db.stallions.add(stallionRow('S14', 1, 4))
  await db.mares.add(ownMareRow('D24', 2, 4))
  return db
}
```

```ts
/**
 * 登記或更正受胎狀態（需求規格 9.1、BRD-02、BRD-25）：四種狀態原樣保存，傳 null 清回沒有結果。

 * 事件 conception-set 記原狀態與新狀態。配種紀錄找不到、屬於其他局，或狀態不是四種之一時丟出錯誤。
 */
export async function setConception(
  db: WPStudBookDatabase,
  gameId: string,
  breedingId: string,
  conception: Conception | null,
  options: WriteOptions = {},
): Promise<WriteResult<BreedingRow, ConceptionBlock>> {
  if (conception !== null && !CONCEPTIONS.includes(conception)) {
    throw new Error(`受胎狀態不符：${conception}`)
  }
  return runWrite(db, gameId, [db.breedings, db.horses], options, async (context) => {
    const current = await loadBreeding(context, breedingId)
    const from = current.conception
    const to = conception ?? undefined
    const blocks: ConceptionBlock[] = []
    if (from === to) blocks.push({ kind: 'unchanged' })
    else if (to !== '受胎') {
      const foal = await linkedFoal(context, current)
      if (foal) blocks.push({ kind: 'foal-exists', horseId: foal.id })
    }
    if (blocks.length > 0) return { status: 'blocked', blocks }
    const breeding: BreedingRow = { ...current }
    if (to === undefined) delete breeding.conception
    else breeding.conception = to
    await db.breedings.put(breeding)
    await context.addEvent({
      kind: 'conception-set',
      horseId: current.mareId,
      breedingId,
      ...(from === undefined ? {} : { from }),
      ...(to === undefined ? {} : { to }),
    })
    return context.done(breeding)
  })
}
```

```ts
import { checkSubAbilityTotal, isSubAbilityGrade } from '../core/foal'
import { normalizeAbilityNumber } from '../core/identity'
import { normalizeSystemName } from '../core/systems'
import type { FoalExistsBlock } from './breeding-writes'
import type { WPStudBookDatabase } from './database'
import type {
  FoalDisposition,
  HorseAbility,
  HorseRow,
  Sex,
  SurfaceAptitude,
  WriteWarning,
} from './records'
import {
  confirmation,
  findSameHorse,
  gate,
  loadMare,
  resolveSire,
  runWrite,
  sameSire,
  type Prepared,
  type SireInput,
  type SireNameBlock,
  type SireRef,
  type WriteOptions,
  type WriteResult,

// 自家產駒的寫入操作：建立產駒、正式馬名與牧場處置（需求規格 9.3～9.5；技術設計 4.3「寫入操作」）

/** 建立產駒的輸入（需求規格 9.3）；選填的文字欄位留空或只有空白都當作沒有填 */
export interface FoalInput {
  /** 母馬：這一局的母馬（進過自家繁殖圈），在圈與否不限 */
  damId: string
  sex: Sex
  /** 出生年；畫面預填目前遊戲年 */
  birthYear: number
  /** 父馬；連結配種紀錄時可以省略，有傳時要和配種紀錄一致 */
  sire?: SireInput
  /** 父系：父馬的子系統 */
  sireSystem?: string
  abilityNumber?: string
  ability?: HorseAbility
  /** 牝系的名稱 */
  femaleLine?: string
  note?: string
}

/** 能力中檢查值域的項目 */
export type AbilityField =
  'speed' | 'stamina' | 'subAbilities' | 'subTotal' | 'turf' | 'dirt' | 'offspringQuality'

/** 能力值不合法；field 是哪一項 */
export interface AbilityBlock {
  kind: 'ability'
  field: AbilityField
}

/**
 * 建立產駒的阻止原因：
 * - foal-exists：同一母馬同一出生年已有產駒（BRD-06），horseId 是那一匹
 * - birth-year：出生年不是整數，或晚於目前遊戲年
 * - ability-number：能力番号的格式不符
 * - same-horse：能力番号與出生年都和這一局既有的馬相同（6.2）
 * - ability：能力值不合法
 * - sire-name：父馬的外部名稱空白或只有前綴
 * - sire-mismatch：傳了父馬，但和連結的配種紀錄 breedingId 不同
 */
export type FoalBlock =
  | FoalExistsBlock
  | { kind: 'birth-year' }
  | { kind: 'ability-number' }
  | { kind: 'same-horse'; horseId: string }
  | AbilityBlock
  | SireNameBlock
  | { kind: 'sire-mismatch'; breedingId: string }

/** 芝、ダート適性的四種符號 */
const SURFACES: readonly SurfaceAptitude[] = ['◎', '○', '△', '×']

/**
 * 建立產駒（需求規格 9.3、9.5、11.4、BRD-06）；手動建立與之後的四月匯入共用。
 * 母馬「出生年減 1」那一年的配種紀錄是 `受胎` 時連結：父馬取自配種紀錄，有傳父馬而不一致時阻止；
 * 八系指定配種所生的出生紀錄記規則快照的預計產出，牧場處置為保留；自由配種所生沒有系與代數，處置為待售。
 * 沒有 `受胎` 紀錄時警告並確認，確認後不連結，父馬用輸入的（可以不知道），出生紀錄是空的，處置為待售，
 * 比照自由配種。同一母馬同一出生年已有產駒時阻止並指出那一匹；七項副能力齊全、也帶了 `サ` 而不符時警告並確認。
 * 父母名與父系的來源依事件的來源：手動為手動輸入，匯入為經匯入確認。產駒還沒有正式馬名，顯示追蹤名（9.4）。
 * 事件 foal-added。母馬找不到或屬於其他局，或父馬是找不到、屬於其他局的馬匹或牝馬時丟出錯誤。
 */
export async function addFoal(
  db: WPStudBookDatabase,
  gameId: string,
  input: FoalInput,
  options: WriteOptions = {},
): Promise<WriteResult<HorseRow, FoalBlock>> {
  return runWrite(db, gameId, [db.mares, db.horses, db.breedings], options, async (context) => {
    const { game } = context
    const { damId, birthYear } = input
    await loadMare(context, damId)
    const blocks: FoalBlock[] = []
    const existing = await db.horses
      .where('[gameId+damId]')
      .equals([game.id, damId])
      .filter((horse) => horse.birthYear === birthYear)
      .first()
    if (existing) blocks.push({ kind: 'foal-exists', horseId: existing.id })
    const yearValid = Number.isInteger(birthYear) && birthYear <= game.currentYear
    if (!yearValid) blocks.push({ kind: 'birth-year' })
    const abilityText = input.abilityNumber?.trim() ?? ''
    const abilityNumber = abilityText === '' ? undefined : normalizeAbilityNumber(abilityText)
    if (abilityNumber === null) blocks.push({ kind: 'ability-number' })
    else if (abilityNumber !== undefined && yearValid) {
      const same = await findSameHorse(context, abilityNumber, birthYear)
      if (same) blocks.push({ kind: 'same-horse', horseId: same.id })
    }
    const ability = checkAbility(input.ability)
    if (!ability.ok) blocks.push(...ability.blocks)
    const sire = input.sire === undefined ? undefined : await resolveSire(context, input.sire)
    if (sire && !sire.ok) blocks.push(...sire.blocks)
    const breeding = yearValid
      ? await db.breedings
          .where('[gameId+mareId+year]')
          .equals([game.id, damId, birthYear - 1])
          .first()
      : undefined
    const linked = breeding?.conception === '受胎' ? breeding : undefined
    if (linked && sire?.ok && !sameSire(linked, sire.value)) {
      blocks.push({ kind: 'sire-mismatch', breedingId: linked.id })
    }
    if (!ability.ok || abilityNumber === null || blocks.length > 0) {
      return { status: 'blocked', blocks }
    }

    const warnings: WriteWarning[] = []
    if (!linked) {
      warnings.push({
        kind: 'no-conception-record',
        ...(breeding === undefined ? {} : { breedingId: breeding.id }),
        ...(breeding?.conception === undefined ? {} : { conception: breeding.conception }),
      })
    }
    const imported = ability.value?.subTotal
    const total = checkSubAbilityTotal(ability.value?.subAbilities ?? {}, imported)
    if (total.mismatch && total.total !== null && imported !== undefined) {
      warnings.push({ kind: 'sub-ability-total', total: total.total, imported })
    }
    const stop = gate([], warnings, context.confirmed)
    if (stop) return stop

    const sireRef: SireRef | Record<string, never> = linked
      ? linkedSire(linked)
      : sire?.ok
        ? sire.value
        : {}
    const placement = linked?.kind === 'designated' ? linked.rule?.output : undefined
    const disposition: FoalDisposition = placement ? 'keep' : 'for-sale'
    const sireSystem = input.sireSystem === undefined ? null : normalizeSystemName(input.sireSystem)
    const pedigree = 'sireName' in sireRef || sireSystem !== null
    const femaleLine = input.femaleLine?.trim() ?? ''
    const note = input.note?.trim() ?? ''
    const foal: HorseRow = {
      id: crypto.randomUUID(),
      gameId: game.id,
      ...(abilityNumber === undefined ? {} : { abilityNumber }),
      birthYear,
      sex: input.sex,
      ...sireRef,
      damId,
      ...(sireSystem === null ? {} : { sireSystem }),
      ...(pedigree
        ? { pedigreeSource: options.source?.kind === 'import' ? 'import' : 'manual' }
        : {}),
      birth: {
        ...(linked ? { breedingId: linked.id } : {}),
        ...(placement ? { placement } : {}),
      },
      ...(ability.value === undefined ? {} : { ability: ability.value }),
      ...(femaleLine === '' ? {} : { femaleLine }),
      disposition,
      ...(note === '' ? {} : { note }),
    }
    await db.horses.add(foal)
    await context.addEvent({
      kind: 'foal-added',
      horseId: foal.id,
      ...(linked ? { breedingId: linked.id } : {}),
      disposition,
      ...confirmation(warnings),
    })
    return context.done(foal, warnings)
  })
}

/** 連結的配種紀錄記的父馬：內部識別或外部名稱 */
function linkedSire(breeding: {
  sireId?: string
  sireName?: string
}): SireRef | Record<string, never> {
  if (breeding.sireId !== undefined) return { sireId: breeding.sireId }
  if (breeding.sireName !== undefined) return { sireName: breeding.sireName }
  return {}
}

/**
 * 驗證能力值並統一寫法（需求規格 4.7、9.3）：SP、ST 為 0 以上的整數，七項副能力為 G～S+，
 * `サ` 為 0～105 的整數，芝與ダート為 ◎○△× 之一，出生時的仔出為 0～15 的整數；距離適性原樣存文字，
 * 去掉前後空白。阻止原因依上面的順序列全。沒有填的項目不存，全部沒有時為 undefined
 */
function checkAbility(
  ability: HorseAbility | undefined,
): Prepared<HorseAbility | undefined, AbilityBlock> {
  if (ability === undefined) return { ok: true, value: undefined }
  const blocks: AbilityBlock[] = []
  const integer = (field: AbilityField, value: number | undefined, max?: number) => {
    const valid =
      value === undefined ||
      (Number.isInteger(value) && value >= 0 && (max === undefined || value <= max))
    if (!valid) blocks.push({ kind: 'ability', field })
  }
  integer('speed', ability.speed)
  integer('stamina', ability.stamina)
  const subAbilities = compact(ability.subAbilities ?? {})
  if (!Object.values(subAbilities).every((grade) => isSubAbilityGrade(grade))) {
    blocks.push({ kind: 'ability', field: 'subAbilities' })
  }
  integer('subTotal', ability.subTotal, 105)
  for (const field of ['turf', 'dirt'] as const) {
    const value = ability[field]
    if (value !== undefined && !SURFACES.includes(value)) blocks.push({ kind: 'ability', field })
  }
  integer('offspringQuality', ability.offspringQuality, 15)
  if (blocks.length > 0) return { ok: false, blocks }
  const distance = ability.distance?.trim() ?? ''
  const value = compact({
    ...ability,
    subAbilities: Object.keys(subAbilities).length === 0 ? undefined : subAbilities,
    distance: distance === '' ? undefined : distance,
  })
  return { ok: true, value: Object.keys(value).length === 0 ? undefined : value }
}

/** 去掉值是 undefined 的欄位 */
function compact<T extends object>(value: T): T {
  return Object.fromEntries(Object.entries(value).filter(([, item]) => item !== undefined)) as T
}
```

```ts
/**
 * 填入、更正或清空自家產駒的正式馬名（需求規格 9.4、BRD-08、BRD-10）：只限自家產駒（有出生紀錄）；
 * 市場馬的手動馬名用 correctHorse。馬名經匯入確認時阻止；fullName 是 null 或只有空白時清空，
 * 清空後沒有馬名，顯示回退追蹤名。基本馬名跟著完整馬名，馬名來源為手動輸入；牧場處置不變。
 * 事件 foal-named 記原名與新名；一月總表取代手動名時的別名由 CE 匯入計畫處理。
 * 馬匹找不到、屬於其他局或不是自家產駒時丟出錯誤。
 */
export async function nameFoal(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  fullName: string | null,
  options: WriteOptions = {},
): Promise<WriteResult<HorseRow, FoalNameBlock>> {
  return runWrite(db, gameId, [db.horses], options, async (context) => {
    const current = await loadFoal(context, horseId)
    const text = fullName?.trim() ?? ''
    const name = text === '' ? undefined : splitHorseName(text)
    const blocks: FoalNameBlock[] = []
    if (current.nameSource === 'import') blocks.push({ kind: 'name-confirmed' })
    else if (name === null) blocks.push({ kind: 'horse-name' })
    else if (name?.fullName === current.fullName) blocks.push({ kind: 'unchanged' })
    if (name === null || blocks.length > 0) return { status: 'blocked', blocks }
    const foal: HorseRow = { ...current }
    if (name) {
      foal.fullName = name.fullName
      foal.baseName = name.baseName
      foal.nameSource = 'manual'
    } else {
      delete foal.fullName
      delete foal.baseName
      delete foal.nameSource
    }
    await db.horses.put(foal)
    await context.addEvent({
      kind: 'foal-named',
      horseId,
      ...(current.fullName === undefined ? {} : { from: current.fullName }),
      ...(name ? { to: name.fullName } : {}),
    })
    return context.done(foal)
  })
}

/**
 * 牧場處置（需求規格 9.3、9.5、BRD-15、BRD-26）：保留、待售、已售出。只限自家產駒；
 * 出生紀錄沒有系與代數的產駒（自由配種所生或比照自由配種）不能改為保留；和目前相同時阻止。
 * 事件 foal-disposition-changed 記原處置與新處置。馬匹找不到、屬於其他局或不是自家產駒、
 * 處置不是三種之一時丟出錯誤；自家產駒缺少牧場處置時丟出 RangeError。
 */
export async function setFoalDisposition(
  db: WPStudBookDatabase,
  gameId: string,
  horseId: string,
  disposition: FoalDisposition,
  options: WriteOptions = {},
): Promise<WriteResult<HorseRow, DispositionBlock>> {
  if (!DISPOSITIONS.includes(disposition)) throw new Error(`牧場處置不符：${disposition}`)
  return runWrite(db, gameId, [db.horses], options, async (context) => {
    const current = await loadFoal(context, horseId)
    const from = current.disposition
    if (from === undefined) throw new RangeError(`自家產駒缺少牧場處置：${horseId}`)
    const blocks: DispositionBlock[] = []
    if (disposition === from) blocks.push({ kind: 'unchanged' })
    else if (disposition === 'keep' && current.birth?.placement === undefined) {
      blocks.push({ kind: 'free-foal' })
    }
    if (blocks.length > 0) return { status: 'blocked', blocks }
    const foal: HorseRow = { ...current, disposition }
    await db.horses.put(foal)
    await context.addEvent({ kind: 'foal-disposition-changed', horseId, from, to: disposition })
    return context.done(foal)
  })
}

/** 這一局的自家產駒（有出生紀錄）；找不到、屬於其他局或不是自家產駒時丟出錯誤 */
async function loadFoal(context: WriteContext, horseId: string): Promise<HorseRow> {
  const horse = await context.db.horses.get(horseId)
  if (!horse || horse.gameId !== context.game.id) throw new Error(`找不到馬匹：${horseId}`)
  if (horse.birth === undefined) throw new Error(`不是自家產駒：${horseId}`)
  return horse
}
```

```ts
import type { WPStudBookDatabase } from './database'
import type { MatingGrade, MatingRatingRow, MatingRatingValue } from './records'
import {
  loadMare,
  resolveSire,
  runWrite,
  sameSire,
  type SireInput,
  type SireNameBlock,
  type UnchangedBlock,
  type WriteOptions,
  type WriteResult,
} from './writes'

// 總合評價與爆發力的寫入操作（需求規格 9.2；技術設計 4.3「寫入操作」）

/** 評價的輸入：種牡馬，以及總合評價與爆發力（至少一項） */
export interface MatingRatingInput {
  sire: SireInput
  grade?: MatingGrade
  /** 爆發力：0 以上的整數 */
  burst?: number
}

/**
 * 評價的阻止原因：
 * - empty：總合評價與爆發力都沒有填
 * - burst：爆發力不是 0 以上的整數（BRD-23）
 * - sire-name：種牡馬的外部名稱空白或只有前綴
 * - unchanged：和目前相同
 */
export type RatingBlock = { kind: 'empty' } | { kind: 'burst' } | SireNameBlock | UnchangedBlock

/** 總合評價的五個等級 */
const GRADES: readonly MatingGrade[] = ['S', 'A', 'B', 'C', 'D']

/**
 * 登記或編輯一組種牡馬＋繁殖牝馬今年的總合評價與爆發力（需求規格 9.2、BRD-17、BRD-18、BRD-23）：
 * 記在目前遊戲年；母馬要是這一局的母馬，不限在圈；種牡馬是內部馬匹或外部名稱（去掉前綴存基本馬名），
 * 同一匹種牡馬以內部識別與外部名稱登記時算不同的組合。同一組同一年已有時整組取代，和目前相同時阻止；
 * 跨年另起一列，舊值保留。事件 mating-rated 記原值與新值。
 * 母馬找不到或屬於其他局、種牡馬是找不到或屬於其他局的馬匹或牝馬、總合評價不是 S～D 時丟出錯誤。
 */
export async function rateMating(
  db: WPStudBookDatabase,
  gameId: string,
  mareId: string,
  input: MatingRatingInput,
  options: WriteOptions = {},
): Promise<WriteResult<MatingRatingRow, RatingBlock>> {
  if (input.grade !== undefined && !GRADES.includes(input.grade)) {
    throw new Error(`總合評價不符：${input.grade}`)
  }
  return runWrite(db, gameId, [db.mares, db.horses, db.matingRatings], options, async (context) => {
    await loadMare(context, mareId)
    const { grade, burst } = input
    const sire = await resolveSire(context, input.sire)
    const blocks: RatingBlock[] = []
    if (grade === undefined && burst === undefined) blocks.push({ kind: 'empty' })
    if (burst !== undefined && !(Number.isInteger(burst) && burst >= 0)) {
      blocks.push({ kind: 'burst' })
    }
    if (!sire.ok) blocks.push(...sire.blocks)
    if (!sire.ok || blocks.length > 0) return { status: 'blocked', blocks }
    const year = context.game.currentYear
    const current = await db.matingRatings
      .where('[gameId+mareId]')
      .equals([gameId, mareId])
      .filter((row) => row.year === year && sameSire(row, sire.value))
      .first()
    if (current && current.grade === grade && current.burst === burst) {
      blocks.push({ kind: 'unchanged' })
      return { status: 'blocked', blocks }
    }
    const to: MatingRatingValue = {
      ...(grade === undefined ? {} : { grade }),
      ...(burst === undefined ? {} : { burst }),
    }
    const rating: MatingRatingRow = {
      id: current?.id ?? crypto.randomUUID(),
      gameId,
      mareId,
      ...sire.value,
      year,
      ...to,
    }
    await db.matingRatings.put(rating)
    await context.addEvent({
      kind: 'mating-rated',
      horseId: mareId,
      ratingId: rating.id,
      ...(current ? { from: ratingValue(current) } : {}),
      to,
    })
    return context.done(rating)
  })
}

/** 評價的內容：總合評價與爆發力，沒有值的不列 */
function ratingValue(row: MatingRatingRow): MatingRatingValue {
  return {
    ...(row.grade === undefined ? {} : { grade: row.grade }),
    ...(row.burst === undefined ? {} : { burst: row.burst }),
  }
}
```
