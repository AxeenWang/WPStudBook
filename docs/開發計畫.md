## 計畫目的

本計畫將已確認的需求規格轉為可以逐階段實作、檢查及驗收的工作順序。開發重點不是先完成大量畫面，而是先建立不會錯接血統、不會覆寫歷史、可以可靠備份還原的資料核心，再逐步加入年度匯入、卡片式操作及八系循環防錯。

第一版採「先完成一條完整生命週期，再擴展到八系」的方式。最早可驗證的流程必須能從建立遊戲局、第一系及零代親馬開始，完成配種、受胎、產駒、後繼選定、升代、退役或售出，最後經 JSON 匯出與重新匯入後保持同一組關聯。

## 實作原則

1. **資料安全先於功能數量**：任何正式資料異動都必須經驗證與交易處理。匯入失敗不能留下半套資料。
2. **內部識別先於顯示名稱**：馬名、系名及追蹤名可更正，所有關聯使用永久識別。
3. **歷史只新增或更正，不靜默改寫**：退役、售出、接替、轉場、種牡馬更換及年度更正都保留事件。
4. **目前狀態由歷程彙整**：可由既有紀錄推導的年齡、顯示名稱、最新代數、群組數量及場地型摘要不重複人工維護。
5. **未知值不是零值**：`null`、空白、數值 `0` 與布林 `false` 必須保持不同語意。
6. **年度來源分權**：一月、四月、五月及七月資料只更新各自負責的資料範圍。
7. **使用者保有決策權**：系統負責計算、提示、阻擋錯系錯代與保存歷程，不替使用者選系、選馬或決定後繼。
8. **單檔離線運作**：正式成果不得依賴 CDN、網路服務、本機伺服器、瀏覽器擴充功能或 Cheat Engine 即時連線。
9. **先做垂直流程，再做完整廣度**：每個階段都交付可操作且可驗證的成果，不先建立大量無法串接的畫面。
10. **實作、驗證與使用者驗收分開記錄**：通過程式檢查不等於已取得實際遊戲資料驗證，也不等於使用者驗收。

## 單檔 HTML 內部結構

即使最終只有一個 HTML，JavaScript 仍按責任分區，避免介面、資料庫與遊戲規則互相直接修改：

```text
啟動與錯誤處理
    ↓
介面狀態與畫面控制
    ↓
應用服務與使用案例
    ↓
八系規則、代數、血緣與年度規則
    ↓
資料驗證、查詢及交易
    ↓
IndexedDB／JSON／TXT／TSV／CSV
```

### 分層責任

- **常數與列舉**：代數顯示、牧場編號、受胎狀態、配種評價、能力等級、場地適應力及各類狀態。
- **資料模型與驗證器**：建立紀錄、欄位型別、必要欄位、數值範圍及跨集合關聯檢查。
- **資料存取層**：IndexedDB 開啟、結構升級、索引、交易、分頁查詢及錯誤復原。
- **領域規則層**：代數成立、姊妹接替、現任種牡馬、年度狀態、八系建立、內循環配對及血緣檢查。
- **應用服務層**：新增母馬、離圈、配種、產駒、補名、匯入、更正、回溯、封存及還原等完整操作。
- **匯入匯出層**：文字解碼、表格解析、預覽、差異、JSON 契約、壓縮及完整性驗證。
- **畫面層**：儀表板、卡片、右側詳情欄、表單、篩選、通知、進度及鍵盤操作。

所有正式寫入只能透過應用服務進入資料交易。畫面不得直接操作 IndexedDB，匯入器也不得繞過領域驗證器。

| --- | --- |

| 系統 | 八個逐步建立的位置、子系統、親系統、代表色與建立狀態 |
| 馬匹 | 永久識別、跨階段不變的能力番号、目前生命階段、目前階段馬番号、階段馬番号歷程、名稱、父母、出生年及性別 |
| 種牡馬任期 | 所屬系、代數、預定後繼、現任期間、供用狀態及更換原因 |

| 配種組合年度值 | 父馬、母馬、遊戲年、總合評價與爆發力 |
| 年度繁殖紀錄 | 配種年度、受胎狀態、實際種牡馬、預定生產年與產駒連結 |

| 名稱別名事件 | 追蹤名變更、手動名稱及總表名稱取代歷程 |
| 後繼決定 | 姊妹候選、正式保留、取代對象及決定理由 |
| 匯入批次 | 檔名、雜湊、年度、時點、摘要、差異及套用結果 |

| 應用設定 | 活力門檻、少量介面偏好與資料結構版本 |

### 識別與隔離

- 所有永久識別保存為字串，優先使用 `crypto.randomUUID()`，不支援時使用具碰撞防護的本機替代方案。
- 所有領域紀錄帶有遊戲局識別與時間線識別，或具備可以明確解析其有效時間線的關聯。
- 能力番号在同一匹馬存續期間從幼駒、競走馬到繁殖牝馬或種牡馬都不變，是跨階段配對的主要外部識別。舊馬離場多年後遊戲可能回收此番号，因此它不是整個遊戲歷史的永久唯一鍵，也不取代應用程式永久內部識別。
- 馬番号屬於生命階段。幼駒、競走馬、繁殖牝馬與種牡馬各有自己的馬番号，轉換階段時保存新值並將舊值留在歷程。馬番号不得單獨作唯一鍵，也不得與能力番号組成跨階段永久組合鍵。
- 進入繁殖牝馬階段後，繁殖牝馬馬番号預期固定跨年度使用。這項穩定性只限繁殖牝馬階段，不可推論幼駒與競走馬也使用相同馬番号。
- 新時間線只繼承分支點以前的共同歷史，分支點以後的新舊資料由時間線解析器隔離。
- 同名馬、重用外部編號及不同遊戲局不得自動合併。

跨階段配對演算法固定採以下順序：

1. 以目前遊戲局、目前時間線及能力番号查找零至多筆目前或歷史候選，不假設整局永久唯一。
2. 以馬名、父母、出生年、性別與生命階段篩選。只有一筆相容候選時沿用既有永久內部識別，匯入馬番号依來源標成幼駒、競走馬、繁殖牝馬或種牡馬階段，並保留先前階段馬番号。
3. 同番号只命中已離場且身分明確不同的歷史馬時，視為能力番号已回收，建立新的永久內部識別。舊馬不得刪除或改號。
4. 同番号候選仍在繁殖圈、仍是現任種牡馬，或資料不足以區分舊馬回歸與番号回收時，停止該筆套用並列入衝突清單。
5. 能力番号尚未登記時，才以唯一馬名、父母及出生年作輔助配對。輔助配對後可以補入能力番号，不得覆寫不同的既有能力番号。
6. 舊版 `能力番号＋馬番号` 索引只保留相容性用途，不能優先於能力番号加身分核對，也不能作為新資料模型的跨階段身分。

### IndexedDB 索引方向

至少針對下列常用查詢設計索引：

- 遊戲局＋時間線。
- 系統＋代數＋目前繁殖圈狀態。
- 遊戲局＋時間線＋能力番号。
- 馬匹＋生命階段＋馬番号歷程。
- 父馬識別、母馬識別及出生年。
- 繁殖牝馬＋配種年度。
- 是否待補正式馬名。
- 匯入類型＋年度＋時點＋內容雜湊。
- 事件對象＋遊戲年＋發生時間。

結構版本從 `1` 開始。每次資料結構變更同時提供 IndexedDB 升級與 JSON 逐版遷移，不能只修改目前畫面可見欄位。

## 匯入管線規劃

所有文字快照採同一條安全管線，但由使用者先明確選擇「一月二歲馬」「五月繁殖牝馬」或「七月受胎確認」：

```text
選擇檔案與資料時點
→ 讀取 ArrayBuffer
→ 依 CP932／UTF-8 解碼
→ 辨識 Tab 或 CSV
→ 核對欄數與必要欄位
→ 正規化但保留原值
→ 依能力番号辨識同一匹馬
→ 將馬番号標記為來源生命階段並建立歷程
→ 建立配對與差異預覽
→ 執行領域規則驗證
→ 使用者確認
→ 單一交易套用
→ 顯示結果與備份提醒
```

### 共通要求

- CP932 `.txt` 是第一版必要支援格式，UTF-8 作為相容輸入。
- 解碼、分隔符號或欄數無法可靠辨識時停止，不嘗試猜測資料用途。
- 匯入預覽必須分開顯示可套用、忽略、待人工核對、警告及錯誤。
- 完全相同的年度與時點快照依內容雜湊阻止重複寫入。
- 相同年度與時點但內容不同時，必須進入「資料更正」或「讀檔回溯／重玩」選擇。
- 任一阻擋錯誤發生時不寫入正式集合，既有資料與畫面狀態保持不變。
- 同一檔案內能力番号重複時拒絕套用。馬番号相同或不同都不能解除能力番号重複衝突。
- 同一能力番号命中既有馬匹時，必須再核對名稱、出生年、父母、性別及現役狀態。身分相容才沿用原永久內部識別，匯入的不同馬番号作為新階段馬番号。
- 同番号只命中已離場且身分明確不同的歷史馬時，允許建立第二筆具有新永久內部識別的馬匹，代表遊戲已回收能力番号。備份與索引必須支援歷史能力番号重複。
- 正式套用只保存必要來源摘要，不長期保存完整原始二歲馬總表。

### 四個年度時點

| 時點 | 權威責任 | 明確不得處理 |
| --- | --- | --- |
| 一月二歲馬 | 以能力番号銜接既有幼駒，保存競走馬馬番号並替產駒補正式馬名 | 不要求競走馬馬番号與幼駒馬番号相同，不新增非本牧場馬匹，不變更持有或售出狀態 |
| 四月誕生幼駒 | 建立本年度實際出生幼駒，保存幼駒馬番号，連結父母及前一年度繁殖紀錄 | 不建立非管理母馬產駒，不猜測父母或性別，不改寫受胎結果 |
| 五月繁殖牝馬 | 以能力番号銜接既有競走馬，保存繁殖牝馬馬番号，補齊父馬、母馬與父馬所屬系統，處理繁殖圈名單、據點、活力、增強狀態、仔出、繁殖年數及繁殖頭數 | 不要求繁殖牝馬馬番号與競走馬馬番号相同，不把受胎欄位寫成正式結果，不把父系寫成培育目標系 |
| 七月繁殖牝馬 | 正式受胎狀態及實際配種種牡馬，並補齊仍空白的父馬、母馬與父馬所屬系統 | 不重跑新進、回歸、售出判定，不覆寫五月快照或不同的既有非空血統資料 |

## 開發階段

### 階段 0：需求基準與可追蹤性

**目標**：確保後續每項功能都能追溯到需求與驗收情境。

工作內容：

- 將需求文件標記為第一版需求基準。
- 建立本開發計畫並確認不含未授權的 HTML 實作。
- 實作開始時建立驗收追蹤表，目前共 200 項，記錄「未開始」「已實作」「已驗證」「待真實樣本」「使用者已驗收」。
- 把需求變更記為追加決策，不直接刪改已產生資料的既有語意。

完成條件：需求沒有阻擋問題，計畫、需求與 README 的狀態一致。

### 階段 1：應用骨架、資料庫與備份核心

**目標**：建立可以安全保存空白局與基本資料的單檔應用骨架。

工作內容：

- 建立 `src/WPStudBook.html`，完成離線啟動、全域錯誤提示與基本版面骨架。

## 驗證計畫

### 資料與規則驗證

- 驗證所有識別唯一性及父母、系統、接替、年度紀錄的參照完整性。
- 驗證同一能力番号跨幼駒、競走馬、繁殖牝馬或種牡馬階段只對應一個永久內部識別。
- 驗證階段轉換時馬番号可以改變，原階段馬番号、階段、遊戲年及來源保持可查。
- 驗證能力番号相同但馬番号不同時仍視為同一匹馬，能力番号不同但馬番号相同時不得合併。
- 驗證同一繁殖牝馬跨年度重複匯入相同繁殖牝馬馬番号時不建立重複歷程。
- 驗證同一母馬同一生產年度最多一匹產駒。
- 驗證四月誕生幼駒只建立受管理母馬的唯一配對結果，並連結前一年度繁殖紀錄。
- 驗證四月樣本未提供時，選檔與拖放都不會誤用其他年度解析器或寫入資料。
- 驗證同父同母候選只有一匹正式保留者。
- 驗證每系同一時點只有一匹現任種牡馬。
- 驗證已成立代數不因在圈數量變成零而消失。
- 驗證自由配種產駒必定待售且不能成為正式後繼。
- 驗證五月缺席自動售出不覆寫已手動登記的退役。
- 驗證受胎 `0`、`1`、`2`、`3` 與未知值完全分離。
- 驗證數值 `0`、空白及布林否在 JSON 往返後不互相轉換。

### 匯入匯出驗證

- 空白局、一般局、特殊字元、日文馬名、中文備註及大量資料 JSON 往返。
- `.json` 與支援時的 `.json.gz` 往返。
- 舊版格式逐版遷移與未來版本拒絕。
- 截斷 JSON、錯誤 gzip、重複識別、缺少父母與集合筆數不符時拒絕匯入。
- CP932、UTF-8、Tab、CSV 引號、逗號、空白、換行與錯誤欄數。
- 相同檔案重複匯入、同時點資料更正及讀檔重玩分流。
- 匯入前後比較各集合筆數、永久識別、關聯、狀態、別名與關鍵欄位。
- 以同一能力番号及三個不同階段馬番号依序完成四月幼駒、一月二歲馬與五月繁殖牝馬往返，確認只有一筆馬匹主體且三段番号歷程完整。
- 分別用候選 TXT、五月及七月繁殖牝馬匯入驗證父馬、母馬與父馬所屬系統可保存。手動留空資料由五月補齊，七月只補空白，任何不同非空值都進入衝突清單。
- 驗證只有父母姓名而沒有 `fatherId`／`motherId` 時，概要與血緣頁籤仍顯示匯入父母及父馬所屬系統，並清楚標示尚未連結內部馬匹。

### 介面驗證

- 以最新版 Edge 與 Chrome 直接開啟正式 HTML。
- 桌面、多欄卡片、平板與窄螢幕單欄。
- 篩選單獨使用及多條件交集，不顯示其他系或其他代資料。
- 詳情欄的滑出、欄外點擊、`X`、`Esc`、焦點移入與返回。
- 鍵盤完成主要表單，錯誤訊息與欄位建立可理解的關聯。
- 顏色之外仍有狀態文字或輔助標記，避免只靠藍色、洋紅色或灰色判斷。
- 重新載入後保持目前遊戲局與已保存資料，不依賴網路。

### 效能驗證

- 使用一萬、三萬及五萬筆綜合關聯資料逐級測試，不把這些數量當成遊戲硬上限。
- 記錄啟動、系代篩選、關鍵字搜尋、卡片重繪、血緣展開、JSON 匯入與匯出的實際結果。
- 若大量資料造成明顯凍結，優先調整索引、批次處理、分頁與虛擬清單，不刪減歷史資料規避問題。

## 主要風險與處理

| 風險 | 影響 | 計畫處理 |
| --- | --- | --- |
| `file://` 路徑或瀏覽器設定檔改變 | IndexedDB 看似消失 | 固定正式路徑、顯示備份狀態、關鍵操作後提醒匯出 |
| 未涵蓋據點或時點的實檔欄位與現有樣本不同 | 匯入器無法直接套用 | 欄數與必要欄位先驗證，保留預覽，收到真實樣本後做相容修正 |
| CP932 解碼或欄位內容異常 | 日文馬名損壞、錯配 | 以 ArrayBuffer 解碼並在套用前顯示原文預覽，不可逆亂碼時停止 |
| 外部編號在不同局或重玩後重用 | 馬匹錯誤合併 | 配對範圍加入遊戲局、時間線與共同歷史節點 |
| 將馬番号誤當跨階段唯一識別 | 幼駒轉競走馬或退役轉繁殖時建立重複馬匹 | 以能力番号取得跨階段候選，馬番号按生命階段保存歷程，禁止馬番号單獨合併 |
| 能力番号在舊馬離場後被遊戲回收 | 數百年後的新馬被合併到舊馬 | 能力番号查找後再核對馬名、出生年、父母、性別與狀態。身分明確不同且舊馬已離場時建立新永久內部識別 |
| 舊馬可能回歸且番号也可能回收 | 同番号資料無法判定新舊身分 | 同名與相容身分資料視為舊馬回歸。證據不足或舊番号仍由現役馬使用時停止自動套用，不刪除任一歷史紀錄 |
| 舊資料缺少能力番号或已有歷史重複能力番号 | 無法安全自動銜接 | 只允許唯一馬名、父母與出生年輔助補值。多筆候選無法由身分資料唯一化時進衝突清單 |
| 八系規則與實際父母不一致 | 近親或錯代沿續 | 規則任務與實際血緣雙重檢查，資料不足不顯示安全 |
| 單檔 HTML 持續變大 | 維護與除錯困難 | 內部明確分層、集中常數、避免重複模板，發布前檢查來源與交付檔一致 |
| 瀏覽器不支援 Compression Streams | 無法產生 `.json.gz` | 自動退回完整 `.json`，備份流程仍可完成 |
| 大型 JSON 造成畫面凍結 | 使用者誤以為失敗 | 分批處理、顯示進度、交易前驗證、失敗保留原資料 |
